# 自动选测与完整验证

Refs: D173。当前默认是 **shadow 对照模式**，完整检查仍为合入门禁。

## 本地使用

| 入口 | 作用 |
| --- | --- |
| `make check-plan BASE=main` | 生成计划，不执行检查；始终包含覆盖基线到当前源码的累计差异 |
| `make check` | 完整检查，然后执行可缩小的选择集合；计划要求全量时复用完整结果 |
| `make check-full` | 原有完整 Go/race/Web 检查 |
| `make check-baseline` | 在干净的已提交源码上完整验证，再逐包编译、逐根隔离采集覆盖 |
| `make check-benefit` | 读取 `.local/impact/cases.json`，在独立临时 clone 内做五 PR 回放 |
| `make check-faults` | 在索引对应的精确版本注入状态规则、事务回滚、HTTP 和 Web 反例，核对全量失败根是否被选择并实际执行 |

`IMPACT_INDEX` 默认 `.local/impact/index.json`；`IMPACT_REPORT` 默认 `.local/impact/result.json`，同目录的 `plan.json` 记录选择理由。计划及结果包含源码提交、完整源码指纹、语义构建配置、执行状态和阶段耗时；执行前后变化则失效。`TEST_COUNT=1` 强制重跑，`0` 保留原生结果缓存。CPU、分片和隔离预算沿用现有检查器。构建标签、工具链和语义编译选项必须匹配，调度器注入的并行编译预算不改变语义配置；持久化计划在配置变化时失效并恢复完整 Go 检查。可完整归属的包使用 race、atomic coverage，每包只编译一次，每个 Test、可执行 Example、Fuzz seed 根分别启动独立进程；不会持续 fuzz。进程边界包复用普通全量的逐根 run/pass/skip 记录，明确记作静态回退，不再单独启动无法完整归属的进程树。普通全量缺少任何根的执行事件都会拒绝发布索引。

试验可以显式运行 `make check CHECK_MODE=affected`。此入口仍保留 Go 静态检查、协议和 CLI 能力覆盖门禁；Web 变化保留类型、lint、格式、样式、构建检查。Web 通过当前 Vitest 的模块依赖图发现文件，空匹配扩大到完整 Web 清单，不以通用“无测试也成功”选项放行。它不替代当前完整合入门禁。

## 选择与扩大范围

索引记录根测试执行过的完整函数。函数体变化选择所有历史调用者，即使改变的是当时未覆盖的分支。函数身份由包、接收者类型和名称构成，行号只用于将原始覆盖映射到采集时的函数。测试自身变化至少运行自身；helper 或共享声明变化运行包内全部测试。存在包级变量、无法证明测试间状态隔离的相关测试包保留完整集合。签名、类型、常量、全局变量、初始化和文件清单变化扩大到生产反向依赖及直接使用这些生产包的测试；测试 import 不继续作为生产边传播。

缺少历史执行的函数、进程边界和未知资源保守扩大。进程边界沿生产依赖传播，测试依赖仅作为终端；不能将未归属的子进程当作零依赖。父测试启动的程序未必存在 Go import 关系，因此任意源码或资源变化时保留全部进程边界和资源读取测试包。跳过的根保留静态依赖。迁移、协议基础定义、依赖和工具链、选择器及构建配置变化要求全量。基线缺失、损坏、不兼容或非祖先也要求全量。源码清单包含 staged、unstaged、未跟踪的非忽略文件，以及 Go 实际编译和嵌入的忽略文件。

Web 配置、锁文件、setup、mock、snapshot、CSS 和未知资源回退完整 Web。前端运行代码、资源及公共浏览器设施变化保留全部现有浏览器回归；能独立对应的脚本变化选择对应的必需回归脚本。本地完整集合不新增浏览器与交叉编译；CI 保留浏览器和 Windows/macOS 构建。

Web 源码中出现文件系统、子进程等模块标识时，模块图无法证明其读取数据的范围。首版对此采用完整 Web 回退，任何源码变化都保留这些检查，包括读取 Go 文件的跨语言测试。识别来自源码，不维护测试名称标签；这项保守回退的成本计入实际收益。

## CI 基线与 release

PR 使用事件的不可变合入候选 SHA，所有任务检出同一 SHA；base 推进后必须重新获得该合入候选的检查。main push 也重新计算累计影响。汇总门禁要求全部必需任务真实成功，普通 skipped、缺失结果或失败不算通过。shadow 的全量回退由必需完整任务承担，独立 job 记录明确的复用理由。

`impact baseline` 工作流只在 main 生效。它在串行刷新真正开始时读取当前 main，恢复最近成功基线，按提交祖先范围查询 GitHub 已合入 PR 关联，以不同 PR 计数；一个 rebase PR 的多提交只计一次。第 5 个 PR 后完整验证、采集、浏览器和交叉编译全部成功才发布索引。刷新不中断，待处理请求合并；刷新期间的新提交只在下一次祖先区间计数。最近两份成功索引保留，过期、下载失败或配置不兼容回退全量。全量失败不会推进计数，也不会被后续成功的无操作检查清除。没有夜间定时任务。

release 从 main 手动触发 `ci`，选择 `mode=release`，`ref` 必须是完整提交 SHA。发布前必须核对该次工作流完整成功，以及 `validation` 产物里的候选 SHA、模式和完整验证状态；仅检查 main 的最近一次绿色状态不足以证明指定版本成功。本功能不改变业务协议、升级协议或 release manifest。

## 回放与验收

每个候选在第一组计时前统一准备普通及 race 构建缓存和 Web 模块缓存，准备命令不执行测试断言，也不填充测试结果缓存。`Preparation` 单列编译、依赖安装和模块收集，`CommonDependencySeconds` 将共同依赖成本同时计入两种策略；编译缓存准备是实验控制成本，单列报告，不能当作选测节省的时间。报告同时保留历史根执行成本供计划估算参考。

样本清单格式如下；SHA 均必须是完整 SHA，五个 PR 必须按祖先关系连续，准备清单时另核对 GitHub 合入记录。

```json
{
  "Baseline": "<cycle-start-sha>",
  "Cases": [
    {"PR": 1, "Commit": "<first-merged-pr-tip>"},
    {"PR": 2, "Commit": "<second-merged-pr-tip>"},
    {"PR": 3, "Commit": "<third-merged-pr-tip>"},
    {"PR": 4, "Commit": "<fourth-merged-pr-tip>"},
    {"PR": 5, "Commit": "<fifth-merged-pr-tip>"}
  ],
  "Web": {"PR": 6, "Base": "<extra-web-pr-base>", "Commit": "<extra-web-pr-tip>"}
}
```

额外 `Web` 样本可省略；需要补充时必须提供其真实 PR 起点，独立建立覆盖基线并单列成本，不能将较新的索引用在非祖先版本上。

回放保存真实初始和刷新索引；每个候选三组全量/选测交替配对、显式关闭结果缓存，再单独记录周期末原生缓存首次与暖缓存结果。报告分开列出首次建基线、后续刷新、源码分析和执行阶段、墙钟与 CPU 时间以及开始/结束系统负载。`NetSeconds` 是包含第五次完整刷新的稳定周期净值，`BootstrapNetSeconds` 另计初次采集和工具准备成本。正数才表示节省时间。长回放可以通过 benefit 子命令的 `-resume <prior-report>` 复用完整成功且源码、配置、CPU 预算与清单均匹配的初始基线；所有配对重新执行，原始采集成本和来源指纹保留，不能把失败或未完成采集当作已建立基线。首次成本不能从报告中省略，不能从本机数字推算 CI 收益。

仅有“两边都绿”不能证明没有漏选。正确性验收还必须包含真实失败反例的全量失败根集合与选择集合对比、缺失/损坏索引、跨多 PR 累积、声明、helper、构建约束、Example 输出、Fuzz seed、进程、超时和取消。没有全部正确性证据及正向周期净收益就保持 shadow。测量失败同样保存，不作为绿色或性能提升证据。

回放中，具备本轮完整执行收据的失败测试仍保存并继续收集后续配对，报告逐轮保存 `Success`、`Error`、`Execution`。`Completed` 仅表示采样完成；`Validated` 才表示所有必需样本成功。任何失败使最终命令非零退出，`Failures` 保留失败，且不产生可验收净收益。缺失、过期或矛盾收据、源码漂移及取消立即终止。刷新失败不推进索引，另单列 `MissingBaseline` 的真实全量回退耗时。

原生缓存观测按 full、affected 的固定顺序执行，后者会共享前者已经填充的 Go 测试结果缓存；首轮及后续暖缓存均单列。这部分用于展示顺序运行的日常缓存表现，不能用其差值宣称两种策略的收益。收益对照只使用关闭结果缓存的交替配对。

Go 测试也可能将 Web 文件、文档或其他仓库资源当数据读取。首版将 Go 的文件系统、原生系统调用和源码读取模块导入（包括 `os`、`io/fs`、`io/ioutil`、`path/filepath`、`syscall`、`golang.org/x/sys/unix`、`go/parser`、`go/build`、`C`）保守视作文件系统边界，并保留已有的 Go 源码字符串识别。资源读取与进程边界沿生产依赖传播，测试依赖只作为终端；任意源码或资源变化都运行这些测试包。该规则不能只限于 Go 文件变化，也不能假设 Web 文件只由 Web 测试读取。

已完成的真实故障注入、修复前资源漏选及修复后的双侧原生事件见[正确性报告](findings/test-impact-correctness.md)及[机器可读证据](findings/test-impact-correctness.json)。这些正确性结果不替代收益与完整门禁验收。

收益不足时的测试集合审计见[重复与昂贵前置流程报告](findings/test-redundancy-audit.md)。其中包含具体合并候选和原始测试 CPU profile，尚未实施删减，不将候选成本当作已获得收益。

文件系统边界在完整 Go 依赖图中传播，包含第三方依赖和仅测试导入的依赖。Go `-overlay` 会使用清单指定的替换内容进行构建（见 [Go 官方说明](https://go.dev/src/cmd/go/internal/work/build.go)）；清单、替换内容及原始磁盘输入共同进入身份。首版对 overlay 始终完整验证，并拒绝建立函数覆盖基线；启用后不能用函数映射缩小范围。

Go `-modfile` 的有效清单与 sum、活动 `go.work` 与 sum，以及实际构建的本地替换模块源码、原生文件和嵌入资源也进入身份。alternate module/workspace 首版只运行完整验证；本地可变依赖按不透明资源边界处理。路径不变而内容变化必须使既有计划失效，不能出现空选通过。依赖解析可能创建 sum，清洁状态在解析完成后确认。

当计划包含当前全部 Go 根及完整 Web 时，`LocalFull` 明确记录本地完整集合等价，shadow 与 affected 复用一次完整验证结果。浏览器和交叉编译继续使用各自计划，单个浏览器脚本变化不会因此扩大为其他脚本。该复用只消除重复执行，不代表减少原有完整门禁成本。

资源软链接读取目标内容及执行权限；目标不在普通源码清单中时额外绑定身份，已覆盖目标保持原有指纹。链接模块按有效内容识别文件读取边界。目录、悬空和循环链接无法建立精细依赖，首版完整验证并拒绝函数映射基线。选测直接运行本轮编译的 race 调度器，取消时先通知调度器清理其独立子进程组，再应用有界终止。
