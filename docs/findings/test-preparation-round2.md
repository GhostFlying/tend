# 公共测试准备与剩余长流程

Refs: D151。承接[第一轮](test-setup-deduplication.md)，保留完整race门禁、业务根、子场景及现有CPU预算。固定源码的完整前后墙钟、累计CPU、测试清单和最终候选CI结果统一记录在[PR #241的验证部分](https://github.com/GhostFlying/tend/pull/241)。包级或采样数据不能替代整轮结果。

## 已实施的准备精简

- 从storefixture抽出不依赖store或数据库驱动的dbfixture，只共享通过真实建库、关闭并确认WAL已清空后的不可变字节。各副本仍有独立文件、连接、时钟和原文件目录，既有目标文件不能覆盖，首次初始化失败保持失败。
- Store普通事务/投影测试复用模板，迁移、历史升级和专门的建库/重开用例保留原路径。dispatch、views、Telegram和Feishu的普通准备复用当前schema空库，绑定、投递、回调、重连、故障与持久化断言不变。
- App索引重建对照的四个场景复用初始空库；仍执行真实索引SQL、关闭及重开，比较完整视图和原始历史，并核对查询计划。历史schema82升级由原有Store迁移测试继续验证。
- 只为原生日志中未登记且至少八秒的14个未修改App根增加固定放置提示；分片数不变，测试集合仍由动态发现决定。调度收益与减少计算量分别核算。

## App公共准备采样

采样源码为`7970ab961a1f1f636c8bc067972ef6a64fc941d5`，Go 1.27.1、race、GOMAXPROCS=2、count=1；预先编译，运行fixture并发隔离、100条来源的有界review，以及四场景usage索引对照三个真实测试根。

该样本墙钟78.71秒，CPU采样总量79.05秒。配置同步与公共计数路径合计约0.29秒，占样本约0.37%；newHarness累计7.49秒主要包含第一次空库模板初始化。store.Open累计28.37秒，其中迁移26.47秒，四场景索引对照逐场景重新建空库是可明确消除的重复准备。

这是特定测试根的采样，不能推广成全部App测试的固定占比。当前证据不足以支持额外配置快照及ID序列恢复机制，本轮不引入它们。

## Sandbox与浏览器审计边界

- Sandbox的真实Owner API/runner用例验证启动、种子重放和真实交互；story用例验证多轮推进及repair后的恢复；retained-data用例验证进程重启、心跳和未完成问题的继续处理。三者已使用快速节奏，存在准备重叠但未发现可以直接删除的相同合同，本轮保持原样。
- 浏览器仍保留14个必需脚本。完整issue-surfaces和`--navigation-only`虽共用文件，实际进入不同分支；后者验证五个断点的导航。copy-only诊断子集原本就不在CI集合中，不能再次删除并计为收益。ui-tour还包含离线、Service Worker及懒加载失败恢复，不能仅按页面名称与局部布局回归去重。
- 已通过的第一轮候选CI中，按相邻命令启动日志估计ui-tour约102秒、issue-detail约81秒、issue-surfaces约71秒、usage约64秒，包含命令切换开销，并非逐断言CPU测量。它们是后续浏览器准备/交互采样的优先对象，尚未获得该部分的实测加速。

## 验证记录

新增未checkpoint的WAL拒绝与模板临时目录清理验证，继续执行已有并发数据库隔离、文件隔离、既有文件保护、首次初始化失败保持及新鲜schema一致性验证。原有Store事务回滚各故障切点全部保留。
