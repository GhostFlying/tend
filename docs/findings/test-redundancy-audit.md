# 测试重复与昂贵前置流程审计

本次按 D172 收益回放期间的补充要求分析，审计源码为 `5c018f2d` 的 Go 测试及生产依赖；后续报告编辑不改变被审计的 Go 源码。本次没有实施业务测试删除、断言削弱或生产 SQL 优化，候选尚无删减后的实测收益。

## 已确认的重复与优先顺序

## 当前测量证据

真实覆盖基线的普通/隔离执行根耗时：看板分页595.00秒、关系查询221.39秒、sandbox综合471.74秒、聚合四阶段回滚64.88秒；两个工作区 E2E 根分别31.67/32.09秒。这些是同一旧基线上的原生根耗时，受当时机器负载影响，不是当前候选墙钟预测；存在分片并行，禁止相加后宣称会缩短整轮同等秒数。

仓库原有[长尾调查](../plans/race-tail-latency.md)也记录过：看板分页约280秒，其中231条准备约260秒。该历史采样没有形成一次完整检查通过，本文只把它用作成本线索，另对原始未修改测试进行 CPU profile 核对。

## 自动扫描的边界

按当前普通构建配置的 `go list -json ./...` 取得 TestGoFiles/XTestGoFiles，用 Go AST 格式化函数体并按包和 SHA256 分组。扫描2537个 Test/Example/Fuzz 命名声明，以及465个非平凡字面量 t.Run 函数体，没有发现同包内函数体完全一致的组。该扫描不把未输出 Example、动态子测试或 integration 的声明数当成实际执行清单，也没有分析 Web 测试的语义等价。

零个语法完全重复不代表零个语义重复。上述 E2E 前置流程属于同一个 helper 被不同参数重复执行，函数体哈希自然不会发现。覆盖同一函数、名称相似或共享 helper 都只能提供候选；断言、边界和故障检出能力才决定是否可以删减。

## 已排除的直接删除建议

- `TestFinishedTaskPages` 与看板分页不能直接互相替代：前者走 `finished=1` 和 `ListFinishedTasks`，后者走 `all=1` 和 `ListTaskPage`，HTTP输入、筛选和游标分支不同。
- `runRunnerManager` 的正常、单 slot 派发、rate limit 接续和丢失 start 回执四种参数改变实际故障与资源路径，完整根不构成重复。可单独缩短共用准备，但不能只保留绿色正常路径。
- `TestCommittedMaintenanceProductionAssembly` 与 receipt recovery 变体验证不同的持久化不确定状态、授权和启动屏障。共同 helper 不证明重复；真实子进程隔离保护环境与进程身份。
- CLI、HTTP 和 Web 决策流程分别验证命令分派/输出、协议、会话与流式回送，不能仅因最后都将任务取消而删除跨端验证。
- migration、历史协议读取、unknown、独立验收和取消清理各自保护不变量；本轮运行失败不等于测试多余。纯 domain 状态表通常很便宜，优先级低于反复建库、创建大集合和重启进程。

## 后续删减的验收

对优先候选先列出被移除段落的独有断言及接替测试，再注入相关故障：游标停滞/截断、筛选丢失、逐关系扫描、复用首次跳过评审资格、重启后换 pin、各事务阶段泄漏、脚本中断后继续回调。保留测试应实际失败，而非两边都绿。随后在同版本、同 CPU 预算、相同缓存条件下比较完整检查，单列根执行成本与整轮墙钟；未完成这些步骤前，候选节省量均保持未知。
