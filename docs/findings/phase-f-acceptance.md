## F7 评审与恢复边界

独立评审中确认的七个问题均已修复并回归：

1. 初始视图读取失败时有限退避重试，即使 SSE 仍健康也能恢复；重连后重新读取。
2. 实时旧消息更新不污染连续历史分页边界。
3. 长轮次超过最新会话页时仍保留处理中的 owner 消息和停止入口。
4. 当前 run 的日志使用可取消长轮询，不依赖 ledger 事件。
5. 历史分页使用稳定消息 DOM 锚点，不将同时发生的末尾输出计入前插高度；回到底部时恢复自动跟随。
6. 停止请求持久化完整 envelope 和 request ID；重连先查询原请求，无记录且 HTTP 尚未确认时才按原 ID 恢复投递。已记录的 accepted、succeeded 或业务 unknown 只对账，不重发新中断。
7. 不同轮次的停止请求独立投递，旧 HTTP 响应不阻塞新轮次，也不能覆盖新状态；同一请求仍合并在途调用。

未采纳未发布开发版本地存储格式迁移的建议：部署前线上尚无 Web 客户端，没有该格式的存量用户数据。

行内代码中的任务 ID 显示为可点击任务标签，围栏代码保留字面内容。生产构建探针验证历史分页阅读位置误差为 0px，手动回到底部与显式跳到最新都能继续跟随。

CI 还暴露了既有 orca 故障测试的同步竞态：测试可能在 worker 续接前模拟完成，随后续接把假 agent 改回 working。测试改为先等待新 continuation 实际送达，并使用有界 context；生产 worker 未改。

## 浏览器与真实模型

使用生产构建的嵌入式服务和真实 CSP，验证桌面、平板及手机尺寸下的任务标签、展开工具、任务控制、两种待决回答、离线外壳和不缓存 API。交互边界使用 API fixture 与真实本地 SSE。

另在隔离账本上使用真实托管模型、未模拟的 owner API 和两个独立 Chromium context 验证：

- 一端发送，两个 context 收到同一真实回复。
- 离线发送，确认本机持久化回显后刷新，联网恢复；账本只有一条该消息。
- 真实长回复处理中，断网点击停止，离线刷新、联网刷新后沿用原 envelope 和 request ID。独立 SQLite 读回只有一条该中断请求。
- 目标消息最终 interrupted，下一条正常 replied；四条 owner 消息最终为 replied、replied、interrupted、replied，浏览器运行时错误为空。

该真实模型轮次验证的是跨刷新恢复；最后的跨轮次在途请求修复另由故意悬起旧 HTTP 响应的回归测试覆盖。
