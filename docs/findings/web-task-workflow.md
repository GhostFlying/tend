# Web 任务工作流与后续关系（D75–D77）

## 交付行为

- 全部任务按六个生命周期阶段展示；每列独立分页，项目过滤支持历史任务，侧栏与窄屏入口可查看最近完成。
- 详情优先显示当前阻塞、当前验收问题、真实待决操作和控制动作；已完成任务突出当前交付。完整要求、工作区、标识和历史记录可展开。
- 每个新完成转换同事务写入系统会话事实，重启、请求重放与重复 verdict 不重复通知。通知经 SSE 同步，不自动启动模型；下一轮 delta 或完整上下文可读。
- 任务定义支持 follow_up 与 related 声明，创建和修改均走去重及事务；修改关系校验 revision，双向可读，不重开原任务。后续任务拥有独立要求与验收，需显式确定代码基线。
- 已完成详情的“跟进 / 修改”将原任务引用加入聊天草稿，保留已有输入并聚焦；owner 补充后手动发送。任务关系支持跳转到活动或历史任务。

## 评审修复

独立评审复现并修复五项问题：当前产物使用服务端身份而非跨产物验收代次排序；隐藏聊天暂停历史分页并保存阅读锚点；连续账本事件合并到进行中的读取之后；旧版创建请求省略新增空字段以保持请求身份；反向关系变化同事务通知目标任务，使跨项目上下文不会保留已移除的关联。

另修正草稿中的实际换行，以及看板将下一实现代次误标为当前代次的问题，卡片改为展示 spec 版本。

## 验证范围

Go 验证覆盖事务故障回滚、旧 spec 和重复结果、请求重放、完成通知 SSE/重启/下一轮上下文、不自动推理、超过 200 条任务分页、关系循环和跨项目 delta、迁移前数据保留。统一检查包括 Go race、vet、staticcheck、协议生成一致性，以及 Web 类型、lint、格式、测试和生产构建。

生产构建浏览器 fixture 覆盖桌面、平板和窄屏明暗主题；各列分页、过滤迟到响应、持续事件和慢请求、当前与历史验收、待决操作与 revision、详情返回、聊天草稿、系统消息插入、后续入口及四种关系方向。300 条消息场景验证隐藏后不继续翻页，返回阅读位置误差不超过 1px。界面 fixture 不调用真实模型，不创建 worker workspace。

关系新增数据库迁移 23。恢复准备使用先前服务版本加同一追加迁移的兼容构建，在隔离账本副本验证新表写入后仍可启动旧行为、读取既有任务、保留关系并重新切回候选版本；不以直接启动不支持新 schema 的旧二进制作为回退方案。
