# 调查与独立验收的现场事实

需要核对 Tend 生产内部状态的任务，在创建或更新 spec 时声明最小读取范围：

```json
{
  "observation": {
    "work_item_ids": ["<target-work-item-id>"],
    "deployment": true
  }
}
```

这部分由调度者明确指定，不从仓库名、follow-up 关系、共享背景或报告推断。只读某工作项不必开启 deployment；只核对部署也不必选择工作项。缺少该字段的旧任务不获得新权限。未知工作项、重复 ID 或空授权范围在 spec 校验时拒绝。

具备 `worker-observation-v1` 的 runner 向两种角色提供无参数的 `read_observation` 工具。服务端按调用 run 的精确 spec 读取范围；工具不能临时申请另一个 ID。两个角色应各自读取并保存返回 JSON，记录水位、采集时间、spec 和生产版本。旧 runner 不领取此类任务，升级后恢复领取；界面保留明确的能力排队原因。

快照提供指定工作项的计划状态、执行投影、关联任务及必要运行事实、持续责任状态。它不包含共享背景、详细设计、消息、产物报告、凭据或文件系统路径。授权撤回或 spec 更新通过正常任务变更处理；旧 run、终止或过期租约不能继续读取。

部署部分分别记录当前服务进程身份、已安装迁移版本和最近升级记录。最近批次完成不自动证明进程运行该版本；须核对实际进程 hash 和安装回执绑定。未配置受控更新器或证明不可用时按返回的 unknown/unavailable 状态记录，不能补写推测。

## 验收边界

此工具核验服务端事实，不授予浏览器登录、SSH、owner API 或生产变更权限。需要验证 UI 时可使用生产事实驱动隔离的真实组件，明确标注这不是生产登录页面的实测；要求实测生产页面的任务必须另行安排对应的受限浏览器环境或由 owner 侧采集证据。其他系统的状态也不在此工具范围内。

调度前先确认每项验收的事实来源和读取渠道。不能要求 worker 寻找 owner 凭据，也不能等到验收失败后悄悄把必须检查的内容改成可选。现场在两次调查之间升级时，保留旧报告的版本范围；需要回答“现在是否存在”则更新任务范围并重新调查，不能只用旧报告重试新版本验收。
