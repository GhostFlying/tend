# Worker 执行过程浏览（D117）

任务详情的执行过程卡片可选择具体实施/验收 run，保留原 run、代次及正式执行状态；不会把文本中的成功、工具退出或可见最后一条记录当作任务完成。收起显示当前动作与步骤耗时（有可靠时间时），展开默认显示最近六步，可继续显示更早步骤。点击步骤只展开该步；“查看完整过程”打开桌面宽面板或手机全屏，步骤旁的详情入口定位该步。返回按钮、Esc 和浏览器返回关闭完整过程，原卡片展开状态、焦点和阅读位置保留。

两种模式共用步骤投影和一个数据请求所有者：同一原生 thread/turn/item 的开始及完成组成一个步骤，正文按 Markdown 阅读，工具默认一行摘要，展开查看输入输出。身份不足的历史记录保留独立行，禁止猜测配对。原始记录、run ID、水位及采集说明在显式详情中查看。卡片与完整模式不提供另一个显示模式开关。

步骤耗时只显示执行器明确提供的 durationMs；持久记录的 created_at 是服务端接收时间，不推导执行时长。暂停历史阅读只停止过程追加，正式 run 状态仍从任务详情更新，不将缓存窗口中的旧状态作为当前状态。任务详情不再预取旧 logs 尾页或启动另一条日志监听；CLI 等现有 logs API 调用保持可用。

owner 读取 `GET /api/v1/runs/<run_id>/rollout` 获取持久窗口：默认最近 100 条，`before` 读取较早窗口，`after` 读取较新窗口，两者不能同时给出。返回有序 `logs`、首尾游标、全局 run 水位和两侧是否还有记录。缺口、截断、未提供原生 ID 和来源覆盖边界都保持可见；空的较新页沿用原 after 游标。

历史与 live 共用同一个步骤组件及 API。live 以持久 seq 去重追加，每两秒读取较新记录；有积压则继续追到水位，最多保留 400 条可见记录，更早内容可分页。完整模式底部跟随新内容，向上阅读暂停跟随；“回到最新”恢复。加载更早内容保留可见步骤锚点。暂停跟随保留当前阅读窗口，恢复或重新连接沿持久游标读取，不重新执行原生操作。请求失败保留已读内容并重试；切换 run 或卸载取消旧请求和计时器。模式切换本身不重读最新窗口，查看某个历史步骤时保持历史阅读。

当前 TraeX 上传 turn/item 开始、completed item 和 turn 结束，已知子 thread 的持久事件保留独立身份。正文 token delta 不作为持久片段上传。工具、命令和 Agent 回复作语义展示，原始已采集 JSON 可展开；传输层原本已截断的内容无法由展示恢复。Orca 既有状态、恢复和摘要仍可查看，但不能称为其完整 provider transcript。不读取宿主机其它会话或历史文件补齐。

同一 run 的“本次用量”读取消费请求账本，全生命周期累计与全局时间筛选分别表达；缺失不视为零，具体计量和来源限制见 `docs/token-usage.md`。本改动不改变调度、owner 决定或正式完成条件。
