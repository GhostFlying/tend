# Issue 活动身份与过程入口

## 合入后独立验收超时诊断

原 main CI 的 Orca 子例在等待独立验收完成时失败，但既有 artifact 只有逐例 JSONL，没有 fixture/journal；有限本机原例、观测副本、前序用例及原基线对照均通过，不能据此判定原因或放行部署。

1. 仅在原等待的失败路径、清理 harness 之前捕获同一采集时点的 Task、动作、Run、租约、实现产物、验收和原生回执，以及 runner journal 的阶段与未决请求。只投影必要身份/状态，不输出凭据、指令、工具内容或完整请求。
2. 采集共用有限 context、只读事务与只读 journal 连接，限制行数和字段长度；错误作为诊断事实，不覆盖原超时。保留原 15 秒等待、轮询、业务断言、TTL、race 和执行顺序，不增加阶段重试或 sleep。
3. 验证成功路径不调用采集、失败回调发生在清理前；用真实 fixture 验证状态与 journal 关联、取消、界限和无写入。新候选按实际 delta 完成本机检查，交原 Maple 审阅责任增量复查，再有目的采集同资源/顺序 CI；未复现只说明该次结果，不能确定旧失败根因。

## 背景与边界

用户无法从卡片、接手活动、历史回复辨认 Agent/主机；思考状态缺少可查看入口；消息的省略号直接打开关联编辑器，目的不清楚。此前后台变化来源与原件链接已交付，保留该路径，不重复实现。

## 实施顺序

1. 沿历史 trigger / Run / frozen inventory 恢复作者及主机；不借用当前负责人补历史。未知身份明确标记。卡片用既有具名身份配合描述责任状态。
2. 检查公开执行过程的数据路径，为无工具内容的回合也提供过程说明；仅展示已公开的回复、工具与状态，不读取原生隐藏推理。
3. 用明确的关联入口替代省略号，说明消息作为 Issue 上下文与资料的归属、用户锁定，以及不改变授权、负责人、完成状态；保留 CAS 和原请求核对。
4. 补历史身份、空过程及关联业务契约回归，执行完整 Web、make check 与桌面/手机交互，留存截图与日志。
5. 使用既有用户 Git 身份提交，建立 draft PR，交回原 Issue 组织独立审阅。首轮不合入部署。

## 业务路径与故障

入口为 Issue 看板、活动与消息关联编辑器；终点是可识别真实作者、打开已公开过程、理解并修改上下文归属。历史快照缺失时不猜测；过程未产生时说明现状；关联读取失败不能保存，CAS 冲突读回最新版本，unknown 仅核对原操作。后台来源 producer/projection 和原件权限保持不变。

测试区分纯投影 fixture、真实 producer 契约与浏览器 fixture，不把 UI fixture 当成线上执行证明。CLI 已有消息关联和过程查询能力，本轮不增加操作或更改协议。

## 独立审阅后的增量修正

- R1：关联入口使用明确的横向布局和 14px SVG，桌面/手机测量图标及按钮真实尺寸，保留原 owner、CAS 与 unknown 语义。
- R2：将 processing 的空过程放入与首条 Agent 输出相同的渲染序列，首个回复组按原 trigger 固定组件身份；验证空态打开→首条 running 工具→公开回复连续更新，保持展开和焦点，不影响其他回复组及分页。
- 本机沙盒用未修改工作区的私有 overlay 做原 base/候选同配置短观察：完整 demo 与去除无关 seed 两组均保存阶段、Task/action/Run/lease 与 outbox 原件。90 秒诊断截止不是正式 watchdog，也不作为整包通过；原十分钟失败与最终本机检查未完成事实保留，不擅自归因或调整正式门槛。

## 必要检查阻塞的最小修复

独立沙盒诊断与原 base/候选隔离显示：全局调度事实及复杂查询反复构建存在于原基线；真实业务仍能推进，但组合场景受 CPU 与写连接占用拖慢。三份原失败发生在不同阶段，不能归为单个请求卡住。为完成本目标必要检查，先仅复用一次 CanonicalIssue 读取已构造的 executionFacts：任务摘要、排队负责人、Attention、准入与子 Issue 使用同一份事实。历史版本不加载当前事实；下一次读取重新构造。不引入跨请求缓存，不修改派发预检或最终写事务授权、unknown、handoff、receipt 边界。

回归验证一次读取只构造一份事实、历史读取零构造、后续读取反映新增未决执行事实；保留原结果与错误语义。随后先运行原沙盒功能测试，观察实际阶段及终态，再完成必要 make check。若仍存在首个未满足条件，保留证据重新判断，不提高 watchdog 或删减业务断言。

## 浏览器返回位置的就绪前置条件

精确候选 CI 的手机第三页返回断言失败，原日志保留。隔离探针用相同产品 bundle 及可控对话读取门闩重现：输入区尚未出现时保存的 scrollTop 为 732，输入区就绪后 viewport 变矮，再将 Task 入口滚入视口得到 828；返回实际为 828，旧用例仍比较 732。字体记录均为 loaded。按实际输入区就绪与两个动画帧后定位入口、保存阅读位置，相同延迟顺序通过。原 CI 未记录几何，不能声称排除了其他原因。

修正该用例的前置条件：初次和返回都显式延迟实际对话读取，验证输入区就绪带来的 viewport 改变后再比较位置；去掉固定 150ms 等待，保留 2px 容差、第三页内容/续页深度及独立新访问缓存清理断言。产品滚动逻辑不因未证实的原因改写，最终完整 fixture 与精确 CI 继续验证。

## 并发场景的候选构建重复

单次详情 facts 复用后的原场景单跑通过，但最终自动预算并发检查仍在回答示例 worker 后等完成（429行）到达原600秒 watchdog。保留完整失败与已通过各组原件，向本次检查 coordinator 发 SIGINT 并确认全部子检查退出后再改源码。该结果不是整体绿色，也不归因于单个 GET 或磁盘。

最小后续改动：initial owner 候选仍逐个读取 canonical aggregate 并校验当前/历史一致性，但把同一次扫描中重复的四类旧执行/交接屏障查询及 IssueAdmissionFacts 查询按全部候选批量读取。每个 Issue 保留自身下一代次、全部阻塞类别、租约、旧事件和未决投递条件；不按主机猜测排除，不改变预检、materialize 或最终分配事务的选择/授权逻辑，不跨调用缓存。原单 Issue 屏障接口保持，作为混合 Issue/代次/状态对照回归的独立 oracle。

用混合 unknown/原生回执/投递去重/未停 Run/未释放 lease/未应用事件验证逐 Issue 等价，并用查询次数验证一次批量扫描不会按候选数量重复准备复杂 SQL。原回执、handoff、准入业务契约及原沙盒/最终本机检查继续保留，不放宽 watchdog。

## 空 claim 的只读类别排除

批量候选后的原完整场景单跑 exit0，功能504.03秒；此前自动并发整体仍失败，不能用单跑替代。当前只读快照确认六个未物化初始候选均为 planner 类别，主机当前库存只有 manager/reviewer 类别；原全局 potential 判断仍使空 claim 占用 writer。为修复这条已证实故障链，在已有只读预检中仅排除“当前库存没有任何 Agent 声明所需类别”的初始候选。类别匹配只作保守上界，不依据暂时 availability、slots、model 或 capability 推断不能领取；无库存、未协商 named execution、无效/空选择均返回原写路径。已有 Run 原身份、普通 implement/accept、manager maintenance、停止交接、到期 external wait 及 receipt-only pending action 保留原保守路径。实际选择、授权、租约与 unknown 核对仍在最终写事务，不缓存读结果。

回归用明确占用 writer 的屏障证明未匹配初始候选仍能完成 idle 响应，释放后改为匹配选择能真实领取；定向覆盖 maintenance/receipt-only/unknown 与暂停恢复原契约。之后直接运行最终自动预算 make check，而非只重复单跑或放宽 watchdog。
