# 负责人正式报告进入 Issue 活动

`issues.update_delivery` 的 `submit_result` 在同一事务中保存成果、`issue_owner_results` 正式登记与 `issue.result_submitted` 事件。当前活动只处理普通任务的 `artifact.submitted`，所以已登记的负责人报告可以通过成果接口读取，却没有对应的讨论卡片。

1. 在现有活动查询中按所属 Issue 纳入正式登记对应的提交事件。沿用原事件位置、成果 ID 和卡片渲染，支持首次读取、向前翻页及打开页面后的增量刷新。
2. 沿用成果及附件的读取接口。活动条目只带成果标识，不提前加载报告正文或附件数据。负责人任务仍走原来的执行、草稿和过程可见性规则。
3. 用正常负责人报告提交和关闭操作验证活动 API，覆盖执行中、关闭后、跨 Issue 隔离、重复读取和附件授权。用真实浏览器打开本地 API 生成的两个状态，验证一张结果卡、PNG 预览和 Markdown 原件，并运行现有 Issue 详情浏览器回归。

登记成功后即可查看报告。若成果详情暂时读取失败，现有卡片仍提供重试，重试读取原成果。
