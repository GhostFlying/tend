# 主线后的运行路径与交付维护

## 原目标、故障起点与完成条件

原目标是 Agent 按既有工具、测试和受控升级完成业务交付。已记录的故障包括：
长测试目录生成无法绑定的 Unix socket、工具约束未导出、拒绝/主机不可用的
当次事实缺失，以及后台通知没有具名主体和实际变化。

本计划分别修正既有路径，不新增 Agent 启动菜单、执行审批、成果发布前置、
证明账本或历史 Run 迁移。DB 与测试时间语义由另一组合修改交付，本计划不重写。

## 实施

1. D237：testkit 分配真实、短、私有且唯一的通信目录，检查最终 Unix 地址字节数。
   updater 默认控制地址仍由 StateDir 派生，测试用短 StateDir；DB/报告不迁入短目录。
   现有生产入口在监听前明确配置错误，不改变端点身份、权限或恢复语义。
2. D238：共享 schema 同步已有实际字段限制，错误返回具体对象、版本与适用入口。
3. D239：现有关键判断点分级记录失败谓词、相关身份和预算；不将日志变成业务门槛。
4. D240：后台变化展示真实具名 Agent、变化对象/内容与入口，不冒充模型已执行。
5. 审计重复证据准备和读取，仅修实际缺陷；既有原件引用已足够则保留，无新抽象。
6. 旧记录及 PR 刷新后分别收尾，不因关闭纯记录而创建 runner 执行任务。

## 测试与恢复

socket 回归在长临时根、长测试名和并发下完成真实监听/通信/关闭；权限继续为私有，
先关闭 listener 和子进程后清理。配置过长时可继续读取/纠正原配置，不重放升级。
共享契约通过实际 schema 生成消费者验证；日志验证在拒绝发生点保留事实且不泄露正文。
UI 验证具名与未知主体、来源变化和可访问入口。

最终组合在最新 main 上完成独立审阅、完整本地检查、所需 CI 后 rebase 合入。
DB/测试组合可先合入；所有交付最终只进行一次新完整 format 2 受控升级，核实际
制品、进程、健康、控制 ACK 和配置，不以完成状态替代实际安装。
