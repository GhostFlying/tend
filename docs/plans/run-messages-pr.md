# Worker 补充消息接手与 PR 交付

## 范围与依赖

继续原任务的持久队列、原 run 接收与回执修订，交付 PR，不合入或部署。依赖主代理 steer PR 中的原生 fenced turn/steer 适配并复用其错误语义，避免重复定义相同协议类型。

## 实施

1. 整合原功能与未提交的回执修订；追加新的 server 迁移，保留既有迁移、用户工作区与审计信息。
2. 已保存的回执独立于 worker 恢复，在完成与释放阶段仍沿原请求身份上报；不能重新启动 worker 或重发正文。
3. 原 run 释放后只允许固定历史回执认证，不能恢复 claim、投递、控制或任务写权限；从 runner HTTP 入口覆盖该边界。
4. 保留 Orca TUI 的同 run 协作接收与显式 ack，不通过 PTY、interrupt、新 turn 或重建模拟。accepted 与模型消费和业务完成分开。
5. 覆盖通信兼容、journal 重启、晚到回执、控制修订与实际执行器路径；运行 make check、独立 review，再提交并发起依赖 PR。

## 独立评审修订

- 回执上传超时后继续核对已保存信封，不退出活动 worker 的消息循环或重新调用原生投递。
- 同一 TUI 进程中 receive/ack 的网络失败在后续 receive 恢复；领取与回执沿原请求身份重试。
- ack 同时校验原接收桥、native session 与 terminal；会话被替换时保留 unknown，不能制造 accepted。
- 本机原 worker 停止验证优先于网络回执恢复，最终业务报告仍受未完成回执约束。

## 发布集成

Owner 已授权合入和受控部署。对齐托管主协调专用入口，删除发送补充消息的外挂免来源分支，所有发送保留真实消息来源和规划序号。公开端到端测试改由托管主会话动态工具驱动，保持原 run HTTP、回执和 host 权限检查。server 迁移顺延到 50，设计引用 D116；journal 10 与协议 1 能力协商保持不变。完整检查、独立评审、依赖合入和最终提交 CI 通过后线性合入。

Journal 升到 10 时，运行时上报和下载预检统一使用 journal 包的当前版本常量；嵌入迁移数量必须与该常量一致。下载回归覆盖仅支持当前版本的发布与仅支持前一版本的拒绝，避免未来合法升级卡在 download_failed。
