# Worker 受限现场核验（D100）

## 目标

调查和独立验收需要核对部署与指定工作项的实时事实，但 run 凭据目前不能读取 owner API。提供显式授权的只读快照，避免任务安排了无法执行的验收要求。不授予 owner token、SSH、全库或会话读取能力。

## 实施

1. 在不可变 spec 中声明 observation 范围：指定 work item IDs 和 deployment 开关。校验对象存在、标识唯一；未声明不授予权限。注册 runner capability，调度和恢复检查该能力，旧任务行为不变。
2. 增加 run-authenticated GET 与 worker `read_observation` 工具。两角色可独立刷新；服务端以当前有效 run、精确 spec 与租约校验范围，事务一致读取执行投影、水位和采集时间。返回最小状态字段，不含背景设计、聊天、凭据或任意路径。
3. 部署事实包含实际进程二进制身份、数据库迁移版本与发布记录，明确采集时点和来源；发布记录与运行进程证据分开，未知不猜测。任务快照不是浏览器渲染证明。
4. 调度说明要求对生产核验显式绑定 observation 范围，缺渠道时先补能力或拆分核验范围。独立验收自行取最新快照，不以作者报告代替。
5. 覆盖无授权、跨范围、终止/过期 run、两角色、新旧 runner 调度、版本刷新、事实字段与无关信息排除。完成 make check、独立 review、CI、受控发布。
6. 保留旧复核任务报告和 blocked 验收历史，更新 spec 到新版本现场与显式核验范围后恢复调查/独立验收；不把旧版结论视为新版结论。

## 兼容性

新增可选 spec 字段、读取端点和 capability；旧 spec 无新权限，旧 runner 不领取要求新能力的任务。评估恢复校验是否改变旧有效请求，不修改既有协议默认语义。新能力不需要修改历史迁移。

## 完成标准

两角色通过 run 凭据独立获取指定现场事实；不能越权读取其他工作项或会话；缺能力时排队原因明确。原复核能执行所需生产事实检查，历史保留，测试资源清理。

## 实现核对

- 恢复期间是否可读以正式对账后重新激活的租约、当前 spec 与 desired 状态为依据。running 事件尚在上传队列时，合法恢复的 live 状态仍可读取；过期、unknown、终态和已撤回执行权保持拒绝。独立 review 复现后已增加正式 Hello 路径回归。
- 新 GET 不扩展旧任务权限，恢复门禁仅针对新增 observation scope，因此保留当前协议版本。无新增迁移；实际迁移版本在快照事务中读取。
- 全量 App race 测试在持续创建隔离数据库时触及默认十分钟包超时；测试超时改为可配置 TEST_TIMEOUT，默认二十分钟，保留全部测试和断言。
