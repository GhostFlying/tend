# 空原生回复的回执结算

## 原因与边界

原生历史允许正文为空的 agentMessage。实时消息流已经跳过从未发布的空回复，
历史对账却尝试将其创建为用户可见消息。业务入口拒绝空正文后，对账提前退出，
已完成 turn 的待处理回执一直保留，正常负责人续行被阻塞。

## 实施

1. 在历史到业务消息的投影边界跳过尚无已发布记录的空回复，仍保存完整原生回执。
   已发布回复的权威空终态继续更新，不能丢弃清空已有流式文本的事实。
2. 对账失败携带原 request、thread、turn 和 item 身份，保留底层错误；不记录正文。
   保持业务入口对新空消息的拒绝，不把原生完成当作最终业务报告或 Issue 完成。
3. 覆盖只有空回复、有正常进展加空终稿、已发布文本被空终态替换，以及重复对账。
   核对原回执结算、消息数量和原件，不能通过新模型 turn 或重放业务操作恢复。
4. 按仓库要求独立审阅、完整本地检查及最终候选 CI，经 PR 合入后使用完整发布集
   受控升级；保留配置与原责任，再由负责人消费已有审阅、继续原任务交付。

Refs: D226。
