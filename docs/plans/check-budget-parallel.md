# 有界并行检查入口

## 问题与范围

一次本地检查的外部启动器显式设置 `CHECK_JOBS=1`，将可独立运行的质量、Web 和测试组串行排队。官方入口已有有界调度器，但没有要求说明串行原因，八 CPU 自动分片也未充分利用该预算。

## 实施

1. 保留 `make check` 单一入口、原测试集合、超时和 E2E 隔离规则。按有效 CPU 预算自动选择组并发和分片；八 CPU 默认 jobs=2、App=2、suite=2、child=2、package=1。
2. 多 CPU 下显式 jobs=1 必须通过 `CHECK_SERIAL_REASON` 或 `-serial-reason` 说明原因。自动低预算串行记录自动选择依据；单 CPU 无需额外授权。旧 jobs/shard 环境变量仍有效，旧无理由显式串行会给出可操作错误。
3. 启动记录 CPU、组、分片、子进程预算与串行原因；每个阶段记录起止时间和耗时，可核验重叠。继续使用现有逐例报告向协调者报告 phase/case/elapsed，不新增巡检、强杀或自动重跑。
4. 仓库约定要求外部启动器使用自动预算，例外记录原因；缓存、临时路径和整机重任务仍由协调者分配。

## 验证与门槛

先验证八 CPU 默认预算与串行 guard 的失败，再执行检查工具定向 race 测试，覆盖并行阶段重叠、并发上限、E2E 独占和失败聚合。使用独立临时缓存，不运行另一套 full。独立 review 与 PR CI 并行，合入前完整本地门槛保持不变。
