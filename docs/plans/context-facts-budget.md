# 固定说明与动态账本预算分离（D94）

## 问题

外挂完整快照目前把 AddonInstructions 和账本事实一起计入预算。增加文件输入说明
就能挤掉完成结果，甚至让基线之后的增量通知消失；操作说明的长度不应决定事实
是否可见。托管主 Agent 的固定指令已在 thread 配置中，不受这个具体问题影响。

## 实施

1. Render 的预算明确为 UTF-8 字节；外挂完整快照的固定 AddonInstructions
   单独输出，不计入动态部分预算。包身份、项目概况、分区标题及账本条目仍计入。
   固定指令完整保留，不截断规则，不改变 watermark、去重或确认语义。
2. 外挂完整快照默认给动态部分 2000 字节，固定说明另计；原先 8000 是包含约
   6 KiB 固定指令的整体目标。新默认保持总体大小接近原来，同时让事实预算稳定。
   外挂增量仍为 4000 字节；托管快照/增量保持 16000/6000。
3. 保留既有事实优先级、完整行省略提示和受保护的待处理事件。不借本次变更无限
   注入所有历史。超出动态预算仍可提示工具查询，但不能由固定说明造成省略。
4. 补完整快照的完成结果与待决保留测试、动态条目超额仍压缩测试、实际 addon
   hook/API 回归；完整 make check、独立 review、CI 后同一 PR 发布。

## 验证

- 固定说明本身超过所给动态预算时，预算内的任务完成与待决仍完整输出。
- 大量低优先级条目只占用动态预算，保留必要通知、按完整行省略并提供查询提示。
- 不改增量及托管包的预算行为；既有事件水位、首次使用与重复通知测试通过。
- 不增大主 agent 模型上下文窗口或改变数据库保存范围，不增加协议或迁移。
