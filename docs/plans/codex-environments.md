# Codex 独立环境与扩展管理

## 目标与边界

为本机 Codex 提供独立的固定运行 home、skills/plugins 的 clean/projection 模式，以及 AGENTS.md 的 independent/sync 模式。保留项目能力和管理员要求，不改变协调 Agent 的权限。仅 Linux 的 bubblewrap 文件视图提供严格隔离；未配置的运行环境行为不变。本次不迁移生产配置、清除缓存或选择投影白名单。

## 实施步骤

1. 实现 HuJSON 环境描述、本机请求去重与 revision、不可变包快照、安装与来源身份、只读差异和故障恢复。Codex TOML 使用现成解析器。
2. 用 mount namespace 替换用户技能、兼容入口、插件工作目录和生成配置；保留 HOME、固定会话/SQLite/日志、共享 OpenAI auth、项目扩展。进程组、取消及快照引用与执行生命周期绑定。
3. 提供完整 tend codex-env 命令及能力目录，以组装注入保持 CLI 边界。实现系统用户服务自动同步和明确的已发布/已采用状态。
4. 通过可选 runtime 到环境映射接入 server/runner。worker 固定 run 快照；协调会话只在已确认空闲且无待对账操作时采用新快照，不重发输入。
5. 验证 clean、投影更新、并发/崩溃、符号链接与路径别名、内置/项目能力、MCP/hooks、角色边界、用量路径。完成完整检查、独立 review 和 PR；提供迁移预览与回退文档。

## 验收

主环境已有或新加的未选技能不会进入目标；投影完整且单向；本地插件管理从不操作账号级安装记录；更新失败保留有效快照，运行/恢复仍使用原引用；自动同步不调用模型。临时环境验证真实 Codex 与 bubblewrap 组合及最小模型 turn，不能据此声称生产环境已采用。

## 独立 review 补充验收

- 首次原生执行前将 run 的本机环境目录与 ID 写入其固定状态目录；恢复不采用变更后的 runtime 映射，历史未隔离线程保持原加载路径。
- 未显式设置 rollout roots 时加入映射 home 的 sessions；显式 roots 和空数组仍保持调用方选择。
- 仅关闭 enabled 的控制更新独立提交，不要求失效的投影源重新构建；保留原快照及运行引用。
