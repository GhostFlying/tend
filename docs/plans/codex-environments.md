# Codex 独立环境与扩展管理

本文件保留 D197 的原实施记录。D202 已按后续用户决定移除外层 bubblewrap，改为启动前、六小时节流的个人 skill 排除清单；当前行为以 [托管扩展计划](managed-extensions.md) 与 [操作说明](../codex-environments.md) 为准。

## 目标与边界

为本机 Codex 提供独立的固定运行 home、skills/plugins 的 clean/projection 模式，以及 AGENTS.md 的 independent/sync 模式。保留项目能力和管理员要求，不改变协调 Agent 的权限。仅 Linux 的 bubblewrap 文件视图提供严格隔离；未配置的运行环境行为不变。本次不迁移生产配置、清除缓存或选择投影白名单。

## 实施步骤

1. 实现 HuJSON 环境描述、本机请求去重与 revision、不可变包快照、安装与来源身份、只读差异和故障恢复。Codex TOML 使用现成解析器。
2. 用 mount namespace 替换用户技能、兼容入口、插件工作目录和生成配置；保留 HOME、固定会话/SQLite/日志、共享 OpenAI auth、项目扩展。进程组、取消及快照引用与执行生命周期绑定。
3. 提供完整 tend codex-env 命令及能力目录，以组装注入保持 CLI 边界。实现系统用户服务自动同步和明确的已发布/已采用状态。
4. 通过可选 runtime 到环境映射接入 server/runner。worker 固定 run 快照；协调会话只在已确认空闲且无待对账操作时采用新快照，不重发输入。
5. 验证 clean、投影更新、并发/崩溃、符号链接与路径别名、内置/项目能力、MCP/hooks、角色边界、用量路径。完成完整检查、独立 review 和 PR；提供迁移预览与回退文档。

## 验收

主环境已有或新加的未选技能不会进入目标；投影完整且单向；本地插件管理从不操作账号级安装记录；更新失败保留有效快照，运行/恢复仍使用原引用；自动同步不调用模型。临时环境验证真实 Codex 与 bubblewrap 组合及最小模型 turn，不能据此声称生产环境已采用。

## 独立 review 补充验收

- 首次原生执行前将 run 的本机环境目录与 ID 写入其固定状态目录；恢复不采用变更后的 runtime 映射，历史未隔离线程保持原加载路径。问题回答的新 run 延续原线程时继承前序环境身份。
- 未显式设置 rollout roots 时加入映射 home 的 sessions；已使用 home 通过本机登记表在移除映射后继续保留；显式 roots 和空数组仍保持调用方选择。
- 仅关闭 enabled 的控制更新独立提交，不要求失效的投影源重新构建；保留原快照及运行引用。

- watch 的无外部效果预检失败明确结束请求；可能已发出的 systemd 操作仍以原请求对账。

- 执行引用索引启用 WAL 与有界 busy timeout，读目录不阻断原生状态写入；独立进程关闭证明回写原环境采用引用，未确认退出仍保留 unknown。

- 原生启动前环境预检失败保留未启动证明；启动后状态持久化失败走既有关闭与所有权回执流程，不丢失已验证的退出事实。

最终恢复审查补充：server 本机协调会话按既有 named binding identity 保存环境绑定，重启恢复前读取原线程是否存在，旧未隔离线程不自动采用新映射；不可读取的新映射只影响对应执行器就绪状态，不阻止 runner 加载保留目录与原 run；控制请求的 staging/原生校验与执行引用写入分锁，退役仍在检查活动引用至提交期间排斥新 pin。分别加入映射更换/移除、旧线程、新映射缺失和阻塞校验期间关闭写入的确定性回归。

分锁后的 watcher 失败诊断也必须使用同一配置控制锁；阻塞人工校验期间的诊断写入不能跨锁改写 state.json。以阻塞校验、诊断截止、人工请求提交及原请求对账覆盖这一写入边界。本 PR 尚未发布的中间协调引用格式不新增迁移路径，线上未启用环境管理的旧线程继续遵守既定 legacy 绑定规则。
