# 独立审阅登记与中断续行

## 业务起点与终点

共享审阅的第二轮曾绑定报告 Task 的失败执行。正常重试与等待提醒启动了同 Task 的后继 Run，但旧轮次的 generation 仍阻止登记。旧 wait 请求的返回未知，workspace 仍为同 Task 预留。另有独立的 PR 与主分支冲突，解决后需要匹配新候选的证据。

Issue 负责人沿现有报告 Task 和 PR 审阅入口安排真实独立审阅。后继 Run 从正常读取入口取得观察到的候选、要求摘要和已共享原件。正式登记读取实际完成的报告及其产生执行。先前的 findings、报告、执行和请求历史均可回读。交付沿现有候选适用性、严格 CI、版本和未知操作校验。

## 实施

1. 保留预绑定兼容路径。扩展现有 record，在显式指定已完成 reviewer Task 并校验当前候选与审阅版本时，登记真实后继报告。等待和代次仅用于识别历史执行。既有结论沿原路径结算，无法确认的旧报告及外部输入继续等待原身份对账。每条正式结论绑定实际 reviewer、Run 和 artifact。
2. 同 Task 保留 workspace 的等待结算使用已有停妥检查。物理执行、工作区内任何实际写入者和未对账请求仍阻断。保留通用 Task 的资源释放行为。
3. 沿共享审阅读取接口查询原请求的审阅提交历史。已提交时返回原修订与结果，缺少记录时保持未知。沿现有材料权限和候选读取入口暴露，私有 trace 与 rollout 保持隔离。
4. 使用真实业务接口覆盖首轮 findings、失败重试、提醒续行、保留 workspace、未知回读、后继报告和受保护交付。用本地 Git 重放原 PR 冲突并保留终态，生产仅通过已授权的读接口核实事实。

本地 Git 冲突重放使用隔离分支，PR 原候选及生产 Task 归其原负责人。
