# C4：主会话设置与累计正文 UI

依据 D73、D74 和冻结的 owner API 契约，前端只使用生成的类型，不修改后端或生成文件。

输入框上方展示服务端模型与思考强度；修改模型采用目录默认 effort，提交使用当前 revision 和 request_id。成功、冲突后重读，回执不确定时保留原请求身份对账，禁止重复点击产生新操作。设置由账本事件同步；暂不可用时保留已知值、禁用修改，以有上限的退避重读，关闭时清理计时器和请求。提示设置用于下一次开始的回复，含离线排队消息。

累计正文沿用稳定 message_id/seq 的合并和滚动锚点，区分生成中、完成、停止、失败、结果未知；终态保留正文，空正文生成中给出提示。带 assistant_state 的条目时间戳代表首次创建，不再据此推算完成耗时；静态正文使用 memo 避免其他流式条目更新时重复解析 Markdown。

补设置目录/默认值、共享事件、不可用恢复、revision 冲突和未知回执对账，以及累计正文替换与终态的回归测试。使用生产构建和桌面/手机 Playwright 检查控件、流式更新及阅读位置，临时服务和浏览器在 finally 中清理；不使用 orca，不涉及 Max mode 或安装 Web App。提交前通过 make check 和 diff 检查。
