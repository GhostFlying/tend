# 工作项进展、后续安排与启动可靠性

## 目标

按已批准方案实现详情首屏进展、持久化下一步选择卡、启动诊断及有限重试、升级完成证据。保留已验收移动端布局、历史任务和原工作区。阶段由调度 agent 动态定义，不引入固定交付流水线。

## 实施

- P1：核对并整合已验收移动端提交；详情展示去重后的真实执行计数、动态当前步骤、当前/已结束/全部任务与状态筛选，背景和历史折叠。
- P2：新增工作项选择存储、事务用例、owner API 和 agent 工具；支持回答、撤回、替代、owner 消息依据、事件去重和恢复。聊天与详情引用同一实体，不占 worker，不直接执行部署。
- P3：完成事件核对已有授权，继续授权工作或一次性询问；清理过时选择但不代答，不隐藏仍阻塞 worker 的问题。
- P4：Orca 提供结构化启动诊断和投递确定性；Tend 保留诊断，仅对明确未写提示的就绪超时、确认旧终端停止后同 run 有界重试。默认一次，配置零关闭，持久计数独立于模型恢复。
- P5：新增 upgrade 证据，服务端核验已完成批次及实际目标回执，冻结核验快照。不能替代产品验收或自动关闭工作项。
- P6：自动化回归、窄屏/桌面渲染验证、独立 review、CI、线性 PR 合入和受控发布。Orca 遵循 fork 发布规则；测试资源验证后清理。

## 验证与发布

覆盖执行状态计数和去重、筛选与实时刷新、历史视图；选择重复通知/并发回答撤回/重启/自由文本/过时点击；启动未知投递/人工接管/重试预算/重启；升级未完成/部分完成/跳过主机/历史快照。必须通过 make check 和独立 review。兼容性按实际协议差异评估；迁移仅追加，生成类型通过生成器更新。

先发布兼容 Orca 诊断，再发布 Tend server/Web 与 runner，保留会话和在途任务。最后以真实 C 批次结清遗留升级事项，不重复升级；仅核对当前未决定后续的工作项，不批量为历史事件生成选择卡。

P6 的真实启动验收使用 integration-tag 隔离测试：本地 HTTP server、独立 store/journal 与真实 runner/Orca worker，创建 temporary + files 任务并由独立验收下载核对唯一 nonce 文件。显式环境变量启用；默认只运行无模型的 fixture 验证。正常完成后通过既有 workspace Cleanup 精确注销自有 folder 并清理本地目录；停止或归属不确定时保留现场，不依赖生产保留期限，不改生产数据或增加清理 API。
