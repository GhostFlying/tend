# 工作项、动态阶段与交付跟踪

## 目标与已确认边界

在执行任务上增加持续关注的工作项。调度 Agent 按每张卡片的用户意图动态定义、拆分、重排阶段；项目不配置固定业务阶段。现有 task、独立验收、workspace、升级器继续使用。本轮完成不自动结束工作项；后续未定保持可见，不占用执行资源。

共享背景只包含目标、现象、用户约束、确认的决定、原始输入引用和有来源的事实。详细设计、实现思路和作者自评留在阶段产物；独立验收默认不注入这些内容。工作项背景与按角色选择的阶段输入分开。

## 实施批次

- W0：先集成现有移动端入口和仓库列表 PR，按仓库 review、检查、CI 规则合入并部署。
- W1：工作项账本、动态阶段/依赖、任务关联、后续事项、背景、收尾/重开、默认 workspace 和投影。写入遵循请求去重、版本校验和事务事件。
- W2：主 Agent 工具、上下文、任务创建关联、按角色构建 worker 输入和完成事件唤醒。已有承诺继续推进；未知后续展示待安排；计划编辑不扩大授权。
- W3：工作项白板与详情，通用列为待安排、进行中、待检查、待处理、暂缓、已结束。卡片阶段自由；保留 task 详情和历史证据，不做流程配置器。
- W4：独立于 harness 的 runner 外部观察。首期仅 GitHub（gh）和 Codebase（bytedcli）。轻量只读，不启动模型、不占用 worker slot；保存身份、状态、commit、来源和核验时间。开放对象默认 5 分钟、暂缓对象 1 小时刷新，终结对象停止周期查询；失败保留最后事实，旧查询不覆盖新观察。
- W5：整体验证后归档旧业务并切换。保留仓库、主机、凭据、设置；一致性备份账本、附件、runner journal。全部项目无运行和未确认操作后才切换，新账本不接收旧 run 重放，不删除旧 Orca 工作区/用户终端。新会话从新账本启动，归档不作历史工作项迁移。

## 语义

阶段可分组和建立无环依赖；一个任务可覆盖多阶段，一个阶段可关联多个任务。阶段图与共享任务形成的实际等待图都须无环，校验包含组继承和已有任务依赖；同一任务覆盖连续阶段仍可执行。计划修订保留稳定身份与历史。影响运行任务的变更必须显式说明继续旧约定、更新或停止，不能静默改变已启动任务的要求。阶段完成须有验收、外部观察或用户决定证据；删除阶段不能抹去承诺或完成证据。

后续事项区分承诺、问题、建议，保存来源、处理状态及承接关系。收尾分已完成、决定不做、已交接、被替代，必须说明依据和遗留去向。当前任务/阶段完成、任务数为零、用户沉默均不足以收尾。明确责任终点或用户结束决定可以收尾；用户关闭 PR 只有身份与意图证据充分、无剩余承诺时才可推断结束。活动任务、未确认停止、unknown 操作和未处理承诺不能被收尾隐藏。允许重开，不改变旧任务终态。

工作项记录默认 workspace，连续同仓库任务优先复用；并行、独立分支和其他仓库允许独立资源。复用必须沿用现有独占、停止证明和 source_task_id 解析，不自动清理/切分支；目录复用不等于会话复用。共享发布任务可关联多个工作项并分别记录覆盖结果。

## 验证

覆盖调查完成后继续、阶段拆分并行、历史保留、任务要求同步、共享任务、workspace 复用、用户约束跨交接、收尾守卫、重开、上下文隔离、GitHub/Codebase 观察解析与失败/乱序、重复核验的页面更新时间但不唤醒模型、查询失败的待处理投影、未知刷新请求的事实对账、事件重放、过期版本、桌面/移动白板、归档恢复与旧 journal 隔离。每批通过 make check、独立 review、CI；生产切换前执行真实查询和浏览器验收。定时催办、完整话题聊天、通用流程脚本和标准 GitLab 适配不在本期。
