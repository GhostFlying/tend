# 批量用量上传复用来源元数据

`runner.usage_upload` 在一次写事务里处理至多 256 条样本。先由真实
操作入口记录 1、64、256 条的新记录批和重复批，分别测写连接排队、
事务回调和另一条写请求的排队，通过同一测试对照改动前后。测试同时
使用单一来源和具有历史来源的账本。

写入来源会话后，读取一次同一根线程的来源 provider、session、purpose
和 parent session。占位的 provider 仍由第一条有效样本绑定，后续样本
必须与它一致。保持现有 runner host 检查、逐样本线程会话和归属校验，
复核同一 run/thread 可同时有恢复和 runner 来源的实际查询。两种路径
共用原事务，后续无效样本应回滚此前写入及 provider 绑定。

测试空批、重复批、子线程和不同 host 归属，并验证绑定、历史记录和
刷新事件的提交或回滚结果。
