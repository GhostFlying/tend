# 完整 race 检查的长尾优化

Refs: D151，延续 D149。

## 依据与目标

上一轮本地完整检查约九分钟，E2E、mainthread、其他包分别约 547、526、500 秒，App 四分片约 428 秒、API 410 秒。不能仅加速一个包；完整检查由剩余最慢组决定。保留全部质量检查、race、Web 检查和 CI 浏览器/交叉编译门禁，不以缓存命中代表未缓存测试收益。

## 实施顺序

1. 为 race 入口增加可选 Go 原生 JSON 耗时报告。先在未改变测试行为的基线上强制重跑，记录根测试及各包耗时；报告保存在忽略的本地目录，不能改变默认缓存身份或选择范围。
2. 逐包检查 E2E、contextbuilder、runnerapi、tools 的公共初始化，复用现有不可变数据库模板。每次仍独立复制并正常打开数据库；迁移、已有路径重开、恢复和专门测试启动行为的入口保留真实路径。用实跑确认收益。
3. 按测得长尾扩展 API、mainthread、E2E 的独立进程分片，并改善 App 分布。稳定分组覆盖所有根测试、Example 和 Fuzz seed，新测试自动纳入；统一约束高容量机器的分片与其他包并行，低容量继续保留 E2E 独立阶段和顺序回退。CI 按 runner 容量选择预算，避免直接复制开发机配置。
4. 若其他包成为瓶颈，结合模板收益和剩余容量调整包预算；不盲目扩大连接池或启用所有测试并行。
5. 冻结候选，执行强制未缓存完整检查并比较日志，运行调度/覆盖/隔离回归及规定的独立 review；完成 PR CI 和最新 main rebase 后合并。浏览器与缓存进一步优化留作后续，有实测依据再扩展。

## 验收

- 可选报告能定位根测试长尾，默认检查保持原生缓存。
- 所有根测试恰好执行一次，不丢失子测试、Example 或 Fuzz seed；新测试不会遗漏。
- 每个 fixture 保留独立数据库、原文件目录和时钟；重开不复制覆盖已存在数据库。
- 本地与 CI 的完整检查全部通过，记录未缓存耗时和容量预算，区分目标与实测结果。

## 耗时采样与实施选择

原预算的强制 race 采样中，API 的 `TestTaskBoardPagesEveryLifecycleBeyondSnapshotLimit` 约 280 秒，其中准备 231 条数据约 260 秒；App 的关系查询测试约 119 秒。不能假设增加分片会按比例缩短单个根测试。App 四个进程约 302、342、358、462 秒，按根数量分配有明显长尾。

该轮采样期间修改了采样工具源码，造成工具自身的包编译不一致；其他业务包的完整根事件仍可用于放置权重，但该轮不计为完整检查通过。此前冻结候选的完整未缓存检查 552.5 秒仍作为通过的对照。最终验收必须冻结所有源码后执行。

采用固定的稀疏成本提示，三秒以上根测试保留向上取整的秒数，其他根成本为一。根名称仍来自当前 `go test -race -list .`；成本不决定执行范围。放置采用按成本降序、名称打破并列、分配到最轻分片，并对正则中的名称排序；不读取上一轮本地报告，避免运行之间动态改变缓存身份。更新提示时从完整未缓存报告提取顶层通过事件，不叠加子测试时间；缺失或旧提示只影响均衡度。

本地自动预算示例：64 个有效 CPU 使用 App 八分片、其余三个长包各四分片、其他包六路，每个 Go 测试进程 GOMAXPROCS 为二；32 个 CPU 使用 App 四分片、三个长包各两分片、其他包三路。按最多同时运行的组所含进程总数约束 GOMAXPROCS；小于 32 个 CPU 继续隔离 E2E。CI 的 App 仍显式四分片，其他长包按有效 CPU 自动选择，普通小 runner 不强制扩容。

第一轮冻结源码后的完整未缓存检查通过，约 370 秒。mainthread/E2E/App/API 分别约 81/92/207/286 秒，其他包约 370 秒成为剩余瓶颈。sandbox 自身约 307 秒，等待编译和执行槽位使整组增加约一分钟；因此对未分片包增加固定成本排序，将 sandbox、store 等重包提前交给 Go，保持包并行度不变。未知包继续完整纳入，只使用零成本提示排队。

## 入口与报告

- `make check`：完整自动预算，保留原生缓存。
- `TEST_COUNT=1 TEST_REPORT_DIR=.local/test-reports make check`：完整强制重跑并输出原生 JSON；每组创建独立目录，每个分片保留独立文件，重复调用不覆盖已有报告。
- `APP_TEST_SHARDS=4 TEST_SHARDS=2 make check`：显式调整 App 与其他长包的分片上限，仍统一计算进程预算。
- `CHECK_JOBS=1 make check`：自动 App 与其他长包分片均回退为一，各组依次运行。
- `TEST_SHARDS=1 make test TEST_GROUP=e2e`：单进程运行完整 E2E，便于排查分片相关行为。

迁移、已有路径重开、恢复相关入口仍直接使用 store.Open；模板只用于新建空库，绝不覆盖已有文件。sandbox 测试通过真实启动入口覆盖服务组装与迁移，本轮不为它增加绕过启动路径的注入。

## 并发下的短租约回归

重包优先后的复验中，`TestSlowBindingPreservesExistingWorkerLease` 出现真实时间短租约 fencing 失败；诊断版单独重复五次通过。原测试将 800 毫秒业务租约与固定 1200 毫秒的主机等待绑定，无法区分绑定阻塞心跳与主机调度延迟。

改用现有可控业务时钟，仍保留 800 毫秒租约和阻塞的真实 provider 调用，分十二次推进到 1200 毫秒；每步确认真实 HTTP 心跳已在独立数据库中持久延长同一个 run 的租约，并检查 worker 没有被停止。不延长租约或轮询超时，不忽略失败或自动重试整组。该用例另以重复运行及故意阻塞绑定读取的负对照验证，再冻结最终候选完整复验。

## 最终验证

最终冻结候选的 `TEST_COUNT=1 make check` 完整通过，耗时 321.7 秒（5 分 22 秒）。质量/Web/mainthread/E2E/App/API/其他包分别约为 11/56/78/92/210/290/322 秒。相较此前通过的 552.5 秒记录约缩短 42%；两轮基线包含不同的 main 增量，这是同一开发环境的样本比较，不是固定耗时承诺。

原生报告逐一对照当前 Go 发现结果：App 876、API 97、mainthread 141、E2E 52 个根目标均执行一次，无缺失、额外目标或重复。保留完整 race、质量与 Web 检查。短租约用例独立连续十次通过；故意持有仓库观察锁直到 provider 返回的负对照按预期超时失败，之后恢复生产文件原始字节。调度、覆盖、失败汇总、工具路径和报告回归通过；最终规定模型与推理强度的独立 review 无可操作缺陷。
