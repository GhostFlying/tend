# S8 稳定披露与实时状态实施计划

Refs: D131、D132
Plan: S8

1. 确认 Issue 整页 ResizeObserver 与执行阅读器跟随逻辑；自动跟随只响应末尾数据更新，不响应用户披露高度变化。共享披露位置保护覆盖原生 details 与按钮，保留分页锚点、最新提示及焦点合同。
2. 增加纯状态推导和测试；主对话、Issue 负责人轮次及任务执行复用单行阶段、动画和用时。步骤默认折叠，手动展开保持，结束后替换为紧凑摘要；阶段播报不包含计时 tick。
3. 沙盒默认每轮思考、真实工具调用及回复约 6–12 秒，执行约 15–25 秒；显式快速节奏用于测试，延迟可取消且不影响正式边界。
4. 在既有浏览器巡检增加桌面和手机披露位置断言，含 Issue 底部跟随；使用独立临时数据与空闲端口截图，不操作已部署服务。
5. 分别提交滚动、状态 UI、沙盒节奏；串行运行全部 Web 分片门禁、沙盒及 Web Go 测试和 touched Go 静态检查，记录截图、限制与主计划进度。

不新增依赖，不修改生成 API、迁移、owner API 或 runner 协议；独立 review 和最终验收由协调者执行。

## 实施与可观察性边界

- 整页与执行阅读器的内容 ResizeObserver 会把用户披露当成新输出；改为只在数据变化时跟随，空轮询不触发跟随。全局披露保护在布局提交后恢复控制点；Issue 会话设置作为定位面板展开，不再抬高输入区。
- 主对话与 Issue 复用负责人轮次状态；任务详情与 Issue 执行区使用持久原生事件阶段。工具原始输入、输出、失败与中断记录及分组内阅读状态继续保留，外层步骤默认收起。
- 主对话优先使用已有处理观察起点，Issue 缺少原生起点时用已有触发源时间；阶段无法识别时使用真实工具中文标签，不捏造读文件或命令。历史执行窗口缺少开始／结束事件时用时未知；当前挂载时观察到的结束保留本次计时。无需 API 字段或协议变化。

## 回归补充

- Issue 活动中的流式正文可能更新非末行的稳定 ID；内容水位检查包含当前活动窗口，保持底部跟随与离底最新提示。空轮询不因对象身份更新而滚动。
- 披露改变高度但没有改变 scrollTop 时，聊天仍刷新离底状态与最新入口；不把正在阅读的披露当作新到达内容。工具附带决定卡留在外层可操作区；结束折叠前内部焦点退回开关。
- Issue 执行区读取实际任务详情与 run 状态，避免将任务执行态当成原生 run 状态，并复用同一折叠步骤视图；选择历史 run 时按身份重建窗口，避免混用计时。

## 独立评审修正计划

1. 将恢复跟随和回到最新作为显式滚动请求；即使完成执行没有新内容，也滚至末尾，并在最新页回执后再次落实请求。
2. Issue 披露激活后暂停跟随，布局提交后重新计算是否离底；展开工具读取时后续流式更新不抢阅读位置，继续验证开关位置。
3. 长回复截断仅作用于 Markdown 正文；状态、决定与步骤工具明细留在截断区之外。浏览器覆盖长回复工具输出完整可见。
4. 单独新增修正提交，不改写已有提交；运行完整 Web 分片门禁与全部浏览器脚本。

## 独立评审修正实施

- 完成或静默执行在历史位置恢复跟随时立即滚至末尾；回到最新另保留一次待落实请求，最新页返回后再次滚至末尾，不依赖记录内容变化。
- Issue 披露激活立即清除两种跟随状态，布局稳定后重新计算离底；流式更新保持工具阅读位置，展开和收起继续使用控制点保护。
- 回复预览的截断 class 仅传给正文 Markdown 容器；状态、决定、标签与工具步骤处于截断区之外。
- 浏览器增补完成静默执行的恢复／最新、长回复步骤和工具输出的非截断祖先、输出高度、底部披露后流式更新与控制点几何断言。既有业务断言完整保留。

## 第二轮独立评审修正计划

1. 完整执行阅读器在披露激活后暂停跟随，布局稳定后根据离底距离决定是否恢复；聊天已有布局后离底判断，保留其原实现并继续由既有披露与焦点跟随断言约束。
2. 已存储图片附件在下载地址返回前预留与缩略图相同的固定高度，避免异步插入抬高末尾；浏览器验证延迟加载后仍位于底部且最新入口准确。
3. 完整执行阅读器退出时优先回到原触发元素，原元素因结束折叠移除时回到常驻执行开关；补齐结束且弹层仍打开的焦点断言。
4. 不扩展跟随逻辑架构；单独新增修正提交，完整重跑 Web check 与全部 test:*。

## 第二轮独立评审修正实施

- 完整阅读器在步骤披露时暂时停止跟随，稳定布局后仅在原本跟随且仍接近底部时恢复，展开末尾输出后后续记录不抢阅读位置。
- 已存储图片的缩略图容器预留现有 135px 高度；下载地址延迟返回不改变消息高度，不需要恢复整页内容 ResizeObserver。
- 原触发元素仍存在时维持原焦点返回；结束自动折叠移除原元素时使用常驻执行开关，不让焦点落到 body。
- 浏览器覆盖末尾工具展开后新记录、完成且弹层打开时的焦点返回，以及桌面／手机延迟图片加载前后的页面高度与底部位置。聊天已有披露布局后判断，保留其实现；未扩展或重构跟随架构。

## 第三轮独立评审修正计划

1. Issue 在滚动和披露稳定布局后记录可见锚点；活动内容水位变化且跟随暂停时恢复锚点，不对纯高度变化或披露切换纠正。
2. 同步验证聊天与完整执行阅读器在较早内容增长时的暂停阅读；缺少数据更新恢复分支时复用可见锚点 helper，仅以内容水位变化触发。
3. 浏览器覆盖三个阅读面在可见后续记录前的正文增长，并保持既有披露和工具阅读断言；完整重跑 Web 门禁，独立新增提交后停止。

## 第三轮独立评审修正实施

- Issue、聊天和完整执行阅读器在滚动时保留可见锚点；数据内容水位变化且跟随暂停时恢复该锚点，单纯披露或空轮询不恢复锚点。
- 共用捕获 helper 优先选择从视口内开始的后续记录，避免跨越整屏的较早长正文遮蔽真正正在阅读的后续条目；仍保留其它可见记录作为身份变化后的回退。
- 完整执行行提供稳定的滚动身份，披露稳定后更新阅读锚点；保持显式最新、分页锚点与披露控制点合同。
- 新浏览器断言覆盖 Issue 较早展开回复增长、聊天较早正文增长及完整执行较早输出更新；原披露几何、展开工具、返回焦点和末尾跟随断言继续执行。单元验证长前行增长 1020px 时后续记录位置不变。
