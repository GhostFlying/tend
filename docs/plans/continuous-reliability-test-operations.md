# 持续可靠性：测试与操作证据

## 范围与原业务目标

本组落实 R5、R6、R7、R16、R17：使原有 runner 重启、短租约续期、独立验收和沙盒业务场景以可观察转换验证；减少与迁移目标无关的重复 fixture 初始化；保留检查停止、实际数字退出值及原子终态；收窄私有观察器默认输出；在原有部署前读取中保存配置哈希并生成部署后的真实差异。

历史沙盒查询放大由原 profile 支持，产品查询优化由读模型组负责。历史 Orca 验收和短租约失败的唯一首个未完成转换仍为 unknown，本组不追认其成功或补造原因。有限 watchdog 只诊断卡住；业务租约时间使用注入时钟，保留过期、fencing、身份、重放及 race 断言，不通过延长租约或单独提高 CPU 预算修复。

## 实施

1. 对原有短租约重启场景记录准备、首个执行、重启恢复、续期和验收阶段。按实际心跳确认后推进业务时钟，证明原租约经过多个续期仍有效；保留真实掉线后到期的独立故障场景。
2. 复用现有独立数据库模板处理 runner 业务测试中的重复冷迁移；迁移与真实 reopen 测试继续直接打开数据库。保留所有正常业务命令和安全断言。检查现有包分组和影响选择，已有完整覆盖边界不降级，不改正式 PR 全量 CI。
3. 在现有 check 入口记录每阶段 PID、开始和终止时间、实际退出码、取消原因及清理结果；可选目录保存原子 JSON 回执，未启动和信号终止保持明确状态，不能伪造 exit=0。取消后先等待协调者清理，再做所属进程组最终清理。
4. 私有观察器只改 saved-evidence 展示，按原件 ID 和字段白名单返回增量；不运行 collector、不重启已停 timer。保留原文、附件、可见 ACK 精确集合及 SHA 校验，用离线 fixture 验证。
5. 私有部署证据工具接受明确文件清单，保存非秘密配置摘要与字节哈希，部署后比较同一清单；失败和缺失保持 unknown。该工具由唯一部署者顺带调用，不增加审批和重复证据包装。

## 验证与交付

先运行小范围 testkit 与离线 Python fixture。资源重型场景与读模型组串行协调，继承父级 CPU 和包并行边界，以原生 JSON、数字退出码及终态回执记录新的检查。重启/续期测试覆盖真实正常转换，数据库模板测试验证隔离和失败保留。完整最终检查、独立审阅、PR、合并与部署统一交给集成者；本组不启动这些门禁或生产操作。
