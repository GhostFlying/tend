# 空闲 CPU 开销修复

状态：实施中。

## 目标与边界

用量采集跟随执行生命周期：执行开始或恢复时接续原游标，完成时排空，
已停止且追平的来源休眠；没有活跃执行或未决收尾、上传时阻塞等待唤醒。
不新增文件监听、历史巡检或查询结果缓存，不修改模型执行与 runner wire 语义。
部署另行安排。

## P1 用量采集

- server、主会话、runner 按活跃执行和未决来源调度，数据库候选排除已完成历史。
- 注册、开始、完成、停止和恢复唤醒采集；只有成功关闭证明允许标记 writer stopped。
- 保留分页、半行、未知停止和原 Envelope 上传恢复；失败按来源退避 2 至 30 秒。
- 共享发现索引、缓存稳定文件头；保留文件替换、截断、改写和 session 归属检查。
- 无变化不持久化，来源状态变化不能被旧收尾覆盖。

## P2 updater

拆分完整 Inspect 与轻量观察；保持一秒监督。启动、接管、升级、恢复和信号边界
仍完整验证，稳定监督与已发信号后的退出等待不反复哈希。身份不确定不视为退出。

## P3 Web

共享用量读取，接入现有账本事件和重连；投影有效更新同事务通知一次。
隐藏时停止读取和重试，可见后补读；仅动态窗口可见时按分钟刷新。
保持现有 HTTP API 和 CLI，测量完整 Go 查询路径而不预设缓存需求。

## 验证与交付

覆盖历史规模空闲、开始/完成/恢复、分页与半行、替换改写、关闭失败、上传恢复、
PID 复用、exec 变化、隐藏/重连/并发查询以及事务回滚。
记录固定工作负载的 CPU、读取、解析、哈希、写事务和同步延迟。
各批聚焦验证后，最终候选完整 make check、独立 review、required CI；
最新主干 rebase 后 rebase merge。生产部署及现场收益单独验收。
