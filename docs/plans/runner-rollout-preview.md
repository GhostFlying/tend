# Runner 原生 rollout 按需预览（D144）

## 目标与边界

所有 runner 执行共用 Web 过程入口，执行中步骤级更新，结束后继续按需读取。原件保留在原生目录，仅新增持久定位索引，不复制原件、不在 server 新增详细正文归档。支持可确认归属的历史执行，第一版不提供原件打包下载或逐字输出。外部删除和 runner 退役不保证恢复。

## 实施顺序

1. 原生 reader：在 harness 集中解码已支持原生格式，校验 session、run/turn 边界，支持增量完整记录、分页、长内容、关联原文与明确子会话；文件替换、截短、缺失及未知格式显式可见。
2. Runner 索引：追加 journal 迁移保存 deployment/run/session/turn/来源定位，独立于待上报事件；新执行及时登记，历史按已持久身份按需定位。清理不删除登记原件，预览不启动模型、不获取执行 slot。
3. 按需转发：增加协商能力 rollout-preview-v1，独立的 host 鉴权长轮询接收诊断请求。server 仅内存转发，有截止、取消、实例校验和有界分页；正式执行状态与用量账本不受读取影响。
4. Owner/API/Web：新增只读预览与长内容接口，复用执行过程阅读器；约两秒跟随、关闭停止、历史锚点与重连保留。原生记录与既有服务端日志区分，明确离线/未知/丢失/不支持。UI 先设计图 review，再编码。
5. 验证：原生格式与外置正文、会话边界、活跃与历史、暂停/满负荷/重启、断线/超时/兼容、归属/路径与无副作用测试；隔离浏览器验收与真实历史只读验证；make check、独立 review 后经 PR 交付。

## 协议与默认值

runner wire 保持 2/1；已有 runtime capabilities 声明能力，hello 可选回执确认后才调用新增端点。旧接口和日志继续有效。诊断请求不进入业务请求回执表，正文不写 server 日志或事件。默认最新 100 步，响应有字节预算，长内容按窗口读取；未完成尾行下次继续。manager 按确认 turn 切分，不用时间接近猜测来源。

## UI 沙箱 review 阶段

按 owner 后续指示，先交付可访问的交互沙箱，完整 runner 预览实现及 PR 交付暂缓。UI 定位为只读 monitor，采用 DSH Trajectory 的紧凑事件表与右侧记录检查器；不提供输入、执行重试、停止或接管。遵循 D132，通过独立二级路径进入，不再使用页面级浮层。以最近确认的精简设计稿为沙箱依据：紧凑页头、轻量搜索与折叠、无装饰时间线、按内容高度排布的详情；沿用 Tend 全局导航与语义 token。

沙箱更新顺序：

1. 增加任务下的 run 阅读路由，Task/Issue 原有入口跳转至同一页面；返回沿用路由的焦点与位置恢复。
2. 复用已采集日志窗口与步骤归并，展示可选择的事件摘要，检查器提供概览、输入、输出和原始记录。明确实际来源，不能将服务端日志标作完整原生 rollout；缺口与截断继续可见。
3. 历史接近边界自动补页并保留锚点，向上阅读暂停跟随，回到最新恢复；长输出独立滚动。读取断开保留内容，重连只重试读取。
4. 桌面并排检查器，手机在页面内部切换列表/详情，保持返回、键盘操作和触控尺寸；运行记录切换使用共享菜单及 SVG 箭头。
5. 完成 Web 检查与浏览器交互、截图对照，更新现有隔离沙箱供 owner 体验。保持原有脚本样例数据，不部署生产、不提交 PR。此阶段不能作为 runner 原生读取验收。

### 沙箱增量：横向过程概览

按 owner 确认，在现有 monitor 工具栏下增加 DSH Trajectory 风格的三轨概览。第一版使用当前加载窗口内的语义记录顺序，明确范围与未加载历史边界，不使用服务端接收时间推断模型或工具耗时。点击记录联动列表与只读详情；拖选范围聚焦对应记录，清除后恢复列表；支持横向缩放与恢复概览。搜索结果、当前选择和错误在轨道中可见。补历史或流式追加时按稳定记录序号保留选择，不把当前窗口冒充整个 run。概览本身不触发正文预取，不更改执行和用量。验证点击、拖选、清除、缩放、搜索联动、历史边界、原有自动分页与手机布局后更新同一沙箱。

### 沙箱增量：监控页配色

按 owner 最新反馈提高配色饱和度：输入/事件使用中性灰，模型使用鲜明紫色，工具使用清晰蓝色，选中与拖选统一为蓝紫强调色；红色仅表达失败。颜色集中为 monitor 专用的明暗主题 token，不改变全局诊断页和其他业务状态的颜色。移除正常工具轨道对告警色的复用，以实际浏览器截图核对默认、选中、拖选及暗色状态后更新同一沙箱。

浅色与深色主题均采用明确的类别色，避免轨道、选中与拖选整体发灰。

## 定稿后的完整实施

Owner 已确认当前三轨 monitor、列表/详情交互和鲜明蓝紫配色，继续完整实现并经 PR 交付。以下工作在最新 main 上实施，沿用既有决策并使用 D144：

- 将原生 reader 补齐身份验证、turn 切分、历史定位、有界原文/关联正文与游标失效；验证真实历史文件。
- journal 只追加原件定位迁移，保留同 run 的全部来源及 deployment 边界；native 原件不由 Tend 清理。
- 实现协商后的独立 runner 诊断循环、server 请求取消/超时和当前实例与原始归属校验。
- Web 接入原生预览状态与长内容读取，现有已采集日志仍可独立查看；保持已确认的 monitor 外观。
- 完成定向故障与兼容测试、浏览器验证、make check、仓库要求的独立 review，提交 PR。生产升级不属于本次代码交付。

### 与最新主干集成

主干新增 D140/D141 central TraeX worker 后，按冻结的执行 inventory 选择原件所在端。普通 app-server/Orca 执行仍通过独立 runner 诊断通道；central 执行通过组装层注入只读 native reader，使用 central 已有 home，不创建原件副本。其持久会话身份沿用原有 run 日志，分页索引仍只在内存中保存。owner 不能指定读取端、session 或本机路径。

journal 追加 0015，wire 仍为 2/1；配置、分页限制及保留边界见 `docs/rollout-preview.md`。已登记原件若位于待清理 workspace/验收 scratch 中，清理会拒绝删除并保留原有延后处理行为。

### 独立 review 回归

首轮独立 review 的六项意见全部采纳，并增加相应回归覆盖：

- Orca 确认 native 身份时即定位登记，避免第一次 owner 阅读之前清理掉原件。
- 字节预算内的 backward 页从请求边界向前截取，再恢复正序，保持历史窗口连续。
- 历史 manager 从完整 `ManagerNativeReply` 回执中提取成功 turn，拒绝错误、拒绝和未完成回执。
- 合并工具步骤的输入、输出分别定位到提供该字段的原生记录；custom tool 使用 native `input` 字段。
- 紧凑已采集日志中的单条跳转携带来源，不将其序号误用于原生流；来源切换同步阅读路径。

额外覆盖历史 mutation 同行多消息的独立身份，以及不支持的 history rewrite 不暴露其他 run 的快照正文。

### CLI 能力约定集成

主干 D142 新增 CLI 能力全集与路由覆盖门禁；与 D143 的目录及版本续接合并后，本计划使用 D144。同一 PR 提供 `tend run preview`，完整支持状态、记录分页、原生 generation、单条字段和关联长内容的 offset/reference；复用 owner 只读鉴权和相同游标校验，不提供通用 HTTP 调用代替业务入口。能力目录、帮助、真实 CLI 入口与路由覆盖一并验证。读取失败可沿相同游标重试，不创建业务 request_id 或执行动作。

第二轮 review 的三项意见亦全部采纳：较早空来源首次增加记录时使旧游标失效；带 record 的入口先读取目标附近窗口并暂停跟随，合并后的调用按原始 frame 定位；用户消息的输入标签读取原生正文。补充同 session/turn 下的显式 call_id 输入关联，跨窗口仍可读取工具输入；未知 history rewrite 不回传跨 run 快照正文。断线保留原生 generation 与来源，消息正文沿既有 Markdown 样式阅读。

最终复查发现并复现了读取期间原件被原子替换的归属竞态。已采纳：单次读取持有并复用建立索引时验证过的文件描述符，正文不重新打开同名路径；读取返回时统一关闭描述符。原子替换压力测试验证不会把另一 turn 的正文配上旧身份和 generation。下一次读取继续按文件身份和游标规则识别替换。

### PR CI 的监控页回归迁移

合入跟踪中发现既有用量/rollout 浏览器脚本仍依赖已退役的完整过程浮层、手动分页及原生 select。将隔离回归迁移到已确认的二级 monitor、记录详情和共享菜单；保留用量范围、自动历史分页与连续性、工具配对/输出、跟随与暂停、正式状态更新、断线保留与恢复、返回任务/浏览器返回、空页转非空和历史执行选择的校验。同步验证导航、全路由及跨平台编译，最终候选重新通过 make check 和独立 review 后更新同一 PR。此修正不改变已确认 UI。

迁移后的真实浏览器回归复现了窗口尺寸变化触发程序滚动时意外取消跟随。按用户滚轮/触摸/滚动键与程序布局变化区分滚动意图，显式回到最新时清除历史手势许可。紧凑入口按合并步骤末条记录定位以涵盖完整工具结果；选择最新执行恢复后续 run 的默认跟随。

新增独立 review 的 P2 已采纳：浏览器前进返回监控页时需恢复历史阅读位置。仅在当前浏览器历史入口内保存来源、generation、邻近记录游标和可见锚点；重新读取有界窗口后恢复暂停与位置，不在浏览器新增正文归档，也不在 server 保存正文。游标失效沿原有原件变化处理。补充原生及已采集日志两种来源的返回/前进恢复回归。

分页监控区域显式标记由组件按锚点恢复，避免通用路由恢复旧窗口的绝对 scrollTop 与新分页窗口互相覆盖；其他页面仍沿用原有路由恢复。

手机详情打开时隐藏的记录列表不参与锚点更新、尺寸恢复或边界分页，避免布局归零触发额外读取。

独立复验新增两项 P2 全部采纳：当前选中步骤可能在重建窗口之外，需在当前浏览器历史入口内保留这一条已读步骤的上下文（仅内存，按来源及 generation 校验，不写 localStorage 或服务端正文）；显式回到最新会清除路由中的旧 record 定位，并保留最新跟随意图。补充原生/日志两种来源的远处选中详情及单条入口回到最新后前进恢复测试。

### 组合版本的并发与长过程回归
