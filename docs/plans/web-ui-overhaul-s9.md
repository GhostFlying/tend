# S9 活动归属与多轮沙盒故事

Refs: D132、D133
Plan: S9

1. 从不可变事件的请求身份解析活动作者，复用冻结负责人显示名，执行及主机身份保留明确回退；活动行与当前进展展示作者，不改变分页、披露或业务状态合同。
2. 通过真实主会话、负责人工具、owner 命令及进程内 runner 播种多轮故事，包含进展、决定回答、失败后重新派发、交付及独立验收。稳定请求与完成回执保持幂等，播种使用快速节奏，交互保留默认节奏。
3. 补齐身份和故事测试，分为归属与故事两个原子提交；每个提交通过构建与检查，最终串行运行所有 Web 巡检、Go race 与 make check。
4. 使用独立临时目录和空闲回环端口运行沙盒，在桌面与手机捕获故事页面，停止本次进程；不操作已部署沙盒、生产或其它工作树。

时间分布优先使用现有注入时钟；如无法在不干扰 runner 租约与背景调度的情况下安全分离播种时钟，保留真实时间并在报告说明。

## 实施记录

- 活动 Author 从不可变请求主体和冻结目录解析；交付行与当前进展同步展示作者。收件箱的主机／系统回退不再误称负责人。无需新增字段或生成类型。
- 多轮故事走真实主会话、负责人工具和 owner 答复；同一任务保留第一次失败、显式重试与独立验收。真实上下文读取、40 条原生检查消息及完整说明覆盖本轮续页；多轮讨论和进展覆盖较早活动分页。完成回执缺少故事时使用相同稳定命令追加升级，删除完成回执后完整重播也不重复对象。最终由负责人移到待评审，另一执行仍待 owner 回答。
- 快速节奏只覆盖播种阶段，完成后恢复默认交互；维持真实时间，因为共享服务时钟同时约束租约及后台调度，不为展示分布而改变它。
- 定义历史、跟进规则修订和顶部最近时间没有携带独立动作作者；未增加新的读投影。原始来源与外部交付已显示已有作者，保持其内容。
