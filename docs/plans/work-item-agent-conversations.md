# 工作项后台 Agent、消息关联标签与上下文管理

状态：实施中，未达到发布验收。后台默认关闭；按 owner 后续指示，原生工具暂时允许保留，后台显式使用 auto mode。设计依据：D111。不包含自动合并或生产部署。

## 目标与边界

后台事件的读取、核对和整理移到独立 agent；主 agent 继续负责业务调度、用户协调，以及维护对话与工作项关联。每个工作项一个持久逻辑后台会话，用户可以查看过程、直接补充消息，主 agent 可查询其持久 rollout。实现消息标签、owner 纠正、上下文同步、会话抽屉、ctx 圆环及原生 compact。外挂不增加主动运行能力；worker 实现和验收职责不变。

## P1：消息关联与上下文

- 程序自动收集确定关联并提供回复候选，主 agent 判断自然语言的语义关联；一条消息可关联多个工作项，闲聊不强制绑定。assistant 回复按实际内容登记，不复制整轮关联。
- 关联只表示相关性，不构成授权或完成证据。目标、约束、授权、拒绝、承诺、未决问题分别保留来源、范围和取代历史。全局和项目约束按范围继承。
- 正式工具支持读取和修改关联、登记事实、准备历史基线。明确 owner 来源进入相关上下文后才能用于调度、计划修改和交接。缺失关联返回可修正错误；不确定语义保留待关联。
- owner 可批量增删消息标签，带修订和请求身份；保留操作者及前后状态。owner 移除的关联不被 agent 自动恢复，agent 只能提出建议。
- 关联纠正推进所有受影响工作项的上下文版本，通知主 agent，使旧摘要、基线和后台结果失效；派生事实待核对。已发生执行不自动撤销，原文和审计不删除；模型收到明确纠正，未来快照排除旧关联。
- 每个工作项的上下文包括需求沿革、约束和授权、承诺、未决问题、阶段任务、验收交付观察，以及相关消息、工具、报告和附件索引。关键事实直接注入，长原件分页读取。
- 新工作项创建基线；已有工作项由主 agent 首次整理并记录检查范围及缺口。后台每轮读取新版本；恢复、compact、thread 交接后补充关键事实。版本过期结果保留但不能结清或驱动动作。后台可向主 agent 请求补充已有背景。
- 保证截至水位已登记来源可追溯、关键事实已交付、变化不静默丢失；不声称程序能证明自然语言关联绝对完整。

## P2：后台会话与运行

- 工作项首次需要时创建一个逻辑会话，原生 thread 代次独立。同会话串行，跨会话并发默认 2，可配置，不占 runner 槽。后台 harness 与主进程分离，不持有主会话锁。
- 模型和推理强度初始继承主会话，之后按会话修改。工作项关闭后停止自动处理，保留历史；重开继续原会话。无工作项事件由主 agent 判断关联，异常和待决即时可见。
- 独立后台身份和服务端 Tend 工具白名单，仅可读所属工作项、继承约束和关联证据并提交结果，禁止通过这些工具执行业务调度写入。按本文件末尾的临时权限调整，原生工具保留并使用 auto mode，不承诺原生文件和命令的工作项级隔离；技术调查仍委派 worker。
- 保留批次合并、领取冻结和来源。结构化提交绑定批次、上下文版本、水位和证据：无变化静默保存；新事实无动作保存简报；推进、异常或待决唤醒主 agent。未完成 completion review 必须由主 agent 处理。
- 回传持久去重、双向链接，不自触发循环。主 agent 行动前读取当前账本和授权。自然语言回复不是正式提交。
- owner 后台消息保留原文、附件、身份和归属，同时向主会话发原文引用及协调通知。owner 消息优先未领取批次；不新增自动 steer。停止只影响当前会话 turn。

## P3：用户界面

- 保留现有侧栏、消息、浮动输入框和手机底栏。主/后台两级入口；后台打开工作项抽屉，桌面右侧覆盖，手机全宽覆盖。按最近持久消息降序，搜索、状态筛选、游标每页 30 条；工具碎片和 token 不抬升排序。
- 抽屉展示名称、消息预览、时间和排队/处理中/空闲/失败/待核对。选择后关闭抽屉，标题和输入框明确接收方，有返回主 agent 和工作项入口。
- 草稿、附件、回复引用、滚动、模型配置、发送队列按会话隔离；重试固定原目标。
- owner 和 assistant 消息底部低对比度工作项标签，最多两个再加 +N；工具行不重复。标签以稳定 ID 显示当前名称；点击打开详情，菜单可查来源和纠正。无关联消息操作菜单可添加，正文不变。
- 主聊天去掉通用后台触发卡、全局后台队列及重复处理提示；主运行指示只表示自己。当前会话用户队列、撤回、取回、完成/选择/待决卡保留。后台源轻量折叠，回传链接到处理过程。历史归属不伪造迁移。

## P4：rollout、ctx 与 compact

- 提供会话/turn/游标的持久记录读取：消息、完整可用工具输入输出、状态、compact、回传、原生 thread 链。来源可定位；只查登记身份，不接收任意路径；缺失历史明确标记。
- 输入框模型旁小圆环，点击显示占比、活跃 token/有效窗口、采样和测量状态、compact 历史及手动入口。使用运行时同 revision 的 ContextUsageSnapshot，不以累计 token/费用计算；缺失、估算、断线标明。
- 手动 compact 使用原生接口，在当前 turn 后、下一输入前执行，与交接互斥。受理不代表完成，按事件确认；unknown 对账不重放。完成刷新 ctx 和关键事实基线；原生 compact 与 thread 交接分别记录，不支持时明确提示。

## P5：数据、兼容和验证

- 增量增加逻辑会话、消息关联与审计、版本上下文、批次结果、回传、ctx 及 compact。旧聊天归默认主会话，保留 ID/顺序/附件。
- 新增列表、关联编辑、上下文、compact、rollout 接口；旧聊天/附件/队列/设置增加可选会话目标，省略仍为主会话。SSE 含身份；标签与上下文使用同一来源。API 类型生成，不手写。

- 桌面/手机、长标题、多标签、键盘和浅深主题浏览器验证；实际截图与接受设计对照。旧客户端和历史回归，make check、独立 review 和交叉编译。
- 先隔离真实 harness 验证，再小范围启用。观测主消息等待、后台排队、唤醒率、关联纠正、过期和 unknown。本期不部署。

## 后续：topic/channel

本期只记录，不添加入口、channel 表或多主 agent 执行。topic/channel 组织对话，工作项组织责任和执行，二者多对多；标签不能被 channel 归属替代，同工作项跨 topic 上下文仍汇聚。逻辑会话不等于原生 thread。未来单独设计创建切换、未读、引用、移动和约束继承，以及共享还是独立主上下文。

## D111 临时权限调整：后台使用 auto mode

本节根据 owner 的后续明确指示修订前述原生工具隔离要求：暂时允许后台会话保留原生工具，权限使用 auto mode，不使用 yolo，也不再要求原生动态工具白名单作为启用前提。

实施步骤：

1. 移除 server 和 harness 中针对后台原生工具清单的无条件拒绝；后台创建、恢复均显式使用 `workspace-write`、`on-request`、`auto_review`。不继承 worker 的 `danger-full-access + never`。
2. 后台仍使用独立进程、后台身份和受限 Tend 工具；业务调度与完成决定仍由主 agent 执行。后台使用独立工作目录，避免多个会话默认共享可写目录。
3. 验证真实 app-server 创建和恢复后的有效权限，正常后台核对可以运行；额外原生工具的存在不再令测试失败。保留严格工具隔离的历史探测结论，明确它不再是本期启用门槛。
4. 自动审查交给原生运行时。Tend 不代替审批器自动批准意外返回的审批请求，也不因拒绝或失败降级到 yolo；核对未完成仍走既有失败/回传路径。
5. 更新 D111、能力报告和针对性回归。其余完整计划中的未完成项继续保留；本次调整不包含生产部署。

当前保证限定为 Tend 工具边界的服务端校验和运行时 auto mode。原生工具仍可能在其权限范围内读取文件、执行命令及申请升级，auto mode 不能被描述为工作项数据的强隔离，也不能替代 owner 的业务授权。

临时权限调整已完成针对性回归、真实 app-server start/resume 的 race 集成验证、完整 `make check`、Windows amd64 / macOS arm64 命令入口交叉编译及独立复审。复审未发现本次调整的可证实缺陷；自动审批器实际决策与上述完整计划未完成项仍待验收。

## PR 前最新主线整合

合入统一详情覆盖层后的最新主线行为：工作项详情保留后台会话入口，由 Shell 统一关闭详情并清理 URL；保留材料预览、详情导航与返回行为。整合后重新执行类型检查、浏览器会话与详情回归、完整检查及独立评审，再创建 PR。

PR 独立评审修正：本机取回编辑与另一发送器提交竞态时，服务端队列核对必须从持久原消息 envelope 读取 conversation_id；不能依赖当前 UI 会话或缺省查询主队列。增加后台及旧主会话路径的回归，验证服务端撤回和草稿恢复。

PR 独立评审修正：受控升级必须聚合主会话与后台进程池 drain；升级 gate 下停止后台启动和领取新投递，compact 不能绕过 gate。持久 starting/running/unknown compact 也阻止升级，包括已退出进程的后台会话；增加后台活动、gate 和 compact 回归。

PR 独立评审修正：后台恢复等待 manager 完成 startup settlement 后再确认旧投递；停止请求对账沿用只读 Control.Reconcile，不重发 interrupt。持久控制请求遇到 HTTP 5xx 时按未确认传输查原回执，查不到则保留原 request_id，不清除本地 journal。分别增加恢复与 503 回归。

PR 独立评审修正：正式 assessment 记录其 return_message_id，失效结果回传不被 turn settlement 再次唤醒。追加迁移按实际主会话归属限制摘要 coverage 触发器、最大序号和活跃时间，后台消息、工具、附件及 turn 不污染主摘要；消息删除及主会话关联更新继续推进水位。
