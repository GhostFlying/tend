# 运行时判断点诊断

Refs: D239。

## 业务路径与边界

原目标是让现有调度、Task／Run／Issue 操作以及完整发布集滚动升级，在被拒绝或暂停时可以从当时的结构化日志解释原因。升级曾在 server 恢复后因「其他执行主机不可用」进入 attention，但该判断只返回布尔值，之后查询到的主机状态不能还原暂停瞬间。日志不参与授权、状态机、租约、重试和完成判定；日志输出失败不能产生新的业务卡口。

路径为 serverkit 注入原有日志器 → App.Execute → 原命令事务内判断／持久化 → 提交后记录结果。升级主机可用性仍使用原有在线、心跳截止、slots、控制模式、运行模式及控制 ACK 谓词，不更改选择或授权。诊断保存该次判断已读取的值，不增加新的查询来近似重建过去状态。

## 实现

1. 复用原有 slog handler 与输出轮转。server／runner／updater 的实际进程入口统一读取 `TEND_LOG_LEVEL`（空值为 info，verbose 为 debug 别名，非法值明确拒绝启动），原有全局日志也使用该 handler；入口帮助和运维文档说明该环境配置。App 的日志器由构造选项注入；测试未配置时不额外输出。
2. 命令拒绝记录 operation、错误码、对象身份、request／trace、预期控制版本；不记录 payload、reason、用户文本、凭据或完整内部错误。提交后的 Task／Run／Issue／upgrade 事件在 info 记录事件名、对象与版本，其他事件及无效果观察在 debug。事务失败不伪称状态已提交。
3. 其他主机可用性判断返回同一次读取的逐主机事实。正常观察在 debug；升级确实因无可用主机暂停时，在 warning 保留该次快照、目标主机、阶段、原始期限与失败谓词。明确区分有限 normal ACK 等待和真正不可用，不将缺失事实填成成功。
4. server 启动日志记录实际 PID／父 PID、可执行文件与标准输出／错误文件描述符的定位信息，便于找到正在运行进程的真实日志流。路径来自运行时；不记录命令参数、环境或配置正文。

## 验证

- 验证 debug／verbose／info／warn／error 及空值的实际 handler 过滤行为，非法值不创建 logger；环境帮助可见且不影响业务命令输出。
- 用现有 server-first 完整业务 fixture 走到 normal ACK 间隙，再制造离线、心跳过期、无 slots、非 normal 运行模式及控制 ACK 落后；验证暂停与等待行为不变，日志捕获的是控制恢复前的原始观察和精确失败谓词。
- 通过真实 App.Execute 验证提交事件、业务拒绝与回滚结果区别，且不泄漏用户 payload／reason。
- 对变更包运行定向 race 测试与 vet；完整检查、独立审阅和 CI 由汇总交付协调者在最终候选执行。

## 不纳入

不修改 DB 缓存／读池、测试时间语义、协议或生成类型；不增加证明账本、通用启动器、永久恢复迁移或业务审批。不从新日志推断历史缺失请求的唯一原因。
