# 移动聊天附件操作间距

Refs: D70。

## 范围与证据

原移动端截图及已交付调查都显示主聊天附件名称与移除操作相接。当前入口仍将名称文本
紧邻 link 按钮输出，按钮也沿用紧凑文字高度。诊断聊天的附件卡片不能替代首页主聊天。
本变更只修这个可复现的布局缺口；不将 Chromium 验证冒作 iOS standalone 安全区、
字形栅格化或原生选区拖动的验证。

## 实施

1. 为附件行分配明确的名称区域、行内间距和独立移除操作，长文件名可换行，按钮不被压缩。
2. 移动端移除操作采用既有触控尺寸，保留实际文件名、移除与显式发送行为，不自动上传。
3. 在现有真实客户端全页导航回归中加入短/长附件、320/390 窄屏与深浅主题，核对名称到
   操作的实际矩形间距、无横向溢出、触控尺寸和移除后剩余内容。保留修复前失败证据。
4. 当前粘贴功能的独立候选若先合入，按新 main 保留它的预览卡片并复核本布局；不覆盖
   已有剪贴板、撤销或附件队列行为。独立 review 与检查通过后合入，部署由集中重建安排。

## 顶部安全区补交付

首页主聊天与共用 PageHeader 没有应用顶部 safe-area inset，旧诊断聊天反而已处理。
在 viewport-fit=cover 下，真实入口应独立预留 inset，不能靠诊断页面的正确样式替代。
仅在移动断点为这两个默认 header 增加顶部 inset 与相应高度，不改已有自定义 header。
利用 Chromium 的实际 CDP safe-area override 依次验证 0/47/0px 的首页与收件箱文字、
header 高度及回退，不模拟 iOS 的字形栅格化或原生光标拖动。原生两项仍保验证边界。

独立审查确认任务详情同时有外层 PageHeader 和旧内层 Details header，顶部 inset
必须只由外层拥有。Details 当前只有这个调用点；移除内层重复 inset，并加入实际
任务页正文位置的 0/47/0 回归，防止只验证外层 header 而漏掉正文双重下移。
