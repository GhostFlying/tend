# Agent 安装引用的受控维护（D106、D123）

目标：同一 runner 同时登记不同 CLI 的 Orca runtime，允许通过现有配置维护批次追加安装引用；不绕过维护冻结、排空、配置哈希、健康确认及回滚。

1. 配置校验仅在既有 Agent 来源和执行后端不变时允许追加安装引用；旧引用不得修改或删除，runner 身份、transport、存储及其他配置继续固定。
2. 使用固定来源的严格 Agent 配置解码及 registry Prepare 校验完整引用关系；新增安装引用必须使用绝对路径，原文件 SHA-256 必须与声明一致。校验不接受配置、不登记库存、不调用模型。
3. 安装引用变更沿现有单主机配置维护应用，同程序重启后仍须显式 validate/reload Agent 定义。旧 accepted snapshot 和正在使用的执行配置继续保留；配置备份不声称恢复独立的 Agent 定义文件。
4. 用配置维护边界测试验证追加成功、旧引用修改/删除拒绝、来源/后端变化拒绝、无效定义/哈希拒绝和校验无副作用；通过 make check、独立 review 和 PR 后发布。
5. 部署时先发布校验能力，再逐主机维护追加 Orca/Codex 安装引用，显式接受与登记新定义。实现分类分为 implementation 与 implementation-economy；后者选择 TraeX 的 Flash/high，调查和评审选择 Codex。Issue owner 按任务确定性选择分类，质量与独立验收标准一致。部署私有配置、模型可用性和实际命令证据另存本机笔记，不提交公开仓库。

协议评估：仅扩展 runner 本机配置校验的允许范围，复用现有配置维护能力与消息，不改变 server/runner 的通信结构、必填字段或既有请求默认语义。
