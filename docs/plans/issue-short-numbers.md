# Issue 永久短号

## 业务入口与终点

- Owner HTTP/CLI 的 Issue 创建与 Agent 协调工具进入 canonical owner command，最终通过 `SaveCanonicalIssue` 写入 `work_items`。旧 `work_items.create` 也写同一表。两个入口的稳定业务 ID 和重试规则继续沿用。
- 现有记录在打开数据库时补号。Issue 当前详情、历史详情、看板、搜索和人类引用读取同一个映射。状态、项目变更、重开、会话绑定和自动化继续使用原 `wi_` 主键。
- Web 在载入 /issues/T123、/issues/t123 和旧 /issues/wi_… 时解析路由，规范化地址并保留查询、片段与阅读定位。页面加载后的业务读写仍使用内部 ID。
- 正式 Issue 搜索复用列表及详情读取。带 T 前缀的查找支持号码前缀，裸数字在 Issue 查找与 CLI 中按号码解释。聊天输入在 T 前缀下提供按号码和标题的候选，发送后的文本按普通 Markdown 引用呈现。纯数字、#123、文件和外部链接沿用原语义。

## 持久化和兼容

- 追加迁移，为 `work_items` 的身份建立实例级映射。按创建时间、内部 ID 的稳定顺序补号。独立的 SQLite AUTOINCREMENT 主键跨项目分配，唯一约束确保每个内部 ID 只有一个号码。
- 由 `work_items` 插入触发器在同一写事务中分配编号，覆盖 canonical 和旧入口。回滚不保留可见映射。成功创建的重试命中原 ID 时读取同一编号。通过独立投影读取当前和历史短号，保留原快照、事件和 API 内部 ID。旧 Work Item API 也返回补号。规范 Issue 链接和建议使用已存在的 canonical Issue。
- 把输入解析留在人类可用的读取边界。短号不参与命令信封、授权、父子关联和消息投递身份。发布可选 `short_code` 字段并重新生成 Web API 类型。

## 验收证据

- 从上一个迁移版本打开有多个项目和终态 Issue 的数据库，验证补号顺序、历史详情与现有 ID、重复打开稳定。
- 通过真实创建入口验证跨项目与并发分配、事务回滚和原请求重试。验证查询前缀、大小写、裸数字与内部 ID。
- 用项目浏览器测试验证旧地址及大小写跳转、query/hash 和历史消息定位，检查 Issue 链接、聊天提示、引用插入及普通数字和外部引用。运行 `make check`，记录候选及基线、独立审阅与必要 GitHub CI，受保护 rebase 合入后核对提供方与 Tend 记录。

## 审阅发现与恢复验证

- 进入 Issue 详情时重新验证共享身份缓存中的 404。聊天里的预查询继续共用缓存与请求。回归从同一标签页的聊天引用开始，在 Issue 可读后通过短号进入详情。
- 历史消息定位沿用可取消、会退避重试的读取器。读取失败时保持当前 Issue 内容和定位参数。回归在历史回复的元数据请求返回一次 503 后验证自动续页定位。

## 看板按最近进入可见阶段的时间排序

1. 在不可变的规范 Issue 控制修订上派生当前可见阶段的最近进入时间。Web 看板将进行中和待检查合并为一列，在两种内部状态之间切换保留进入时间。API 和 CLI 的未分组选项保留独立列及各自进入时间。创建及跨列变更在原事务中登记，普通修订保留当前进入时间；运行调度不读取该投影。
2. 迁移按每项最新连续的控制修订段恢复阶段开始，在可证明的创建或相邻异阶段边界取可信时间。缺少证据时回退到不可变创建时间，并在 API 及看板标明。用时间降序加内部 ID 固定同毫秒顺序，游标携带完整排序键，筛选与列归类沿用原规则。旧看板游标应从第一页重读，Web 加载更多沿用现有的逐页重读机制。
3. 通过真实 HTTP 和真实浏览器验证初次进入、移入、离开重入、普通修改、同时间、过滤及跨页。单独用旧数据库迁移测试验证历史段、缺口回退、后续更新和回滚。运行同一 PR 最终候选的本地检查、原审阅者复核和必需 CI，完成受保护 rebase 后核对回执。

重基到带「待我处理」和合并审阅列的主干后，分别投影独立列和合并列的连续历史。两种投影各自保留页内排序索引，基于对应投影单次求取阶段计数、筛选和分页；卡片继续返回内部状态，保留待检查标识。实测同时覆盖待我处理筛选和开关分组时的状态归类。

链接兼容继续处理第二轮审阅发现的在途 404、历史锚点被详情初始滚动覆盖、文件路径误识别。三个场景有同标签页、慢请求及普通消息/Markdown 回归。

第三轮补测发现短号可能嵌在带连字符的文件名或路径中。按完整文件词段判断后再识别短号，保留普通标点分隔的引用和旧内部 ID。增加文件名、相对路径、Windows 路径和历史回复行内代码回归。

保留主分支已有迁移，包括 0144–0145 的聊天迁移和 0146 的 Runner 工作区清理迁移。短号、独立列和合并列迁移依次为 0147、0148 和 0149。迁移测试分别从上一版数据库打开。

第五轮复核发现，从旧链接直接定位到第三页回复后，手动续读仍从默认页数开始。让读取器记住已成功读取的深度，手动续读持久化下一页深度。用桌面和移动端的浏览器用例从旧地址定位到第三页，随后一次点击显示第四页，同时保留第三页回复。

独立复核补充两个旧链接场景。别名请求迟到的 404 不应覆盖已由另一条身份读取确认的永久短号。公开过程消息定位时展开对应回合并显示目标所在的较早步骤，实际可见后再确认定位。用桌面和移动端从真实详情及聊天访问入口复现交错响应和折叠过程定位。

第七轮复核覆盖同一 Issue 内的历史消息链接。没有重载的导航会切换浏览器历史条目，续读的读取订阅和写入应使用同一个当前条目，切换条目时关闭前一条目的未完成续读。用实际 Markdown 链接在桌面和移动尺寸覆盖页内点击、一次继续读取下一页、回退和前进恢复。

第八轮复核覆盖两种较慢的加载路径。前进恢复历史时，同时恢复该条目已显示的读取深度，首次续页从已恢复的末页继续。公开过程中的待发布工具有稳定 ID，普通消息缺少该记录时按当前会话匹配可公开的步骤和原触发消息，仅返回定位元数据。读取不发布工具或正文。

与首屏可读投影合并时，普通历史回复仍沿本轮消息游标定位，公开工具锚点通过已经存在的公开过程读取器逐页查找。普通访问沿用首屏异步预取和显式展开；浏览器后退或前进仍恢复已展示的本轮消息深度。

第八轮复核覆盖四个入口。新聊天引用可重新核对旧的 404，同一次在途重查由共享读取器合并。延迟的工具面板挂载后重新执行同一个定位动作，主动滚动可取消待定位。自动展开的公开过程与手动展开一样观察版本刷新，关闭后沿用原预取行为。CLI 的 `message original --conversation` 进入限定会话的读取路径，兼容旧命令的无参数请求。
