# Web 重连状态诊断

浏览器已收到主事件流后，顶栏的黄色状态点表示正在重连。原来的原生 `title` 无法保证鼠标悬停后出现，也无法通过键盘或触屏可靠查看。用户需要看到浏览器在当前重连期间观察到的现象；此次历史生产断开的原因仍未知。

- **入口与状态**。从桌面侧栏的完整状态、窄桌面侧栏和移动顶栏的紧凑状态进入。保留 `ApiClient`、`EventStream` 和 `startConnector` 的重连、游标与恢复流程。状态保留当前重连中已知的事件流观察。没有观察详情时显示「原因未知」；收到流结束只描述事件流已结束。
- **交互**。重连期间提供可聚焦的按钮与非模态说明。鼠标移到按钮或说明时可读，离开后收起；键盘焦点进入时显示，失焦或 Escape 后收起；触屏可点按切换或点按外部收起。重连成功时移除说明。使用现有样式变量，检查内容换行与各视口的实际位置。
- **验收**。在独立的 loopback HTTP fixture 加载真实 Web 应用，先建立 SSE，再实际结束连接或发送游标重置信号，经正常连接器触发黄点。Chromium 用真实鼠标、Tab、Escape 和触屏输入断言可见内容、关闭行为以及流恢复；验证已知观察和未知详情。复用仓库的 Playwright 与 CI 布局入口。保存浏览器日志、截图和验证结果；运行受影响的 `make check`，并在独立审阅和 PR CI 对应最终候选与最新 `main` 后按保护规则 rebase 合入。

## 独立审阅后的修正

- 状态文本使用持续挂载的 `role="status"` 节点。黄点按钮独立提供诊断操作；浏览器回归核对在线、重连和恢复时是同一个状态节点，且文本随状态更新。
- 将重试过程中收到的游标拒绝详情送给诊断浮层。无详情的流重置仍显示「原因未知」。通过 SSE 断流、HTTP 游标拒绝和无游标重连验证完整顺序。
- 按钮按当前展开状态切换。通过实际 Tab 和 Space 验证首次激活收起、再次激活打开，保留 Escape 与失焦路径。
