# 维护审计的按需账本查询

维护 Agent 在计划审计中自主选择证据。当前 issue/task 详情返回整个对象，等待列表返回整个 Task 的历史。一次正常等待也需要分开确认原 Run、等待条件和进程停止，检查候选时还要单独核对观察和原件。维护探针未报告 case 时，原账本仍必须可查。

## 实施

1. 保留现有认证的 Issue 和 Task 详情 API。在 CLI 对原 JSON 的顶层字段做可选投影，沿用整个对象的键名和值。保留缺失、null、空数组、空字符串和 unknown 的区别。无参数时保留既有输出和 Issue 历史版本选择。JSON 投影缩减 CLI stdout。
2. 在现有 owner 等待 GET 增加可选 run_id/status，在同一 Task 范围内精确筛选并保留原排序与记录。无参数时保持全列表。复用现有状态和授权，查询不触发继续、重新检查或停止。
3. 参考 #376 的具体子命令帮助，去掉受影响读取帮助里无效的共有 flags，登记能力示例和审计查询索引。复用活动分页、对账、候选和原件查询。保持探针、定时审计和权限不变。

## 验证

- 实际 CLI → owner HTTP → ledger。相同 fixture 比较完整与窄查询的键和值、输出字节数，覆盖无匹配、组合筛选、不同 Task、历史版本及认证。
- 建立正常停止的等待和一条原 Run 停止/收据不明的反例。实际跑既有检测器，展示它的结果和 Agent 按条件、原 Run 及原始证据独立查询的结果。在报告中明确正式转换和 fixture 预置的边界。
- 运行仓库受影响检查和候选独立审阅，交付可审阅 PR。
