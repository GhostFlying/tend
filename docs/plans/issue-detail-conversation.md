# Issue 详情与负责人对话统一

状态：已实现，本地工程与浏览器验证通过；最终复审和 PR CI 作为合入门禁。设计依据 D129，保留 D121 的 canonical Issue、独立执行及来源边界。

## 目标

Issue 默认打开应用内完整详情页。主栏依次呈现待处理事项、负责人进展与下一步、可展开定义、直接子项和讨论／关键结果；辅助侧栏承载交付、执行、来源、跟进与历史。负责人逻辑会话是固定交流入口，实施和独立验收原生历史保持隔离。

## 实施顺序

1. P1：追加摘要迁移和请求命令，保留 CAS、assignment epoch、原子 revision／event／receipt；扩展当前及历史安全投影、实际会话与父路径。
2. P2：实现基于已提交账本的分页活动与执行交付只读索引，保留准确 artifact／spec／验收身份、来源和作者。
3. P3：完整详情导航、共享会话资源、主栏及响应式辅助面板；复用草稿、发送队列、附件和 Task 详情。
4. P4：接通事件刷新、原 Attention 回答、交付预览、父子与返回状态、摘要编辑和 manager 工具提示。
5. P5：定向事务／权限／分页／媒体测试、浏览器桌面与窄屏回归、完整 make check、交叉编译和规定独立 review；PR CI 通过后线性合入。部署另行交付。

## 合同

- IssueProgress：summary（500 字符）、next_step（240 字符）、issue_revision、updated_at、updated_by；独立摘要 revision 表，普通定义更新不覆盖。
- issues.update_progress：owner 或当前本项 manager，沿原请求信封、控制 revision 与 assignment epoch；原子保存、可重放，两空字段明确清除。
- IssueView 增加 progress、conversation 和 ancestors；历史只读取对应 revision 摘要，不返回当前执行或可发送入口；GET 不创建会话。
- GET /api/v1/issues/{id}/activity：分页已入账回合和关键业务事实；稳定顺序与水位，排除心跳与原生工具噪声，不复制子项全文。
- GET /api/v1/issues/{id}/results：按 primary Issue 汇总不可变交付与对应验收；外部交付沿原 deliveries 接口，输入附件不变成交付。
- 前端从服务端获取会话身份；每逻辑会话复用一份草稿和队列，页面与会话 reader 分离，unknown 保留原请求。

## 验收

覆盖摘要幂等／旧版本／旧 epoch／跨项拒绝及历史读取；对话草稿和路由隔离；活动分页与流式更新；精确交付验收绑定；父子跳转及 Task 返回；decision/action 与 information 区分；交接、用户负责、暂停、结束与离线状态。浏览器覆盖桌面、平板及 430／390／320px，浅深主题、长文本与媒体。首次打开先看到当前情况、待处理和固定收件人，不强制滚动到日志。

## 发布兼容
