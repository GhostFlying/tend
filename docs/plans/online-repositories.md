# 在线仓库注册与 runner 绑定（D110）

## 目标

新增仓库属于运行态资源管理，不再要求 server 或 runner 重启、排空现有任务。提供正式 owner CLI/API 与 runner 本机 CLI；不创建仓库或任务，不移动已有工作区。

## 实施

1. server：新增带请求去重和控制修订的 `repos.register`，记录在线管理标记。配置只管理未被在线接管的仓库，重启不能覆盖或退役在线登记。已有远程身份不能在线替换；支持基线候选及停用状态。
2. runner：增加私有本机 Unix socket 和 `repo bind` 命令。校验既有 Orca 仓库及实际 origin，将显式选择解析为固定 provider ID，持久化绑定后更新内存。绑定只允许新增或相同身份重试，避免运行中任务被重新解释。
3. 准入：以现有 hello/heartbeat 的可选仓库观测发布已加载绑定，仅发送精确 remote 地址的 SHA-256 指纹，不包含本机路径或 provider ID。server 仅将与登记 remote 匹配的绑定加入该 host 的有效仓库集合；保留旧静态 host/repo 配置语义。调度、队列和仓库列表共用该集合，未确认绑定不能派发新任务。
4. 兼容：仅在 hello 能力确认后发送可选观测字段，不改变协议 1 或 0 的既有有效请求及默认行为，不提升通信协议；新增 SQLite 迁移保留所有旧数据。本机 registry 不是程序更新器配置维护，不绕过 D106 或重启门禁。
5. 测试：注册去重/修订、配置重放保护、退役、新旧 runner、绑定校验/持久化失败/重试、动态 host 准入、工作区身份与并发读取。执行 make check 和独立 review，CI 通过后 rebase 合入。
6. 部署：构建固定提交的不可变发布；经已有滚动升级流程等待 run/未知操作排空。部署后在线接管 lynx 注册并在两台 runner 绑定现有 Orca repo，核对同一 PID、账本 host 准入和历史身份。需要重启的是本次能力升级，后续加仓库不需要。

## Review 修正

- 绑定写入使用单独的写者锁，Orca/Git 校验及磁盘持久化不占用心跳观测的读取锁；发布时只交换不可变快照。短租约 worker 在慢绑定期间继续续租。
- 在线退役不使既有 bootstrap 模板无法加载；新挂载仍根据账本 retired 状态拒绝。
- remote 使用精确地址指纹，不推断传输别名、`.git` 后缀或 SSH 路径根的等价性。
- 在线绑定的固定 provider ID 优先于旧启动配置显示名；owner CLI 对账先读已有请求结果。

- 本机控制 socket 对长 home 使用短私有目录，CLI 与服务共用定位逻辑，旧的长路径配置仍可启动。
