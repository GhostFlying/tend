# Inbox 普通待办手动收尾（D125）

用户在 Inbox 打开一条由服务端确认可清理的普通待办，点击「无需处理」后沿原撤回事务变更同一事项。待处理列表、徽标和 Planner 从已提交的状态更新，历史保留原记录、操作者、时间和撤回方式。

- 检查生产来源与责任表示，选用明确的普通来源分类。读取投影和写事务使用同一判据，写入以真实 owner、当前收件人及原 revision 为准。历史缺分类、真实阻塞、决定与授权继续走各自路径。
- 在既有撤回协议加显式模式，保留有理由撤回与技术负责人收尾。原请求回执用于未知结果核对。
- 增加 Inbox 独立 action 控件和历史展示，减少与决定交互 PR 的重叠。同步 CLI、能力声明及生成契约。
- 使用隔离数据验证正常流程、权限、历史、竞争和未知回执。运行仓库影响验证和浏览器交互，提交独立可审阅 PR。

独立审阅后补齐旧版撤回和回执恢复。旧请求仅沿用信封的撤回理由。明确选择新模式时校验该模式的请求字段。Web 核对回执时也检查原责任版本。CLI 在发送前显示重新核对所需的原参数。
