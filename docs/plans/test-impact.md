# 自动测试影响分析与分层验证

Refs: D173，修订 D145/D149/D151 的检查选择策略。

## 目标与边界

Go 用实际逐根执行覆盖和 AST 函数身份选择测试，Web 用模块依赖选测，浏览器保守回退。初期 shadow 同时执行选测和完整检查，只有正确性与五 PR 周期摊销收益都成立才切换默认策略。本次不删除业务测试、不优化生产 SQL、不部署服务。

## 实施顺序

1. 用标准库实现源码快照、构建配置、动态根发现、逐包一次编译和逐根隔离采集；覆盖所有本模块生产代码；进程边界包通过普通全量的完整逐根事件建立静态回退，不重复隔离启动未知进程树。失败或缺失数据不能形成可信基线。
2. 按 AST 比较函数体；声明、资源、测试 helper 和未知情况使用包依赖或全量回退。比较可信祖先基线到候选的累计差异，包含本地未提交和新增文件。记录完整选择理由及执行前后源码身份。
3. 接入现有 race 调度和 Web 模块选择，提供 plan/full/baseline/benefit 入口及 JSON 报告；保留快速质量检查、CPU 预算、取消清理及本地/CI 检查集合边界。
4. CI 从可信 main 成功工作流取基线，初期继续完整门禁；每累计五个不同 PR 合入后串行完整刷新，不设夜间定时。只有完整成功才推进基线，失败恢复完整门禁。release 对固定源码执行完整 CI。
5. 冻结候选，做故障注入和连续五 PR、三组交替配对回放，计入初次采集和第五次刷新成本；分别报告本地与 CI 结果，按净收益决定是否切换。完成独立 review 和 PR CI。

独立 review 的源码读取反例补充：Web 测试可通过文件系统读取 Web 或 Go 源码，这类依赖不在 Vitest 模块图内。首版自动识别文件系统及进程 API 的模块标识；存在这种边界且源码发生变化时扩大为完整 Web 检查。将文案扫描及跨语言常量读取的真实失败反例加入验收，不人工维护业务测试标签。

并行检查使用各自的私有执行计划，先核对磁盘计划与本次选择一致，再冻结副本交给 race 调度器，避免共享报告路径被另一轮检查覆盖后缩小执行范围。

每个 Web 故障反例使用新的报告目录，并核对本轮 Vitest 原生结果。命令提前失败、缺少本轮结果或仅有旧文件不能证明故障测试已经执行。

## 正确性验收

- 根发现含 Test/Example/Fuzz seeds，初始化和全部子测试属于对应根；覆盖、超时、取消、子进程、源码变动均有明确完整性边界。
- 函数、方法、签名、常量、类型、init、测试自身/helper、迁移、嵌入资源、构建配置、新增/删除、未知文件均有测试。
- 生产反向依赖与测试终端依赖分开；基线缺失、损坏、不兼容、非祖先或覆盖不完整不能少选。
- 故障注入以完整运行真实失败根集合为依据，要求选测包含所有失败根；编译失败不能被跳过。
- PR 4/5/6、多提交、重复事件、刷新期间继续合入、失败及候选漂移均不丢计数或伪造成功。

## 收益验收

每个候选先编译普通及 race 测试并收集 Web 模块，使第一组配对也使用暖构建缓存，避免首次全量替第二次选测承担构建成本。依赖安装、Go 编译和 Web 模块准备分别记录；实验准备与每轮测量分开列示，下载等共同成本同时归入两种策略，不从净值中隐藏选择器的独有成本。

在同一机器、工具链、源码和 CPU 预算下，连续五个真实 PR 候选逐个比较完整与选测，每个三组交替运行，关闭测试结果缓存但统一构建缓存状态。单列首次覆盖采集、第五个 PR 后完整刷新、分析/编译/下载开销和资源时间；补局部 Web、缺基线及必须全量场景。没有正确性与正向净收益证据则保持 shadow，报告未完成的证据，不以小样本或历史不同机器耗时代替。

收益回放的失败收集补充：检查结果具备本轮源码、构建配置和执行完成证明时，失败样本保留状态、原生收据与耗时，继续后续配对；取消、源码漂移、缺失或矛盾收据立即停止。每轮原子保存进度。完整采样与收益验收分别记录，任一失败使最终命令非零退出且不计算可验收净收益；刷新失败保留旧索引，不能发布失败基线。另记录真实缺基线回退的强制重跑。

反向资源读取补充：增加 Go 测试读取 Web 源文件的原生失败反例；Go 的文件系统模块导入视为不透明资源读取，生产依赖和测试终端依赖仍分开。任何源码或资源变化都保留未归属进程和资源读取测试包，不能仅在 Go 文件变化时保留。先复现漏选，再修复并重新冻结收益工具；此前完成的配对保留为旧版本诊断，不能混入最终冻结周期。

CI 环境固定补充：本轮真实工作流的两个浏览器分组均在安装阶段因 ubuntu-latest 分配 Ubuntu 26.04 而失败，锁定的 Playwright 1.55.1 不支持该环境。将 CI 及基线工作流的 Linux runner 固定为受支持的 Ubuntu 24.04，保证普通验证与基线环境一致；保留依赖锁文件及测试集合。该配置修复不改变已冻结的本地 Go/Web 测量工具，CI 使用新的精确候选重新验证。

设计编号校对：沿用既有 D172 的原 Issue 责任复用定义，自动选测单独登记为 D173。编号调整只涉及文档引用，冻结实验仍保留原提交及源码摘要。

独立 review 的补充反例：第三方 helper 也可能读取仓库资源，文件系统边界须在完整依赖图中播种并沿生产/测试终端边传播。Go compiler overlay 的清单与替换文件内容必须纳入身份；启用 overlay 时执行完整验证，首版拒绝建立函数覆盖基线。补充两类原生失败反例和执行期间替换文件变化的失效检查。

本轮固定回放继续保留原冻结工具版本，新增修正与测量版本分开登记。对五个基础变更候选比较新旧完整选择集合及默认构建配置，只有集合一致的完整路径才引用既有耗时；受新扩大规则影响的前端选择量另行记录，不把旧版本数字当作新版本收益，也不据此切换门禁。

有效模块输入补充：独立 review 复现 `-modfile` 文件路径不变、replace 内容改变后旧计划空选且通过。将 alternate module/sum、活动 workspace/sum，以及实际参与构建的本地替换模块输入纳入身份；alternate module/workspace 首版完整验证，本地可变模块属于不透明边界。构建依赖解析后再确认清洁状态与有效配置，避免把 Go 自动生成的 sum 记录成未发生变化。

当前仓库的完整依赖传播使所有 Go 根都落入资源边界。计划须明确标记“完整本地集合”等价，并复用完整 Go/Web 结果，避免 shadow 再跑一次同样集合；浏览器脚本与交叉编译范围保持各自的计划规则。新增真实全量执行一次、所选执行器拒绝启动仍能成功的回归，证明复用路径执行了原始测试。

本轮 CI 捕获取消回归的准备标记竞态：`WriteFile` 创建文件与写入 PID 之间可能被读取。只在解析出有效 PID 后确认准备完成，保留原有取消、进程退出和清理断言及时间预算。

再次独立 review 的两项原生反例：资源软链接的忽略/仓库外目标内容改变时必须进入源码身份，不能仅记录链接文本；已由普通源码清单绑定的目标保持既有指纹格式，目标内容仍用于解析资源读取边界。无法绑定的目录、悬空或其他目标只允许完整验证，不发布函数映射基线。嵌套 race 调度器执行须使用可传播取消的路径，让它先清理自身独立进程组，再应用有界强制终止；增加实际 Run 路径的子进程存活检查。

执行权限反例补充：本地替换模块的实际构建/嵌入文件同时记录内容和执行权限，并以真实完整执行证据建立基线后 chmod 注入故障。首版本地可变模块始终完整验证；实际构建输入之外的外部运行时资源不形成精细依赖，不能仅凭构建文件未变就空选。

基线可用性与故障审计补充（D173）：仓库已跟踪的包管理缓存可能包含目录或悬空链接。保留未知链接的完整回退规则，允许仅凭本轮普通完整运行的真实成功事件建立 `static-resource` 索引，全部根均不得声明函数覆盖；当前或基线存在未知资源均要求完整验证。新增真实基线 CLI 回归，证明这种清洁仓库可刷新且不缩小范围。故障审计同时要求全量失败根被选中、实际启动并在选测的原生事件中失败；其他根或质量检查失败不能代替。既有六个反例重新解析双侧原生失败事件，保留原工具身份与执行路径复用依据。
