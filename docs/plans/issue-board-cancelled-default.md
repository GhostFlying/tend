# 已取消列默认展开收敛计划

依据 D127，按已批准的最小交互修正六列 Issue 看板：横向布局、六列工作状态、筛选与 URL 语义保持原样，仅使未保存过新版主动偏好的浏览器首次打开时默认展开“已取消”。

## 执行边界

- 继续使用既有展开／收起操作。旧版挂载时会自动保存缺省值，无法辨认旧 `false` 是否来自主动点击；保留旧 key 原值作为来源未知的迁移证据，不再读写它。
- 新版使用独立的版本化 key，仅在用户实际点击展开／收起时保存；缺失时统一展开，后续主动收起的偏好继续生效。
- 存储不可读时默认展开，不使存储故障改变初开体验。
- 不引入四列默认、当前／历史模式、新筛选持久化或详情页改版。
- 不修改 API、协议、request_id、CAS、状态变更或 CLI 能力。
- 复用原看板 PR，将此前超出最终批准范围的实现移出候选；保留原提交供历史追溯。

## 实施步骤

1. B1：调整已取消展开偏好的缺省值及存储不可读时的回退，加入仅由真实点击保存的最小版本化偏好，保留旧值，更新 D127 说明。
2. B2：同步已有布局验证的初开预期，一次验证旧来源未知值迁移为展开、主动收起与恢复、旧值保留、窄屏已取消页签，以及原筛选和 URL。
3. B3：在最终候选上完成定向验证、仓库要求的独立 review、完整 `make check` 与 CI；检查通过后由统一发布负责人执行合入和部署。
