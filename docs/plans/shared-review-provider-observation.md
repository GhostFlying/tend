# PR 当前观察归一化

## 问题与目标

Issue 只保存 PR 引用及自身需求、贡献和交付责任。当前 PR 候选、CI、合并状态不应再按 Issue 复制保存。旧模型先按 Issue 查询，后来虽有 PR 级 server 观察，仍向每个 Issue 写快照，造成历史副本否定正式审阅、观察者切换选错旧事实、分发窗口内读到不同当前候选。

审阅、授权、执行和已接受结算保留各自冻结的候选证据。它们是历史事实，不作为当前 PR 缓存。原查询 nonce、generation、截止与迟到回执属于执行身份，迁移必须保留，不重发未知请求。

## 实施边界

- A1：复现旧副本否决当前通过审阅和 server/runner 观察者切换问题；梳理全部观察读写、通知与交付结算路径。
- A2：追加存储迁移。保留旧 Issue 观察原件用于历史审计，当前状态归并到 provider/repository/number 唯一事实；Issue 观察表仅保留明确的查询元数据与通知游标，不再写 provider Snapshot。存在的 server 当前事实优先，legacy 数据的归并不得掩盖新失败或未决查询。
- A3：统一当前事实读取，并分开 provider 结果写入与查询元数据写入。server 与仍受支持的 runner 结果都在原 nonce/generation 准入后更新同一 PR 事实；迟到回执继续按原请求留存。观察者切换不能让旧 server 缓存压过新 runner 结果。
- A4：通知保留每 Issue 的有界游标和查询责任，禁止再复制候选、CI 或合并状态。PR 侧保存当前变化的前一状态和错误类型，缓存分发与 runner 结果均通知全部相关责任；取消请求不留下虚假的刷新 pending。PR 事实的查询 baseline 来自实际查询，不能被 Issue 后来领取的 baseline 覆盖。同 PR 新查询串行，旧合法回执保留原协议接受语义并留作历史。
- A5：共享审阅继续检查需求、贡献、执行身份及注册引用，仅按唯一 PR 当前事实核候选；动作入口与视图同源。评估协议兼容，保持现有有效请求和线上字段，新增迁移只追加。
- A6：覆盖迁移、历史保留、当前未知/错误/刷新、server/runner 切换、迟到 fenced 回执、分发通知、真实候选变化与正式交付的回归；检查覆盖最终源码及迁移。
- A7：完成最终候选完整检查、独立审阅、CI，按最新 main rebase 合入。使用 format2 完整发布集同配置受控部署，核实实际 updater 与服务、数据格式及正常确认，再让 Tend 继续原 PR 交付。

## 验证与来源

回归通过原查询和交付入口验证：同一 PR 的多个 Issue 立即读取相同当前事实；关闭的责任不阻止新审阅；server/runner 切换后新结果可见，旧回执只能按原身份留存；真实候选变化和查询未知仍可见。迁移验证旧原件、查询身份和冻结交付证据的保留。全部机器路径、主线标识、原始证据、请求与部署现场记录保存在本机忽略目录，不进入公开仓库。
