# Workspace 复用与可组合交付

状态：已实现（2026-10-23）。发布遵循下列 review、CI 和部署门槛。设计细化 D33、D51、D63，现有任务和请求重放保持兼容。

## 目标与接口

- Workspace 模式为 `new`、`reuse`、`temporary`，省略时沿用 `new`。复用通过来源任务解析并绑定稳定资源 ID，不因来源任务重来而改变。
- `deliverables` 支持 `commit`、`report`、`files` 的组合，兼容旧 `delivery=commit`。所有任务都可附带报告，报告任务不要求 Git 改动。
- 普通目录位于 `<runner.home>/temporary-workspaces/<workspace_id>/`；每个资源独立目录，重试和验收沿用原路径。目录任务的 workspace profile 按 D35 执行并持久化输入缓存，与 Git workspace 保持一致。
- Workspace 独立于任务，记录顺序使用历史。只复用 tend 管理的资源；保留目录、分支和脏状态，记录使用前基线。

## 占用与生命周期

- 同一资源同时只由一个任务占用，包含实现、验收、返工、暂停、待决和人工接管。任务终止且运行确认停止后才释放；未知运行继续占用。
- 排队复用引用阻止清理，但不提前占用。主机固定，缺失资源不得静默重建。复用任务原主机不可用时只提供等待或取消；需要换环境时新建独立任务，不通过 start-over 替换已有绑定。
- 临时资源最后一次使用结束且进程确认停止后保留七天；清理和复用互斥，通过持久化操作和 runner journal 恢复。
- 仅删除确认属于自身的资源、终端和目录；切换 harness 后无法核对原提供方、或目录已注册给其他 provider 身份时拒绝删除。单个资源回收受阻不阻塞其他释放与回收。报告、交付文件及验收历史不随目录删除。
- 历史进程对账按运行时记录的 worker 来源处理，不按当前配置猜测。旧 app-server 仅在原生会话身份、无人工接管、本地终止及服务端成功完成事实齐备时确认关闭；失败或来源不明的历史运行继续占用。取消已保存完成结果的运行转入可恢复的停止与释放，迟到回执不得撤销停止状态。

## Orca 与 Cove

- 为 Orca 原生 folder workspace 增加所需 CLI 创建、查询、更新、删除及分组入口。保留人工查看、接管，不新增无 workspace 启动模式。
- 持久化提供方资源身份、主机、路径及实例信息。恢复不依赖显示名；创建结果未知时先对账，不盲目再建。
- 显示名为 `<当前任务标题> · <短任务 ID>`，不含仓库名、tend 前缀或状态。复用实际取得占用后更新名字，不改路径和分支；备注保留任务链接、阶段、类型和来源。
- Cove 当前支持零挂载 task 和独立入口目录。未来一个 tend workspace 对应一个 Cove task/workspace，顺序任务创建新 tab，路径由 provider 返回。
- 完整 Cove 后端及其控制者观察、程序化输入、临时凭据和安全回收接口不在本次实现范围；不绕过提供方删除目录。

## 交付与验收

- 实现者显式提交摘要、Git 产物、可选报告、证据、不确定项和指定文件；验收继续提交独立 verdict。
- 文件单独二进制上传，run 鉴权、request_id 去重；runner 原子持久化上传身份，提交工具在确认成功前拒绝重复文件名或身份；内容保存在服务端 SQLite，结果引用不可变摘要和清单。默认单文件 20 MiB、单次结果 100 MiB，可配置。
- 复用记录 HEAD、暂存及未暂存修改、未跟踪文件和必要快照。不自动 reset、clean、stash 或切分支；继承改动纳入提交须由任务范围明确承接。
- Worker 完成结果先写入 runner journal，再关闭外部 agent；重启后先核对终端控制权，再恢复停止、收集和提交，不重复已完成的操作。人工接管或停止暂时失败时保留结果，等待归还或停止确认。新任务和独立验收使用新 Agent 会话，同一运行恢复原会话。操作验收核对状态，不重复有副作用的操作；不确定结果进入待决。
- 主 Agent 工具、上下文、Web 详情和完成消息提供交付摘要及文件入口，不自动注入全部文件或启动新 turn。
