# Agents 目录排版与运行信息修正（D143）

## 已确认设计

使用已审阅的桌面与手机改稿：平铺当前 Agent，桌面独立类别、运行位置、运行方式、模型/推理和观测列，右侧查看详情；手机紧凑列表，选择后进入独立只读详情。历史定义折叠保留，原快照链接仍能直接打开。页面标题和详情标题 16px，Agent 名称 14px 中等字重，辅助信息 12–13px；品牌保持 16px。目录样式不影响其他页面。

## 实施步骤

1. 分离位置与运行方式；服务端定义显示“服务端”，用途显示主对话/协调/咨询。CLI 只能来自 runtime 显式声明，不能从旧 runtime ID 或 executable 名称推断；缺失时只显示已知适配器，详情说明未声明。配置与运行观测分开，缺观测显示“未上报”。
2. 允许 format 2 的 hosted runtime 显式声明 codex/traex，保留旧配置省略字段的兼容性、安全投影及版本校验。字段沿用现有 CLI/API JSON，无新 API 或 runner wire 变更；通过 CLI 分发回归核对输出。
3. 实现紧凑表格、位置筛选、运行方式筛选、刷新、历史折叠和响应式详情，保留 URL 筛选/选择及旧链接语义。绑定版本、完整观测和既有责任放入详情披露区，不删除账本证据。
4. Playwright 验证桌面 1536×1024、手机 390×844 及窄屏 320×640，检查浅/深色、字号层级、当前/历史选择、筛选、刷新、Categories、无横向溢出、键盘与只读边界。对照已确认设计与浏览器截图记录排版差异并修正。
5. 定向 Go/Web 检查、完整 make check、独立 codex review、PR/CI。发布状态单独报告，不把本地构建当作线上生效。

## 约束

不改变身份、runtime ID、模型、冻结合同或续接语义；显示名称不替代稳定身份。历史 runtime 始终取原快照。显式声明 CLI 属于配置版本变化，不能改写旧配置快照；部署配置修正使用新版本，已有责任保持原合同。不运行模型来证明元数据。

## CI 全路由巡检修正

全路由巡检把 `aria-expanded` 视为原地披露控件，并验证开合时控件位置不变。目录行现在选择右侧/独立详情，应使用 `aria-pressed` 表达选中；独立详情进入时从顶部显示，返回时恢复列表位置，不属于原地披露。保留巡检对真正披露控件的锚点检查，增加目录选中/返回与详情内披露回归，并补齐巡检夹具的 format 2 hosted runtime、模型及登记字段。页面布局与已确认字号不变。

独立 review 发现窄屏隐藏历史行身份附注，会让同名且执行配置相同的历史版本无法区分。历史行在紧凑布局保留 local ID、定义版本与 inventory 版本；回归使用同名历史定义，直接验证版本标识可见，并继续验证原快照与 runtime 的选择和重载。
