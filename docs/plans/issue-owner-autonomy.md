# Issue 负责人自主推进与统一清理

Refs: D193。编码前记录统一实施范围；先完成当前主线收尾，再整合保留的修复，
使用一次最终候选的完整检查、独立审阅、CI 与受控部署。

## 目标

Issue 承载持续目标、已有用户授权、材料和负责人。负责人选择调查、实施、协作、
补证、审阅和交付方法，并判断事实变化是否影响任务及授权。普通事实变化通过已有
合并事件通知负责人，不由哈希、阶段、默认次数或展示记录直接推导暂停、重建任务
或必须重新取得人类批准。真实用户限制按其明确对象和范围保留。

保留请求身份、实际副作用、并发控制、明确暂停/取消、真实性和失败历史。
这些机制保护具体操作；它们不决定普通知识可读范围或替负责人作语义判断。
本批不重做已部署的普通 Issue 资料读取，不为本批子项建立独立发布流水线。

## 统一范围

| 项目 | 当前问题 | 本批完成条件 |
|---|---|---|
| A2 | 来源、定义或祖先摘要变化成为后续执行许可 | 普通变化只合并通知；原执行默认保持，由负责人明确修改、暂停或继续。快照记录历史，不把逐 Task 适用性确认设为正常推进前提。 |
| A3 | 负责人普通工作工具默认禁用 | 负责人可使用所在设备已配置的普通工具和工作空间，决定短调查与协作方式；独立长期责任可建 Issue/Task，不为每次普通工作强制新建责任。 |
| A4 | 同项目材料复用与交接重复办理分享 | 同用户、同项目的相关知识默认可发现和复用，交接不因 epoch 改变丢失知识；保留明确隔离和原件身份，不转交 owner 凭据。 |
| A5 | 普通报告默认独立验收，未来 reviewer 条件挡当前开工 | 普通调查/解释/报告由负责人决定是否另请审阅；明确用户要求的独立验收保留，当前阶段只检查当前所需能力，未来缺口供负责人安排。 |
| A6 | review 两轮硬限导致必须逐轮向用户申请 | 两轮作为收敛建议和成本事实，负责人在已有授权及真实预算内安排后续；不把 blocked/inconclusive 或默认阈值自动升级为人审门。 |
| A7 | 已完成 review 报告格式错误没有补正出口 | 原负责 reviewer 可在原审阅责任追加不可变补正，保留旧报告；格式补正不复活终态 Task、不额外消耗正式审阅轮数。 |
| A8 | 连续工作机械拆成实现与交付许可 | 已有 Issue 授权覆盖的连续工作可正常推进；记录真正 merge/deploy 的请求与参数，允许负责人选择任务划分，保留人工模式及真实范围限制。 |
| A9 | app-server 异常退出后缺少可用恢复出口 | 负责人能够观察、停止/隔离并恢复原执行或从 Issue 重建新 session；所有等待有期限，保留原执行及实际外部结果未知，不因观察器寿命丢失永远占用资源。 |
| A10 | 纯读展示行的 unknown 封住整个会话 | 业务请求账本及原生终态作事实依据；纯读可重新读取，写按原身份核对，未知仅阻止实际冲突操作，不阻止阅读、诊断和无冲突工作。 |
| A11 | 看板展示历史执行结束，却掩盖当前责任 | 卡片和详情展示真实当前下一步、待办和当前负责的升级问题，历史执行计数保留为详情；不以 origin 过滤丢掉当前负责待办。 |
| A12 | Agent 自设预算/报告边界扩大成人类审批门 | 既有目标内允许技术参数、脚本、合理未来预算和真实剩余 follow-up；保留已消耗尝试和完成报告，真实用户成本/次数限制继续有效。 |
| D192 | 后续维护使已完成历史部署无法结清 | 复用保留的原执行/原批准/绑定安装/独立验收结清能力；观察器保存事实与通知，责任的处置由负责人明确选择。旧准备态历史仍可正常读取结清。 |

## 实施方法

1. 以已完成独立审阅和保留复现为输入，每个子项先确认实际调用链及真实失败，
   直接删除或放松代替 Agent 判断的规则。使用现有事件合并、资料面、责任及操作
   身份；不再添加一组“允许继续”的临时开关、每阶段 grant 或新的审批状态机。
2. 普通来源与 provider/部署事实只写事实和通知；显式用户干预、负责人决定以及
   具体副作用的准入各自保持原身份。暂时读失败不抹掉既有真实执行和批准。
3. 资料共享、普通工具和同 Issue 连续工作默认可用。工作空间、资源和进程仍归属
   已配置 Agent 与实际 runner，不隐式修改模型、思考强度、登录或 provider。
4. 审阅补正和故障恢复追加事实。当前负责人可以处理历史责任，冻结版本、旧报告、
   花费和原未知不被覆盖。新 session 可从 Issue 的持久材料重建上下文。
5. 协议/持久化变化先评估 N/N−1 与退役规则；优先复用既有身份及恢复原语。
   如确需改变通信或存储，提供实际迁移、兼容和拒绝证据，不为规避升级规则留旁路。
6. 用户能力同步 CLI、工具、可读结果、必要的 Web 投影及帮助。生成文件统一从源
   生成，不手改。设计文档在最终行为提交中与实际实现一并更新。

## 验证与交付

- 针对正常目标被机械规则挡住的路径提供真实 RED→GREEN 或已有因果证据。
- 验证事实变化仍通知当前负责人、连续工作不会无故中断、正常知识可读取、报告
  可补正、有限恢复能结束等待；明确用户暂停/取消、真实范围及未知写仍准确保留。
- 不为低影响文字改动添加镜像测试；不重跑已经通过且未受新改动影响的验证。
- 所有子项完成并冻结后统一生成协议/客户端类型，执行一份最终完整 make check、
  一次全 PR 独立 review 与必要同 reviewer 修正、最终 CI、线性合入和不可变构建。
- 同配置受控部署；保持每台设备已有登录、Agent 模型/思考强度、slot 及数据身份。
  验证真实进程与安装回执后才报告统一修复已部署。每项状态分别保留，未完成不
  冒充完成，审阅或局部验证不冒充产品清理。

## 实际协议与持久化范围

- 新增 server migration 0102，将候选型 live Task 交付来源纳入原 delivery duty；
  原验收型/结果型来源与 execution 外键保持迁移，保留全部历史行。
- Runner 普通负责人工具通过可选能力广告、领取时的原 Run 标记和显式线程模式
  共同协商；无标记的旧 Run、旧 server/runner 及回执专用路径保持旧语义。
- 审阅补正、材料授权读取和看板当前责任采用可选读字段/新的 owner operation
  输入，不收紧既有有效 runner 请求。保留旧冻结 Task、模型、effort 和认证配置。
- app-server 进程归属记录位于本机原 run state directory，是新增执行的本地证据；
  不修改线上协议版本或 runner journal。旧无记录执行仍走既有 unknown/隔离出口。

## 独立整批审阅的修正

首轮完整检查保留全部真实失败，独立审阅固定同一候选。修正后交回同一 reviewer
只复查修正增量及原发现，不为每个子项重新建立整份审阅或发布流程。

1. 同 Issue 协作必须分别保存原 Issue 责任代次和实际执行 Agent，明确交接后旧
   代次结果作为历史事实；不能因允许选择协作者而省略原责任来源。
2. Runner 原生负责人保持父进程退出约束；该进程寿命约束独立于普通工具配置。
   普通工具不应丢失租约监督边界，系统私有摘要也不借此获得工作工具。
3. 历史结清区分最后成功的 provider 快照与最近读取尝试；后续读取失败不清除
   已知身份冲突，真正未知也不被伪造为有效安装或批准。
4. 同项目知识的默认可读性与加载方式分离。默认材料、分页发现和精确原件查询
   只加载其实际需要的范围，不在每次读取中构建整个项目的全部历史上下文。

明确人类独立验收要求继续冻结其真实请求与理由。旧故障场景确实需要验收时，
夹具明确选择该流程；未来 reviewer 不应挡当前实现，实际验收仍检查其当前能力。
来源变化测试改为核实合并通知、原 spec 不变和真实结果，而非要求自动暂停。

历史传输测试的辅助主会话统一使用其实际 driver context 执行工具和账本读取，
停止时先取消并等待 manager/dispatcher，再等待 fake harness 的回调退出。
测试函数返回后的正常取消不报为业务失败；driver 仍活动时的真实读取或执行错误
继续失败。验证覆盖所有复用该 helper 的用例，不以逐用例删除、重试或放宽期限
处理共享清理竞态；产品规则和原 Run、lease、问答及终态断言保持。
