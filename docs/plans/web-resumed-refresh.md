# Web 事件流续传后的视图恢复

D69、D225 已区分带游标续传与需要全量重建的首次连接、过期游标。当前浏览器在每次 `start` 都执行 `LiveData.reload()`，会重读全部已打开的看板列、会话历史和子会话，并使已加载的历史分页失效。

1. 首次连接、身份变化、游标拒绝和流内 reset 继续从当前账本重新建立视图。有效续传复用已加载的账本投影，断线期间的事件沿正常分发路径补齐。保留缺失/失败读的恢复和运行时观察的重读；可见性、路由与查询切换仍由各自的订阅负责。
2. 区分全量重读和连接恢复。恢复每个保留会话的持久队列，包括暂时隐藏的会话。只将读取与事件转发给活跃会话。主队列仍走原来的联网恢复及业务幂等路径。
3. 用浏览器驱动实际页面与可控 HTTP/SSE 来源，记录开始、断开、有游标续传、补发业务事件和 reset 后的请求与可见状态。补充失败、在途和保留会话的回归。按实际 diff 进行 Web 影响验证及独立审阅。

续传保留 snapshot（运行时心跳）、可见 runner catalog（按读取时刻计算在线状态）、已打开的原生入口/会话目录、模型设置、handoff 和诊断读。仓库列表在连接状态恢复时自行重读。快照订阅者仍接收当前运行时事实。任务列表和引用补读错误；其他账本读取保留原退避和在途脏标记。IM 专用流过滤部分账本事件，保留它对历史输入的独立对账。
