# 持续可靠性业务恢复与统一交付计划

## 范围与业务目标

本轮在既有交付状态机上实现 R8、R9、R10、R11、R13、R18，并统一集成数据库读模型、执行环境及测试基础设施的独立改动。原责任、Task、Run、审阅轮次、验收结果及 unknown 外部动作均保留；已关闭的历史主线不重开，既有安装不重放。

## 真实故障起点与正常终点

- R8：已创建审阅轮次绑定旧候选，协调报告已结束但没有质量结论。开始审阅前原子校验当前候选；正常暂停/恢复只改变协调状态，保留轮次和空质量结论，再沿同 Task 审阅准确候选。
- R9：旧部署执行绑定尚无升级 ID，新运行能力安装前无法提交准备结果。通过正式交付更新入口归档未启动绑定并恢复原交付责任；有真实升级或 unknown 时继续原身份对账。
- R10：持续 Task 的新 artifact 已排队验收，但承载旧验收的子 Issue 已关闭。新验收经正常入口恢复原持续载体的调度资格，保留旧 artifact 和验收，不新建增量 Issue。
- R11：技术回答实际 actor 是主 Agent，但附带 owner_subject。依据真实 actor 分类，保留控制版本、决策答案和停止交接边界。
- R13：外部等待 checks.target_id 错用 URL 或不存在的业务 ID。返回字段明确的 invalid_request/not_found，确定输入错误不进入自动重试，不持久化无效等待。
- R18：组合验证准备、独立审阅、拒绝、继续、main 变化、普通进度、安装与报告；真实内部转换经现有接口执行，外部 provider/安装回执使用显式替身，fixture 预置边界单独说明。

## 实施顺序

1. 对照实际恢复原件追踪入口、当前状态机及既有回归，先确定最小契约。
2. 按故障链实现正常恢复入口、API/CLI 帮助及契约验证，补充组合回归；不覆盖既有十一项交付修复。
3. 各责任组提交后一次性集成；共享设计和生成文件由集成责任人更新。
4. 定向验证及交叉组件验证收敛后冻结候选，执行仓库要求的独立整 PR 审阅，关联纠正复用同一审阅者。
5. 最终干净来源执行一次强制完整检查及自然 PR CI，读取当前规则、终态聚合与新 main 后使用 SHA 保护的 rebase merge。
6. 依据合入来源执行一次完整 format 2 统一部署；安装前保存配置与未结操作基线，安装后验证真实进程、二进制来源、健康、提交回执、正常 ACK、CLI 与同步服务周期。未知结果保留原身份，不重发 Start。

## 协议与设计

Refs: D248；保留既有 D247 的阶段与安装约束。新增 owner 协调动作和可选候选预期字段是可选扩展，不改变 server/runner 消息格式或增加线上必填条件，不需要递增 runner 协议。生成 schema 和 Web 类型由原生成器产生。

## 验证边界

定向测试证明选定入口和转换；完整检查与 CI 证明其精确来源；合入不代表部署，安装回执不替代业务动作恢复。部署现场不以一次性数据库修改作为本轮验收。所有私有主机、路径、身份及回执存放在忽略目录，不进入公开文档。

R8 独立审阅纠正：预绑定验收缺少 whole-PR 证据后，原审阅者的补充报告仍属于同轮实际质量来源。先以正常验收、补充报告和 wait 入口保存负面回归，再让 record/wait 共用有效轮次解析；覆盖补充 changes_requested 的记录与 disposition 门槛、passed/blocked/inconclusive、无质量结果的正常接续，以及活动执行和未结副作用。原验收、失败、unknown 和审阅历史不改写。
