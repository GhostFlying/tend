# 数据库热路径与测试执行的组合交付

Refs: D113、D130、D236。承接 `database-access-reuse.md`、`test-time-semantics.md` 与 `affected-validation.md`；保持各原子提交的职责，不增加部署入口或新的业务状态。

## 业务目标与边界

列表、Issue 与对话的普通读取不应为稳定 deployment identity 重复查询和不断创建 SQLite reader。成功身份缓存绑定 App 生命周期；有限读池复用连接，单 writer、认证、旧身份拒绝、事务和取消语义保持。失败不缓存，新 App/Store 重新读取，不支持在存活 App 下换账本。

功能测试的业务时间与初始化速度分离。通用组装继续用真实迁移后关闭的独立模板，真正冷启动、迁移和 retained restart 保持真实路径。慢准备不得消耗后续功能预算，真实错误、取消、恢复及副作用身份仍须验证。结合读池后的 Close、fixture checkpoint/拷贝、重开、初始化失败与重试需要实际验证。

## 实施与来源

1. 在最新已合入 main 上组合数据库与测试两个已冻结提交系列，只解决真实冲突，保留原失败和不可变定向证据；不引入其他未审阅功能。公共设计使用 D236，与并行的 socket/工具/诊断/展示修复独立。
2. 保留本地实际差异/反向依赖/能力契约选择与原生 Go 缓存。正式 PR CI 继续完整覆盖，影子计划不排除任何正式作业；未决定的 CI 裁剪 patch 和 daily 任务不启用。
3. 依据实际 CI 重包关键路径，将 serverkit、Sandbox 和 runner 测试从 other 分组独立并行，其他包仍默认发现。共享本地/CI 分组，验证所有 Go 包及动态根不重不漏，更新有限缓存角色；不以分组为由减少测试、race、断言或原错误输出。完整本地检查继续使用实际 CPU 自动预算。
4. socket helper 与其 fixture 接入由另一修复者负责；本组合只复用其必要已提交修复，不另起替代实现，不覆盖对方修改。

## 验证与合入

先验证 DB 初始化/失败/取消、读池限制/释放/Close、模板独立性、真实组装与 retained restart 的组合；未变且仍适用的原定向证据不机械重跑。最终候选经独立整 PR 审阅，实际问题沿同一 reviewer 修正；原失败与拒绝保留。审阅收敛后执行一次真正全覆盖 `make check CHECK_MODE=full TEST_COUNT=1 CHECK_JOBS=0`，核对全部阶段、原生 JSON 根平衡与真实 skips；不能让本地影响选择器裁掉正式验收。

自然触发的精确候选 PR CI、实际保护聚合及新鲜 main 适用性均核实后 guarded rebase merge。CI 缓存命中不称作本次重新执行。一个组合 PR 直接验证读池与测试生命周期交互，避免两个 PR 重复完整门槛；DB 与测试各提交仍可单独审阅。

本组合负责源码合入，不单独部署。全部本轮修复源码合入后，由唯一部署负责人沿既有完整 format 2 受控升级执行一次统一部署并核新增安装事实；不重复旧业务输入、Task、timer 或升级操作。
