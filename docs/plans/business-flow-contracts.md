# 业务主链与故障边界验证计划

## 目标

约束辅助能力的故障传播，并用真实 Tend 组件和可控外部替身验证 Issue 从执行、独立验收到用户可见结果的连续性。沿用现有业务身份、授权、原件访问和未知结果对账语义。

## 实施

1. 在工程约定中补充辅助路径的故障边界、业务目标恢复和测试契约，避免引入额外审批或形式化流程。
2. 扩展现有单 slot manager E2E，验证 Issue、Task、Run、独立验收、用户可见结果及资源释放，而不是另建模拟 Tend 内部行为的测试系统。
3. 结合归档与事件链的并行修复，在 runner/HTTP/server 路径注入归档不可读与未知回执，验证工具调用和终态、隔离与恢复；以最终合入实现为准保留真实原件约束。
4. 扩展真实 manager 故障恢复场景，覆盖执行已经停止、事件传递失败、runner 重启和原身份收口。
5. 在共享 PR 审阅及交付链覆盖无关和相关基线变化，验证沿同一责任处理和候选证据准确性。
6. 对测试揭示且属于同一边界的结构性问题做最小修复；其他问题保留证据和后续范围。

## 验证

先运行新增的定向测试和受影响包 race 测试，再对最终候选运行 `make check TEST_COUNT=1 CHECK_JOBS=0`、独立 review 和 PR 所需 CI。最终候选基于最新 main 验证后按仓库规定 rebase 合入。线上部署和真实模型冒烟不在本计划内。
