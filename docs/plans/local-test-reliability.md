# 本地测试可靠性与阶段资源边界

## 目标与范围

在既有完整验证覆盖、race、真实迁移/重开、每例数据隔离和取消清理不变的条件下，减少真实长 socket、环境初始化、阶段 CPU 分配和误导性计划日志造成的故障。此批只做针对性实现与原子源码交付，由集成者一次完成组合审阅和最终验收；不改变交付失败根恢复流程（T6），不引入通用 launcher、永久检查账本、历史 Run 迁移或新定时器。

## 实施顺序与故障契约

1. **T1：路径与空间**。审计真正 bind/dial 的完整 pathname，而非仅验证目录前缀。运行时 IPC 使用私有、真实、短目录并按实际 suffix 验证；Go 编译临时目录与 Go 1.27 testing 临时目录按调用链分开安排，保留调用方明确配置并在不可满足时给出准确诊断。只修已暴露的 fixture/默认入口，不迁移生产数据或改变 socket 权限边界。
2. **T2：剩余 manager 登记场景**。区分 fixture、迁移/恢复、触发、等待登记与后续业务到期，使用实际事件/可控同步及注入业务时钟；有限 watchdog 只防卡死。失败输出对象身份、阶段、实际状态和可用堆栈/等待信息，保留取消、unknown、不重复副作用和清理断言。
3. **T3：监督与退出**。先对照原进程回执、仓库检查器、Go 子进程与宿主执行层的退出信号责任。仅修正常调用仍可能发生的取消传播、子进程清理与退出信息缺口；历史父进程为何消失缺证仍为 unknown，私有包装脚本错误不转化成产品能力。
4. **T4：阶段预算**。以实际活跃进程集合计算有界预算，在独占阶段重新分配已释放 CPU，同时尊重明确调用方预算。用执行参数和并发边界回归证明，不使用设备速度作为功能 SLA，也不全仓盲目提高并发。
5. **T5：可复用准备与成本**。先从原生逐例/阶段记录及真实调用次数量出迁移、seed、功能与清理成本；仅对非迁移契约的重复准备使用真实迁移后关闭的不可变模板。冷库、迁移失败、保留数据重开专用场景继续走真实路径，每例仍有独立文件、连接、时钟及原件。
6. **T7：准确 full 诊断**。显式 full 可跳过依赖图发现并选择 `./...`；明确打印包模式/未展开状态，不把一个模式打印成只发现一个包，也不因主动省略 graph 追加 removed/undiscovered 理由。此为文案修正，不声称发现漏测。

## 文件边界与验证

测试组负责 testkit 的 socket、check、racecheck、impact、testbudget、testphase，必要 Makefile/CI 入口，以及非升级业务的 e2e/serverkit/sandbox 测试。升级组负责 updater/upgradectl/blobstore 与升级专有测试，DB/观察器组负责 store/pricing、公共设计与规则文件。共享文件先交接，不同时编辑；本计划不修改公共 docs/design.md 或 AGENTS.md。

为实际故障补确定性 RED/GREEN，验证完整地址字节、环境分离、阶段与取消语义、进程组清理、CPU 参数和准备调用次数；保留所有失败/未知和源身份。使用有界定向 race/vet 与脚本测试，不启动整轮 full、PR、CI、部署或 Tend 业务。设计片段随冻结候选交给集成者，Refs D243，延续 D236–D237 的隔离与覆盖约束。
