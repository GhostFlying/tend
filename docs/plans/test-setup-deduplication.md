# 消除重复测试准备

Refs: D151。此前自动选测实验已停止，本次直接减少测试准备和重复业务流程，不引入选择器，不改变完整检查、race、CI、生产 SQL 或业务语义。

## 范围和顺序

1. 保留看板超过200条、全部生命周期及跨页筛选的数据规模，用一次真实业务创建获得合法模板，在独立测试数据库的单个准备事务中批量构造读取数据；HTTP分页、游标、筛选与非法输入断言全部保留。
2. 保留150个关系、双向关系、执行事实、次序、无截断及队列扫描次数和真实claim；批量准备相同的合法任务/动作数据，避免重复执行无关创建业务。先复核模型必需字段，不手工复制生产迁移或放宽规模。
3. E2E普通与Orca变体保留完整配置约束、reload、restart及独立验收。显式/默认workspace复用变体保留各自真实已完成来源与资源释放、首次双角色准入、恢复后执行及原pin检查，去掉重复的配置拒绝和重启序列。
4. 后续模板/冒烟候选只在可明确保留独有断言且有收益时扩展；不为了减少测试数量删除不同业务合同。

## 验证和停止条件

- 修改前保留当前main源码及目标根的race/count=1耗时；修改后使用同一工具链、CPU预算和缓存条件比较目标根。完整检查另进行一次固定预算的前后对照，不进行多PR长周期回放。
- 实际注入分页截断/筛选或游标错误、重复关系队列扫描/关系截断、复用首次跳过review资格故障，要求保留测试确实失败；注入只在隔离副本执行，保留原始失败，不带入提交。
- 准备模型需满足真实读取/claim依赖及数据库约束；每个测试独立数据库、时钟、ID、工作区，不共享可写状态。
- 完成目标测试、完整本地make check、规定独立review及PR CI。没有目标收益或检错能力减弱的候选不交付，不将CPU采样比例当作已获得的墙钟收益。

固定放置权重同步：仅根据本轮修改后根测试实测更新看板、关系查询和workspace复用三个已变化根的提示，避免旧的大成本将其他根挤到同一分片。权重仍只决定放置，不决定执行范围；其他根继续动态发现并完整运行。
