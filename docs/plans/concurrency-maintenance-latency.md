# 并发维护与领取事务的延迟收敛

Refs: D153。

## 问题与边界

部署观测已将秒级写事务定位到并发定时检查及 runner claim；写连接等待与
事务回调时间有独立记录，但回调内各步骤尚缺少固定阶段观测。当前每秒都重算
完整调度等待并清理历史，远高于三十秒冷却和三十分钟升档的控制需求。

本次保持单写连接、现有准入事务、控制版本、请求去重、unknown 占用、原生
终态释放和十秒采样缺口失效规则。不移动最终准入到事务外，不改协议、schema、
CLI 或预算配置，不操作生产部署与现有进程。

## 实施顺序

1. 为执行状态同步、完整等待计算、并发采样、manager 刷新、候选收集、执行器
   解析和历史清理补充固定阶段耗时；沿用释放连接后输出的慢写日志，不记录业务
   payload、SQL 参数或身份配置。
2. 定时采样改为五秒；完整等待计算最多每三十秒执行一次。在升档的其他证据
   已满足时，必须在同一事务内重新计算真实等待，禁止凭旧等待需求升档。
   回调获取写连接后取业务时间，排队时间不当作旧时刻的健康观察。
3. 历史清理改为一分钟一次的独立事务，并限制每批处理数量；清理失败不得影响
   控制采样，去重记录和当前预算不删除。时间倒退或重启使维护重新到期。
4. 维持每次采样及 claim 的现有执行状态对账与最终准入，避免削弱未知、父子
   额度和停止证明。依据新阶段观测再决定是否需要更深的增量重构。

## 验证

- 固定诊断时钟验证阶段完整性、错误路径和原事务结果；检查回放不重复执行。
- 可控业务时钟验证五秒采样保留完整稳定窗口，超过十秒缺口仍清除升档证据。
- 在非需求刷新轮次强制等待投影失败，证明正常采样不触发完整等待查询；升档
  前必须看到新鲜需求，旧的非零等待不能造成无需求升档。
- 验证低频维护首次执行、到期、失败后的重试与时间倒退；历史分批清理不破坏
  拥塞去重；保留跨 runner 原子准入、unknown、原生回执和父子额度既有回归。
- 运行相关 race 测试及完整 make check，按仓库约定独立 review，经 PR 交付。
  隔离测量与源码验证不等于生产延迟恢复。
