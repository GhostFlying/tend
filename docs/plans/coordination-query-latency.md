# 协调查询延迟收敛

## 背景

续租请求在等待写事务入口时超时，导致 runner 按既定租约规则 fencing。
有界 CPU 采样同时定位到写事务内的 manager handoff 查询和原生关闭回执查询；
Token 用量读取也执行较重的关联查询。修复保留请求身份、租约边界和所有对账事实。

## 实施

1. 使用独立合成数据库复现采样中的查询路径，记录查询计划和增长趋势。
2. 为实际缺失的关联查找追加迁移索引；必要时改写等价查询，避免在写事务中遍历无关历史。
3. 保留 handoff blocker、未确认 callback 和用量冲突/重叠语义，增加代表性历史规模回归。
4. 定向测试及基准通过后冻结候选，执行独立 review、本地完整检查与并行 PR CI。

## 边界

不延长租约，不绕过 fencing，不取消保留 run，不改变业务结果和协议。
只使用合成数据验证；生产状态与升级由既定的唯一运维执行者处理。
