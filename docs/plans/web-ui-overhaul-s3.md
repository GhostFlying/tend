# S3 导航与聊天头部实施计划

Refs: D131
Plan: S3

1. 保存主对话、Issue 看板与详情、收件箱、设置在桌面、图标栏与手机尺寸下的深浅主题基线截图。
2. 将侧栏收敛为对话、工作、资源分组与底部设置，使用真实链接与嵌套路由激活；提取共享待处理计数，主机显示汇总状态点。删除不再使用的摘要组件。
3. 统一侧栏宽度，增加中等屏幕图标栏；手机四标签及更多资源页，保持详情与弹层下隐藏标签栏和内容避让。
4. 保留主对话当前待处理区为唯一摘要入口；只在空对话提供最近更新的活跃 Issue 链接，不重建持续跟进区。
5. 精简聊天头部为标题、说明、会话名切换、关联 Issue 与更多菜单；来源和执行记录保留原提交／读取逻辑。主题改为设置页分段选择；仅保留离底时的浮动跳转按钮。
6. 更新既有布局脚本导航，保留业务断言，补充分辨率、侧栏宽度、嵌套激活、计数与手机避让检查；保存同夹具全部指定尺寸的前后截图，串行完成 Web 门禁后提交。

不新增依赖，不修改生成 API、Go 服务端或业务合同。对话常驻与不可见时关闭短暂浮层的合同保持。

## 实施说明

- 侧栏只保留分组链接，嵌套详情激活父入口；共享待处理计数沿用原标签栏的去重规则。主机状态来自最近快照，不把失联期间的最后观察状态伪装成实时信息。
- 主对话保留现有空态说明，不增加可选 Issue 建议：当前 summary 协议不含更新时间且按 ID 分页，不为了展示建议遍历所有 Issue 详情，也不把任意前三项称为最近更新。
- 原侧栏摘要／最近三项的展示断言改为组件缺席与任务页可达性检查；发送、来源、Attention 回答、任务控制、草稿、焦点和滚动业务断言保留。

## 回归同步修正

- 资源页后退探针记录到两个提交阶段：Issue 标题先出现，计数尚未读取时原 opener 的结构路径不存在，路由先聚焦标题；计数到达并插入头部子节点后，原路径与按钮重新匹配，现有 observer 正确恢复焦点。旧脚本只等待标题即断言 opener，属于测试时序竞争。
- 夹具显式扣住回到看板时的读取，验证未完成时尚未恢复 opener，释放后等待实际焦点并保留原断言。不增加超时，不改变产品路由恢复逻辑。其余失败为已移除侧栏按钮的选择器，改为真实导航链接，保留回答与 unknown 核实断言。
