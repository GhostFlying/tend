# S10 Issue 对话始终面向负责 Agent

Refs: D132、D133、D140
Plan: S10

## 背景

Issue 详情的输入区当前只在负责人是已领取的 Agent 时可用。新建 Issue 默认负责人是 owner；按类别委派后，在执行主机领取前负责人也暂记为 owner。结果是大部分 Issue 打开后看到“由你负责，没有负责人 Agent 对话”，无处输入。multica 的语义是：Issue 上的评论发给负责的 Agent，新建时选择 Agent 负责。tend 是单 owner 系统，给自己写备忘没有意义，因此对齐为：Issue 对话总是发给负责 Agent，默认由 Issue 负责人类别承担。

不做：owner 私人备注、不改变负责人的“临时请某个 Agent 处理一次”。

## 设计

在 D136 的普通 Agent owner 责任之上增加对话交互；新建与类别交接使用 `owner` / `issues.request_owner`，保留恢复的历史 `manager` 请求，不静默升级历史合同。待领取会话在共享发布路径建立，不改变 owner policy、身份约束、assignment epoch、实际 owner runtime binding 或领取后的配置冻结。

1. **新建默认类别**：新建（含子 Issue、从消息创建）默认选中 `issue-manager` 类别；该类别不可用时退到第一个活动类别，没有活动类别时才默认“我自己负责”。选项文案区分“Issue 负责人 Agent（按类别，由执行主机领取）”和“我自己负责（不会有 Agent 对话）”。原请求恢复的选择保持不变。
2. **待领取期间可发送**：按类别请求负责人（创建时或交接时）在同一事务内建立该 Issue 的负责人对话。视图在 `manager_pending` 时返回会话 ID 且 `can_send=true`；消息照常写入并排队，投递仍由现有 admission 等到领取后才交给领取的负责人，不选择替代者、不提前启动会话。界面说明“等待负责人领取，消息将在领取后送达”。
3. **退回 owner 时不静默丢失**：待领取被取消或负责人交回 owner 时，尚未交给任何 Agent 的 owner 消息继续保留在原队列，界面明确显示“未送达，交给 Agent 后送达”，并沿用已有撤回能力；已发送或 unknown 的消息仍走原有核对路径，不重发。优先复用现有 admission 与队列状态，不新增消息状态。
4. **owner 负责的 Issue**：不显示收件人和输入框；用一条说明和主按钮“交给 Issue 负责人 Agent”（一键按默认类别请求负责人，复用交接命令与请求身份），次级入口打开完整交接面板。
5. **负责人显示**：待领取时看板、详情、筛选与新建结果不显示“你”，显示“待领取 · 类别名”；领取后显示 Agent 名。详情复用已有 manager 字段；看板投影追加可选只读 pending_manager_category_id，由当前未领取的非终态负责人任务派生，不对每张卡片读取完整详情。API 类型通过生成器同步。
6. **沙盒**：沙盒 runner 必须能经真实 runner 协议领取类别负责人任务，并以脚本会话回复，使默认新建流程在沙盒中从“待领取”走到负责人回复。沙盒看板只保留一个明确“我自己负责”的示例，其余示例经类别请求或已注册负责人承担；需要 reset 才能看到新种子。

## 实施与提交

- 提交 1（服务端与视图）：对话建立时机、`can_send` 推导、退回 owner 时 owner 消息状态与看板待领取类别只读字段；在 `docs/design.md` 增加 D140 并引用本计划。

- 每个提交独立构建通过；不改 runner wire 协议版本，不新增依赖，不修改已提交迁移。

## 验收

- App 测试：类别请求后立即可向 Issue 对话发送；领取前不启动会话；领取后同一消息交给领取的负责人且只处理一次；取消待领取后消息不丢失、不重复投递。
- Web 浏览器巡检：新建默认选中负责人类别；待领取详情可输入并展示说明；owner 负责的 Issue 一键交接；看板显示待领取。桌面 1440 与手机 390。
- 沙盒：默认新建 Issue 后发送消息，负责人领取并回复。
- `make check` 全绿。

## P2 默认负责人读取修正

- 类别首次读取未成功时，不将未知列表当成空列表；未触碰负责人选择的新建表单等待读取，显式 owner 选择与原请求恢复不受阻。
- 在现有 Issue 浏览器巡检中暂停类别响应，验证默认不能提交 owner，显式 owner 可以提交；保留既有业务断言。
- 串行运行 Web 检查、全部浏览器脚本与完整检查，将修正折入 Web 提交。
