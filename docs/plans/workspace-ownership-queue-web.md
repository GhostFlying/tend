# 执行等待投影的 Web 呈现

依据 `workspace-ownership-queue.md` 的执行投影，保留六列及列 ID，将广义 active 列称为“推进中”。工作项卡片、侧栏概览与阶段显示服务端执行数量；阶段原始状态明确标为计划状态，active 不代表 worker 已启动。

任务使用服务端 execution 状态显示排队、执行、验收、等待用户及未确认事实；等待说明只翻译服务端 queue_reason，不从生命周期、目录或前端容量猜原因。占用或依赖任务可直接打开。历史计划不展示当前执行投影，缺省字段兼容旧快照。

复用既有样式与任务导航，不增加依赖或独立调度状态。定向测试覆盖计划 active 无执行、1 执行 2 排队混合计数、等待原因与未知缺省；生产构建后的本地 fixture 覆盖桌面及 320/390/430 窄屏、明暗主题、任务跳转和无运行错误。仅使用隔离 API fixture，不调用生产或创建工作区。

独立评审补充：详情转摘要的缓存保留 execution 与 primary_work_item_id。快照之外的活跃任务引用在任务、run、工作区、主机等事实变化后重新读取服务端摘要；读取期间的新失效合并为后续一次重读，避免迟到结果永久保留旧排队事实。历史终态引用不因无关主机心跳反复读取。

二轮评审确认 idle 只描述当前没有执行，不证明历史从未运行，文案改为“当前未执行”。预算耗尽、验收环境及工作区故障沿用服务端等待用户的投影与既有原因，不新增白板列或执行枚举。
