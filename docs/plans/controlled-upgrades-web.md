# 受控升级 Web 实施子计划

依据：D82、D83、D84、D85；完整范围见 `controlled-upgrades.md`。

1. U1 等待后端生成主机在线、心跳、维护、构建及协议视图后，复用主机组件分别展示连接、维护和槽位。缺省心跳为未报告，不推断离线；网页断线保留最后观察并说明等待恢复。手机折叠入口显示维护数。
2. U3 采用服务端权威发布视图和通知类型，Shell 共享只读详情，Chat 和看板均可进入；维护主机可跳转所属批次。阶段、下载及阻塞留在详情，重连重读，普通更新合并避免请求风暴。取消与重试维持 CLI。
3. 系统通知按协议类型显示标题，保留 Markdown、稳定消息身份和阅读位置，不从正文猜测通知类型。
4. 添加缺省兼容、主机状态独立、断线保留、受控刷新和通知类型回归；使用生产构建替身验证桌面、手机明暗、键盘关闭及无副作用。Browser 插件未提供，使用已有 Playwright，结束时清理自有浏览器与服务。

协议字段由后端冻结并生成；不手写生成类型，不修改服务端。

## U3 冻结协议与通知投影

- 使用 `Snapshot.upgrade` 和生成的 `UpgradeView`，批次摘要由 Chat/看板共享，细粒度进度留在统一只读面板。
- 使用 `ConversationItem.notice_type/upgrade_id/host_id` 分类系统通知，缺类型保持历史任务完成文案。
- 新增 0029 通知元信息表与事务写入接口，Conversation/Events 共用投影；任务完成通知显式标记类型，不改旧正文或唤醒模型。
