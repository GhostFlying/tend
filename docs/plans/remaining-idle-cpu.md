# 剩余 CPU 调查与修复

状态：实施中。Refs: D199。

## C1 固定证据

固定源码与历史规模，分开测量完全空闲、不可运行积压、活跃与停止收尾。
记录 user/system CPU、SQL、事务、读取/哈希、完整 API 调用频率与分配。
现场 profile 的主要线索为后台会话资格检查、用量 API 与并发调度；不同负载
不能直接作为前后性能对比。逐项解释原积压的等待及唤醒条件。

## C2 消除重复工作

后台调度采用提交后的事实变化和最早截止唤醒，启动恢复候选，执行前新鲜校验；
保留 Issue、配置、租约、原生回执与队列顺序，不能仅因 Issue 关闭就丢消息。
查明 API 请求方和触发原因，再修复重复请求和实测组装热点，不加响应缓存。
其他循环仅修复已证实的无变化工作；缺文件保持具体未决项与按来源退避。

## 验证与交付

至少现场规模的积压与历史，虚拟时间一分钟无变化不重复完整资格检查、历史读
或无变化写；事实变化和截止仍恢复，原请求/未知不得丢失。API 覆盖通知、动态
窗口、可见性和重连。每项保留触发、调用链、复现与前后证据。
聚焦验证、最终 make check、独立 review、required CI 后经 PR 合入；不自动部署。
