## 原生绑定交接与采样顺序

- `runner.claim` 预留额度，`runs.report_started` 确认 Run 已运行，原生会话 ID 由之后的 `worker.concurrency` 回执提供。共享控制器同步时，最近确认运行且反馈仍新鲜的 Run 可以短暂等待原生绑定。此期间继续占用额度并保留窗口内已证明的观察，暂停健康时间和满载累计，禁止升档。绑定完成后从有完整反馈的采样继续。长时间未绑定、真实 unknown、失联和长采样空洞仍中断观察。
- 以写事务中的时钟采样。请求入口的时间仍用于原请求记录。若输入的时间早于同一组最后实际采样，按该采样位置应用本事务新确认的状态，避免再次积分。真实拥塞仍在该组的前进时钟上结算，原始反馈时间和去重键保留。
- 通过正式领取、开始、反馈、心跳和 tick 验证待绑定与恢复，以及持续不可用、长空洞、有效拥塞和缺少证据时的判定。用可控时钟让正式领取在配置写入后落库，验证不回拨且保留新预留。现网 23:23:34 的重置原因仍待证实。
