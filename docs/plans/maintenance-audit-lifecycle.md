# D201 维护器创建对账与定时审计会话复用

定时器调用 `tend-maintainer audit`，经 Unix 控制接口提交命令，或在服务停止时取得同一状态锁提交。控制器先保存创建意图，再向 Codex 发 `thread/start`。创建回执丢失时，控制器必须保留原创建与待办。现有入口可以认领可核实的原线程，但没有办法结清已证实退出的创建。成功的审计也会在归档前清空输入和 turn ID。

1. 创建错误关联原创建 ID，先持久化首次错误和收到的线程标识，再报告需要对账。沿 `maintenance reconcile` 增加本机操作者核实后的退出结清，要求当前修订、原创建 ID、原线程 ID、正向退出证据及未执行输入的证据。控制器核对原创建仍无已提交输入，并原子保存历史和收据。超时、无记录和普通配置变更都不结清。原线程认领仍可用。
2. 定时命令沿原有同小时去重保存每轮请求身份。成功审计先保存原输入、turn、冻结水位与实际终态，再把可复用的线程引用留在独立空闲状态。只有同后端、工作目录和维护指令，且可读、可启动的线程才用于新一轮。从明确不可用的空闲线程切换到新的线程，以持久化审计事实接手。已提交的未知输入继续查原线程，不因失败查询而重新发送。保持现有 timer 配置。冻结变更清单是线索，定时独立查漏即使清单为空仍运行。
3. 隔离验证覆盖 Unix 业务入口、丢响应的 Codex 替身、控制器重启以及原请求回执。并发与重复定时触发、不同 turn 和独立游标、会话失效和待对账路径使用可控原生证据验证。生产记录只提供故障背景。
