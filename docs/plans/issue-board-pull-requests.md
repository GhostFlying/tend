# Issue 看板卡片显示关联 PR

Issue 已登记的交付详情继续复用同一份 GitHub 观测。看板应在列分页中携带可直接打开的轻量状态摘要，登记与工作分支或执行会话的更换相互独立。

1. 为 Issue 的现有交付操作增加只追加 GitHub PR URL 的入口。人可从 CLI 调用，负责 Agent 可用当前 Issue 工具。服务端从 GitHub.com 的 PR URL 解析仓库和编号，在当前 Issue 事务内沿已有交付引用生成观测任务，重复登记返回既有 ID。登记无需 Task 交付职责。
2. CLI 提供补漏模式。只从同一 Issue 的指定 Task 查找其工作区首次准备时记录的挂载与原分支，要求它的远端仓库身份可以核实。用一次有时限、最多两条结果的 GitHub 查询确认唯一同仓同分支 PR，再沿显式入口登记。没有证据、无匹配、歧义或查询失败时保留原登记，显式 URL 仍可用。执行完成链无需等待此查询。
3. GitHub 观测读取 `isDraft`，以可选布尔值表达缺失。看板只读取当前页 Issue 的登记和共用 provider 状态，按正式推进、未关闭及原登记次序排序。未确认的生命周期显示中性图标。PR 状态和排序与 Issue 工作状态、审批和安装职责独立。
4. 卡片项目名右侧加 16px Primer 图标和完整短号，保留工作状态菜单。链接支持键盘聚焦和状态提示，`+N` 使用现有可触屏对话框列出 PR，保留返回焦点。
5. 验证显式登记与重复、原分支补查的唯一/无结果/歧义、草稿切换和观测失败、轻量分页及 PR 排序。使用现有看板浏览器 fixture 核对四种图标、未知状态、键盘和窄列触控。运行受影响检查，记录最终候选、独立审阅及 CI。
