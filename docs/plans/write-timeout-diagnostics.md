# 写连接超时的可归因诊断

## 问题与目标

一次 manager 事件消费在等待 SQLite 写连接五秒后超时，最终排空也未完成。
现有日志保留了 connection_wait 与事务阶段，却只把内部写入归为通用
App.write，缺少 Run、事件序号和当时写连接占用者。事件后来全部消费完成，
但不能据此解释最初排队的具体操作，也不能把连接等待误认为某条 SQL 执行超时。

本计划补足诊断身份与时间边界，保留现有写入、请求去重、事件消费确认和恢复语义。
不通过放宽业务完成条件、延长超时或重发原业务来消除症状。设计补充见 D212。

## 实施

1. 为内部 manager 事件处理及消费确认附加固定操作名、原 Run 和原事件序号，
   另列 attachment Run/合成协调序号；历史回放携带原身份的本地诊断字段，
   无原身份时明确未知，不改变 ACK/wire。保留外层已有 request_id/trace_id，
   不记录事件正文、SQL、凭据或环境。
2. 内部写入的诊断保留有界调用链，能区分通用写事务包装器与实际调用者；
   为单个 Store 的诊断写入分配进程局部编号，并记录开始及 deadline 时间。
3. 维持连接等待、BEGIN、callback、commit、rollback 的独立耗时；记录当前
   pool 状态。连接获取失败时，若有已观测的活动写入，保存其操作、调用者、
   编号和已占用时间，明确这只是失败时刻的快照，不断言它占满整个等待窗口。
   诊断状态属于 Store 实例，不作为业务身份、授权或调度状态。
4. Claim 内 manager refresh、候选收集、选择准备补固定 inclusive 子阶段，
   不改变执行顺序、刷新规则或 NoEffect 结果。
5. 仍在释放事务与连接后调用观察回调。新增诊断同步不能包住数据库调用、
   observer 回调或业务代码；不增加周期查询、模型请求或全量快事务日志。

## 验证与交付

- 有界故障回归覆盖真实 writer 占用时的连接等待超时、实际内部调用者及
  Run/事件归属、已有请求身份保留、writer 释放后的快照清除，以及并发 race。
- 日志序列化核对新增安全字段、准确阶段与时间单位；既有错误与确认结果不变。
- 定向验证后运行仓库完整 make check、规定的独立 review 和所需 CI；
  最终候选按既有 PR 与线性合入流程交付，部署另保留实际安装证据。

## 并行维护边界

manager 启动受到 receipt-only fence 拒绝的另一项故障正在独立调查；
只有原始 action/回执与源码证实具体缺陷后才另立修复计划，不以本诊断改动
放宽隔离或把尚未接收的输入视为完成。
