# 主会话调度职责与任务输入（D88）

## 目标与边界

主会话只对齐 owner 目标、选择仓库与交付、关联输入、调度跟踪和呈现结果；代码调查、复现、技术 spec 和独立验收交给 worker。简单任务允许调查与实现合并，复杂任务先报告再 follow-up；不强制增加阶段。仓库选择沿用 repos_list 的登记信息，不暴露源码目录来鼓励主会话自行调查。

附件作为任务 spec 的显式输入引用保存，冻结原件元数据与来源；实现和验收都通过 run 身份下载，runner 流式校验后落到本轮临时目录。不要求 worker 寻找 owner 凭据，不隐式继承所有聊天/前序任务附件，不新增文件大小或分辨率限制。已有无输入任务与旧 runner 保持可用；有输入任务只能派给具备对应能力的 runner。

完成、待决及其他需要协调的明确账本事件可以唤醒主会话，读取结果并在已授权目标内继续。通知本身不授权新工作，不能因静默超时盲目重试。事件进入持久队列，重复投递、重启和当前 owner turn 忙碌时不丢失，也不并行启动多个 turn；心跳和普通进度不触发模型。需要 owner 决策时仍走既有待决流程。

## 实施

1. 收紧常驻指令；核对实际 harness 支持的配置，关闭主会话 shell 等执行入口，保留 Tend 调度与有界读取工具。覆盖恢复与 handoff；通过分页 conversation_read 恢复较早 owner 原文，关闭 shell 后不依赖旧 rollout 路径。
2. 在 spec 增加显式输入引用，app 校验附件存在并冻结元数据，展示于任务/assignment；run 鉴权的文件读取涵盖本 spec 输入。能力协商阻止旧 runner 静默忽略新输入。
3. 实现与验收 harness 暴露 download_file；runner 从输入及交付清单定位文件，校验大小/hash 后原子落盘；prompt 说明来源和下载方式。跟进任务按显式引用复用附件。
4. 复用持久消息/turn 队列实现明确事件唤醒，限定事件种类与重放边界，保留 owner 消息优先和串行处理；展示事实与模型回应但不伪造 owner 指令。
5. 区分 workspace 的物理运行目录与 mount 的逻辑标识：runner 上报可选 mount.directory，schema 32 持久化并在任务视图返回，旧记录未知不拼接推断、旧报告不清空已知目录。修正单仓库路径误读；主会话任务 ID 由客户端渲染标题，不在旁边重复同一标题。
6. 更新 D88 设计；针对跨主机输入、无 owner 凭据、原字节、隔离/恢复、事件去重与重启编写回归测试，运行 make check 和独立 review；PR 经 CI 与 review 后合并。

## 验收

- 主会话可用 repos_list 选择登记仓库，无 shell 自行读源码；可创建 report-only 调查及显式 follow-up。
- 同一附件能作为实现和验收的输入，经下载字节与原 hash 一致；无关文件不可由该 run 读取；缺失/重复引用产生明确错误，旧无附件任务不受影响。
- GIF 与任意二进制不被转码/截取；文件传输不全量驻留内存。
- 任务结果和待决事件在无新 owner 消息时进入串行主会话；重放无重复事件 turn，忙碌与重启不漏处理；心跳不启动模型。
- 不改变已完成移动端任务的分支，不通过直接写生产数据库来测试。
