# Agents 当前任务负载

## 目标与口径

Agents 目录直接显示真实运行任务数，并默认将忙碌 Agent 前置。计数按执行时冻结的环境和 Agent 身份聚合，不依赖当前 Issue 负责人、目录可用性或任务生命周期猜测。统计具有 Run 的 Task（Issue owner、实施和验收）；主对话和咨询的消息轮次不是 Task，不混入此数。

启动、运行以及仍占用执行的等待 Run 计入运行任务；unknown 和 interrupted 单独展示待确认任务，不声称运行或空闲。同一 Agent 上同一 Task 的重复 Run 只计一次；存在运行 Run 时不再同时计为待确认。finished/failed 和已停止的历史问题排除。当前身份汇总其所有冻结版本，历史定义行不重复展示身份总数。

## 实施

1. 在既有 runner/hosted Agent 目录只读响应中添加可选任务负载汇总，在同一读事务内从 Run 与冻结 pin 读取，不引入调度、存储迁移或配置变更。既有 CLI 目录读取保留完整 JSON 字段，并补充帮助文档与输出验证。
2. 目录显示运行数、空闲或待确认，缺少汇总时显示未知。默认运行 Agent 前置，待确认其次，其余随后；分组内保持既有目录顺序、名称、筛选与详情导航。运行/任务事件经现有 coalesced read 刷新，失败保留上次值并提示。
3. 添加聚合回归与真实应用入口的启动/结束读回验证；前端验证稳定排序与事件刷新。浏览器在桌面和窄屏检查负载、筛选、详情往返与状态更新。
4. 最终候选完整 make check、精确 CI、同一原 Issue 下独立完整 PR review。按本 Issue 自动政策正常合入和受控完整发布集交付；未知或明确拒绝沿原操作处理。

## 业务路径与验证边界

入口为 runner 正常领取/上报执行事实，经过 runs 与 run_agent_executions 的只读汇总，再由目录 HTTP/CLI 和 Web 展示；终点为开始和结束后可观察的计数与稳定分组变化。SQLite fixture 只证明状态矩阵、冻结身份和去重，不证明真实启动；App 正常入口测试补充相应转换。浏览器使用真实构建与 HTTP fixture，证明布局和交互，不证明真实模型、物理设备或线上推送。线上仍须核对实际安装回执；测试成功不等于部署完成。

源码基线与当前安装之间只有已合入的业务恢复说明变更。本功能不修复通用自动部署链；遇阻先核对原操作和正式恢复能力，保留责任与授权边界。
