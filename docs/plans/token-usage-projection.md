# Token 用量写时投影

Refs: D117、D157、D158、D176。

## 问题与目标

原生请求事实已持久化，但每次读取都扫描全部 current fact，解码原文、解析归属、逐请求计价，然后才筛选窗口。页面轮询因此重复历史工作。保留 API、CLI、页面交互及原始账本合同，将这部分工作移到 app 写事务。

## 实施

1. 追加迁移，建立有效请求贡献、四小时汇总桶和持久 dirty 身份队列。事实不变；迁移只登记现有 current 身份，服务启动在开放入口前完成首次投影。
2. app 统一写事务收尾更新 dirty 请求的贡献，并只重建受影响的汇总桶。原生补传、revision、冲突、legacy overlap、归属证据和报价变化均在同一事务更新。没有新增定时任务。
3. 归属依赖变更通过数据库触发器登记受影响请求；执行状态、Task 标题、Issue 标题/父链、冻结 inventory、原生 turn/log 和本地 actor 均保持原解析语义。Issue 展示结构或报价改变允许写时历史重算，普通心跳、游标与覆盖状态不触发历史重算。
4. 读取使用汇总桶；滚动窗口和当前时点切过桶时，只读取该桶中已投影的贡献。分页明细最多读取 51 条投影记录，分组列表只读游标身份，不再逐条查归属和报价。未知时间与未来原生时间保留原合同，缺失计数不补零，价格继续使用精确十进制逐请求规则。
5. 验证修订替换、重传、冲突及 overlap 回退，动态归属/报价、时间边界、明细分页和重开持久性。以既有调查快照做前后输出对照与查询计数/耗时验证；私有样本及报告只放忽略目录。完成完整 make check、独立 review 和 PR CI。

## 边界

不改变采集频率、run 完成语义、runner 协议、自动并发政策或部署资源配置。原始事实仍是可重建依据；本次不直接部署或合并。
