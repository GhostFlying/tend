# 主代理原 turn steer：接手与 PR 交付

## 目标与边界

继续已授权的 owner steer 功能及未通过验收的问题修订，交付可独立评审的 PR；本轮不合入或部署。保留原始 owner 来源、同 turn 规划幂等、unknown 不重发和单一协调者语义。

## 实施步骤

1. 将已有功能提交与验收修订整合到最新主线，保持新会话范围、仓库注册及图片预览行为。为新持久化表追加唯一迁移，不修改已提交迁移。
2. 核对规划去重固定原 turn 初始消息，owner 审计保留实际来源；覆盖换 call ID 重试、结果丢失和 steer 后序号共用。
3. 覆盖消息/附件准备失败的中性提示与无原生调用事实；核对真实 steer 不通过中断或新 turn 模拟。
4. 重新生成协议产物，运行针对性测试与 make check；按仓库约定独立 review 并处理意见。
5. 用现有用户 Git 身份提交和推送分支，创建 PR 并附上验证与已知限制；保留合入和部署给后续安排。

## 发布集成补充

Owner 已授权合入与部署。本轮先对齐托管主协调专用入口、正式消息判定和逻辑轮完成门禁；同时保留 steer 原文来源、同 turn 规划幂等以及 unknown 不重发。主线已使用迁移 45–48，新表顺延为 49，设计编号顺延为 D115。冲突处理后重新生成协议产物并运行完整检查、独立评审及最终提交 CI；合入使用线性 rebase，发布后经受控升级协调器替换服务端与 runner。

### 独立评审补充修订

历史 owner 答案的审计 parent 不能代替当前执行身份；将宿主固定的 execution request 通过命令包装传入 App，消息与工作项事实检查统一落在当前逻辑轮。补充消息仅 accepted、尚无消费回执时的 stop 先解析原 native turn，再停止对应逻辑轮并取消已排队的自动修正；不把未消费消息伪造为 consumed。覆盖两个独立评审复现场景后重新执行检查与评审。

### 重启、澄清接续与回复索引

后续评审复现已完成原生回合但逻辑检查未完成的补充消息被线程重开错误标成 interrupted，以及澄清责任多次接续后旧回合补充消息未收束。重启只处理实际未收束的 native turn；消费已知但原生结果未知时保留消费事实并显示 unknown，等原始回执与逻辑检查完成。完成逻辑轮时沿 resumed_by 的前驱链收束各自原生回合的补充消息。回复查询将直接回复与多来源回复按索引合并、去重、排序；追加迁移 50 创建 source-first 索引，不修改现有迁移。增加重启/回执/修正、两次澄清接续以及实际 SQLite 查询计划和分页回归。

迟到与恢复回执：在已完成逻辑轮中新接纳补充消息时重新标记待审查，复用现有受限修正流程；显式停止与澄清状态保持其控制语义。原生历史恢复需保留 user/assistant 项目的先后顺序，按实际消费边界恢复回复来源，并优先保留已持久绑定；缺少对应消费历史时保留不确定性，不推断该补充消息没有回复。

集成验收补充：会话断开产生的 synthetic interrupted 不可终结仍待原生回执的补充消息；从补充消息停止时需沿逻辑轮找到当前修正执行并取消等待修正；工具记录以已验证并冻结的 callback source 为准，早到的 started 项目在来源确定后校正到同一来源。

旧 head CI 复现的暂停取消测试失败来自 400ms 真实租约在 race/SQLite IO 下意外过期；该场景改用 server/runner 已共享的可控时钟，并等待实际 Release 回执，保留短租约续期与丢失的专用测试。

停止后的准入：steer 必须仍对应 processing 的原始逻辑执行、无待对账原生回执；停止或修正阶段的新输入留在正常队列。原生规划重试集成场景聚焦同一业务 turn 的去重与消费证据，脚本未做归类/事实审查时应断言 consumed 和未完成责任，不把原生完成当成逻辑完成；受限修正执行独立计数。

工具来源并发：callback 来源冻结与工具项目的读取/持久化串行化，避免早到项目读取旧来源后跨过冻结事务写入。项目来源校正后的重放使用包含来源的视图请求身份，不与校正前的请求 payload 冲突；不改变业务工具去重身份。

共享回复展示：API 各来源块继续保留真实归属，Web 全局投影按 message_id 去重，优先放到已加载的实际 reply_to 来源块，缺失时放到最后一个可见关联块；共享流式快照采用较新 revision。分页控制独立于剩余回复条目，不能因去重而隐藏继续读取入口。

独立逻辑轮共享来源：审查结束后的收尾查询同时枚举该轮已审查消息所关联的 consumed steer 原生 turn，不能只遍历 resumed_by 祖先；每个原生结果仍取其自身状态，并要求关联原责任已完成及全部共享逻辑审查完成，覆盖两种审查完成顺序。

停止与原生完成竞态：已消费输入的关联责任若已明确 stopped，后续原生 completed 回执应投影 interrupted 而不是重新发出 processing；真实原生 completed 事实独立保留，断线待对账仍先保留 unknown。

共享来源中明确 stopped 的责任也作为关闭路径处理，但不能伪装 facts-reviewed；其余仍开放的责任继续阻止完成。完成或停止事件均在原事务内核对共享来源，原生 pending receipt 仍保持 unknown，已结束原生执行对应的停止消息不残留 processing。

显式恢复：只对有真实消费凭据且原生已完成的 stopped 补充输入重新打开审查投影；保留原生失败/中断事实，不重投业务输入。恢复后审查完成必须能从 consumed 收尾；覆盖原生完成与原生中断两种情况。

投递优先级整合：新业务回合已按前台优先规则越过旧 pending 元数据修正时，owner steer 也跳过 pending repair；保留 sending 修正、handoff 与 compact 的阻塞顺序，防止低优先级修正永久挡住活跃业务回合的补充消息。
