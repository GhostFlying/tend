# 主代理原 turn steer：接手与 PR 交付

## 目标与边界

继续已授权的 owner steer 功能及未通过验收的问题修订，交付可独立评审的 PR；本轮不合入或部署。保留原始 owner 来源、同 turn 规划幂等、unknown 不重发和单一协调者语义。

## 实施步骤

1. 将已有功能提交与验收修订整合到最新主线，保持新会话范围、仓库注册及图片预览行为。为新持久化表追加唯一迁移，不修改已提交迁移。
2. 核对规划去重固定原 turn 初始消息，owner 审计保留实际来源；覆盖换 call ID 重试、结果丢失和 steer 后序号共用。
3. 覆盖消息/附件准备失败的中性提示与无原生调用事实；核对真实 steer 不通过中断或新 turn 模拟。
4. 重新生成协议产物，运行针对性测试与 make check；按仓库约定独立 review 并处理意见。
5. 用现有用户 Git 身份提交和推送分支，创建 PR 并附上验证与已知限制；保留合入和部署给后续安排。

## 发布集成补充

Owner 已授权合入与部署。本轮先对齐托管主协调专用入口、正式消息判定和逻辑轮完成门禁；同时保留 steer 原文来源、同 turn 规划幂等以及 unknown 不重发。主线已使用迁移 45–47，新表顺延为 48，设计编号顺延为 D115。冲突处理后重新生成协议产物并运行完整检查、独立评审及最终提交 CI；合入使用线性 rebase，发布后经受控升级协调器替换服务端与 runner。
