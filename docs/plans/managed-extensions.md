# 按 Category / Agent 托管扩展与指令

Refs: D202。本文是本轮实施计划；取代新托管环境对个人 home 的持续投影，不退役历史执行的恢复路径。

## 合同

- server 独立管理 skills、完整 plugins、MCP 定义和用户级 AGENTS.md；显式编辑草稿、校验、发布和回退，发布版自动分发。
- 执行使用本次选定的一个 category，加完整 Agent identity 的覆盖；资源按 ID 合并，Agent 可以覆盖和显式禁用。AGENTS.md 先 category 后 Agent。
- 无任务类别的会话只在唯一类别时自动选择；多类别必须显式配置。组合引用不改变 native thread 身份。
- 项目级 skills/plugins/MCP/AGENTS/config 与管理员约束保持原生行为。保留固定运行状态 home、显式 OpenAI auth 共享和本机凭据。
- 移除 Tend 的 bubblewrap 层，保留原 HOME、设备、终端、用户组、网络及宿主执行权限。个人 skills 使用原生逐文件禁用规则；启动前按本机用户共用的持久缓存生成，至多每六小时刷新一次。首次无清单时立即生成，不启动后台轮询。该选择接受六小时内新增个人 skill 尚未进入禁用清单的窗口，不再承诺目录级持续隔离。
- 包支持固定 Git revision/子目录、npm 明确版本/子目录和完整本机导入；不执行安装脚本。MCP stdio 在执行主机启动，秘密和 OAuth 不分发。
- 角色权限优先；Traex 不进入本轮。新 run 固定发布版和组合；恢复沿用原引用，长期会话空闲门禁后采用，unknown 不重放。

## 实施顺序

1. **E1：数据与包边界。** 新增可移植资源/组合/发布 DTO、纯合成和校验；独立包获取、内容寻址归档与安全解包，复用现有 codexenv 快照和进程私有 plugin 缓存。
2. **E2：控制平面。** 追加 store 迁移；草稿、资源与绑定编辑、发布、回退通过 app 去重/CAS/事务；不可变内容先暂存。补齐 owner API、CLI 管理与能力覆盖。
3. **E3：分发与执行。** 增加协商的可选版本目标/观测；鉴权下载、持久缓存、有效组合就绪；任务、owner、常驻和咨询固定类别与引用，旧执行仍可恢复。
4. **E4：诊断与界面。** CLI resolve/status/inventory/doctor 分别展示来源、下载、验证、依赖、认证和实际采用；Web 只读页面和显式会话类别选择，生成类型同步。
5. **E5：验收交付。** 临时源与模拟模型回归、两台测试主机真实 Codex/项目扩展和宿主执行语义验证；最终 make check TEST_COUNT=1、独立 review、CI、PR。记录迁移与回退预览，不自动切换生产。

## 不变量与验证

发布资源不含主机路径、认证、会话或运行配置。类别/Agent 扩展 revision 独立于模型和 Agent 定义。有效组合有确定摘要；文件、资源和传输均校验。部分下载、冲突、缺依赖与未知请求保留真实状态，不误报采用。

覆盖个人技能显式引用被屏蔽而项目扩展正常、覆盖/禁用/多版本、AGENTS 顺序、插件技能去重、MCP 凭据引用与命名冲突、并发 CAS/对账/重启/离线、worker 续跑、长期会话安全采用、权限与线程/rollout/用量归属。

迁移只从已确认清单一次导入资源；MCP 默认空，AGENTS 一次导入后独立维护。现有 Codex categories 先使用同一基线、Agent 覆盖为空；旧 watcher 在受控迁移完成后停止。保留旧 home、缓存、认证与快照。生产维护前展示精确差异，slots、用途与模型保持原设置。

## 原生启动与六小时排除缓存

普通 `bwrap --bind / /` 引入 nodev，dev-bind 仍引入 nosuid/NoNewPrivs。本轮按用户明确选择完全移除 Tend 的 bwrap 依赖，不安装特权挂载组件。Codex 自己按所选权限模式施加的约束保持。

每个执行使用固定状态 home 下的稳定私有配置 home：独立的 config、AGENTS、完整 skills 和可写 plugins 副本。执行锁持有到进程关闭并清理后才允许重建配置，避免同一执行的进程重叠。CODEX_HOME 指向此配置 home；sessions、archived_sessions、OpenAI auth 和线程写入锁链接回原固定状态 home，sqlite_home 和日志目录显式固定。MCP OAuth 文件在私有配置 home 中由 Codex 原生维护并跨该执行的重启保留；不使用其原生写入会拒绝的文件软链接，不复制个人凭据。执行结束保留会话路径别名，防止原生 SQLite 中记录的 rollout 路径失效；历史清理仍不得删除可能被恢复或对账引用的内容。个人 HOME 与项目文件不修改。

排除缓存使用本机用户的 Tend 缓存目录与跨进程锁，server/runner 的并发启动共用一次检查。只枚举个人发现目录中的 SKILL.md 路径，解析软链接并排序去重，不另行解析 skill 内容，不排除项目或管理员来源。成功与失败尝试均持久记录；六小时内不重复扫描。刷新失败保留最后有效清单并诊断；尚无有效清单时明确阻止该环境启动，不隐式接受空清单。每次启动从固定清单生成进程自己的原生路径禁用规则，不重写个人配置。

验收覆盖首次生成、六小时内复用、到期刷新、并发启动、重启恢复、软链接、失败保留旧清单与首次失败；托管组合并发不串用 config/AGENTS/plugin cache；原生 thread 恢复与 rollout/SQLite/认证/Kaboo 仍使用原固定状态路径。在原生进程内比较 mount 属性、UID/GID/附加组/NoNewPrivs，并重新打开设备、使用 PTY、以 DEVNULL 启动子进程。增加无外层 bwrap 的真实 Codex 模拟模型请求验证。

## 合入前集成验证

基于最新主分支重新整合维护服务与 updater 自更新：保留 owner API 两组能力、完整 CLI 登记、runner 的 updater 观测和托管扩展协商，以及 server 两组只读诊断注入。重新生成协议类型，核对历史迁移编号与设计编号不冲突；最终候选重新完成完整检查、独立 review 与 CI 后，以精确 head 校验进行 rebase merge。生产迁移仍单独执行。

### 最终独立评审修正

- 扩展发布目标变化唤醒既有 runner reconciler，下载未就绪沿原重试路径等待，不新增业务输入。
- 旧逻辑 turn 的冻结组合优先于当前发布；仅确认空闲、维护结束及回执已明后重启会话，由既有启动选择恢复原组合，后台准备也遵守该选择。
- owner 转 worker 时重新按目标 runtime 的托管声明和任务 category 选择组合；已有 task/run 的持久 pin 不重选。
- 新准备请求之前按原 request ID 对账未完成请求，再读取 revision；完整包先解压到临时同级目录，再原子发布，不能从残留半包恢复就绪。
- 各缺陷补针对性回归；最终源码重新执行完整检查、独立评审与 CI。
