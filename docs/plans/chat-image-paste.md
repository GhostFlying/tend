# 聊天图片粘贴补全（D86、D87、D142）

## 目标与边界

首页正式 IM 与主/Issue 共用 Composer 支持剪贴板原文件，加入可预览、可移除的待发送附件；用户显式发送，分别复用 messaging.send 与会话发送队列。不改服务端协议、CLI 业务能力、上传身份或重试规则，不增加大小、数量、分辨率门槛。CLI 已有附件上传与消息发送能力，此处仅补浏览器输入适配。

## 实施步骤

1. P1：共用同步提取器以可用 file items 为主视图，无可用 item 时回退 files；不拼接两视图、不跨事件按名称去重。保留非图片文件，空名称补默认名，提取失败反馈，不吞无文件时的原生文本。
2. P2：两编辑器接入相同 paste 行为；混合纯文本按选区插入并恢复光标。未加载/无权限/saving 不修改草稿；交接等仅禁止发送的状态仍可保存文字与附件草稿。IM 复用 LocalAttachment，移除、发送、卸载沿用 object URL 清理。
3. P3：定向单测与浏览器回归覆盖 items/files/fallback/null、多图同名、混合文本/选区、忙碌状态、手选与失败恢复。运行 make check，记录实际结果。
4. P4：隔离本地服务与数据，以 Xvfb、系统剪贴板及真实快捷键验证首页、主/Issue 粘贴→预览/移除→显式发送，核对下载原件。截图与环境细节作为独立附件交付，不把私有环境写入公开仓库。移动验证使用独立 Dora 租约；条件不满足则如实记录范围。
5. P5：复用原候选并基于当前 main 重新运行相关验证，旧报告单独标明历史范围。通过独立 review、完整本地检查与 CI 后由集成责任合入，部署保持集中安排。

## 当前独立审查修正

混合图文替换选区时保留原生文本撤销历史，支持编辑命令的浏览器走原生 insertText，
仅在缺少能力时保留原选区插入回退。使用当前真实编辑器分别验证混合粘贴后的
Ctrl+Z/Ctrl+Y、附件仍待发与不自动上传；纯文本继续由浏览器原生粘贴处理。

CI 原 Issue 详情回归确认交接期仍需编辑草稿。Composer 的 disabled 仅限制发送，
不等于队列未就绪或权限阻塞；恢复文本和附件草稿入口，增加交接期附件粘贴与禁止
发送的同一真实组件回归，不通过改测试去允许被禁用的输入框。
