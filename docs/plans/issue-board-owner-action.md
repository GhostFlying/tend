# Issue 看板的「等我处理」筛选

来源为 Tend Issue wi_0HERHYBHG9CC1JJZ1TF404BTN6 的 owner 要求。以当前 main 为独立交付基线，核对 #346 的列布局和测试重叠。如果 #346 先进入 main，重基并重验受影响的桌面与窄屏行为。

1. 在正式 Inbox 的 owner Attention 与个人行动读取中提取共用责任条件。决策或动作必须仍然开放并由当前人类负责人处理。个人行动遵循 Inbox 的 open / blocked 和关联 Attention 投影。由真实 origin Issue 关联匹配，一条 Issue 只出现一次。
2. 在 owner API 的既有看板读取中增加可选筛选，沿用 Issue 状态分列、项目与负责人筛选、计数和游标。按匹配集合计算每列结果与总数。CLI 提供等效筛选、帮助、结构化结果和分页。读取接口可以按同一查询重新执行。
3. 看板顶部提供可切换的复选框。沿用每列加载、错误和重试以及 SSE 更新。保留各列、移动端状态标签及原有滚动行为。将 Issue 的 in_review 显示统一为「审阅中」，涵盖看板、详情和状态通知。
4. 用正式 HTTP/CLI 验证人类归属、跨列、重复关联、分页、关闭原行动后的移除与筛选组合。浏览器验证桌面及窄屏加载、失败和恢复、空结果、键盘与触摸滚动。最终候选按实际基线运行 make check、独立审阅和必要 CI。
