# 调查与设计报告交付后的实施决定

用户只委托调查、诊断、方案或设计时，Main 在原 Issue 中记下报告结算时须询问的约定。用户明确只交报告或已经授权实施时，沿用现有流程。已关闭的历史 Issue 沿用原记录。调查过程中的辅助审阅报告仍可按原流程结算。

1. 正式结算报告时校验当前报告及原有质量要求。以该 Issue 的实施决定为稳定业务身份，原子提交结算、阻止结案的用户决定及同一负责人 Run 的外部等待。决定引用原报告和拟实施范围。已经提交的决定及报告可读回对账。
2. 用现有 Inbox、等我处理和已授权的报告及附件读取入口。入站答复通过原决定的版本与 owner 身份验证，只有明确选“继续实现”才授权所列范围。
3. 沿用原 runner 的停止回执。答复先于回执时保留原答复和 slot。未答复时保持 Waiting，无提醒触发的模型执行。“继续实现”由原 Issue、原负责人接续。“暂放 Backlog”停止准入。“仅报告结案”沿用证据和结案限制，其他责任仍需按原规则结清。
4. 通过正常 App 和 runner 入口验证正式报告、Inbox、停止和三条答复路径。验证报告和附件权限沿用现有入口，答复和提交重试复用原决定，且停止结果未知期间没有下一次执行。测试使用真实 Tend 存储与业务命令、可控 runner 和时钟。Web 按实际报告引用读取现有端点。

实施交付是可审阅 PR。验证在隔离测试实例进行，不向线上历史 Issue 注入测试答复。
