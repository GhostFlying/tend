# U2：固定更新器与发布目录

依据 D84 与 `controlled-upgrades.md`。本切片只实现发布产物校验、单用户本地控制接口、进程监督与可恢复安装；发布批次及业务排空由 server 编排。

- 发布目录包含严格 JSON manifest 与角色/平台二进制。发布 ID、协议范围、存储范围、大小与 SHA-256 是固定身份；拒绝路径逃逸、符号链接和重复目标。安装先完成全部校验，再写入不可变版本目录。
- 固定 Go 更新器常驻，持有 Linux flock；状态通过同目录临时文件、fsync、rename、目录 fsync 持久化。非 Linux 保留编译但拒绝自动监督安装。
- 单服务用户 Unix socket 提供状态、安装、受控安装、重试及取消（直接重启暂拒绝）。服务端固定授权必须绑定批次、逻辑实例、当前进程实例、manifest 和产物哈希；下载或校验失败不停止当前进程。
- 停旧进程前、离线备份完成后、候选启动前均记录阶段。用 Linux PID 加启动时钟识别原进程，绝不只凭 PID 杀进程。启动结果不确定时先读状态和进程证据，禁止重复启动。
- 候选以新的进程实例与维护状态启动，健康观察必须绑定同一实例/哈希；连续两次健康后才确认安装完成。是否恢复接单由 server 授权。出现任何已接受新业务/写入的证据后持久禁止恢复旧数据；健康未知不推断安全回退。
- 备份仅复制配置中明确列出的持久文件及 SQLite sidecars，不查询/修改业务表，不改变凭据或服务配置。只在进程已退出且有明确可回退证明时恢复匹配文件。
- 首次 bootstrap 只在已确认空闲后收养原进程，记录实际二进制与参数，保留原数据；同版本人工重启本期明确拒绝，待具备独立排空协调后开放；意外退出仅恢复已提交版本，不向运行中的服务发停止信号。
- 测试覆盖损坏/逃逸 bundle、原子文件写失败、重复控制、各安装阶段恢复、候选退出/健康未知/不可逆边界、PID 重用、独占锁、真实 Linux 子进程启动停止及跨平台编译。生产安装与滚动演练另行执行。

- 确认回退后保留原候选完整 binding，并由固定本机 socket 提供 terminal rollback receipt；只有旧版本、实际运行进程实例与哈希匹配且未跨不可逆边界时才报告，供服务端恢复维护授权。中间恢复阶段或未知启动不构成证明。

- 停止后授权过期且候选从未启动时，仅重新启动旧版，不复制数据库；停止回执不确定时先检查原进程身份，活原进程保留并形成终态证明。旧版启动明确未发生可重试，未知启动仍只对账。初次收养要求 launch ID 与 runtime instance 相同。取消批次按本机原 binding 查询历史批次，仅 staged 阶段以原子 CAS 撤销，不依赖 latest 批次。

## Review 3：回退证明与停止观察

- 将最新有效回退的完整 binding、恢复版本与已证明进程单独持久化，不依赖当前 operation。自动重启只在前驱进程和同一版本精确匹配时推进证明；未知启动不推进，换版本后旧证明不再适用。
- SIGTERM 已发给已固定的进程后，临时观察失败不作为退出，也不中断等待；继续等到明确退出、context 取消或停止期限。信号前检查仍严格失败，不重复发送未知信号。
- 依赖 Linux supervisor fixture 的测试加构建约束，纯 receipt 测试继续跨平台编译；增加确定性观察故障及真实进程重复验证。

## Review 4：提交证明与 admission fence

- 候选健康达标只允许本机提交；提交持久化 irreversible 和完整 binding/version/process 的 committed proof。协调器只有收到当前实例的提交证明后才恢复 admission。同版本自动重启沿已验证前驱推进证明，原候选 binding 保持不变。
- 选择回滚时保存完整授权，要求 server/control revision 为正、admission 持久 fenced、rollback safe 且未接收新工作。每次停止活候选前重新获取并保存授权；确认候选已停和恢复数据阶段只使用已有持久 fence，不依赖已停止的本机桥。
- 未知观察/授权保持暂停；已提交或 irreversible 不可恢复旧数据。增加重启、陈旧授权和停止前 admission 变化回归。
- 原子状态写入报错（包括 rename 后结果不确定）时，不对外发布内存中的 commit、rollback 或取消证明，也不继续下一外部步骤；状态接口只报告最近成功持久化的快照及错误。修复存储后重启 updater，重新读取并 checkpoint 实际文件再对账；受管服务不因此被终止。
- 本切片信任同用户的 server、runner 和 updater；身份/版本关联用于处理合法重启、消息延迟/重复和 admission 并发，不防御恶意同 UID、伪造本地状态或 root。
