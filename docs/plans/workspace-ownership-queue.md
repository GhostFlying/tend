# 工作区归属与执行等待可见性

## 目标与边界

独立工作项不能因复用同一个仓库目录而意外串行。reuse 仅用于同一工作项内延续已有工作状态；同仓库、只读任务或多工作项关联都不扩大复用权限。需要仓库的独立调查创建独立 worktree，不需要仓库的任务使用 temporary；共享 Git 对象或下载缓存是 provider 的内部优化，不提供共享可变工作目录的只读锁模式。

排队属于执行事实，不新增白板业务阶段或列。保持动态计划及持续责任语义，在卡片、阶段与任务旁明确执行/等待标记及原因；计划 active 不再被当作 worker 正在执行的证据。

## 实施

1. 为任务主工作项与 workspace 归属建立稳定可核验的关系，追加迁移并保留历史事实。创建、默认工作区及更新入口校验同一归属；新增次要关联不能改变所有权。已有运行继续执行，不重置目录或迁移运行现场。
2. 对尚未开始任何 run 的排队复用任务，支持通过现有 revision 校验的任务意图更新改为独立工作区；解绑、spec/action 更新与事件在同一事务提交，不能更改正在运行或已有执行历史的绑定，也不释放其他任务占有的资源。若无法通过该受限路径安全修正，则按明确关联保留旧任务并重建后续任务，禁止直接修改生产 SQL。
3. 从现有调度规则与资源事实生成等待原因，包括工作区占用、依赖、主机或容量，并暴露占用者；避免维护一份与真实调度逻辑不同的解释规则。区分任务生命周期、run 执行与工作项计划，不把资源等待误报为无阻塞。
4. 增加工作项/阶段的只读执行投影和 Web 标记，保留原白板分类。没有执行的 queued 任务显示排队中；实际执行、验收和等待用户分别说明，混合状态显示数量。阶段完成/取消及工作项关闭仍遵守原有证据和责任规则，不自动改写计划。
5. 更新托管/外挂主 Agent 工具说明与上下文指引：独立目标默认独立资源；同一工作项仅有状态延续需求才 reuse，允许同工作项多资源并行。跨项交付通过明确 commit/文件/报告引用传递。
6. 回归覆盖同项复用、跨项拒绝、次要链接不扩权、历史运行兼容、从未执行任务安全改绑、事务去重与 revision 冲突、等待投影及混合执行状态。验证桌面与窄屏标记和原因可读性。
7. make check、独立 review、CI、PR 合入及受控升级后，通过正式工具修正当前受影响的排队任务，保留其工作项、目标、输入、验收与历史；修正主 Agent 自行添加的串行约束。运行中任务不被中断，读取最终状态确认独立任务能够并行领取。

## 兼容性与风险

业务所有权由 server 管理，不新增 runner 必填字段，不改变 runner 请求信封或有效请求的处理语义；需要复核协议边界后保持现有通信代次。新增 owner 视图字段为增量。旧持久化记录不能通过猜测当前多对多关联重新归属；优先使用初始 spec 或已有不可变来源，无法确定的历史资源禁止新的跨项复用，但保留已有执行与读回。

本次不实现任意活跃工作区搬迁、并发读写锁、自动合并分支或阶段自动收尾。机器与验收证据放入本地记录，不进入公开文档。
