# S11 Issue 讨论层级

Refs: D132。仅修改前端展示，业务协议与持久化不变。

1. 对照参考实现，将共享轮次过程合并到状态行，默认折叠、平铺最近 12 步；保留决定卡、工具原文、结束折叠与焦点返回。
2. Issue 讨论以作者行头像标记主线、颜色强调结果／待处理／失败重点、可合并披露的低权重系统事件；清除自引用标签及重复时间。
3. 主栏移除交付物，保留侧栏全部交付入口；压缩手机进展和侧栏执行记录，调查初次加载的新进展误报。
4. 扩展浏览器回归，运行全部 Web 门禁与完整检查；隔离沙盒截图验证桌面和手机及两种展开状态。

## 主线集成

Rebase 时保留主线的原生执行预览、用量入口与路由阅读上下文；侧栏执行记录沿用主线的 entry-only 入口，讨论区继续使用本计划的平铺与折叠交互。冲突消解后重新运行 Web、浏览器回归、完整检查及独立 review。

## 回归修正

合并事件组以末条活动身份保持 React 节点，避免读取更早页时丢失展开状态、缩短滚动区域并错误清除未见更新。组与首条成员不重复使用滚动身份；被合并隐藏的成员以可见组恢复锚点。平铺过程的续页仍定位首个新可见工具，保留原分页断言。手机交接警告始终可见，不进入进展的折叠内容。

## 独立评审修正

事件组以首次已见成员的身份登记并映射所有成员，前插分页和末尾追加均复用控件节点；打开过程时冻结可见起点，追加工具不隐藏正在阅读的行。新增浏览器焦点回归，删除已退役工具分组实现，仅保留标签映射。收紧手机元信息、侧栏行节奏和报告预览。此轮运行 Web 全部门禁，完整检查留待后续基线重排。

## 事件组再评审修正

事件合并窗口改为相邻事件间隔，避免前插记录切开原组；身份协调为每个渲染组独占身份，原成员所在组优先继承，合并或拆分不复用 React key。单元测试覆盖跨原窗口前插、组的合并和拆分；浏览器连续读取两页更早记录验证行和滚动身份唯一。

## 体验反馈修正

1. 将 Issue 专属的调度与事件诊断入口移入更多操作菜单，保留 Issue 筛选与事件页目标。
2. 移除讨论区整体的左侧缩进及贯穿历史的竖线；头像参与作者行的正常布局，正文与讨论区左边缘对齐。
3. 统一作者、系统事件和后台来源摘要的图标宽度及文字间距，避免折叠箭头与头像采用不同占位宽度造成错位；失败状态保留强调但不额外缩进。
4. 在桌面和手机检查历史读取、来源折叠、工具过程、事件组与诊断导航，运行 Web 门禁及完整检查，再更新保留数据的沙盒。

## 第二轮体验反馈：按交互职责调整

- 对照参考实现的 Issue 操作菜单、常用字段编辑及完整时间线；参考既有实现的交互结构，不复制其代码或引入依赖。
- 进展编辑保留在进展区，负责人交接放在负责人字段，创建任务放在执行记录区；更多操作使用共享 Menu 的轻量条目、分组、键盘导航与外部点击关闭。
- 所有讨论正文、系统事件文字、后台来源摘要和交付说明使用同一左边缘。事件不预留空头像列；后台来源的折叠箭头移至摘要末尾。
- 删除最近三轮的本地截断及“查看更早记录”按钮。已读取记录全部呈现，历史页在进入顶部边界时自动读取，保持阅读锚点，错误时明确重试且不循环请求。
- 回归覆盖菜单分组、方向键／Escape／外部关闭和焦点返回、自动历史读取与失败重试、实时事件与分页的锚点保持，以及完整行文字对齐。先构建 Web 再运行完整检查，避免 Go 嵌入产物在检查过程中变化；独立 review 后更新保留数据的沙盒。

主线集成回归发现执行监控的来源断言早于异步原生预览读取完成；先等待首个原生记录出现，再核对来源，保持原来源断言与产品行为不变。

## 主线集成独立评审修正

将关联菜单保留在正常文档流，避免过滤当前 Issue 标签后覆盖下一段；记录活动区内的焦点来源，事件合并替换该节点时将焦点移到对应组摘要；负责人元信息在窄屏允许名称换行。浏览器覆盖单事件实时成组的焦点、关联菜单与后文几何边界和长名称的手机溢出。

分组被后补活动拆开时，同样恢复焦点到原事件的可见操作；一次恢复后清除旧焦点引用，避免稍后的无关更新重复尝试。增加成组再拆分的连续键盘回归。

CI 与未修改产品源码的基线均出现返回任务的瞬时断言失败：执行页卸载后，任务投影仍可能异步读取。返回回归先等待任务执行卡可见，再断言，保留返回目标和内容检查。

无查看按钮的纯进展事件以行本身作为程序化焦点回退，使用 tabIndex=-1 保留正常 Tab 顺序；浏览器单独覆盖纯进展组拆分。
