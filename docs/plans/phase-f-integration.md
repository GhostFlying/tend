# 阶段 F 接续：真实托管会话的 Web API 集成验证

依据：阶段 F 计划 §8、D68、D69、D70、D72。

现有真实模型测试只验证托管主会话读取文件，没有覆盖浏览器发送消息后创建任务、独立验收完成以及事件流通知的路径。补充 integration 测试，沿用 owner API 登录、消息与事件流接口，使用真实 traex 托管主会话创建任务。runner 的实现与验收使用已有替身，隔离主会话协议的验证；真实 worker 和设备验收仍按阶段 F 的完成标准另行记录。

1. 沿用生产的主会话配置、动态工具和 dispatcher，运行在测试专用工作目录与临时账本上，不修改部署或用户配置。
2. 经 owner API 登录、打开事件流、发送明确的任务请求，验证真实主会话通过动态工具创建任务。
3. runner 替身实现并独立验收，通过事件流观察任务完成，并经任务读取接口核对完成状态与验收结论。
4. 验证会话记录包含主 Agent 回复及成功的任务创建工具调用；有界等待与退出清理覆盖模型不可用的情况。
5. 运行现有真实读文件测试、新集成测试和 `make check`；记录模型不可用等外部限制。按仓库规则独立 review、PR、CI 后合入。

## 真实 worker 的完整链路

上述控制路径验证通过后，将现有 `TestIntegration_TraexLoop` 的直接消息入口改为 owner API 登录、打开事件流、HTTP 发消息；继续使用其真实 traex 实现与独立验收 worker，并以事件流中的任务完成及任务详情读回作为成功依据。沿用临时仓库，统一托管会话的启动方式，在停止 runner 后再关闭 journal，避免关闭顺序影响退出。此项补齐 §8 的完整真实模型链路，不代替浏览器和真机操作。
