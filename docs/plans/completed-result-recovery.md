# 已提交执行结果的关闭与恢复

Refs: D203。

## 问题

实现执行的 `submit_result` 已保存报告和上传文件引用，原生回合也已结束，
但关闭检查发生在 runner 写入 `worker_done` 之前。关闭不确定时结果仍只在
执行目录中；后续通用恢复只会把原执行解释为中断，缺少恢复已提交结果的分支。
关闭原进程组也不代表所有独立后代退出；关闭前快照中的独立进程还可能继续
派生工作，因此这些 PID 后来消失不能作为完整执行已经关闭的证明。

## 实施

1. R1：实现执行增加与独立验收相同原则的只恢复结果接口。读取原执行目录的
   `result.json`，验证原 Run、目录和 thread 归属及结果格式，确认原执行关闭后，
   返回关闭后重读的原报告和上传文件引用；不创建会话、模型回合、上传或新执行
   代次。不支持独立进程恢复的平台或自定义会话由原恢复路径继续处理，不被可选
   结果恢复入口永久拦截。
2. R2：runner 在通用中断恢复之前恢复已提交的实现结果，并先持久化结果再保存
   关闭确认。正常完成同样先持久化已确定的结果，再执行可能失败的关闭对账。
   无结果沿原流程；损坏结果或关闭未知保留原结果和错误；暂停、接管、取消和
   原生失败仍遵守原控制链，不由文件存在推导授权。原生终态单独持久化并绑定
   原执行，事件 ACK 后仍可恢复，关闭错误不覆盖真实失败；旧执行只有仍保有
   原始终态证据时才恢复该事实，缺证继续保留未知。runner 生命周期结束不能
   被解释为业务暂停而覆盖原生终态；归属证明缺失沿既有有限对账和 fencing
   路径处理，不在活动执行器中无限重试。生命周期取消、暂停、停止与提问交接
   仍完成原关闭和控制处理；可选结果恢复不拦截已有的显式保留会话继续授权。
   原生中断返回原中断恢复路径，由真实关闭证明决定能否恢复执行，不因存在
   临时结果文件而完成任务或授权重跑。
3. R3：关闭检查观察到独立子进程或观察失败时均保留关闭未知，不将原进程组
   退出写成完整关闭证明。已登记独立进程后来退出也不自动补出关闭证明，因为
   其未被快照覆盖的后代仍可能活动。缺少证明的历史执行保留独立外部对账路径；
   只有覆盖原执行及其后代的新鲜独立核验才能记录完整关闭，并保留原件和来源。
4. R4：完成针对正常关闭、关闭失败后重启、损坏结果、身份不匹配、独立子进程
   仍活动、快照后派生且原 PID 退出，以及不支持独立进程恢复的回归检查；完成
   完整检查、独立评审和所需 CI 后合入。
5. R5：受控更新后，对原执行进行新鲜、独立、可审计的关闭核验，保留原件和
   来源。由 runner 自行恢复原结果、提交产物并进入已有独立验收；不重跑调查。

## 边界

不增加服务端或 runner 线上协议字段，不改变既有请求去重、结果版本及业务
授权校验。原始失败和 unknown 历史继续保留。没有完成结果的执行不能通过此
路径升级为成功；结果恢复与是否允许执行新的工作分别处理。
