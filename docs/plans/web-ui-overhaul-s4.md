# S4 页面修复实施计划

Refs: D131
Plan: S4

1. 以现有隔离夹具保存看板／层级、Issue 活跃／结束详情、收件箱列表／详情及设置、任务、用量、仓库、主机、归档、目录的桌面深浅与手机截图；参考视觉基准的紧凑列、标题／摘要／元数据层次，不引入其依赖。
2. 看板头部仅保留标题、计数、新建；使用基础筛选控件、手机筛选 Sheet 和可滚动状态标签。默认折叠已取消列，持久化偏好；收窄列间距并保留最小列宽，空列自适应高度，徽标换行。
3. 收件箱用摘要、类型徽标、关联链接、相对时间、未读点和单一处理状态；桌面无选择时替换路由选中首项，手机保留列表／详情。
4. Issue 详情合并状态行，交付摘要仅在主栏，侧栏保留计数入口；结束说明与重开入口移至输入区上方，输入区与缩略图限制高度。子 Issue 读取从 render 移至 effect，消除跨组件更新告警。
5. 设置采用 Section、基础字段与操作，短数字加单位，禁用原因及保存／待核实反馈就地展示；任务默认在当前读完为空时选已结束，保留显式选择与历史恢复，计数只展示已知值，空态可切换。
6. 对齐资源、归档、目录、升级控件；审计所有顶层页面取消返回按钮，详情保留返回语义。补充几何、自动选择、状态行和 React 告警断言，不删除业务断言。
7. 检视同夹具后截图并修正，串行执行全部 Web 门禁；仅提交本片改动，不 push。协议、生成类型、请求身份及业务合同不变。

## 实施说明

- 子项读取拆为无 IO 的 reader 查找与 effect 打开；层级页采用同样方式，保留分页与 include_closed 合同。
- 收件箱现有投影不带原消息正文，摘要优先使用问题／原因／处理结果；缺失时由挂载行读取关联原始消息的首行，读取失败／无文字显式说明，不伪造摘要。原英文内容不改写。
- 已取消列默认 44px；展开时六列使用较小但固定的最小宽度，1440px 可完整展示。较窄桌面允许列容器内部横向滚动，页面本身不溢出；手机仅展示当前状态列。
- 任务页保留既有折叠资源区与历史读取断言；仅 Issue 顶层头部移除重复资源与执行入口。任务计数为已加载数量，分页未结束时加号明确不是完整总数。

## 门禁根因修正

- 低高度、大字号、失败提示同时出现时，决定滚动区原有 44px 最小高度无法容纳 103px 的已聚焦选项，浏览器把选项中心滚到输入框背后。几何证据确认是产品可达性问题；聚焦决定控件时为内层滚动区保留有限阅读高度，外层 seat 仍可滚动，不增加测试超时。
- 已结束默认标签可能先于原脚本显式切换完成读取；测试在已经选中时显式刷新并保留真实响应与任务数量检查。其余筛选、处理状态、去重交付与顶层返回断言随新结构更新，业务断言保留。
