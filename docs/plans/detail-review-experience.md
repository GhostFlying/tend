## 两种候选

### 宽详情页

工作项与任务占据相同的主内容区。顶层返回看板，任务通过面包屑返回工作项。
保留看板筛选、滚动位置、详情内页签与阅读位置；支持直接链接、刷新和浏览器前进后退。
桌面采用宽阅读区与紧凑的下一步区域；窄屏改为单列，正文和操作均可完整阅读。

### 宽浮层，可切换全屏

工作项与任务使用同一个宽容器，在容器内切换，禁止叠加任务侧栏或第二个详情浮层。
保留背后的看板定位；关闭回到原卡片，返回工作项保留其页签及位置。
支持切换全屏；移动端改为全屏。关闭、返回、浏览器后退和焦点恢复须有一致语义。

## 共同内容

1. 顶部展示工作项目标、执行事实及当前待决定事项，区分“计划验收通过”和“已实施”。
2. 原始输入展示图片缩略图、原文件名、来源消息；点开可放大、下载原件。
3. 调查与交付按任务、产物版本及验收状态组织；默认展示通过验收的当前产物。
4. 报告正文可直接阅读；图片引用在当前不可变文件清单内解析，不依赖 worker 的本地路径。
5. 调查截图与原图并列可比较；不能把复现截图当作修复效果。
6. HTML 设计稿有明确预览入口，执行内容与 owner 页面隔离；不得将交付 HTML 注入主页面。
7. 运行记录入口使用同一详情容器，后续 rollout 读取与 token 采集能力仍按各自任务实施。
8. 下一步决定放在材料旁；阅读和切换界面不会提交答案。

## 实施细化

- Shell 统一管理单个 modal、URL 中的工作项/任务定位和浏览器前进后退；工作项进入关联任务时保持挂载，返回恢复页签、折叠和滚动。关闭恢复看板焦点，直接链接可刷新。
- 两类详情共用宽度、全屏按钮和移动端全屏规则。工作项分为评审材料、阶段与任务、背景与输入、跟进与交付、历史；正在执行的工作项默认阶段页，完成调查默认材料页。
- 评审材料按关联任务独立读取详情，不覆盖全局正在查看的任务。显式标注 spec 与验收状态，使用已有产物身份关联规则，保留历史入口。
- 文件元数据读取沿用 owner 权限，背景中的精确 file_id 可以恢复原件元数据。绑定输入和交付清单提供原件下载及懒加载图片预览，Markdown 只解析当前清单内唯一匹配的相对文件名或 file_id，不加载任意远端图片或 worker 路径。
- 交付文件增加签名绑定 inline 展示；图片依据实际字节类型白名单展示。HTML 仅在无脚本、无同源权限的 sandbox iframe 中静态预览，响应 CSP 禁止脚本、网络、表单、自动导航、嵌套页面及父页面访问；普通下载语义保持不变。
- 回归覆盖同容器导航、前进后退、关闭与焦点、刷新直达、原图和交付预览、失败重试、静态隔离 HTML 与 320px/390px/桌面尺寸。服务器测试核验签名文件/展示方式/owner/有效期边界及原件字节。

## 验收重点

- 相同工作项和任务均使用选定容器；桌面不再出现 380px 的任务正文阅读区。
- 320/390/430px 及桌面宽度无正文截断，图片放大和关闭不丢阅读位置。
- 输入图片、交付图片及 Markdown 中图片均可打开，保持原件身份；错误可重试和下载。
- 保留历史产物及其验收状态，不把未通过版本作为最新通过结果。
- 文件预览沿用 owner 鉴权和单文件短期签名，不把凭据写入页面、URL 或交付物。
- 从看板进入工作项，再进入任务，返回时保留筛选、滚动、页签和焦点。
- 预览内容不能调用 owner 写接口；加载媒体不会回答决定或产生业务状态变化。
- 产品实施完成后按仓库要求运行 `make check` 和独立 review；设计稿本身只做展示与交互核对。
