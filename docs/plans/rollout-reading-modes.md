# 执行过程的卡片与完整阅读模式（D117）

## 目标与边界

按 owner 确认的交互修改现有 PR：卡片以 Multica 的当前动作摘要、耗时和少量最近步骤为参照；完整视图以 DeepSeek harness 的正文阅读流、单行工具摘要与可展开输入输出为参照。点击卡片摘要展开最近步骤，点击步骤只展开该步骤；“查看完整过程”或步骤的详情入口打开宽屏阅读面板，手机全屏。返回保留卡片展开、焦点和滚动位置。模式切换与 Live/历史独立，合入部署仍延后。

## 实施顺序

1. 增加纯展示投影：同 run、原生 thread/turn 与 item 身份相同的开始/完成事件合成同一步；缺失身份不猜测合并。统一摘要、状态、工具输入输出、文本与诊断记录，两种展示共用。
2. 保留一个分页与轮询状态所有者；卡片常驻，默认一行当前动作，展开显示最近少量步骤。完整视图使用相同数据与步骤组件；原始身份、JSON、水位和采集说明收进显式详情。
3. 完整视图采用正文阅读流和折叠工具行。打开定位所选步骤或当前窗口末尾；阅读历史、加载更早、返回卡片均保留位置。底部跟随新内容，向上阅读解除跟随，显式“回到最新”恢复。暂停、重连不替换当前窗口。
4. 实现模态焦点管理、Esc/返回按钮及浏览器返回，桌面宽面板、移动端全屏；长词和输出限制宽高，故障保留已读内容并提供重试。只展示已采集事实，不增加正文 delta 采集或扩大来源覆盖声明。
5. 验证步骤合并及缺失/乱序身份，真实构建的隔离 API 浏览器回归覆盖两种模式、定位、返回、历史锚定、新记录、键盘及 320/390/桌面。Browser plugin not available，使用已有 Playwright；执行 make check 与规定独立 review 后更新 PR。

## 验收场景

- 卡片初始只显示一行摘要，展开步骤、步骤展开、完整模式是独立操作。
- 输入与结果不重复成两步；不同 thread/turn 的相同 item ID 不混合，缺口/截断可见。
- 完整模式关闭、Esc 和浏览器返回均恢复原卡片状态与位置；打开指定步骤不会自动跳最新。
- 历史分页保留可见锚点，Live 在底部跟随且向上阅读后不抢位置；恢复沿持久游标补齐。
- 原 token 面板顺序、未知值及来源边界保留，未操作生产或其他会话。

## 评审修正及兼容性评估

完成事件保留原有顶层 type/text/command 等字段，只追加可选 thread/turn/item 归属，旧 CLI 和 server JSON 读取继续有效；新 UI 同时读取已有嵌套开始事件、子事件与历史无归属记录。不新增 runner/server 必填条件、不收紧校验或改变默认执行语义，因此不构成 runner 协议 breaking change，无需提升版本。超大事件在既有大小上限内保留生命周期归属及状态，截断正文仍明确标记；不能据此恢复未采集内容。

独立评审同时要求保留 Orca 已采集回复及搜索/图片/子代理的已采集输入，区分 backgrounded 与 declined 状态，并修复请求用量的同 revision 冲突受到达顺序影响的问题。后者先检查不可变历史事实再忽略旧 revision，通过全部到达排列及后续更正验证冲突隔离不会被清除。

复审修正暂停窗口遮蔽正式 run 状态、接收时点冒充执行耗时，以及已无 UI 消费者的旧日志预取/监听；步骤耗时只取原生 durationMs，状态仍由独立刷新任务详情提供。浏览器回归需验证暂停期间正式状态更新，并拒绝任何额外的旧 logs 请求。
