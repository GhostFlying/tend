# deployment identity 读取生命周期修复

Refs: D113

## 问题与边界

API 的外层 deployment guard 每次调用 `App.DeploymentID`，原实现即使已有身份也进入单连接写池的 `BEGIN IMMEDIATE`。因此只读请求会等待无关写事务。本修复仅消除这个共同等待机制，不断言它是实际持续加载的唯一根因，也不证明产品或生产恢复。

## 实施步骤

1. 先增加可证伪回归：持久身份已经初始化，写事务通过 channel 确认已占用且在请求完成前不释放；认证只读 GET 必须在有界 context 内返回完整成功响应和原身份。在旧代码上记录失败。
2. `DeploymentID` 先使用独立读事务获取持久身份；存在时直接返回。仅缺失时进入原写事务，再检查并初始化。读事务必须在申请写事务前结束，不升级事务，不新增缓存、连接或依赖。
3. 并发首次调用必须共享唯一持久身份；只有成功提交后才返回身份。读取、初始化或提交失败返回空身份和原错误，下一调用可重试。重新创建 App 后仍读取同一持久身份。
4. 补充并发、取消后重试及数据库错误回归，保留 header、session 特例、mutation guard 在认证前拒绝缺失/过期身份以及匹配身份仍需认证的检查。同步补充 D113，不改变协议、schema 或 CLI 能力。
5. 定向 race 检查后，检查本机资源与现有检查进程；仅一个完整检查 driver，以命令级有界并发执行 `make check`。使用现有 git 身份提交，通过独立 Codex review 与 GitHub CI 准备可审阅 PR。任何未通过或不可取得的证据原样记录。

## 生产守卫

本变更仅交付代码和 PR。生产部署、重启、kill、回退、maintenance 和业务数据库写入全部暂停。原唯一部署窗口需先由原调查责任核实当前 binding、不可逆阶段、updater 与健康状态，取得合法终态及持久回执；随后依赖正式 review/CI、最新主线候选及受控发布，最后才可回读版本、有限 API 和真实 PWA 行为。不能用 coordinator completed 或本任务通过替代这些证据。
