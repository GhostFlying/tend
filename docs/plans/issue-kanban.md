# Issue 看板与状态通知补全

Refs: D127、D121–D126。

## 已确认范围

实现顶层 Issue 六列看板、卡片摘要、项目与负责人筛选、层级切换、桌面拖拽、手机状态菜单、状态通知防抖及系统设置。内部详情页由其他工作维护；本片不修改详情、阶段图或阶段编辑，不提供阶段编辑器。

布局沿已批准稿，样式复用现有字体、字号、颜色、边框、圆角与交互 token，保留 shell、侧栏和手机三入口。深浅主题一致；不引入第三方 UI 或拖拽依赖。

## 实施阶段

1. P1：工作状态与 canonical 卡片投影、按列筛选、完整计数与分页、生成 Schema 和 Web 类型。正式完成与取消仍取原生命周期结果，不保存第二份终态。
2. P2：同一状态命令覆盖拖拽与菜单，沿用请求去重、revision、assignment epoch、收尾守卫；无阻塞直接保存，有阻塞保持原状态。完成依据引用原合法事实，owner 当前请求表示明确操作，不重复要求确认或说明。
3. P3：持久化状态通知合并与系统延迟设置。默认最后一次实际变更后三分钟；零表示立即，或一至三十分钟。状态及历史即时保存，失败、重放、无变化不重置窗口；拖回本轮起始状态不通知。Agent 自身修改不自唤醒。到期按当前负责人投递原 background/outbox；已冻结或 unknown 输入保持原对账。
4. P4：六列看板与卡片、列内追加分页、筛选、拖拽、手机菜单、阻塞与未知结果恢复、设置表单。状态显示与执行事实分离，详情沿原入口。
5. P5：定向故障测试、浏览器桌面/手机/深浅主题与参考稿对照、独立 review、完整 make check、PR CI。合并、发布、运行验收分别记录。

## 不变量与验收

- 工作状态不证明 worker 运行，不隐式暂停或停止任务；已有 close/cancel/reopen 守卫保持。受阻移动不写业务状态或通知。
- 数据来自 canonical 读取，顶层范围不被项目筛选改变；列总数不使用已加载条数替代，不逐卡读取详情，不另造缓存或轮询。
- 每个 Issue 独立窗口持久化；配置修改重新计算未投递窗口，已冻结输入不重写。重启、并发到期、交接、unknown 不丢失责任，不伪造确定成功。
- 当前没有 Browser 插件，使用项目已有 Playwright 完成渲染验证。临时截图与验证输出保存在忽略目录或仓库外。
- 迁移只追加，历史快照不回填，不改变 runner 通信协议，不在迁移时产生通知。
