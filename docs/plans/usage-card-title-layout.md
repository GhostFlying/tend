# Token 用量卡片长标题排版修复

## 问题与范围

手机的「Token 用量 → 按 Issue → 全部历史」中，长中文标题换行后与模型名重叠。
Issue 与 Session 列表共用 `UsageRow`，标题使用通用 Button；需要核对固定按钮高度
对标题实际占位的影响。仅调整用量卡片排版，不改变计价、Token 汇总、筛选或导航逻辑。

## 实施步骤

1. 查看用户原图，在实际浏览器中用原图长标题和隔离 API 数据复现；保存截图与文字、
   标题按钮、模型、费用、Token 明细的 DOM 几何。
2. 在用量标题样式中实施最小修复，让多行内容参与正常布局；保留按钮交互及触控最小高度。
3. 添加浏览器回归：覆盖长中文标题、长模型名、Issue 层级、Session 归属说明、主会话和
   未归属卡片；测量内容边界，核对数字、费用、详情及返回导航。
4. 验证 392px（原图 588px 位图按 1.5 倍缩放推定，实际设备 CSS 宽度未知）、320px、
   1440px；保存修复后截图和可复用证据。模拟视口不冒充真实手机实测。
5. 运行完整 `make check`，使用既有用户 Git 身份提交并创建 draft PR。报告候选、命令、
   日志与限制，由 Issue 负责人关联唯一独立整体 PR 审阅；本任务不合入或部署。

## 验证标准

标题及副标题文字完整处于按钮和卡片边界内，不与模型、费用或 Token 明细相交；
模型与费用互不遮挡，无页面横向溢出。费用、计数、详情入口和筛选导航保持原行为。
保留修复前失败证据，回归必须能够检测原始缺陷。

## 实施结果

通用 Button 的固定高度使标题文字溢出；手机端的最小触控高度仍不足以容纳多行标题，
桌面端较长的标题和 Session 归属说明也受影响。仅为 `.title` 增加 `height: auto`，
保留通用 Button 与其他控件不变。新增 `pnpm --dir web test:usage-cards` 并纳入既有
layout CI 分组；用 `TEND_LAYOUT_OUTPUT` 选择截图和 DOM 几何 JSON 输出目录。
同一回归在原始样式下检测到文字溢出及标题与模型重叠，修复后全部尺寸通过。
