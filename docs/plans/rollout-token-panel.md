# Rollout/live 与 token 面板实施（D117）

## 已确认范围

实现已验收的 rollout/live 浏览与紧凑 token 面板，交付经过检查和独立评审的 PR。合入和部署另行进行，不导入历史原生会话，不访问生产内容。筛选顺序为自然日、自然周、自然月、最近 24h、7d、30d、总共；总共放最右。数值按输入（缓存读取、可提供时的缓存写入）、输出排列，缓存是输入明细，不重复累加。

## 实施顺序

1. 核对现有事件、请求身份、原生协议与计量字段来源；将消费计量与上下文占用分开。缺失保持未知，不通过正文估算消费或伪造模型/时间/覆盖率。
2. 为请求级计量增加追加事实和可替换投影，以来源/原生请求身份去重，支持更正和乱序；主会话与 worker 共享事务内写入路径。原生累计仅作范围明确的参考，不重复计算父子请求。
3. 提供固定时区时间窗口、模型、单 run 与全局查询；同一读事务返回水位、数据截止与覆盖边界。缓存写入和实际模型字段不具备证据时明确未提供。
4. 实现 worker 历史分页和 live 共用展示，保留 run/原生身份与原始记录查看、内容截断标记及断线恢复；执行状态仍由正式状态机提供。
5. 接入紧凑全局面板、单 run 用量和必要导航，验证窄屏、缺失、最终校正及跨窗口；完成 make check 与规定独立 review 后发起 PR。

## 验证边界

新增请求去重、不同传输序号、乱序 final/provisional、更正、模型归属、未知字段与时间边界的事务测试；前端使用真实组件及隔离本地 API。原生工具支持不到的来源标为未提供，不以构建通过宣称全量采集或实机验收。

## 来源验证与实现边界

真实 TraeX 新建会话已验证必须开启 experimentalRawEvents 才能收到 request usage；仅生成 schema 不算采集成功。原生通知不提供可靠实际模型/发生时点，缓存默认值亦不能代替上游字段存在性，当前明确单列未知。恢复会话和 Orca 的请求级覆盖不作已实现声明，未观测来源不填零；详见 docs/token-usage.md。

独立评审修正了相同 payload 不同 attribution 被幂等层吞掉的问题，以及初始无 run 后新增执行、暂停改变阅读窗口、空 live 页和完整短历史的边界状态。相应事务和真实组件回归保留在本轮检查中。
