# 委派工具契约与失败责任修复（D135）

## 问题

真实主会话在拿到 owner 消息及版本后，创建 Issue 时遗漏来源版本，继而尝试改写或省略来源，连续遭拒。失败待办使用的枚举与服务端字段也未在工具输入中准确表达。最终消息审阅完成，通信回合结束，但委派失败没有持久阻塞责任。

## 实施

1. 主 Agent 工具明确要求原消息 ID 与独立版本；导出准确的约束、字段说明与可纠正错误，不改变 runner 2/1 或已有 owner 请求默认语义。
2. planner 工具采用 protocol 内专用写入 DTO，仅提供可编辑字段，类型/状态使用明确枚举；在工具边界转换为已有 owner 用例，服务端继续分配身份、版本和时间。
3. 持久记录具名协调执行中的 Issue 委派结果，失败记录与请求回执同事务提交；成功更正只能消解同逻辑责任（包含澄清继承）、同来源、同业务目标及同委派内容的失败。未知/无权限的身份不获得新准入。
4. 回合结束时，未消解的委派失败进入现有 needs_review，保留明确原因与事件，不因消息审阅完毕标为业务已处理，不自动重放业务写入。
5. 回归验证真实失败参数、精确版本更正、去重、来源围栏、多输入隔离、planner 创建/更新，以及失败后的回合收尾。更新设计决策与必要协议生成结果。

## 交付

完成定向检查及 make check，独立 CLI review，PR CI 与线性合入。以合入提交构建不可变发布包，通过既有受控升级部署；核对 server/runner 实际版本、协议、历史保留及运行状态。保留原失败请求记录，不改写历史或自动重放原 PWA 工作。
