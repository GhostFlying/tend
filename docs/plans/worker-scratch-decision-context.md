# Worker scratch 权限与决策说明

## 目标与范围

- scratch 目录创建和 worker 指令使用同一规范路径，验收 scratch 保持独立。根据后续 owner 决定，所有 worker 使用原生 YOLO 权限，不再通过额外目录授权限制它。
- 准备失败沿 runner 的环境准备失败路径报告。每次启动不执行额外的沙箱写入探针；真实沙箱可写验证只用于测试。
- worker 问题结构化记录环境故障、证据缺口、影响、处理归属、状态和依据；主 Agent 在原决策上补充可追溯的说明，不改写 worker 原始问题，不代替 owner 回答。
- 影响选择的问题与主 Agent 说明直接显示在选项前，原始长证据仍可展开。
- 主 Agent 保持只读文件与现有工具限制，主/后台原生网络显式开放；后台仍使用 auto 审批。
- 为验收角色提供独立模型与思考强度配置，以及任务级验收执行选择；未指定时保持既有模型选择。
- 不修改 gateway；完成检查、独立 review 和 PR 后按受控流程部署并核对实际结果。

设计决策：D118。与 owner 最初提问相关的上下文消息水位排除工具记录，调查定界后主 Agent 更新具体标题。

## 实施

1. 将 scratch 经过规范化后用于创建与启动指令；准备失败不启动 worker。Traex worker 原生使用 bypass_permissions，Codex 保持 danger-full-access/never；主/后台通过原生协议显式开放网络。
2. 为现有 worker 提问增加可选结构化问题字段，追加存储迁移，保留旧请求 hash 与重放语义。旧请求不增加必填字段、不改变默认执行语义，评估 server/runner 协议兼容。
3. 增加主 Agent 对同一决策的说明操作，走 app 去重、版本校验、事务和事件，保留原 worker 内容及说明历史；明确每个问题的处置与需 owner 决定的内容。
4. 更新主 Agent、后台及 worker 工具指令，避免将环境故障描述为外部授权问题；前端直接渲染摘要并保留长证据。
5. 补充路径与权限、失败不启动、验收隔离、旧请求重放、问题持久化、说明授权/版本/去重、前端展示及回答语义的回归测试。
6. 更新设计，重新生成 API 类型，运行 make check、渲染验证及独立 review，修复确认的问题后提交 PR。

## 验收

- 指定 scratch 的规范路径出现在 worker brief；worker 原生 YOLO 生效，验收临时目录保持独立，不将其等同于文件隔离。
- 不引入每次运行的写入探针；准备错误不会变成 ask_owner 业务选择。
- 原始 worker 问题、选项与身份不被主 Agent 说明覆盖；旧 worker 仍可按原内容恢复问题。
- 环境错误和证据缺口有各自影响、处置归属与状态；主 Agent 说明默认可见，owner 回答仍作用于原决策。
- 生成代码使用仓库生成入口；公开文件不包含机器信息或内部链接。
