# 子 Issue 长标题布局修复

范围仅限看板子 Issue 的标题、状态与交互行布局，以及必要的详情和桌面兼容验证；不修改计数、数据来源、协议或交付机制。

1. 下载并实际查看冻结原图，核验大小和摘要。以原图可见的 Review 长标题和同等或更长的中英文混合标题，在当前基线复现并保存截图、DOM 几何及点击证据。
2. 核对通用 Button 与看板局部样式的高度、换行和状态列约束，只在子行局部修正根因，不改变通用按钮或外部 child-only 候选的数据模型。
3. 以同一隔离 API fixture 验证 390、360、320 和 1440 像素：标题、状态、行按钮、查看全部均在卡内，下一卡不重叠，无横向溢出，展开、刷新和点击进入详情正常，直接子集合一致。
4. 运行针对实际差异的类型、格式、样式、单元及浏览器检查；完整检查按已释放的唯一窗口串行执行，不启动并发第二套。交付小提交、补丁及原图/前后截图/几何证据，说明尚待独立验收、组合检查和 CI 的边界。

本次是既有布局缺陷修复，不改变产品设计决策。

## 原验收失败后的同范围修正

保留原提交、验收 changes_required 与 CI 失败，不重建任务。先读取原
layout (1) 的正常 Issue surfaces 调用链，在隔离副本记录展开期间的滚动、
各次坐标读取与同一帧的完整几何，区分产品溢出和跨时刻采样。不得删除或
放宽 containment、overlap、最后一行点击断言。

若证实为采样问题，将相关元素放入同一浏览器求值中测量，补充能稳定揭示
旧读取问题的浏览器回归，同时保留真实固定高度缺陷的负向验证。若证实为
产品布局问题，仅修正子行局部样式。随后运行正常 Issue surfaces/CI 分组入口，
核对最新 main 及 child-only 候选的组合边界，按实际差异串行检查，更新同一
PR 的实际 head 与 fresh CI。完整检查历史不能替代新 head 的检查，独立正式
验收仍由协调方安排；本实施任务不合入、不部署。

## 正式验收后的实际交付

本节仅适用于后续交付合同，不改写前次实施及验收历史。

1. 核实干净工作区、已验收 head、原图、实际 PR、live main、受测 merge
   parents、mandatory CI 与分支保护；只读核对相关 PR 的 head 和合入关系。
2. 同一候选全部门槛仍有效时，按本轮授权执行受保护的 rebase merge 并回读。
   若仓库要求或实际组合需要更新候选，只在本分支最小整合，保留两套测试
   入口及几何、重叠、末行点击断言；提交新 head、实际 diff 和 fresh CI，
   等待独立增量验收，不继承旧 head 的 passed。
3. 更新前核实 active batch、server、updater、hosts 与 merged lineage。
   仅在受支持的排他及 fencing 入口证明无其他 writer 时启动受控更新；
   已有批次时不竞争、不占排空资源，交付精确阻塞供协调方排队。
4. 保留原失败、范围外 source-recovery 观察和未执行项；通过任务产物交付
   操作记录、候选身份、必要验证和版本回读，实施者不代替独立验收结论。
