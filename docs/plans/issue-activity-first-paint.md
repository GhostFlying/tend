# Issue 讨论与进展首屏

现有活动读取按账本位置分页，但会为每个回合读取和编解码公开工具详情及回复中的工具记录。重连时，Web 还会按页重读整个已读范围。

1. 在现有活动接口增加可读投影。按稳定位置读取最近 50 条活动，用响应字节预算提前结束分页。读取用户消息、Agent 正文、关键状态、成果及过程的状态和时间，通过原回合接口按需读取工具输入输出。保留原接口投影及原详情权限。
2. 在可读投影上用账本水位增量合并，以原位置插入新出现的活动，并替换有变化的回合或移除撤回记录。用同一位置游标读取更早历史，保持阅读锚点及展开状态。
3. Web 先呈现正文，再空闲预取有限的最新和附近回合，展开时复用请求。失败允许显式重试，切换 Issue 取消旧请求。已展开的具体工具记录继续使用稳定 ID。
4. 验证正文和过程游标、回合增量、撤回、历史并发、预取请求复用与取消。用同一浏览器条件测量 PR #351 的重记录和轻量 Issue 的正文可读时间、过程展开耗时、活动条数及首屏字节数。

## 第一轮审阅修正

- F1 与并发水位复现：重新进入时先装入已有活动和分页边界，再按保留水位读取差量。历史页与实时请求仍独立完成，在发布实时结果时合并当前已读边界。
- F4：详情元数据未返回时也能处理首次活动响应后的消息更新，绑定可用后只刷新对应 Issue 会话。
- F2 与 F5：保持用户要求的过程页数直到读完。按公开过程游标合并步骤，回调补充选项等元数据，孤立回调保留可见。
- F3：延迟过程渲染后恢复当前阅读锚点。用真实浏览器时序复核异步详情、实时更新与滚动的组合，保留原审阅结果与修正证据。

## 第二轮审阅修正

- F6 恢复任务完成事件的既有活动投影。真实完成回执携带的成果 ID 仍用于成果视图。任务完成活动保留任务、位置与作者，并与其他活动一起计入字节预算。用真实任务完成和后台通知路径验证原活动、可读首屏与增量中的诊断入口。

## 第三轮审阅修正

- F7 在工具改绑事务内为旧来源记录现有的过程变更通知，并保留新来源的工具事件。用实际工具写入、改绑和 HTTP 增量验证两个回合都更新，重放同一绑定时不重复发通知。
- F8 按回合复用在途详情读取。先显示已完成的详情，再合并读取其间到达的最新回合，并补齐仍需读取的页数。验证持续正文更新、显式展开、预取和翻页都能取得详情，离开 Issue 时取消仍在途的请求。
- F9 将已读过程页数与展开状态一起保存在同一个导航条目。验证从关联 Task 返回时恢复原页深，打开新的导航条目仍从第一页开始。
- 保留 GitHub 首次滚动锚点断言的失败。用原 CI 网页构建和相同测试本地对照，并在新候选的浏览器测试中复查。只有可复现的行为或测试边界问题才改动锚点逻辑。

## 滚动锚点检查修正

- 两个候选的 CI 在同一断言失败。用当前失败作业的网页构建与同类字体记录滚动轨迹，确认首次详情使阅读段落短暂跳动 36 px，下一帧才恢复。14 条工具步骤先按全部可见计算滚动补偿，布局副作用随后折叠到 12 条，改变了上方内容高度。
- 首次拿到详情时在提交布局前确定默认可见窗口，并记下默认起点，保留显式展开更多及后续翻页的行为。浏览器测试在每次详情显示后的滚动事件和最终位置上验证同一个阅读段落，继续使用原 2 px 容差。用旧构建复现，并在修订源上验证。
- F10 同一帧用户已滚动而事件尚未送达时，在过程组件提交 DOM 前取当前阅读锚点，提交后恢复。下一帧补偿发现滚动位置再次变化时保留新的位置。浏览器在第一次滚动的同一帧释放详情，再验证显示时的偏移与最终位置。
- F11 在过程变更前同时记录正在追随末尾的状态。过程提交后仍贴住末尾，下一帧发现位置已变时保留最新滚动。浏览器验证较早详情挂起、实时追加后仍贴底，再释放详情仍贴底；既有同帧滚离场景继续验证阅读锚点。
