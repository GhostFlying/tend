# 数据库身份热路径与读连接复用

状态：并行源码优化；当前主线完成后再统一最终验收、合入与部署。

## 业务目标与故障链

列表、Issue 和会话的正常读取都先经过 owner API 的 deployment guard。已有持久身份每次仍开启读事务；读池仅保留少量空闲连接、没有总数上限。并发高峰反复创建连接、初始化 SQLite schema 与分配驱动内存，放大各 API 的首字节延迟和同进程竞争。现场采样支持该访问链，但不把 CPU 样本比例当作请求墙钟归因，也不把文件句柄数当作 DBStats 连接数。

目标路径：server 启动 → 加载或提交唯一账本身份 → 同一 App 的 API 无 SQL 获取身份 → 有界读连接执行原业务快照 → 返回原响应。失败时启动或未初始化请求明确报错，后续可重试；业务身份、认证、旧客户端写入拒绝和 unknown 对账不变。

## 实施

1. **身份生命周期**：D113 的持久 singleton 仍为 SoT。App 在实例内只缓存成功读取或成功提交的身份，先检查请求取消；首次初始化允许有界上下文等待并在失败后重试。server 在开放 API 前完成加载，API、工具和测试的其他组装保留相同惰性入口。新 App/Store 重新加载；正常备份恢复先停止旧进程，不支持存活 App 下替换账本。无 TTL、轮询或包级当前身份。
2. **有界读池**：先审计读回调及其调用图；已有事务内部查询复用传入 Querier，外部等待在事务关闭后进行。连接池保留 8 个可复用读连接，总数与空闲上限相同。已在相同并发读取与 CPU 容量下对照：增加到 32 个读连接会放大驱动分配锁竞争和冷 schema 开销，因此不随 CPU 数量直接扩张；8 个连接同时覆盖 2 与 32 个执行 CPU 的回归，不用无限扩张掩盖排队。单 writer、WAL、query_only 与超时不变。提供内部池统计，保留已有慢写分解；不新增用户操作/协议或每请求重型日志。
3. **事务范围**：核对慢写的 reviewed-context、attention 与 manager 刷新真实依赖。当前证据不足以证明可安全异步化或跳过全部刷新，先记录调用热点及后续测量方向；不拆业务状态、事件、outbox 的原子提交。UI 整组刷新与项目级日志分层另行整合。

## 可证伪验证

- 同一/多个 App 与 Store 并发初始化唯一，失败/提交失败/取消不发布身份，失败后恢复；不同数据库隔离，重开数据库加载原身份，新库拒绝旧写。持有所有读连接和 writer 时，已缓存身份仍返回，证明热路径无 SQL；未初始化实例仍遵守取消。
- 读池高于容量的并发等待可取消、释放后恢复；重复突发不销毁/重建全部连接；读快照隔离、query_only、writer 同时提交保持。原真实读路径无嵌套获取，执行并发 HTTP/业务回归而非只验证常量。
- 使用相同 Go SQLite 驱动、实际 owner HTTP 入口和相同数据/并发/CPU，对照基线与候选的响应、耗时、连接峰值/销毁/等待、CPU 与 writer 队列；保留原始失败和环境，不将局部 fixture 性能等同线上恢复。
- 定向 race、受影响业务验证先完成；独立整 PR 审阅、最终完整 make check、最终候选 CI 及当前 main 适用性由主线后统一验收。不在此并行启动完整检查、不合入或部署。

Refs: D113；本次修订 D113 的“不增加内存缓存”实现约束，持久身份与 guard 合同不变。

## 独立审阅修正：原件校验的嵌套连接

原件 verify 在枚举游标仍打开时通过读池再次解析 retained value；有界池耗尽后，多个校验相互等待并阻断普通读取。先物化最多 limit+1 条元数据并明确关闭 Rows，再逐个解析、读取及校验原件。容量保持八个；分页、原件哈希、缺失/损坏报错与取消语义保留，文件读取不持有枚举连接。

回归通过占用七个既有连接让并发校验只剩一个可用 reader，确定性检测重复取连接，同时保留普通事务读取；覆盖池等待的显式取消、释放后恢复及原有损坏/重开路径。核对其他直接读池枚举入口的 Rows 关闭与后续 lookup，事务内部继续复用原 Querier。原 RED 与独立探针保留，不把最后退出0等同审阅批准。
