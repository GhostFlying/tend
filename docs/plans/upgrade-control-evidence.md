# 升级控制链的授权、安装证明与诊断

Refs: D234。原业务目标是使用既有交付责任安装已审阅源码，再沿正常结果提交、验收、完成和发布结清。当前调查发现：自动授权在两个执行消费者中被重新解释为手工答复；无交付 Task 的完整发布批次保留同哈希 server 时未记录后续验收需要的进程与健康证明；一次控制 tick 共用短 context，且传输错误丢失原始原因。历史批次已经通过单次受控维护完成，本计划只修复正常运行仍会出现的路径，不引入历史迁移。

## 故障起点与完整路径

调用链为交付授权 → 受控升级 Start → server updater 准备/独立 installer → server 原进程保留或替换 → 两次实际健康观测 → runner 串行安装或核实保留 → 正常控制 ACK → 完成批次 → 原责任绑定真实批次、验收、完成。独立维护批次也可被原责任在核实准确源码和安装事实后正常引用。

辅助观察失败不得阻止原批次记录期限或已有结果。未知 dispatch、进程退出和回执仍沿原输入对账；超时不自动重试、不延长批次期限，不把新会话或新 request 当成重做授权。既有租约、来源、审阅、版本与资源约束保留。

## 实施项

1. **统一既有授权消费者**：Start 与已绑定完成批次的续行使用已有 DeliveryGrantValid。覆盖手工和自动授权、撤销/范围变化/来源变化，以及正常完成后续行；只读授权失败与存储错误分开。
2. **保留进程也记录安装事实**：完整发布集的同哈希 server 沿现有候选核实取得准确进程、来源、版本和两次健康事实，无需重启；不能因未绑定交付 Task 跳过。测试实际走过 Start、健康观测、runner 完成和正式安装证据读取，不以预置健康计数代替转换。
3. **按操作拥有有限预算**：观察、授权与 prepare 分别使用有限 context，并受父级取消和原阶段/整体期限约束；prepare 不消费前面观察剩下的预算。保留原协议/本机客户端的操作上限。覆盖观察耗时、prepare、取消、过期和未知响应不重发。
4. **错误和结构化日志**：保留传输错误链；控制器记录步骤、批次/请求、阶段、耗时、原期限及剩余预算；installer 记录派发身份、实际执行、退出/信号与失败阶段。未知退出仍为未知。使用现有 slog 与日志接收器，不另设持久业务账本，不记录凭据或完整输入。
5. **同哈希耗时**：先核对串行等待原因。仅在准确源码/组件身份、现有安装证明、新鲜正常控制 ACK 和无配置变更均可证明时减少重复转换；不能跳过真实替换的 drain、健康与 ACK。若现有证明不支持安全消除等待，则如实记录限制，先让耗时可解释。
6. **操作文档**：准备包、核对实际基线、备份与诊断输入放在执行窗口之前；窗口内由既有控制器推进。说明观察失败、明确拒绝、未知派发、期限到达的不同处理与实际日志发现方式。

## 验证与交付

先保留可重复的故障回归，再修复；覆盖跨层用户结果、依赖失败恢复、同一动作不重复副作用、父级取消及固定期限。针对相关 App、upgradectl、updater 运行 race 与 vet。独立审阅覆盖整个最终 PR；有真实意见时修复并由同一审阅者复核增量与整体适用性。最终候选只启动一次完整 make check（TEST_COUNT=1、CHECK_JOBS=0），记录所有阶段及原生逐例覆盖；自然 CI、保护检查和当前 main 适用性满足后 rebase 合入。源码合入、安装和原业务完成各自保留独立证据。

本计划不扩大自动授权、不增加 schema/wire/grant/并行请求账本，不恢复旧 Task/定时器、不重放历史升级或业务输入。原失败、取消、到期与未知状态保持原样。

## 实现边界与回归入口

- `TestAutomaticDeploymentRetainedFleetReachesFormalCompletion` 覆盖自动授权绑定批次与独立维护后原责任采用两条路径，实际经 Start、原成果提交、控制/健康推进、独立验收、资源释放及 complete。provider 与进程观测是外部替身，批次及业务终态不由 fixture 写入。
- `TestMaintenanceRetainedServerRecordsUsableInstallationEvidence` 独立覆盖无交付 Task 的 server 保留证明和最终精确安装读取；重复时刻不能累计健康样本。
- 自动授权消费者的单项回归隔离已绑定完成边界并覆盖撤销、来源编辑、范围与仓库变化；这些预置边界不被宣称为全链安装证明。
- 准备预算回归使用真实本机 HTTP 连接，观察和准备各耗三秒以复现共享五秒上限；取消、原阶段与整体期限另有边界回归。未知响应沿现有原请求机制观察，不自动再次派发。
- 同哈希 runner 只合并恢复正常与清理本轮元数据的控制更新，仍以实际 ACK 准入下一主机；保留 own-batch updater 证明。没有跳过完整 drain，也没有为提速新建安装证明来源。
- 日志回归检查原错误、身份和期限的关联、重复观察去重、恢复可见，以及写入失败不能输出已提交转换。历史缺失的 installer 退出仍未被重建。

## 完整审阅后的相连路径修正

保留 server 身份时同步进入现有 `server_checking`，使观察失败直至过期后仍可沿原身份核实结果。恢复只取得原进程的准确身份和两次间隔健康事实，不续期、不重新派发、不自动继续安装；正常取消和主会话解阻沿原控制入口完成。保留 server 未改变 runner 时，不改写已经正常且无升级元数据的控制；真实恢复控制仍需 ACK。覆盖观察中断、整体到期、错误进程不得计健康、原期限不变、取消和正常 ACK 间隔，以及下一批次不能继承旧下载目标。
