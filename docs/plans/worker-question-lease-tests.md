# 等待主人回答期间的租约回归修复

## 背景与边界

原失败现场的端到端测试用一秒真实时间租约验证等待回答时的续约，运行延迟可能触发正常的租约保护与恢复，进而使启动次数断言失败。修复测试时间控制与诊断，保持 runner 的保护机制、协议和产品行为不变。关联既有 D19、D29 与 worker 问题的行为约定。

## 实施

- QL1：使用共享受控时钟和显式心跳周期；分段推进并等待原租约续约，跨过初始到期时间，保持原 run、lease、thread 和严格启动次数断言。
- QL2：增加等待问题期间心跳失联的故障回归；断网并排空在途 RPC 后推进时钟，确认旧 worker 停止，再恢复连接；检查原 run/thread、唯一问题、回答关联和任务完成。长轮询读取不阻止 RPC 排空。
- QL3：失败时保留角色、run、attempt、thread、租约状态与更新时间，以及 runner 的保护和对账日志；不输出凭据或完整 spec。
- QL4：重复运行相关 race 测试、完整 `make check`、独立评审；提交到现有 PR 分支并验证最新 CI。合入与部署继续暂缓。

受控时钟测试不依赖机器必须在几百毫秒内完成 IO；每次推进必须有前一轮续约的明确观测，防止测试自身制造租约失效。故障测试保留有界真实时间等待以便在实现错误时及时失败。

同步最新基线时保留托管主会话的测试初始化要求；受控时钟同时注入服务端与 runner，故障恢复测试使用相同的托管上下文。
