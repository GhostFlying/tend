# Web 任务工作流：阶段看板与优先处理界面

依据 owner 在普通浏览器验收后的反馈，实施任务历史入口、传统分阶段看板，以及优先展示操作、阻塞和验收 issue 的任务详情。本轮先交付这些界面；任务完成后的持久化会话通知另行设计与实现，任务完成事实仍沿已有上下文增量在下一轮提供给主 Agent，不因通知自动触发模型轮次。

## 设计与接口（D75）

- 侧栏保留待处理与活动任务，补最近五个 completed 任务和明显的“全部任务”入口。已取消不混入最近完成。
- 大看板按生命周期分为待开始（draft/queued）、实现中、验收中、待返工、已完成、已取消；阻塞、暂停、接管作为卡片标识，不伪造生命周期变化。支持项目过滤、打开详情、各列分页和失败重试；列中的数字明确是已加载数量。卡片不提供拖拽改变任务状态的语义。
- 桌面为横向阶段列，窄屏在看板区域内横向浏览；可清楚返回聊天，详情关闭后仍在原看板。沿用既有 DSH 排版、色彩和控件。
- owner API `GET /api/v1/tasks?all=1` 返回既有 TaskPage；可加 `project` 和以逗号分隔的 `lifecycle` 过滤，以 `before` 续页。排序为 updated_at DESC、task_id DESC，游标由服务端返回，读取不修改账本。旧默认及 finished=1 入口保持原语义。all=1 独立分页，不依赖活动 snapshot 的 200 条上限。
- 前端看板各列请求相应生命周期组，最近完成只请求 completed。事件触发重新读对应列表，重连重新读；页面只合并服务端视图，不推导状态。翻页须去重、保持过滤身份、取消旧请求，旧响应不能覆盖新筛选结果。历史页并发更新按当前列状态核对，避免重连后继续使用旧游标。
- 详情首屏展示当前状态、当前阻塞/验收 issue、真实待决操作和控制动作；已完成任务突出对应当前 spec 产物及验收。历史失败不冒充当前问题。进展/日志随后；完整 spec、工作区、标识及原始证据折叠。复用 DecisionCard 和带 revision 的原操作语义。
- 工作区字段标明仓库和相对路径；值相同时合并解释，分支标签与值使用布局间距，长名称可换行。

## 实施与验收

1. Root 实现 all=1 分页读取及过滤，覆盖超过 200 条、相同时间戳、过滤、非法游标/生命周期及兼容旧入口；API 类型仍用已生成 TaskPage。
2. 原前端 subagent 实现最近完成、阶段看板、详情重新排序和待决可达性，复用现有模型/effort 和消息行为。
3. 独立浏览器验证生产构建：桌面、平板、390/320，深浅主题；各列和过滤、分页/重连/取消旧请求、历史任务打开、待决及控制动作、当前/历史验收区分、长分支、键盘焦点及返回聊天。Browser plugin not available，使用 Playwright。
4. make check、独立 review、CI、rebase 合入，部署已合入版本并独立读回。界面测试用 fixture；无需 orca。需要真实任务时保存证据并清理本轮 workspace/终端。
