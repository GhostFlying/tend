# Worker 过程片段的归档故障隔离

PR #389 的第十轮独立审阅发现，在 SQLite 可写而原件归档目录不可用时，Worker 终止事件附带的过程片段会让整个事件的预暂存失败。正常退出的独立片段同样会留下原序号缺口，导致随后终止事件无法入账。两种场景都从实际 App Manager Native Event 入口复现。

将在线原 Manager 事件顶层符合现有数量、字节和标识限制的 `process_text` 作为同一 SQLite 事件的内联字段保存。正式事件正文、工具和其他原件继续使用通用归档。保持原事件序号、请求重投对比、入账守卫、普通页面的完整正文限制、停止和关闭回执的独立语义。现有已归档的事件继续经原引用读取。

隔离测试只使文件归档不可用，以实际 App 接口发送终止事件及独立退出记录，核对同一事件重复送达、后继终止事件、待处理业务事实和全屏过程原文。补充检查附件以外的原件仍走原路径。保留上一轮独立原件，按同一个共享审阅复核变更候选，严格 CI 通过后按原授权合入。
