# 主 Agent owner 权限与 Issue 工作状态驱动执行

状态：实施中。权限基础先独立 PR 合入，随后从新 main 实施 Issue 状态与暂停交还；两项完成前不部署中间版本。Refs: D124、D127、D142、D146。

## 已确认合同

- 主 Agent 拥有对应 owner 的完整业务、管理与诊断权限，共用领域校验；真实 actor、执行身份、请求域和审计保留，不伪造用户发言。Issue Agent、worker、runner 的身份与责任边界不扩大。
- 所有 Issue 创建为 backlog，仅记录；立即执行由主 Agent 沿原用户目标连续执行 create 和 backlog → todo，不再次索要确认。创建结果未知先对账原请求。
- backlog → todo 是唯一业务启动入口，不能直接进入 in_progress、in_review 或 done；取消仍可从 backlog 发起。类别缺失在推进时补选，runner 主动匹配领取。
- todo 就是待领取集合的业务依据，不另存一份入队授权；容量、能力、依赖决定领取时机并提供等待原因。前置完成不启动 backlog。
- 退回 backlog 立即暂停整条子责任链，确认停止后结束本次 Run、释放槽位；保留 Task、spec、代码、工作区、artifact、会话引用和预算。再次推进创建唯一后继 Run，不重做完成项。
- 主 Agent 与 owner 同样可以取消 Issue；取消优先于尚未完成的暂停，真实停止与未结义务核验后才能完成取消。

## A：统一权限与能力入口

1. 从服务端认证或配置建立主 Agent 对应的 owner 权限上下文；不接受模型指定身份，不以最近的 owner 请求推断。
2. 工具面与 owner 能力目录共用登记，覆盖完整读写、有效输入输出、分页和恢复。删除主 Agent 专属的操作白名单以及分散角色限制，业务规则与 owner 保持一致。
3. 授权身份与 actor 分离。主 Agent 原始消息、决定、提醒、进展和策略保留 Agent 作者；owner 权限事实单独保存，不能通过复制 request_id 冒充。主 Agent 的代理决定真实记录；保留原请求域、Envelope、effect_seq 和历史回执，跨入口恢复沿原身份，不复制为新请求执行。
4. 用成对的 owner/main 用例验证实际可调用性、领域结果与审计；保留其他角色的负向测试和真实执行绑定校验。

## B：状态、领取与暂停交还

1. 创建原语只产生 backlog；负责人选择进入版本化 Issue 定义。自动子项与验收项显式记录 backlog → todo，合同保存实际授权版本。
2. 首次候选由 todo 与负责人选择派生；选中后在 runner.claim 的原事务内创建执行承载、租约和绑定。已有执行与正式验收按原合同去重；不依赖主 Agent 再分派或状态通知防抖。
3. 统一本项、祖先与子责任的业务准入；backlog 阻止新工作，必要回执、停止和 unknown 对账保留。排序复用现有调度规则，以本次进入 todo 为等待起点。
4. 暂停操作持久记录范围、原版本和本操作引入的控制，先禁止新执行再请求停止。子项状态保留，人工接管与其他暂停不覆盖；引用关系不扩大控制范围。
5. 能力协商的暂停交还携带原操作和控制版本，runner 确认受管执行停止后提交持久回执。释放租约后仅允许原成功请求的精确回读/重放，不删除工作区或伪造结果。
6. 停止未知保留占用；物理停止已知而业务回执未知可释放槽位，但继续阻止未经对账的续行。恢复只解除本操作的暂停，生成原 Task 的唯一后继，保留身份与累计预算。
7. 同步 Web、CLI、Agent 工具、帮助与能力覆盖。暂停中显示原操作进度；取消按真实停止/义务事实完成，不撤销已发生的外部事实。

## 兼容、数据与验证

只追加 server/journal 迁移。历史空状态经可恢复的 App 转换追加新 revision：没有负责人或执行责任的记录归 backlog，已有责任按冻结事实保留；历史快照和原请求不改写。转换不唤醒 backlog。暂停交还采用能力协商的可选字段与新操作，保持既有 runner wire 默认语义，验证协议 2/1 与新旧能力组合；不支持交还的旧 runner 不假报槽位释放。

验收覆盖主 Agent/owner 权限对等、create → todo 连续操作和取消、双 runner 竞争、领取与退回竞争、父子实施/验收暂停、正常完成与暂停竞争、暂停被取消、槽位复用、唯一后继、两端各窗口重启、未知结果与原回执恢复、历史迁移，以及实际 CLI/浏览器操作。

每个 PR 完成定向检查、自动 CPU 预算的完整 make check、规定的独立 review 和最终候选 CI。修复有效意见，rebase 最新 main 后使用预期 head 保护进行 rebase merge。交付实际 SHA、验证和后续部署清单；本任务不部署或改写线上账本。
