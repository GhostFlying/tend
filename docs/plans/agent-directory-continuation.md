# Agents 只读目录与定义热更新（D143）

## 已确认合同

侧栏资源组增加 Agents，主路径 `/agents`，原设置路径替换跳转。Agents / Categories 双页签，桌面分组列表和右侧详情，手机行内展开。按主机、运行环境组合组织；`orca/codex`、`orca/traex` 等组合用于分组和筛选，保留 runtime ID，不限制同组合的绑定数量。名字、稳定 slug、类别、模型和 effort 独立。页面只读，不扩大私有配置读取权限。

Agent 定义继续显式 validate/reload/登记，不要求维护。新分配使用最新启用定义，已有责任和执行继续原快照；升级责任走原显式交接。新增安装引用及程序发布仍走维护。停用、移除和类别退役阻止新分配，不自行撤销旧责任。缺原快照/适配器明确阻塞，不自动换 Agent 或重放 unknown。

## 实施顺序

1. 复用不可变 inventory 历史，为任务 owner 合同保存完整 pin，按原 manager/run 的确定来源恢复历史合同。
2. 双向协商 `runner-agent-continuation-v1`；hello/heartbeat 返回仍有账本引用的 pin，runner 在 reconciler 核验后单独上报。runner 同时上报固定工作区 backend，即使当前定义清空也能保留负责人原快照内的工作执行 pin。历史候选仅供精确责任续接，所有 epoch/权限/unknown 围栏继续有效。保留快照不预占执行槽，不运行常驻 CLI，不增加 GC。
3. 实现目录、安全观测匹配、共用名称缓存和负责人解析。配置、登记、执行、协调、在线分别展示，旧观测不能套到新版本。实现搜索、类别/运行环境筛选、URL 状态与历史链接。
4. 定向 Go/race、Web 与真实浏览器回归、完整 make check、独立 review、PR/CI。保持协议 2/1：新增字段仅在明确协商后使用，旧默认合同不变。

## 验收

- 执行中 reload v2 不进入维护；新工作使用 v2，旧工作/负责人等待唤醒和重启恢复使用 v1。
- 停用/移除、类别退役、显式交接、原生清理、unknown、快照缺失和无续接能力的旧 peer 都有确定行为。
- 原负责人安排自执行以及独立验收续接使用冻结定义；历史候选不能获得新工作。
- 同名跨主机、同组合多绑定、多用途、缺 CLI、离线/过期/部分错误、类别分页和空态准确展示。
- 桌面/手机、主题、键盘、返回/刷新和负责人名称通过浏览器检查。

## 交付边界

使用仓库命名指南的现有字段语义，不增加 slug 或自动命名服务，不修改部署身份。程序升级和定义 reload 分开验收；不自动重试历史失败任务或交接已有负责人。线上发布必须在 CI 和 review 通过后保留账本受控执行。

## 与 D141 的同步

集中 TraeX runtime 单独显示为 `central/traex`，沿原快照派生的 worker pin 保留 Orca 工作区 backend；不会把集中适配器当作本机 app-server。集中执行仍按 D141 显式启用，本计划不改变部署配置。

## CI 重启派发验收

保留数据重启的沙盒验收出现派发等待超时。脚本当前只检查最近 50 条聊天，工具记录和后台消息可将原 owner 来源挤出窗口。先用跨页来源定位用例复现，再让脚本沿真实分页游标读取并只匹配原 message ID/owner 作者；不重放业务写入，不通过延长超时掩盖。同步验证普通对话、子 Issue 来源边界及重启回归。
