# 规划工具参数契约与错误恢复

## 问题

主 Agent 在自然语言规划中连续提交不合法背景类型、阶段状态、交付类型和缺少阶段关联的请求。工作项 schema 只暴露普通字符串，合法枚举留在领域校验中；错误未指出具体字段及允许值，诱发猜测重试及删除背景、后续阶段来绕过校验。

## 实施

1. 用同一份协议枚举定义生成 owner API、MCP 与托管动态工具 schema，并用于领域校验。覆盖已有工作项有限取值，不改变已接受的业务语义。
2. 校验错误指出字段路径、错误值和允许值；任务创建明确说明 work_item_id 与 work_item_revision、非空 stage_ids 的配套关系，交付类型提供数组示例。关键关联与形状提示同时放进顶层工具说明，因为真实 harness 可能裁剪字段 description 与条件 schema；服务端继续执行同一校验。
3. 注入失败恢复规则：保留目标、背景、稳定阶段身份及后续事项，仅修正被拒绝字段；不靠清空或删减有效内容绕过错误。未知结果先对账，确定校验失败修改后使用新的业务请求身份。
4. 回放实际错误序列，验证拒绝不改变已存计划；修正请求可保留完整背景和两阶段。核验最终动态工具和 MCP 输入 schema，增加隔离真实 harness 自然语言规划验证，避免只测试预填合法参数。
5. 完成 make check、独立 review、CI、PR 合入及受控发布。发布期间保留现有任务、工作区和聊天，runner 排空后逐台升级；工具 schema 变更经既有主会话交接机制生效。

## 边界与验收

不新增状态别名，不把模型输出自动修成猜测的业务意图，不引入通用 workflow 或修复重试循环，不自动修改现有用户任务的计划。现有 JSON 形状、合法取值及 runner 通信语义保持不变，无数据库迁移；此次明确工具契约不构成 runner 协议不兼容变更。

验收包含每个已有枚举的 schema/领域一致性、错误字段定位、条件必填的说明与服务端拒绝、计划保留与修正后成功，以及真实 app-server 下模型自行构造参数的结果。真实验证使用隔离数据库和临时目录，不创建生产任务或 Orca 工作区。

## 验证记录

- 单元回放覆盖错误枚举、缺少阶段关联及数组/文本形状错误：拒绝不改变原计划，纠正请求后仅创建一次任务。
- 隔离的真实 app-server 请求捕获确认：当前 runtime 保留枚举与本地引用，但裁掉嵌套字段说明和条件 schema；关键说明放到可达的顶层工具描述。
- 使用生产同款模型 GPT-6.1-Sol / high，自然语言规划产生 9 次成功动态调用，无失败；原始背景、设计与后续评审阶段、唯一关联任务及 report/files 交付全部保留，未产生执行 run。此前测试暴露的 scope 数组错误已保留为诊断与回归案例，不将其计入成功结果。
- 独立 review 未发现需要修复的问题；数据库、runner 协议和既有合法请求语义不变。
