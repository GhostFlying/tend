# F7 独立评审修复计划

依据 D69、D70，修复评审发现的四个可复现边界，保持现有 owner API 和依赖不变。

1. 为失败的 snapshot、会话和详情读取保留待重试状态，使用有上限的退避；SSE 每次恢复也重新读取视图。串行合并最新会话读取，关闭连接时取消重试。
2. 独立保存连续历史的分页边界。旧消息状态事件仍可更新记录，但不能改写向前翻页的游标；滚动锚点使用连续历史边界。
3. 最新页全是工具或排队消息时，按现有分页 API 继续向前找到最近一条非排队的 owner 消息，保留进行中消息和停止入口。事件更新继续覆盖读取到的状态。
4. 对详情的最新 run 使用现有日志长轮询，按游标更新有界尾部；切换任务或 run、关闭详情和停止连接时取消，失败时有限退避，终态停止。

补充读取失败恢复、分页间隙、长回复停止入口和长轮询取消的回归测试。运行 `make check`、差异检查和生产构建的浏览器重现验证。真实设备验收继续由 F8 负责。
