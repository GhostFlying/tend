# 任务创建、阶段收尾与异常恢复

实施依据：已批准的整体修复计划。保留任务与原工作区，通过正式用例修正账本；不以长时间无输出判断失败，不自动关闭工作项。

## L1 创建与证据契约

- 增加服务端调度要求 `requirements.host_id`，校验注册状态及 reuse 宿主，旧 runner assignment 不携带此服务端字段。
- 验收读取返回 acceptance_id；参数拒绝提供字段、合法类型及修正提示，保留失败调用身份。
- 创建前核对阶段已有执行，冲突回读，不以标题强制去重。

## L2 阶段核对

- 完成事件产生持久待核对事实，工作项更新用真实证据收尾，核对失败保留可见状态。
- 执行状态独立于阶段计划：已完成、取消、排队及恢复如实呈现，保留待评审和服务责任。
- 历史整理经正式工具执行，不修改原验收或取消记录。

## L3 异常与恢复

- 从匹配根会话轮次的明确失败识别异常，不把 TUI 存活等同执行中；核对后台操作后处理。
- 每 run 默认一次可配置自动恢复，journal 持久保存次数及会话身份。加密历史错误使用新会话和结构化交接。
- 未确认副作用先对账；暂停、取消、人工接管停止恢复；恢复失败进入既有失败/待决流程。
- 复用 Orca 生命周期事实，必要修复按其 fork 规则独立发布，不重启无关终端。

## L4 发布与现场恢复

- 各批次定向测试、完整 make check、独立 review、CI 后 rebase 合入。
- 兼容旧 runner 与历史数据；迁移只追加，不兼容通信遵守 N/N-1 退役规则。
- 发布后整理已验收阶段，保留开放后续责任。恢复原部署前核对批次、旧会话及后台工具，沿用现场，不部署旧版本覆盖新机制。
- 独立核验线上版本、页面、会话和任务连续性；清理本轮自有测试资源。

## 验收

覆盖指定主机与离线排队、reuse 冲突、旧 runner 投递、读取验收到阶段收尾、重复完成事件与失败更新、历史阶段和混合任务状态、根轮次失败/TUI 存活、旧轮次与子 agent 隔离、一次恢复及重启去重、未知部署请求不重放。

## CI 租约故障测试诊断

- 核对心跳中断测试中持久 attempt 与实际 worker 启动的先后关系，区分重复业务执行和启动前自我 fencing。
- 在确定性故障注入下重现 CI 的额外 attempt；若属于测试的时间假设，改用明确故障边界控制，保留同 run、同 thread 与单次恢复的实质断言，不单纯放宽数字或延长等待。
- 为租约中断及 takeover 回执丢失测试增加失败时的账本、runner journal 与控制状态诊断；不输出完整任务内容或凭据。
- 定向 race 多轮通过后交由独立 review 和全量检查，生产租约语义保持不变，除非证据确认实际缺陷。
