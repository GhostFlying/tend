# 运行环境与健康诊断可靠性

## 业务目标与边界

本片覆盖 R4、R12、R14。R4 最终决定为每六小时执行一次所选 skills/plugins 的单向完整同步，不另做变化探测或增量安装清单。下一次时间从本轮完成后计算；无变化时复用内容寻址快照，包内修改在下一轮传播。显式同步立即执行。同步仍完整复制、校验并保存不可变快照，保留 allowlist、回滚暂停、执行 pin 和原未结请求对账。

原生会话复用必须核对工具定义身份；旧身份未知或不一致时，通过既有停止与未知动作结算边界切换新会话，并从持久上下文重新建立输入。Task、Run 和历史 rollout 保留。不得把旧会话菜单当作当前 handler 契约。

升级健康继续要求原有安全门槛，分别报告进程身份、服务 ready、排空、服务端确认及失败原因。阶段耗时用于诊断，不作为削弱安全条件的理由。历史健康超时没有唯一已证实原因，本片不重写历史归因。

## 实施步骤

1. R4：复用完整 materialize 与验证，去掉自动同步前的 sourceStamp 检测和仅为候选 ID 运行的 plan。默认六小时，完成后计算下次运行；已明确配置的旧周期仍需部署时调整。
2. R12：追踪原生 worker 的创建、恢复和执行元数据，把工具 schema 身份纳入复用判定；用正常上下文及停止对账路径验证不兼容切换。
3. R14：在升级健康 DTO、权威控制入口及更新器操作记录中加入独立事实和阶段时间，保持旧字段和可选兼容。
4. 每片执行有意义的定向测试并原子提交；设计与生成文件变更说明交给统一集成者。

## 验证契约

自动同步每轮仅准备一次快照；验证稳定内容复用、包内修改传播、完成后计时、未选择包不引入、失败与 pending/rollback 保持原身份和快照。原生工具身份覆盖匹配、未知、不匹配和完整上下文。健康覆盖 ready 与 drain 分离、身份失败、权威失败及阶段时间，安装门槛保持。
