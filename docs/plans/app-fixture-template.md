# App 测试空库模板

Refs: D130。

## 问题与范围

App 业务测试的 `newHarness` 每次从零执行全部数据库迁移。race 模式下，重复的 SQLite schema 解析与迁移占用了大量时间。局部对照中，复制已迁移空库将简单测试的 race 耗时降低约 90%，完整普通 App 测试耗时降低约 64%；这些是本地样本，不代表最终 CI 收益。

本次只替换 App 通用夹具的建库方式，保留已落地的 race 分片，不改变生产 `store.Open`、迁移文件、业务断言、协议或其他包的夹具。

## 实施

1. 每个 App 测试进程通过真实 `store.Open` 生成一次当前版本的空库。关闭所有连接，确认没有未回写的 WAL，再读取模板字节并删除生成目录；模板仅在当前进程内缓存，不写入仓库或跨运行缓存。
2. 每次 `newHarness` 把模板复制到独立临时目录，再通过真实 `store.Open` 打开。连接、原文件目录、时钟、ID 和配置初始化仍属于各自的测试。
3. 专门构造旧库、验证迁移或重新打开数据库的测试继续调用原入口，不通过模板绕过目标行为。模板保留真实迁移产生的 schema、触发器和初始行，不维护第二份建表 SQL。
4. 模板生成失败必须使测试失败；复制不能使用共享可写库或硬链接。使用 `sync.Once` 发布只读模板，避免并发创建夹具时重复初始化或读到半成品。

## 验证

- 对比真实新库与副本的完整 schema 和迁移记录，验证数据库完整性及外键一致性。
- 在一个副本中写入数据库和原文件，确认其他副本及后来生成的副本都不可见；并发创建副本也保持隔离。
- 运行定向 race、正式 `make check`、CI 和规定的独立 review。CI 必须继续覆盖所有 App 顶层测试根；不以删减用例或移除 race 换取提速。
