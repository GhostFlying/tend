# Issue 状态与子 Issue 进展可见性

## 目标与边界

修复已开始推进却仍显示“待推进”的 Issue，并按已确认的设计在顶层看板卡片展示直接子 Issue 的进展。负责人后台任务的运行事实合入属性中的负责人，不再作为独立首屏区块。保持 Issue、执行事实和正式完成/取消的边界；本计划不包含生产部署。

## 实施

1. 在用例层对实际执行与负责人派发子责任维护进行中状态：仅提升 active、assignment_state=active 且默认/显式 todo 的 Issue，沿父链提升同样符合条件的父 Issue。保留 backlog、待检查、暂停、交接和终态；所有 revision、事件、通知与请求在原事务内提交。普通负责人领取、聊天和等待不算工作开始，结束一轮不回退状态。补充负责人指令，要求开始推进时显式维护工作状态。
2. 看板增加可选的直接子 Issue 只读摘要：总数、完成数、实际执行中的数量，以及有界、按活动优先排序的子 Issue 预览。正式完成只计 closed，取消单独表达。执行事实由服务器汇总，优先沿 run_issue_responsibilities 归属验收等显式责任，保留主任务归属回退，区分父自身和子 Issue；不把负责人协调任务计为工作执行。摘要预览不完整时，通过已有、带分页的子 Issue 列表展开，避免每张卡片预取。
3. Web 保留六列看板及已有阶段摘要；子 Issue 区默认最多展示两项，突出当前活动、标题可进入子 Issue，展开完整列表。无子 Issue 时不渲染标题、分隔线或空占位。负责人属性显示简短的后台任务状态、异常与“查看运行详情”入口，移除独立“负责人运行”标题和笼统的“正在处理本 Issue”。
4. 通过现有 issue list --board / issue show / issue list --parent 完成 CLI 读取和分页；更新人类可读输出、帮助与能力说明。只新增可选 owner 读取字段，不修改 server/runner 通信，不升级协议。
5. 添加事务/回放/干预保护、父子聚合与 CLI 真实入口回归；使用现有浏览器 fixture 验证卡片展开、子 Issue 跳转、无子 Issue 隐藏、负责人状态及桌面/手机布局。Browser plugin not available，使用 Playwright。

## 验收

- 父 Issue 开始实际执行或派发子责任后显示进行中，等待子 Issue 不退回待推进；普通协调领取/聊天不自动升状态。
- 顶层卡片说明哪个直接子 Issue 正在执行；父执行统计不混入子执行；无子 Issue 不出现空区块。
- 子 Issue 列表可分页查看，CLI 与 Web 的数量、状态和身份边界一致。
- 负责人异常、恢复、待对账和队列原因仍可见，运行详情可进入。
- make check 通过，独立 codex review 完成，按线性分支提交 PR；合并和部署分别报告。

## 合入验证

- 浏览器返回任务页时，执行记录卸载早于任务数据重新读取完成。CI 的执行记录回归需等待任务内容可见，再校验任务地址，避免用即时可见性断言误判正常异步加载。
