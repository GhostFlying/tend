# 维护装配测试的阶段预算

状态：外部维护已完成最小测试修复、独立复核及两个真实装配用例的单轮 race 定向检查；待原任务应用到实际候选并完成最终整体验证。未修改生产行为，未完成合入或部署。Refs: D155、D180。

## 问题与证据边界

两个维护装配测试先创建空库、执行真实迁移并写入已有任务、未知执行、固定配置和待核验事实，再关闭数据库。随后生产 `Run` 重开同一账本，验证维护准入、真实健康状态、独立更新器回执、账本关联及原执行保留。因此空库构造是测试准备，实际场景是已有账本的维护恢复。

原测试将两者放在同一个 25 秒 context 下。一次完整检查中，准备阶段仅打开数据库就耗时约 19.48 秒，生产初始化结束已到约 22.02 秒；一次两秒 HTTP 超时和重试后，场景因总 context 耗尽而失败。同轮另一变体的数据库准备更慢，但后续操作较快而通过。另一次隔离 CPU profile 证明迁移和 schema 解析占显著成本，未证明原完整检查中额外耗时来自 CPU 竞争、I/O 或调度。

不能用隔离成功覆盖原失败，也不必为修正已证实的阶段边界混用而推断未知环境原因。现有场景断言不验证从空库启动生产服务的耗时，不替代专门的迁移和首次初始化测试。

## 最小实现

1. 真实账本准备单独设置 25 秒期限，保留 fresh `store.Open`、完整迁移、所有种子和实际关闭，不改用预制账本或共享可写数据库。
2. 准备完成后创建独立的 25 秒场景 context，覆盖生产 `Run`、真实重开、准入隔离、健康采样、独立回执关联和原执行保留；HTTP 请求期限继续为两秒。
3. 父测试为隔离子进程设置 55 秒总期限，包含两个阶段及五秒退出余量，避免清理或子进程退出无限等待。准备和场景错误分别说明所属阶段。
4. 如实记录测试整体允许时长由原单一 25 秒窗口变为两个至多 25 秒的窗口；不声称原总预算完全不变。任务另外指定的 Sandbox 十分钟、模拟 429 九十秒和 resolver 五秒预算保持原样。
5. 不改变生产默认轮询、维护状态机、进程身份核验、readiness、请求去重、CAS、未知结果或已有历史。修复只有测试与计划，不需要业务协议、数据库迁移或运行时发布。

## 验证与交接

- 在维护源码上运行两个真实装配测试的定向 race 检查，保留逐例日志、实际退出和源码差异；核对 fresh 迁移及全部业务断言仍在原路径。
- 独立检查阶段 context、取消与子进程总期限，确保正常场景不继承已经用掉的准备预算，也不因重新计时掩盖准备超时。
- 将精确修复和证据交回原任务责任链，应用到实际候选并由 Tend 完成最终完整检查和原 reviewer 复验。维护源码的定向通过不算 Capability 整体通过。
- 所有原失败、历史验收、未知结果及停止证明保留；不重复原问题答案、不重建替代任务或直接改写账本。

维护源码的两个根用例均实际通过，包级 race 检查退出 0。此结果只验证本次阶段边界修复，不覆盖 Capability 候选、远端 CI 或业务验收；没有据此重跑另一轮外部完整检查。
