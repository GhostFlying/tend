# 复用冲突 index 的基线采集

沿用 D78 的保留工作区与继承变更授权：报告任务及明确授权继承的提交任务可以检查和解决已有冲突，采集基线不得改变真实 index 或工作区。

先读取 Git 的 NUL 分隔 stage 清单。存在未合并条目时保存各路径、mode、对象 ID 与 stage，不要求真实 index 形成 tree；正常 index 继续记录原有 tree。工作区内容仍经已有临时 index 快照保存。状态读取禁用可选 index 刷新，其他 Git I/O 错误直接返回，缓存基线与提交继承授权保持原规则。

用真实 UU 冲突覆盖报告复用及授权提交复用，逐字节检查真实 index、冲突文件与其他继承文件未变化，并检查 stage 对象内容、缓存稳定性和未授权提交拒绝。定向故障覆盖 Git 读取失败不会误当冲突成功；执行 gitws race 与 vet。

Review7 补充：原任务升级后的首次基线采集需将审查起点与物理快照 HEAD 分离，持久化 task_base；同任务非 reuse 沿用原始 Base，后续缓存读取、worker brief 与验收指南保持该起点，Collect 仍比较原有物理记录。新 reuse 仍以接管时 HEAD 开始。Git 基线改为同目录临时文件完整写入后 rename，失败清理临时文件；通过独立子进程文件大小限制重现部分写失败并确认恢复后能重新准备。
