# Runner 离线执行与异步回传

目标是让实际持有 Run 的 runner 在控制服务网络中断期间完成原任务，包括同一目标的后续 turn 和已委托的外部操作。普通执行、验收与 Issue 负责人共用这一约定。需要共享账本或集中后端的动作等待真正依赖的服务。主干合入为交付终点。

## 第一张 PR：原件与同步

执行节点在原 Run 的 journal 中持久保存完整已采集事件，长正文使用不可变原件。传输按序、有界、可恢复，以服务端持久回执清理本地原件。展示独立消费，依据各阅读入口生成预览。服务端已收齐、展示已消费和业务命令已结算分别记录。旧记录只有在证实原件匹配时才能补齐。

覆盖单条超过历史 256 KiB 与 4 MiB 限制的输出、断开传输、丢失最后回执、进程重启以及停止后乱序到达的事件。断开服务端消费者不应结束本地会话。原请求实体和未知外部动作必须可继续对账。

## 第二张 PR：本地执行与观察

在新通信代次把分配、输入、能力、执行后端、工作区独占、版本和责任归属冻结在原 Run。runner 持久接收输入后驱动整个 Run，独立发送进展与结果。心跳表示联系新鲜度。控制意图在送达时本地执行，停妥须有实际观察。旧进程可能仍在写时保留独占。断联重启时凭匹配的 journal、原生进程和动作证据接回或安全继续，未知操作按原身份对账。重连时核对原控制和遗漏事实；晚到结果不能推进已撤销的工作。保留维护、暂停、接管、独立验收和真实权限语义。

升级到协议 7，兼容协议 6，拒绝协议 5 在线通信，保留历史持久资料读取。Owner API、CLI 与 Web 同时提供最后联系、最后进展、控制请求及证实状态和已知同步缺口；正常外部等待保留原因。已有完整 Worker 消息展示工作按实际主干复用。

## 端到端验收与交付

断开 runner 到 Tend 的网络，跨过旧租期，在同一 Run 内完成测试失败、修复、测试通过和创建 PR；重连后一个 PR、一次结算、原文完整。分别在原进程仍活、已停和副作用结果未知时重启。覆盖停止与 PR 回执逆序、ACK 等写连接超时、无 thread 的断连、独占不双写和无关工作继续。使用隔离的依赖及可注入业务时钟。

每张 PR 依据最终候选执行必要本地检查、独立 review 和必需 CI；协议候选执行完整检查，故障用例新鲜运行。按当前主干和精确 head 完成受保护的 rebase merge，读回合入结果。生产部署属于单独操作。
