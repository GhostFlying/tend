# TraeX 终态限流的有限恢复

## 问题与范围

TraeX 的已结束根回合可能把流内限流报告为 `other`，Orca 因而投影为不可重试。原生请求重试结束后，Tend 没有进入既有的同 run 恢复路径。本次修复只覆盖已观测的 TraeX 终态格式，不把普通聊天文案或所有 `other` 错误当成限流，不更换 provider、Agent 或工作区，不重放已经停下来的生产任务。

## 实施步骤

1. T1：在原始 JSONL 读取边界增加窄适配，仅接受 Trae provider、TraeX 来源、精确的终态限流错误和原 session/turn；显式鉴权、额度及其他错误优先，普通 assistant 文本不参与分类。
2. T2：Orca 的原生根回合必须已失败、操作已收敛且身份有效；只有 `other` 可用同 turn 的完整原始记录补足限流证据。保留原来的上下文损坏恢复路径、接管和 unknown 围栏。
3. T3：沿用原 run 的一次持久恢复预算；限流续接前等待 30 秒，冷却截止时间写入现有 worker journal。重启不重置时间或预算，取消可立即打断；发送前重新核对原回合和外部操作。只在原会话继续剩余工作。
4. T4：用真实终态格式的替身测试复现并验证；覆盖消息伪装、错误版本、未完成工具、未知状态、重启、冷却及预算耗尽。执行完整检查、规定的独立 CLI review、PR CI 和线性合并。

## 设计与兼容

补充 D138，沿用 D120/D128 的恢复责任边界。无新增 runner 必填字段，wire 保持 2/1；journal 仅增加可选的冷却截止时间，旧记录缺省为无冷却。等待期间仍保留现有 worker 租约及工作区围栏；本次不扩展共享 provider 调度、跨任务冷却或全局重试控制器。owner 在恢复不可用或耗尽后处理业务决策。
