# 复用历史交付结算用例的准备账本

历史交付结算的负例每次通过真实命令重建同一合法责任、交付与安装历史。现有 App CPU 采样显示这些重复准备是该用例的主要耗时。只在该组用例中通过真实命令准备一次账本，关闭数据库并为每个场景复制完整私有目录。每个场景仍使用独立时钟、ID 生成器、Go App、SQLite 连接和原件目录。

坏事实注入与结算命令继续逐例执行，保留各场景的原断言。先在一个独立副本中验证原始历史能够真实结算，防止副本初始化问题导致所有拒绝断言失去检错能力。其他从空库到结算、服务和 runner 恢复、权限变更用例继续沿现有路径运行。

本地用新鲜 race 校验原负例及正向对照，分别记录旧候选、独立原型和可交付候选的执行耗时及覆盖。
