# Issue 上下文、审阅与交付效率统一改进

状态：实施中。本文合并本轮复盘确认的问题；源码修复、独立审阅、合入和部署仍须分别取证。
设计基线：D186、D192、D193；本批决策：D194。沿用已落地的 PR 共享审阅、负责人判断、合并事件通知、
普通材料读取及历史交付结清，不重新实现这些机制。

## 目标与边界

让程序准确提供事实变化和已有证据，让 Issue owner 判断变化的意义、验证是否可复用及下一步工作。
减少重复模型请求、重复正文、同候选重复检查，以及维护发布造成的反复协调。
缓存输入、未缓存输入、输出、模型请求数、检查耗时分别观察，不用累计 token 总量代替成本结论。

本计划覆盖六项：巡检执行原则、上下文分页、增量上下文、交付粒度的共享 review、实现检查证据复用、
整批维护交付。后两项共用一条证据链，不各建新的审批或结果账本。
当前独立 UI 待办继续按其原责任处理，不转移到本维护批次。

用户已选择上下文一期先做增量读取：保持模型、思考强度、原有登录/provider、并发和现有压缩机制。
不增加每轮摘要 Agent、固定上下文长度限制、自动换 Session、成本触发的 blocked 或新的维护调度状态。
真实用户限制、仓库质量规则、请求身份、具体副作用的并发控制及 unknown 原事实继续保留。

## E1：巡检由系统守时

- 这是维护执行约定，不扩展 Tend 为通用 Codex 调度产品。将“不用模型反复 sleep 等下一轮”的原则
  记录到用户明确授权的长期记忆；后续确需定期检查时，由系统定时器或已有事件机制唤醒一次性检查。
- 每次检查只读增量、产出结果后结束；协调者按约定汇报，包括用户要求的无变化状态。
  原巡检保持停止，本计划不新建或启用定时任务。
- 如果当前环境没有可用的定时唤醒入口，明确报告该限制，不以循环模型调用代替计时器，
  也不把尚未验证的后台唤醒称为已经可用。

## E2：修正上下文工具的分页契约

- 为 `issues_context_read` 使用专用参数定义，不再把其他读工具的字段一并作为可用参数暴露。
  对该工具历史暴露的 `after`，保留数值字符串的兼容别名并规范化为 `after_source`；
  两者同时提供时只接受相同位置，冲突给出明确纠正信息，不能静默忽略任意一个。
- 新工具目录推荐 `after_source`，结果显式回显已应用的位置、下一页位置及 `more`。
  `after` 原本就是当前公开参数，本次恢复其正式别名语义，不引入旧 runner 协议适配器。
  新模式为可选读扩展，工具目录沿既有 hash 更新；未来若撤销别名，须另行明确迁移，不能静默删除。
- 相同有效游标再次读取允许得到同一页，并保留相同内容身份；不伪称读取已前进或已审阅。
  owner 指引要求遇到相同位置、相同内容无进展时检查返回的下一页参数，而非反复原样调用。

## E3：保留稳定会话，提供真正的增量上下文

### 读取接口与内容

- 现有 `issues_context_read` 和 owner context API 增加可选 `view=incremental`、`cursor`、`limit`。
  对应 CLI 为 `tend issue context <id> --view incremental --cursor <cursor> --limit <n> --json`。
  未选择新模式的调用保持原有响应语义；新模式不混用旧 `after_source` 来源分页游标。
- 新模式默认每页 50 项、最多 100 项。响应标明 `kind=snapshot|delta`、读取截止位置、
  `more` 和下一游标；游标是不透明、绑定 Issue 与读取范围的只读位置，不授予权限。
  工具、owner API、CLI 共用同一投影与分页语义。
- 无游标时返回当前工作视图及分页的有效事实/来源索引。工作视图从已有 Issue、Task、delivery、
  review、Attention 和进度说明生成：目标、有效约束、当前执行/候选、未决问题、unknown 和证据引用。
  不添加必须由 owner 维护的新摘要字段，不调用模型生成这份视图。
- 每页返回当前 `context_revision`，来源索引提供本 Issue 的待审义务、实际准入及内容/关联版本，
  使负责人能从增量结果准备既有来源审阅，无需为取版本额外加载全量上下文。元数据仍是当前事实，
  并发变化沿原版本校验纠正；新会话也能发现未结义务所指向的已解除关联来源。
- 后续请求只返回所覆盖区间里的对象变化及必要的当前值/原件引用；每个事实只在其对应页面出现，
  不随每一页来源重复附带全量 facts、旧候选长说明或报告正文。
- 修改旧消息、撤回、解除关联、事实替代及项目/全局有效约束变化都必须被覆盖。
  变化来源使用现有持久事件、修订和当前记录，不只以消息创建 seq 过滤。
  同一对象的多次变化可合并为带实际版本和来源引用的最终状态，原事件仍可查。
- 交付责任变化覆盖真实写入路径：接受或合法免验收的完成 hook 新建责任、live prepare/update、
  创建执行 Task 后的绑定，以及 decision defer 的直接更新。同事务仅对实际变化追加已有
  `issue.delivery_updated` 的来源 Task、责任版本和状态明细，不以普通 Issue 进度重发所有责任。
  Task 条目复用规范执行事实与排队原因；最后解除 review 关联时返回撤回索引，仍有关联则读当前引用。
  普通材料和直接 review 查询使用相同的同项目可读范围，原件引用必须能沿原读取入口实际取回。
- 游标携带可确定的读取截止，翻页期间新变化进入后续区间；不能靠移动截止跳过变化。
  截止限定事件区间；返回对象是读取时的当前版本，可能包含截止后的修改，这些修改仍在后续
  区间再次报告。现有对象表不承诺历史时点快照，不为此新建全对象版本账本。
  旧游标过期或读取范围变化时明确要求重新取得快照，不以空 delta 冒充已同步。
  权限撤回后的变化只暴露当前允许的撤回事实，不继续返回已不可读的正文。
- 完整报告、原始消息、文件和历史版本继续通过现有材料/原件入口按需读取。
  已有任务明确冻结的完整阅读要求保留，不以新默认改写旧合同。

### 会话与通知

- 固定指令和工具定义顺序保持稳定；运行时变化在后续 turn 输入中追加，不反复改写静态前缀。
  同一合法绑定正常续接原生 Session，不为每轮优化主动重建。
- owner 默认使用增量读面，并沿现有会话保留读取位置；不创建跨 runner 的全局消费游标或调度状态。
  新 Session 读取当前快照、有效约束和未决事项，再按需恢复原件，不强制扫描全部历史对话。
- 仍通过现有事件窗口合并通知。Issue 的变化不能因为被程序判断为“不重要”就丢弃；
  owner 决定它只是状态变化，还是需要修改实际任务。读取游标不替代 source review、承诺或授权。
- 工具目录更新引发的必要交接沿已有机制完成一次；其恢复开销单列，不当作日常增量成本。
  不重新搭建通用摘要或 handoff 状态机。

## E4：以真实交付物安排共享 review

- 复用已有 PR 身份、贡献 Task 链接、唯一正式 reviewer、结果导入、适用性判断和聚焦复查。
  补齐 owner 默认指引：可在候选已有时尽早准备 draft PR 并关联本次交付，使一次真实整 PR 审阅
  同时服务于关联责任和仓库要求，而非每个中间 Task 各做一份完整源码审阅。
- PR 准备、状态核对、中间报告默认由 owner 判断是否自查；不按阶段名称自动创建新的报告 Task、
  独立验收或交付许可步骤。已有明确的人类验收要求和冻结任务保持原样。
- PR 创建前已有审阅时，只有其真实候选和范围覆盖完整交付，才能沿现有入口复用。
  证据不足由原 reviewer 补齐或聚焦复查，不由 owner 将普通 Task passed 改写为整 PR passed。
- 不给 reviewer 添加硬轮数上限；修正集中交回原 reviewer，后续审阅范围由 owner 和 reviewer 判断。

## E5：reviewer 默认感知并评估实现者的检查证据

- 当前 submitted artifact 已携带实现报告、文件和检查回执；保留这条路径。
  新增只读的“已有检查证据”索引，按当前候选组织关联实现产物的身份、报告与文件原件引用。
  命令、结束结果、head/tree/base、环境、日志、skip 和未覆盖项由 reviewer 读取原报告核对；
  不从普通叙述猜测标准化检查结果，缺失字段如实显示为未提供。
  索引有明确上界与截断标志，完整贡献链接及 Task 历史仍可继续发现，报告正文不随每页重复注入。
- 原 Task 验收从本 Task artifact 获取；共享 PR 的报告型 reviewer 同时能发现关联贡献 Task 的
  对应证据。复用现有不可变 artifact/report/files 和 Issue 材料读取，不新建强制检查回执提交协议。
  普通报告、缺少标准化字段或不同日志格式不能成为禁止 review 的新门槛。
- 索引的可读性与原件引用使用同一个实际授予上下文：原件共享给相关 Issue 时，读取引用选择
  该既有接收方，而非猜测当前 Issue 或原件所属 Issue。核对当前、祖先及相关同项目接收方的
  实际原件读取和撤回，不新增分享、凭据或授权；可发现不应生成无法执行的取件引用。
- reviewer 先评估候选是否对应、证据是否可信、覆盖是否足够，再选择直接复用、定向复现或完整重跑。
  复跑时在审阅报告中解释原因；这不是需要另行批准的动作，也不强制填写后才能调用测试工具。
- 正常实现指引继续要求实现者完成适用检查；独立性由 reviewer 自行判断代码和证据体现。
  不默认把独立审阅解释为再次执行所有已通过的检查。
- 候选、代码或相关环境变化后，由负责人和 reviewer 判断需要补哪些验证；
  最终候选仍满足仓库要求的完整本地检查、独立审阅、CI 与保护规则，不拿实现者本地通过冒充 CI。

## E6：统一验证、发布与当前状态索引

- 本批使用一份主计划和一条交付链；子项定向验证完成后冻结组合候选，集中进行最终完整检查、
  一次正式整 PR 审阅与必要的同 reviewer 修正、最终 CI、线性合入、不可变构建和受控部署。
  不为每个 E 项各开独立发布流水线。
- 集成场景贯穿当前事实/材料读取、执行产物和检查证据、共享 review 复用、授权交付、
  实际安装与历史结清；期间插入一次独立维护版本推进，确认已完成历史仍能凭原事实结清。
  使用隔离的 fake provider/harness/安装回执；不新增真实生产部署或模型调用作为单测条件。
- 发布后只向相关责任发送一次结构化差异说明：哪些事实/工具改变、哪些原工作可以继续、证据在哪。
  仍由 owner 判断实际影响，不用说明文字取代适用的真实交付授权。
- 私有执行记录维护一个当前索引，连接修复项、PR/候选、release、实际安装回执和剩余事项；
  更新当前索引，不覆盖历史失败、unknown、原截止或旧回执。公开文档只保留一般机制和发布事实。
- 复用现有 usage/诊断记录观察请求数、输入/cache/output、工具结果体积和检查耗时；
  业务执行、owner 协调、review、外部维修与巡检分开归因。外部未采集费用不冒充零，
  报价估算不当作订阅实付。不新增成本审批或自动阻塞规则。

## 回归与验收

| 范围 | 必须成立的场景 |
|---|---|
| 分页 | 历史 `after` 别名实际前进；新 schema 推荐正确字段；冲突位置明确报错；同页身份可辨识；完整翻页无遗漏/重复。 |
| 增量 | 首次快照、无变化空结果、新增/修改/撤回/替代、项目与全局变化、同对象多次变化、翻页期间并发变化、游标过期及权限收回。 |
| 体积 | 固定 facts 配合多页来源时，facts 不随页数线性重复；大历史不默认附带全部旧候选和报告正文，原件始终可发现。 |
| 续接 | 正常同绑定继续同 Session；工具目录必要迁移保持既有边界；新 Session 能从 Issue 恢复目标、有效约束、unknown、待办和证据。 |
| 共享 review | 多 Task/子 Issue 的同一 PR 复用同一真实结果；非整 PR 旧结果不能冒充覆盖；新增证据交原 reviewer；普通报告不强制增加验收。 |
| 检查证据 | 验收型及报告型 reviewer 都能看到对应实现产物的检查记录；缺字段可继续判断；相同候选可复用，有新变化可选择复跑并留下理由。 |
| 全链路 | 从增量事实到交付/安装/结清，保留真实失败与 unknown；后续维护推进目标版本不使已验收历史失效。 |
| 接口覆盖 | owner API、CLI、工具、生成 schema/类型及能力目录一致；旧读模式、旧冻结 Task 和现有 runner 协议保持兼容。 |

固定行为回归使用 fake 和已有脱敏轨迹，不重跑原业务或付费模型。
运行收益在后续正常授权任务中观察，按相近工作阶段比较，单列一次性交接、缓存失效和额外回读。
本期不承诺把现存长上下文立即变短；验收先看冗余正文和无用请求是否减少，再看实际费用与延迟。

## 实施顺序与完成定义

1. E1 记录维护原则；完成 E2 及其协议/兼容判断，建立不会静默卡在同一页的读取基础。
2. 完成 E3 的统一投影与分页，再接 owner API、CLI、工具、启动/恢复入口和对应指引。
3. 组合 E4/E5，使一次交付的 reviewer 能发现、评估和复用实现检查证据。
4. 完成 E6 全链路回归、设计更新、生成代码与整批交付；分别记录 source、审阅、合入和安装结果。

实施前基于最新 main 再核对真实源；保留工作树中无关编辑。设计变化随实际行为提交更新并引用新增决策。
默认采用可选读接口扩展，不修改 server/runner 通信语义或 runner journal；若实际实现需要改变通信，
必须按 N/N−1 规则在本批解决，不能用任务版本或工具说明替代协议兼容。
部署保持已确认的 Agent/slot/model/effort/auth 配置；如确需变更配置，再按用户既有核对原则处理。
本计划写入不等于产品实现或部署完成，也不重新开启已结束主线或已停止巡检。
