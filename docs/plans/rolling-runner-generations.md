# 滚动升级与历史 runner 通信

目标是让有活跃 Run 的主机在升级期间继续工作。完整发布集仍固定源码与产物哈希，跨版本窗口按通信协议代次计算。普通 server 切换可等待在途请求及固定租约授权确认，不能以兼容 runner 排空为前提。

1. 按物理主机登记接单与收尾实例，持久保存 Run、租约和实例的归属。切换新领取权时，以事务隔离并发 claim。旧实例继续心跳、控制、回执与结果投递，原 journal 保留至退役。主机容量与工作区互斥跨实例生效。
2. 升级预检覆盖所有未退役实例和未结 Run。目标 N+1 可与 N 通信；仍有 N−1 实例时，在停止 server 前拒绝普通升级。重连和新登记遵守同一窗口，离线不作为实际退出证明。
3. 本机更新器在独立可执行文件和 journal 上启动候选，验证就绪后切换新领取权。已安装的批次可以结算，原实例的退役继续按原身份跟踪，同协议 server 修复可继续部署。
4. CLI 显式强制维护只处理越窗实例，在原排空截止前等待，必要时按精确进程身份停止。确认停止后才切 server，原 Run 的未知结果继续对账。展示影响、原截止和停止结果，回执丢失不重发。
5. 首个跨代组合为协议 6 server 与已发布协议 5 runner。CI 固定真实历史产物及摘要，用同一旧进程领取长 Run、跨 server 切换续租、收控制、提交结果；再验证同机新领取、兼容修复、拒绝越窗和强制维护的自然/超时/回执丢失路径。部署与真实现场验收另行授权。

已发布的协议 5 runner 仅在本地 ready 后向 updater 提交安装。首次在主机引入双实例时允许一次显式本机 CLI 引导，旧进程继续服务原 Run；此后升级由受管 updater 自动完成。

历史通信测试使用固定 Git 提交及 SHA-256 的 Linux amd64 正式发布包。CI 从对应历史源码构建业务输入夹具，以发布的 server、runner、CLI 创建并执行真实 Run。CI 只替换 server 进程，在原账本上断言原租约续期、结果交付与取消。模型由本地子进程模拟。独立的 runner-compatibility 作业按候选 server 的反向依赖及完整验证计划选择，缺失或失败会阻断合入。更新兼容下限时需要同时更新发布基线；本地可用 bash .github/scripts/released-runner.sh 并可传入已下载的同一归档。
