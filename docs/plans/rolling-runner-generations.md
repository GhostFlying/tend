# 滚动升级与历史 runner 通信

目标是让有活跃 Run 的主机在升级期间继续工作。完整发布集仍固定源码与产物哈希，跨版本窗口按通信协议代次计算。普通 server 切换可等待在途请求及固定租约授权确认，不能以兼容 runner 排空为前提。

1. 按物理主机登记接单与收尾实例，持久保存 Run、租约和实例的归属。切换新领取权时，以事务隔离并发 claim。旧实例继续心跳、控制、回执与结果投递，原 journal 保留至退役。主机容量与工作区互斥跨实例生效。
2. 升级预检覆盖所有未退役实例和未结 Run。目标 N+1 可与 N 通信；仍有 N−1 实例时，在停止 server 前拒绝普通升级。重连和新登记遵守同一窗口，离线不作为实际退出证明。
3. 本机更新器在独立可执行文件和 journal 上启动候选，验证就绪后切换新领取权。已安装的批次可以结算，原实例的退役继续按原身份跟踪，同协议 server 修复可继续部署。
4. CLI 显式强制维护只处理越窗实例，在原排空截止前等待，必要时按精确进程身份停止。确认停止后才切 server，原 Run 的未知结果继续对账。展示影响、原截止和停止结果，回执丢失不重发。
5. 首个跨代组合为协议 6 server 与已发布协议 5 runner。CI 固定真实历史产物及摘要，用同一旧进程领取长 Run、跨 server 切换续租、收控制、提交结果；再验证同机新领取、兼容修复、拒绝越窗和强制维护的自然/超时/回执丢失路径。本次验收仅使用隔离环境，合入后不触发 Tend 部署。

已发布的协议 5 runner 仅在本地 ready 后向 updater 提交安装。首次在主机引入双实例时允许一次显式本机 CLI 引导，旧进程继续服务原 Run；此后升级由受管 updater 自动完成。

历史通信测试使用固定 Git 提交及 SHA-256 的 Linux amd64 正式发布包。CI 从对应历史源码构建业务输入夹具，以发布的 server、runner、CLI 创建并执行真实 Run。CI 只替换 server 进程，在原账本上断言原租约续期、结果交付与取消。模型由本地子进程模拟。独立的 runner-compatibility 作业按候选 server 的反向依赖及完整验证计划选择，缺失或失败会阻断合入。更新兼容下限时需要同时更新发布基线；本地可用 bash .github/scripts/released-runner.sh 并可传入已下载的同一归档。

## 第一批：独立升级 server

完整发布集仍是输入。`tend upgrade start --server-only` 仅选择 server 及其本机 updater；默认 fleet 入口继续处理整个发布集。目标 server 通过二进制能力探测确认能接续这个范围。各活跃 host 仍参加协议窗口和原租约的重启授权检查，但不获取 runner 安装目标。批次状态记录所选范围，恢复原主机接单模式后可结算并进行下一次兼容修复。旧批次沿原范围恢复。协议 6 保留已发布协议 5，下一次提升窗口前普通升级拒绝任何已登记的越窗实例，也拒绝在已批准的升级窗口中接入越窗实例。

只在隔离环境验证。测试进程使用临时 HOME、数据库、journal、显式回环地址和测试私有控制 socket。命令测试单独验证选项、请求和输出；业务测试从测试控制接口启动完整包升级，用原 Run／lease 和已验证的进程身份断言长 Run 在 server 切换时仍在工作，并能在切换后续期和交付。测试替代系统服务管理及安装器时明确标记边界。现场服务、真实 tailnet 和生产凭据均不参与。

后续第二批接入本机引导、单接单实例与多收尾实例、可选 tailscaled 旁路和自然退役；第三批处理显式越窗维护、精确进程停止和未知结果对账。

## 第二批：同机滚动交接

同一主机只允许一个接单实例，可同时保留多个收尾实例。相邻协议窗口约束通信代次；连续发布沿用协议时，即使已有两个长 Run 分属不同旧构建，第三个构建也可接单。所有构建共用物理主机容量和工作区互斥。

第一版只支持显式配置的主机 tailscaled 旁路。一次本机引导后，历史 runner 保留自己的 tsnet 状态；后续各代使用本机 tailscaled 的 LocalAPI 拨同一 server。每个 runner 在其整个生命周期沿用选定路径，旧进程退役无需触发网络切回。普通单实例沿用原网络配置。无旁路的内嵌 tsnet 主机不能进行同机重叠启动；这只影响该主机的 runner 切换。

Server 继续校验 host 或 Run 租约凭据，以及 WhoIs 观察到的节点名或 tag。已有 nodes 规则覆盖主机 tailscaled 时直接复用，否则在启用时登记该节点。成功的候选注册和健康确认先于接单权切换；旁路不可用或未获准时，旧进程继续持有原 Run。CI 使用本机 LocalAPI 替身验证传输与原始凭据以及错误可见性，历史 runner 通信使用固定正式产物。SSH 旁路的对端认证另行设计。

## 分批交付与验收

历史通信 CI 先独立合入。后续三个用户动作分别在隔离的测试实例中验收。每次测试创建临时 HOME、runner journal、server 数据库、控制 socket 和测试凭据；本地启动 server、runner 和 updater，绑定回环地址，使用夹具内的完整发布包。旁路测试使用私有测试 socket 上的 tailscaled LocalAPI 替身。测试不读取生产配置，不连接生产 server、主机 tailscaled 或真实 runner，也不执行生产部署。

主验收从测试实例的升级控制接口驱动实际状态转换，记录进程、租约和结果。CLI 参数、请求字段、输出和错误通过独立命令测试覆盖；需要启动 CLI 子进程时，显式传入测试 socket 和临时发布目录。

1. **有长 Run 时单独升级 server。** 在隔离的旧 runner 已领取 Run 后，向测试控制 socket 提交固定完整发布集的升级请求。原 Run 仍活跃时，新 server 必须已经启动并接受原 runner 对同一租约的续期、取消或结果。按协议窗口检查全部存活实例，包含空闲实例；有越窗实例时，普通升级应在停止原 server 前返回具体的 host、instance 和协议。相同协议的修复允许连续进行。验证时记录升级批次、server 进程身份和原 Run／lease 身份。
2. **同机接单、收尾和自然退役。** 在临时主机目录中测试一次性引导正在执行任务的已发布协议 5 runner；后续升级由测试 updater 自动触发。用三次构建覆盖同一机器上两个收尾实例和一个接单实例。有空余 slot 时第三代可领取新 Run；满载时新 Run 留在队列。逐一完成前两代的 Run，核对原租约、产物、对应进程退出以及其他实例继续工作。旁路连接失败时保留原 Run 和 journal；重复升级或 updater 重启后按原安装记录恢复。此批同时接入接单授权、独立 journal、自然退役和退出回执，避免出现能启动新进程却不能回收旧进程的中间版本。
3. **显式越窗维护。** 命令测试验证 `--force-maintenance` 的请求字段和影响展示，隔离集成测试驱动同一控制接口进入紧急维护。验收覆盖已完成工作的保留、立即停止获准的具体进程，以及退出回执丢失后按原身份对账。server 切换以实际退出为条件；未能确认的 Run 结果保留为 `unknown`，避免重做外部动作。兼容实例和已完成 Run 的结果应可继续读取。

本机引导从指定完整发布包启动经哈希校验的 runner 工具，以主机凭据读取本批次的 supervisor 更新目标，再经固定 updater socket 提交同一目标。后继 runner 自动消费相同目标。updater 以已暂存的 runner 程序请求启动授权，沿用其服务配置与网络路径；原 runner 无需实现新操作。退役的停止授权、精确进程退出、服务端确认分别持久化。升级批次可以先于旧进程退役结束。

退役后的恢复沿用原 journal。manager 的只读历史请求需由接单代按原目录打开会话，保持原 Run、消息和回执身份。检查点记录创建它的 journal，预览、校验和清理按该目录验证。整机紧急恢复在停止服务前确认 journal 归属，恢复后的监督器继续使用已提交的 journal 和原退役记录。隔离回归分别覆盖这三个已有管理入口。

## 第三批实现：显式越窗维护

本机 CLI 将强制维护选择绑定到原升级请求与完整发布集。开始事务按目标协议窗口登记越窗实例、原 journal、具体进程和 Run/lease。状态与 CLI 显示影响范围。普通请求保留原有拒绝行为；兼容实例继续工作。

在 server updater 或 server 取得安装授权之前，以独立阶段等待每个已登记目标。立即向持有原进程的监督器授予有期限的精确停止权，监督器先保存授权再发送信号；原进程真实退出后回报。已完成的结果保留，未确定的 Run 以原 lease 进入 unknown 对账。离线、PID 复用与丢失响应均不产生业务成功。重试、取消和重连沿用原截止及授权状态。

隔离验收从 CLI 请求经过控制器和数据库事务至停止授权、退出回执及 server 升级放行，覆盖自然完成、强制超时、响应丢失、重复请求和兼容实例继续续租。测试使用临时数据库、socket、时钟和进程，不连接现场服务。

### 紧急维护修订

显式强制维护在受理事务中关闭越窗接单实例的领取权，登记同机全部越窗实例及原租约。立即向监督器授权停止具体进程，包括唯一接单且正在执行长 Run 的实例。进程只获得短暂的系统退出宽限；仍存活时对同一进程执行强制终止。监督器在原进程退出后独立确认，重启后沿用原授权和停机记录。兼容收尾实例仍需独立确认重启覆盖。离线或缺少退出证据时批次显示具体未确认目标。隔离验收覆盖单接单代、多收尾代、忙闲状态、监督器重启、回执丢失和 server 放行。
