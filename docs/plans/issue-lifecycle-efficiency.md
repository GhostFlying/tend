# 集中修复：任务连续性、可重建上下文与持久存储

状态：实施中。Refs: D219–D224。编码前记录已确认的统一范围。

## 合同

- 系统持久记录足以为所有角色重建业务上下文。Session 可替换；复用只是 token 优化，不是执行前提。不能因不能复用而阻塞正常工作，也不能重放未知外部副作用。
- 同目标复用 Task，实际执行追加 Run；阶段结果、rebase、等待和 session 更换不自动新建 Task。旧产物、接受、版本和执行事实不改写。
- Issue owner 可直接调查和实现，自主选择协作。一个 PR 使用持续的审阅 Task，不为审阅或复核创建子 Issue；收敛后独立审阅，后续只判断实际增量。
- 来源核对并入正常工作，不再要求独立 review/commit 或启动补手续回合。系统只记录实际投递和处理事实，不声称模型已理解或用户已批准。
- 外部等待持久化条件和恢复位置，真实停止后归还执行资源；server 观察、合并并唤醒。无操作截止时间时每二十分钟合并提醒，不制造人工审批或重放未知操作。
- 原 Issue 的明确授权覆盖范围内连续交付，不因候选改变重复索要批准。连接信息和权限独立提供。
- 已交给 Tend 的独立 backlog 保持原归属，不在本批提前启动。

复用已有 Artifact、Review、blobstore、后台事件和调度机制，不建立第二套业务总线。每个变更保持控制 revision、原 request_id、真实 actor、单事务事件/outbox 与物理结果边界。候选变更不是需求变更；普通续行不消耗失败重试预算。

## 上下文与结果

重建内容包括原始背景/输入、需求和授权、当前判断、已有修改/产物、PR/检查/审阅、失败与未知、等待和下一步、真实环境及工具入口。大原件按索引读取；复用 session 注入增量，新 session 可读取完整业务上下文。当前状态来自账本而非会话记忆。

负责人自执行成果归属原真实执行，沿现有产物/贡献/交付记录登记，不要求额外 worker 或虚构 Run。最终报告先讲背景、问题与结果，再提供可展开证据，以成功消息及附件回执为准。后台提示使用当前责任人术语，恢复状态同组汇总并按实际终态退出。调度前合并最新未报告增量，已确认旧通知不再次唤醒模型。

## 存储与性能

命令原文保存一次；请求及领取回执保存引用和当时状态，读取保持原返回语义。原生 rollout 内容进入 server 持久原件，DB 只保存稳定身份、字节窗口、执行索引和必要状态，不再次逐片复制正文。原件先持久化，业务引用在原事务提交。不存在原 rollout 的历史内容保存为独立原件，不能丢弃。

迁移分批、有进度、可恢复；验证回读一致后移除重复正文，备份覆盖 DB 与文件引用。迁移后再受控压缩，分别报告 DB、原件、备份及总空间，不把逻辑模型当物理收益。

计量按原生响应身份去重，完整重扫不重跑业务。分别表达采集生命周期、原件读取位置、已持久化/归属覆盖；未观测和无数据不能假报 caught_up。

在候选收集内部区分 SQL/scan、转换、manager 候选及校验。读侧预筛减少无候选写事务，领取事务重查当前控制、租约与并发事实。普通日志和 ACK 不驱动全量候选重算。对相同历史快照/负载报告 writer 占用、排队和 API 延迟；旧长停顿未定位前保持未知。
