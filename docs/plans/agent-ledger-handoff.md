# 主 Agent 账本协作与交接摘要改造

## 目标与边界

落实 D119（原计划编号 D115 已被并行合入的 owner 补充消息设计占用）：简单委派沿理解请求、创建工作项和任务、回复推进；减少首次 prepare、成功后的版本回读和回复后的关联操作。摘要以原生历史 H、当前有效状态 L 和历史更正 D 为输入，不重放工具读取历史。网关排查不在本计划内。

## 实施顺序

- A1：工具导出展开引用和组合 schema；写入在原事务返回准确版本及剩余义务，去重重放返回原回执。
- A2：initial_context 支持准确来源版本并完成首次准备和审核；conversation_reply 原子提交正文、关联、事实和审核。旧原生文本保留，不能猜测关联或授权。
- A3：分离事实审核、回合运行和派发；已审核的有效来源可在当前回合结束前派发，真正未审核、更正和未知状态继续阻塞。更新生成 API 类型和界面。
- A4：摘要格式 3 在同一读事务冻结 L、D 与水位。L 保存当前有效计划、约束、任务、运行、决定和交付；D 保存更正、撤回、删除和原生历史缺失通知，不带工具输入输出。完成分页，不声称覆盖截断材料。
- A5：预算内一次摘要；预算外先摘要 H，再在全新私有会话合并 L、D，必要时分批并记录覆盖。默认输入目标为 256000 token 与有效窗口 80% 的较小值；缺少 tokenizer 时使用明确标注的 UTF-8 字节保守上界。用量缺失时两阶段。摘要不执行业务或更换活跃主会话。
- A6：输入构造前登记尝试，所有失败遵循持久化 15 分钟退避；隔离分支始终清理，未知请求核对而不盲目重放。旧摘要保留但不作为格式 3 完整覆盖证明。

## 验证与交付

测试覆盖三次业务写入的简单委派、原子性和去重、并发修订、owner 锁定、旧文本、同回合领取、运行后新约束，以及 H/L/D 的更正和覆盖。大量重复工具读取不得增加摘要 L/D。验证一次/两阶段、无历史第二阶段、分批、取消、重启与退避；保持 runner 协议兼容。执行 make check、独立 review、PR CI、线性合入和受控发布；通过隔离任务回读调用批次、领取时点、摘要覆盖与输入量，不重放既有业务。

## A1–A3 的具体契约

初始化可带 `source_reviews`，每条指定来源消息的内容与关联版本。写入前验证版本，整个事务完成创建、来源绑定、七类事实登记、首次 baseline 与准确版本审核。旧的仅 ID 请求继续可用，但不会因此取得新的版本审核证明。重复的有效事实、关联和已核对的 prepare 不推进版本；真正更正必须明确退休或重新确认事实。

所有主协调写入在事务末构造 `receipt`，保留原结果并补充本回合消息、工作项计划和 context 的准确版本、派发就绪状态及剩余义务。请求记录保存该回执，重放返回原值；后续并发修改由 stale revision 要求刷新，无业务变化的主协调写入也保存原回执。冲突提供需要重查的来源版本。

`conversation_reply` 绑定当前 admitted turn，提交正文、progress/final、linked/unassigned、逐工作项预期 context、七类事实检查和新事实或空事实集。先校验全部预期版本，再原子保存正文、关联、事实、审核和事件。助手自述不能变成 owner 授权；owner 锁定标签继续优先。旧原生文本完整保留并承担自己的审核义务；工具发出的正式消息不需要再发原生正文。回复不结束逻辑回合。

事实同步状态只表达初始化与审核。另行展示协调生命周期、派发状态和带对象 ID/版本的阻塞原因。领取事务重新验证相关消息、事实和任务绑定的有效来源指纹；已完成准确审核的 processing 回合可以派发。未分类的 legacy 文本、失效事实、未核对原生执行和恢复状态仍阻塞。

来源事实的指纹与可编辑计划分开：纯计划调整仍执行既有任务 disposition，`continue_existing` 不改写旧任务。来源事实实际改变后，旧协议不能派发；已派发结果仍保存为事实，但旧指纹的产物或验收不能使当前责任完成。沿现有暂停和协调通知路径要求明确修订，不改写原 run、原 spec 或历史验收。

工具导出展开本地引用并在 anyOf 分支保留共同 object 属性；服务端仍保留原校验。事实输入不强迫模型填写服务端分配的字段。project 指登记项目，repo 指仓库；URL 文本和不可变文件 `file_id` 输入分别表达。

## A4–A6 的具体契约

L 从专用结构化查询取得当前对象，不复用展示裁剪的看板：工作项计划、当前有效及待复核事实、未结束任务/run、待决、最新产物与文件/提交引用、验收、交付和跟进责任。关闭对象只保留当前终态与必要交付引用。事实带来源版本；不复制工具输入输出和全部产物正文。所有行和 D 的分页均在同一数据库读事务内取得。

D 根据消息更正/删除记录、来源版本和原生投递记录构造，排除未 admitted owner 输入和普通工具/心跳。无法证明覆盖的相关正式消息只补当前版本并标记不确定。原生正文未改变的标签更正仅补最新元数据并声明 `native_body_unchanged`，不再次重放聊天正文。撤回、删除和内容更正始终能覆盖原生历史与旧摘要。

预算由原生上下文用量和当前有效窗口决定。新增提示优先使用 tokenizer；缺失时明确记录 UTF-8 字节保守 token 上界。单阶段仅在已知用量且 H+L+D 适合预算时采用；其余情况先在冻结历史分支生成 S1，再在不继承历史的新 ephemeral 会话合并当前记录。每批按完整序列化提示重新计算预算，超大对象按有序 UTF-8 片段覆盖；记录批次范围、输入上界和摘要请求校验值。只有全部批次成功才保存格式 3 完整覆盖，任何中间结果不作为覆盖证明。

格式 3 在既有 snapshot JSON 保存来源水位、H/L/D 量、预算、生成方式、分批覆盖及完整标记，无需改变 runner 通信或删除历史。旧摘要仅作参考；原 v2 成功尝试不会永久挡住 v3 重建。输入准备前登记尝试，准备、模型、取消和清理失败均按已有持久退避处理；新消息只使冻结摘要过期，不补入其覆盖。

## 回归与发布门槛

- 三次写入及原回执重放、无变化写入、冲突回滚、七类初始化、助手不能授权、owner 标签优先。
- processing 同回合领取；legacy、事实更正与未知执行阻塞；新来源约束阻塞旧 spec；运行中产物/验收保留但不能完成失效责任；纯计划继续保持原协议。
- 重复工具快照不增加 L/D；旧摘要保留、标签/正文更正与撤回不丢失；分页和大对象无截断；一次/两阶段、干净第二阶段、分批失败不存中间覆盖、准备失败退避。
- 真实 harness 确认模型请求包含嵌套字段，历史 fork 与全新 ephemeral 会话隔离且释放。真实模型在独立账本验收，生产任务和未知请求只核对，不盲目重放。
- 完整 `make check`、独立 review、PR CI、rebase 合入之后，按受控升级流程部署；运行版本、工具/schema、领取时点和摘要覆盖分别回读。

## 核对后的边界细化

执行指纹覆盖目标、约束、授权和拒绝的来源内容/关联版本及失效状态；协调者的回报承诺、问题和建议本身不改变 worker 协议，执行上的变化须按相应事实种类登记。即使没有独立事实行，尚未解决的来源审核也阻止旧结果完成任务。冻结协议不匹配通过回执及视图报告具体 task、spec 和 control revision，供下一次明确修订使用；它不会禁止后台读取者参与核对。

覆盖边界分别记录 conversation 和 ledger 水位，现有摘要/尝试唯一键使用两者单调和。D 的增量与撤回失效判断只比较 conversation 水位；旧格式按原边界解释。当前产物沿任务的有效产物指针读取，较晚到达的旧 spec 产物仍保留为历史，不能冒充当前交付。

原生启动响应到达前的可信工具回调先持久化 admitted execution 的实际身份；这一维护观察不授予新业务权限，也不复活终态/未知执行。摘要启动丢失回执时用私有调用身份核对原执行，已完成结果直接回收；不重复发起模型调用。分支释放未获确认时不认证完整摘要覆盖，并记录持久退避。

工具 schema 的真实传输检查必须断言参数节点的具体类型，不能仅检查字段名出现。当前原生工具解析器在约 5000 字节以上会裁剪深层结构；导出时移除服务端冻结的 observation/upgrade 输入快照，并将仅表达 required 字段组的 anyOf 以单份共同对象及文字约束表达，服务端继续执行完整原始校验。规划工具的结构预算测试及真实 harness 回环测试共同防止 inputs/source_reviews 再次退化为未知元素。

同回合 worker 结果推进同时要求来源事实有效和原生执行已核对：原生回执 unknown 时仍接收不可变产物/验收证据，但不创建后续验收或完成当前任务。普通 processing 本身不是 unknown，也不靠展示计数变化推断执行不确定。

结果推进与领取共用完整的 context 就绪检查，涵盖同回合未关联的正式文本、来源失效、准确审核版本和原生回执。任务控制、动作创建及待决/选择类协调写入也返回统一回执并沿相同规则保留有效审核，不依赖底层操作名前缀猜测工具范围。

与运行中 owner 补充消息联动时，审核及回执归当前原生 execution，audit parent 保留实际 owner 来源；初始化、context 写入和合并回复不把两种身份混用。正式回复在事务内关联该原生执行已接纳的输入，并排除尚未接纳的排队消息；补充来源仍须准确版本审核。

后台批次中的 conversation_reply 同样是明确的即时发布，直接保存可见消息及其关联和审核，不走普通原生文本的延后暂存分支。正式发布会撤销本轮此前的静默选择；之后的静默 check-in 根据持久请求/消息身份拒绝覆盖该发布。未使用正式发布的原生后台文本继续沿原有暂存及结算流程处理，正文保留。

来源审核保留采用统一规则：事务前必须是该 processing 责任的准确版本审核，事务后来源仍全部有效且已审核，才将受影响 context 的审核版本推进到当前计数；不以 actor/操作名白名单判断队列和生命周期变化。owner 面板已应用的单次控制授权保留为证据，且仅在能核对到其成功请求、原始消息、待决和任务时，从持续执行协议指纹中排除；真实新约束/持续授权仍改变指纹。
