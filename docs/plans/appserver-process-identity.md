# 独立 app-server 的进程身份隔离

Refs: D107

## 问题与边界

Orca TUI 中启动的独立 app-server 会继承外层终端的环境。嵌套测试的
hook 因而可能向外层窗格上报自己的会话、提示和完成状态，触发错误的
接管判断。`TEND_ADDON=off` 与单独的 `TRAE_HOME` 不隔离 Orca 身份。

本轮只修复独立 app-server 的启动边界，保留 Orca TUI 自身的正常身份，
不放松真实接管、未知结果或资源释放规则，不修改 runner 通信协议。

## 实施

1. **E1**：在 `traex.Start` 合并继承环境与显式覆盖后，删除全部
   `ORCA_` 环境项，覆盖身份、launch、hook 路由及别名；大小写不敏感。
   独立 app-server 不继承外层 Orca 上下文，其他配置与覆盖语义保留。
2. **E2**：通过真正启动的替身 app-server 验证进程边界。父进程和
   显式覆盖分别注入 Orca 身份及别名，子进程均不可见；普通配置、
   模型 home、认证及环境覆盖保持有效，父进程环境不被改写。
3. **E3**：完成 `make check` 与独立 review，经 PR 线性合入。
4. **E4**：合入后以保留的 run、原生会话、工作区和产物核对误判阻塞，
   只经正式控制接口恢复；使用不可变产物执行受控升级，独立回读
   manifest、运行进程、安装回执、runner 在线及维护状态。

## 验收

- 不依赖真实模型或生产 hook 的进程测试覆盖全部 Orca 前缀，包括新别名。
- 既有 app-server 握手、调用及关闭检查继续通过。
- 不改写活动任务的工作树，不以数据库修改或新 run 清除旧资源占用。
- 真实部署结果与本地检查分别报告；未知运行或升级结果继续对账。
