# 聊天图片与日常界面收尾

状态：已实现（2026-10-24）。Refs: D81、D85、D86。

## 目标与取舍

1. 设置使用同一个面板和入口位置：桌面保留侧栏底部入口，移除聊天页及看板页头的重复齿轮；窄屏保留可直接访问的设置入口。模型 / think effort 仍在输入框，不合并成全局设置。
2. 聊天支持选择、粘贴及拖入图片，发送前预览、移除，可仅发送图片。图片与文字共用一个持久发送请求，离线刷新和未知结果重试沿用原 request_id，避免图片已上传但消息丢失的两阶段状态。
3. 图片使用有界内联上传，服务端在消息事务中单独保存图片字节；会话列表只返回元数据，图片经 owner 鉴权单独读取。主 agent 收到原生图片输入，不能仅获得图片名或网址文字。初版支持 PNG、JPEG、GIF，每条最多四张、每张最多 5 MiB；无第三方图片解码依赖，不接受 SVG。服务端验证文件内容、大小与类型，单图至多 4000 万像素以约束解码内存。GIF 原图用于界面展示，模型接收首帧 PNG 并明确获知首帧限制。
4. 升级横幅只展示仍在进行或需要处理的发布；完成、取消后自动消失。历史结果保留在聊天通知及发布详情，不增加必须手动清除的持久横幅。

## 实施

- I1：调整设置入口及升级横幅终态展示，核对桌面与窄屏可达性。
- I2：新增图片协议、追加存储迁移、原子消息写入、鉴权读取及主会话原生图片传递；更新生成类型。
- I3：输入框附件操作、发送队列持久化、会话与本地回显图片展示；保留无图消息兼容。
- I4：图片请求去重、校验、图片单独发送、刷新重试、原生输入与视图测试；真实模型图片识别 smoke；桌面与窄屏浏览器交互核验。
- I5：make check、独立 review、CI、PR 合入与部署；记录实际证据及未覆盖边界。

## 兼容与验收

图片为 owner API 的可选新增字段，不修改 server / runner 通信语义或协议版本。存储迁移只追加，既有文本历史及 outbox 可继续读取。发送中的图片与文本作为同一请求保留到服务端确认；预览读取失败提供重试，不伪称图片已显示或模型已读到。关闭页面前尚未发送的草稿与当前文本草稿遵循相同生命周期。

验收覆盖：桌面无重复设置且窄屏可打开；升级 active/attention 显示、completed/cancelled 隐藏；图片选择/粘贴/拖入与移除；纯图及图文消息；离线发送后刷新联网只提交一次；另一客户端读取图片；模型能识别受控测试图内容；现有文本、停止回复、任务通知和历史发布详情不回归。

## 实现验证

- 图片存储、owner 鉴权下载、超过旧 HTTP 限额的合法上传、请求重放、无效图片原子回滚、GIF 首帧及摘要覆盖失效回归通过。
- 真实 Gateway app-server 在无文字测试图及无答案提示下正确识别红色圆形与蓝色背景；测试创建的 thread 已归档。
- 生产 Web 构建在独立 API fixture 下通过 1440、390、320 宽度及明暗主题检查，覆盖选择、粘贴、拖入、移除、纯图/图文、放大关闭、跨浏览器读取和失败重试。
- IndexedDB 离线刷新、丢回执自动重试、未知结果手动重发保持同一请求及图片字节，对应账本仅一条消息。
- 设置入口可达且无重复，发布终态通过 SSE 更新后隐藏，历史通知仍可打开详情。
- 上述浏览器结果来自 Chromium 模拟视口；未将其当作物理移动设备或其他浏览器的验收。
