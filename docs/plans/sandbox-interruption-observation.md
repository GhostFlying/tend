# 沙盒中断测试的目标绑定与完整读取

本次只修复沙盒测试辅助逻辑，依据 D133，不改变 server、runner、调度或协议。
既有失败只证明中断阶段耗尽整个测试预算；历史现场的唯一原因仍未确认。

1. 从真实 owner 操作结果取得 message_id，绑定中断测试的源消息和唯一
   native thread/turn。首段输出早于操作返回时等待身份发布；其他消息、repair
   和重复 native turn 不得被同一开关长期阻塞。取消路径释放身份等待。
2. 仅使用 conversation API 的真实 Items、Seq、More 字段，从原始 after
   起点读取全部分页。每次轮询重新读取旧 seq 的状态；严格检查游标进展，
   最多读取 16 页，仍有 More 时明确报错，不静默遗漏或追逐无限追加。
3. 提取实际测试 helper，用有限替身验证两源并发、首段先于身份发布、取消、
   超过 200 条的后页、同 seq 状态更新以及分页异常。先记录旧行为 RED，
   再执行相同定向 race fixtures 验证 GREEN，不重新运行长场景发现同一缺陷。
4. 保留真实 Stop、双方 interrupted 持久化、700ms 无追加、续聊及原 10 分钟
   预算。公共代码不记录机器路径；资源和原始回执保存在私有记录中。
