# 过期任务问题的生命周期收敛

## 问题与边界

普通任务被取消或完成后，原失败重试决定可能仍为 open；现有清理只覆盖 worker_questions 来源及 Issue 所有权变化。效果版本守卫避免重试旧执行，但旧答复仍可创建消息并记录为有效回答。新复查的预算问题是独立责任，不能按同一父 Issue 批量撤销。

## 实施

1. 为自动任务问题统一判断有效性：任务未终态；单纯暂停或 control revision 改变不作为本批失效依据；worker 问题保持现有运行、动作、代次及交接守卫。没有任务冻结版本的普通产品/范围问题保持原行为。
2. 在原事务中将确证过期且尚未回答的问题标为 cancelled，复用 decision.cancelled 事件收敛对应 Attention；不创造 owner 答案、不修改已回答记录。
3. 回答入口在创建回答消息、绑定来源与应用 effect 之前拒绝过期问题。原请求去重优先，已接纳回答重放仍返回原事实；旧 effect 不驱动新代次。同任务非终态复查替代需精确 action/generation 来源，保留为后续原子变更。
4. 用真实 App/Store 回归取消、有效新预算问题、无 effect 的普通问题、暂停与未知运行、已答请求重放与迟到旧答复。历史数据读取仅使用现有本地审计材料，不启动旧生产实例。

## 验证与交付

先定向 race，再独立规定审查；本地完整检查与 GitHub CI 并行，精确候选全过后由统一集成者普通 rebase 合入。生产保持关闭，本批不做旧数据补写或重建操作。
