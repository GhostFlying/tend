# Issue 看板列宽与移动导航

- 在独立浏览器 fixture 中用含长标题、负责人、执行状态和子 Issue 的卡片复现。900 px 窗口下，已取消列从折叠到展开时，普通列从 180 px 缩到 150 px，卡片随之从 162 px 缩到 132 px。原有看板容器可以横向滚动，但列宽下限过小。
- 普通列和展开的已取消列统一采用 256 px 下限，扣除列边框和留白后卡片至少 238 px。确认窄桌面横向滚动仅发生在列容器，宽桌面各列填满可用宽度，并保留已取消列折叠和偏好。
- 手机保留按工作状态跳转，列容器支持原生触摸横向滚动和对齐，标签随浏览位置更新。每列独立纵向滚动，避免从长列表横扫到短列表时落在内容下方。
- 更新已有浏览器回归用例，覆盖普通列与已取消列、滚轮、触摸、标签跳转和页面边界。保留变更前后的截图及测量值，执行受影响检查、独立审阅和 PR CI。
- 根据独立审阅，在手机横扫切列时将标签条内的键盘焦点同步到当前列。浏览器回归从聚焦的标签开始横扫，确认该列标签仍可见，并继续用方向键访问相邻列。
- 跨越 760 px 断点时，桌面网格产生的滚动事件不应覆盖手机选中的列。回归模拟 390×844 到 844×390 再回到 390×844，确认选中的标签和列恢复。
- 快速切回竖屏时，在新的滚动容器恢复选中列，隔离布局切换前开始的滚动。回归等滚动稳定后检查可见列、标签和可访问性，再继续验证横扫。
- 布局切换前记住看板内的键盘焦点，在新容器恢复同一可用卡片控件。控件不可用时回到手机当前列标签或桌面看板容器。回归用 Tab 到达卡片并验证两个切换方向。
- 将已展开子列表的页码和当前读取结果保留在看板层。两个方向切换后继续显示原页并恢复子 Issue 控件焦点，关闭列表后清除该卡片的展开状态。
- 同页后台刷新保留分页按钮焦点，同时拦截刷新中的分页操作。记录每个手机列的纵向位置和桌面看板的滚动位置，切换回来时恢复。回归模拟延迟的子页响应及焦点在卡片外的触摸阅读。
- 状态标签跳转完成后，余下的滑动惯性不能覆盖选中的列。保持标签选择，直到用户再次在看板内开始滚动。用浏览器回归模拟迟到的旧偏移，再跑原始快速切换探针验证真实触摸。
