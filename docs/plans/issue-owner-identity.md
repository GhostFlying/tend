# 保留 Issue 的具名负责人

## 故障与目标

按类别入队的 Issue 首次领取时，runner 把真实 Agent 写入 assignee。关闭和重开会保留这个 assignee，但新协调 Task 之前从原类别选择恢复候选，导致同类别的另一 Agent 可以领取并覆盖原负责人。

以当前具名 assignee 为继续执行的依据。后继协调 Task 可以有新的 Task/Run 和围栏代次，原负责人暂不可用时仍等待同一身份。暂停恢复沿原 Task 的执行 pin。首次未分配的 Issue 继续按类别选择。现有显式具名替换和备份迁移继续使用各自的授权、围栏和结算。

## 实施

1. 在首次实际领取时保存已领取的具体身份。重开继续使用当前身份，兼容历史仍保存类别的 Issue；普通看板状态变更保持现有选择和交接意图。
2. 让读侧候选、空领取预检和写事务的领取校验使用同一具名目标。正式替换读取当前代次的原授权，已分配的普通领取不能以不同身份写入；历史回执读取仍沿原 pin。沿现有队列状态报告正在等待的 Agent。
3. 在两个同类别 Agent 上调用真实 runner 领取命令。通过正常的停止回执、关闭、两种重开入口、待推进和暂停恢复验证身份及历史。仅通过 runner 库存可用性制造原 Agent 暂不可用的条件。另以已有替换入口验证授权、围栏、正确的交接目标及旧 Task 保留。

## 验证

保留逐例报告和精确候选的影响计划、本地检查、独立审阅及 PR CI。原生产现场只读核对。

独立审阅补充覆盖等待领取的已授权交接。普通类别请求继续沿用原目标，直至交接领取或再次显式替换。在具名替换和备份迁移发出后、旧执行结算前插入普通请求，再通过实际 runner 领取检查原目标、旧回执和 Task 历史。
