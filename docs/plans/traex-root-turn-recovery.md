# TraeX 回合失败检测与有限恢复

## 范围与证据

修复 Orca 根回合观测到 runner 恢复、server 通知和 Web 展示的链路。只对明确可重试且后台及外部操作均收敛的错误沿原 run/工作区/会话自动继续一次；其余情况明确待处理。不修改网关，不扩大 other 白名单，不重新启动已取消的任务。

原先“真实 JSONL 为空”的调查有误：模糊匹配取到了零字节 `.jsonl.lock`。精确 rollout 路径包含完整会话和失败结束事件。paginated 模式不能作为空 JSONL 的原因。测试首先覆盖实际非空历史下的 TraeX 根结束漏检，原生历史接口用于一致的结构化观察。

## 实施步骤

- R1：适配 Orca 可选 rootTurn 及 capability，验证 session、turn、终端启动身份；旧 Orca 保持原 JSONL 证据路径，缺失事实不假定成功。
- R2：沿用持久恢复预算和事件，以原 run/session/turn 去重；连接类故障继续原会话一次，未知发送先对账，原回执无法确认时保留原终端和执行占用，等待处理；不得将其标记为人工接管、完成或释放后重新发送。未知外部操作不重放。上下文损坏保留原有恢复证据要求。
- R3：确认失败时保留根状态与后台状态的区别；无法恢复的异常形成一次持久提醒并唤醒现有协调者，已有待决不重复提醒。Web 展示真实原因，不以 runner 心跳替代模型进展。
- R4：可选扩展通过能力协商启用，保留现有通信版本和默认语义，不新增数据库迁移；状态写入仍经 app 事务和已有日志/journal 扩展。
- R5：先升级 Orca server/CLI，再经正式受控发布升级 server 和 runner；核对实际 runtime、进程哈希、提交回执及原工作区。

## 验收

单元和故障测试覆盖原生失败而 Orca 聚合仍 busy、后台操作待收敛、错误分类、一次恢复及崩溃、未知操作/发送、旧事件与接管、长测试静默及混版本。隔离真实 TraeX 验证，不向生产任务注入故障。完成 make check、独立 review、CI、线性 PR 合入和现场发布回读。

## R3 观察细化补充

引导期间的失败提醒暂缓后，后续原生观察若确认根失败且后台仍未收敛，仍须通过既有事务生成一次提醒。以相同 managed turn 去重，不依赖重新发送 worker.turn_failed；根未失败时的普通后台待收敛不提醒。增加“引导事实 → 原生后台待收敛”的回归，并验证重复观察不重复唤醒协调者。

R4：真实正常链路显示原生读取可暂报 `ending_unconfirmed`。根 hook 仍明确 working 且无失败事实时，此可读但未确认结束的观察不提醒；保留 unknown 根事实与恢复围栏，实际历史不可读或根已结束仍进入核对。增加针对性回归并重新跑真实正常链路。

R5：真实 trace 进一步确认正常结束 hook 比原生结束时钟提前一个补查周期（约 5 秒）。已结束且无失败 hook 时，`ending_unconfirmed` 给两个周期（10 秒）对账宽限，期间仍 unknown 并保留占用；超过宽限仍缺失结束时钟才提醒。历史不可读和失败 hook 不享有该宽限。
