# 消息强制打标、上下文同步与全新部署（D113）

## 目标与边界

每条持久正式消息必须显式判定为关联非空工作项集合或无工作项；缺失记录不表示处理完成。保留流式回复，在逻辑轮完成、业务交接和后台结果生效前校验判定、事实检查及上下文水位。遗漏由同一主 Agent 自动补齐，失败保留恢复责任。

托管主 Agent 始终启动后台能力，移除功能开关，默认并发 2，保留并发配置与 auto mode。无托管运行时必须展示真实不可用状态。topic/channel 不在范围内。

本次合入后立即在目标主机使用空业务库重新部署 server，原主机停止 server，两端重建 runner，保留原完整 Tailscale 域名。旧业务数据直接删除，不归档、不新增备份。不实现存量消息回填、历史基线队列及进度页面；新消息处理、用户纠正和失败恢复必须保留。机器具体清单存于忽略的 `.local/`。

## A. 判定与逻辑轮

- 独立版本化判定：`pending`、`linked`、`unassigned`；linked 非空，unassigned 为空且必须显式提交。歧义保持 pending，记录原因；需要澄清时保存问题与恢复责任，允许原生执行结束但不标记业务处理完成。
- 覆盖 owner（包括纯附件）、正式 assistant 进展和最终回复、持久系统通知和业务卡片。工具碎片仅为证据。后台会话由程序关联所属工作项；主会话不得盲目复制输入消息标签给全部回复。
- 写入携带 disposition、工作项集合、消息内容版本、预期关联修订号，保存 actor、来源、时间、修订历史和事件，请求去重。owner 明确纠正锁定整条消息判定，Agent 不得添加其他标签绕过无归属纠正。
- 本逻辑轮读取接口返回应处理消息的最终版本、缺失判定及待同步工作项。提交只覆盖明确列出的版本及水位，不隐含覆盖晚到消息或继续增长的正文。
- 业务写引用来源时检查目标关联；程序明确引用可同事务补关联。标签不构成授权，授权仍来自原 owner 消息。
- 原生结束先落盘最终文本，再检查逻辑完成条件；满足后原子完成并释放交接。不满足则自动进入受限修正，仅可读取、改关联、登记事实及提交；禁止重复业务操作。修正文字只存 rollout，不产生新聊天标记义务。
- 立即修正最多两次，再按 30 秒、2 分钟、10 分钟恢复，用户新消息优先。unknown 先核对原请求与原生 turn。上限后保留继续处理、原因和纠正入口，阻止相关交接但不阻止其他会话。
- 重启、compact、thread 交接从持久检查点恢复。用户停止后不得立即自动启动新模型执行，后续继续时恢复责任。

## B. 上下文与交接

- 工作项创建携带初始来源、事实、检查范围、缺口，创建与关联、初始化在同一事务完成；创建逻辑轮提交完成后才允许后台处理，不建立历史整理任务。
- 每条已处理消息显式记录事实检查；没有新事实也是结果。允许明确记录没有授权、没有未决问题，不能从缺字段推断已检查。
- 事实包括目标、约束、授权、拒绝、承诺、问题、建议，区分 owner 决定与 Agent 建议，保留原来源、取代关系。全局和项目约束按范围继承。
- 关联、事实、计划和业务变化同事务推进上下文版本。后台增量读取，恢复及 compact 后重建关键事实；结果校验版本，过期结果仅留作证据。
- owner 纠正只重新核对受影响消息、派生事实和工作项，完成前阻止相关交接，不全历史回扫。已执行操作不因纠正而撤销。
- 已领取批次保持原执行身份；未领取来源在上下文就绪后持久、去重地转交后台，禁止重复处理和回传循环。

## C. UI

保留消息标签、工作项详情、后台抽屉。显示 linked 标签、低对比度无工作项、关联处理中及恢复状态；编辑明确选择工作项或无工作项，空选择不能隐式提交。详情显示初始化中、已同步、待核对、正在恢复，以及水位、检查范围、缺口、过程链接。抽屉可见等待上下文的会话，不显示无可靠分母的百分比。统一持久事件驱动刷新，类型由 schema 生成。删除功能禁用分支，不静默回退旧路径。

## D. 实例身份

新库生成持久 deployment_id，正常重启保持不变。握手、会话、SSE 返回身份；Web、CLI、外挂 Agent 写请求必须带原目标身份，业务变更前拒绝缺失或不一致。明确声明 owner/Agent API 升级要求，runner 通信协议不变。

浏览器草稿、附件、队列、控制 journal、缓存按实例隔离。发现实例更换即停止旧恢复与发送，跨标签页关闭旧连接，清理该 origin 旧业务缓存。禁止给旧请求换新身份重试，自动登录不能使旧消息进入新库。轮换 Tend server secret 和 runner 凭据；保留基础设施 Tailscale 身份、账号认证和仓库凭据。

## E. 全新部署执行

所有 traex 入口（主 Agent、后台 Agent、两端 Orca worker）继续通过 gateway；启动策略配置 `--fallback gpt-5.6-sol:high`，Tend 主模型统一为 `GPT-6.1-Sol`，保留 auto mode；Tend 专属启动配置不改变个人会话默认模型。直连仅能用于诊断，不作为部署路径。验收分别记录 gateway 路由、fallback 策略传递和实际切换证据；不把未触发切换的成功请求当作 fallback 验收。

1. 删除前验证目标 server 的 traex、模型认证、auto mode、网络、磁盘、systemd/updater、真实 harness；验证两端 runner、Orca、provider、仓库绑定。保留逻辑仓库配置，按本机路径重新登记。
2. 准备同一合入提交的不可变 server/runner/CLI 产物及新配置；生成仅含资源身份和路径的删除清单。记录 tsnet 身份、server/updater/runner/worker 进程归属。旧 Tend 业务备份、快照、journal 副本纳入清单，不复制业务内容。
3. review、CI 通过，rebase 合入后连续执行，不新增产品确认。禁止旧监督器拉起服务，停止旧 server 与两端 runner/监督器，验证子进程实际退出。
4. 收敛 Tend 创建的 worker、主后台会话与终端；人工接管或归属不明资源单独报告，不按目录名猜测删除。
5. 旧 server 完全退出后仅转移其 tsnet 身份状态，保持同一节点和完整域名；任何时刻仅一个进程使用该身份。不迁移业务库或原生模型 thread。
6. 按清单删除旧数据库、附件、会话、journal/代次、旧 updater 运行备份状态及 Tend 独占工作区。保留共享仓库、个人资源、宿主机 Tailscale 和凭据。
7. 目标主机启动全新 server/固定 updater、空库、新 deployment_id/主会话，两端使用空 journal/新凭据登记 runner；更新 CLI/MCP 指向原域名。原主机仅运行新 runner。
8. 验收后删除临时复制旧身份和清理残留。若认证或身份迁移前提不成立，删除前报告阻碍。删除后修复新空实例，不承诺恢复已删除数据。

参考：[tsnet Server API](https://tailscale.com/docs/reference/tsnet-server-api)。节点状态独立保存；采用停止旧进程后独占转移状态的部署步骤。

## F. 顺序与验收

按数据/逻辑轮 → 工具/新项初始化/恢复/交接 → UI → 实例隔离/移除开关 → 验收/review/CI → 合入部署实施。迁移只追加。

必须验证：

- 单条多关联、系统判定、显式无归属整消息锁、内容版本及并发修订冲突。
- 流式最终文本、多个进展消息、迟到片段进入检查，漏标可自动修复而不能正常完成。
- 网络丢回执、重启、compact、停止、连续失败恢复原责任，不重复业务动作。
- 新项当轮初始化、增量不全扫、局部纠正、旧版本结果不生效。
- 同域名空库阻断旧标签页、service worker、离线发送、控制 journal；旧客户端必须升级。
- 无开关、并发默认 2、故障可见可恢复，真实后台不阻塞主聊天。
- 标签窄屏/主题/键盘/长名称与真实浏览器视觉验收；运行 make check、独立 review、CI 交叉编译。
- 原域名 HTTPS、服务在目标主机、旧 server 退出、双 runner 新状态心跳、实际哈希与产物一致。
- 新系统创建明确验收工作项，验证当轮判定、初始上下文、两端 worker、后台消费/回传与主 Agent 读取 rollout；保留新验收记录。
- 删除清单逐项确认，共享/个人资源保留，归属不明残留明确列出。

独立复核补充：澄清交接持续接收迟到消息和上下文；继承事实来源变化推进所有适用工作项版本；修正轮启动前确定失败仍进入有界恢复，未知结果继续对账。

真实 worker 验收补充：Tend 的 Traex 项目配置使用原生 `permission_mode=auto`，不再写 Codex 的 sandbox/approval 配置；专属启动器排除继承的 yolo 参数，个人启动参数保持原样。

验收预算：扩大 schema 与恢复测试后，race 用例层单包实测约 19 分钟；统一测试超时提高到 40 分钟，保留有界运行，避免原 20 分钟上限因正常主机负载抖动误判。浏览器集成 fixtures 同步新部署身份契约。

最终复核补充：停止与已领取修正任务的原生启动互斥；停止逻辑责任产生持久事件。未核清原生回执前保留旧 thread，恢复后再进行 schema 交接。停止与跟进控制 journal 同样绑定部署身份，旧标签页延迟清理不删除新实例记录。受限修正轮输出简短非空结束文本，仅保存在 rollout，避免模型服务把空结束视为错误。

自动修正原生执行进入当前会话 active 投影，沿用原消息身份提供停止入口；不进入可撤回或取回编辑的 owner 待发送队列。原生停止确认前保持运行状态可见。
