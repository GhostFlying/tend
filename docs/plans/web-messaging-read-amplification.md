# 减少 Web 消息页读取放大

- 在消息页可见时订阅消息事件。离开页面或浏览器标签页隐藏时停止流和消息读取，保留草稿、发送队列、已读数据和事件游标。返回或游标失效后重新读取权威状态并补齐漏掉的消息。
- 消息新建、状态变化和关联变化分别处理。新建事件按消息序号向前读取，已有消息的变化按 ID 更新。普通 Issue、Task 与 Run 事件仅使受影响 Issue 的已加载输入状态失效，不触发最近消息整页读取。
- 在现有读事务内先确定最多 100 条消息，批量读取本页正文、附件元信息、来源、问题状态和读取/投递状态。保留现有顺序、前后翻页游标、状态优先级、内部交互过滤及附件访问校验。只对输入消息查询处理状态，查询最近消息状态时使用事件对象类型与 ID。
- SSE 在读取一批事件时批量判断消息方向和存在性，继续保留全局水位、重连和过期游标恢复。独立验证真实消息页切换、事件风暴、待处理状态、显式已读、翻页、附件权限和重置，用同一组 10/100 条消息对照记录 SQLite 语句数。

续跑以原工作树中的批量读改动为起点。先补齐交互卡片状态读并对照旧投影，再让 IM 事件直接使用轻量批次，不经过 Chat 的消息投影。普通工作事件仅在命中当前已加载输入所关联 Issue 时刷新该输入。消息发布以序号补齐，消息状态按 ID 刷新。页面隐藏时中止读取并保留游标，流明确重置后重新同步最近窗口，旧历史仍可翻页。
