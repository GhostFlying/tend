# 协议兼容、持续心跳与受控滚动升级

状态：实施中。设计依据：D82、D83、D84、D85。

## 已确认的目标

本地发起发布，检查所有启用 runner 的在线状态及协议，等待主会话当前轮结束后切换 server，再逐台排空和更新 runner。只有一个未结束发布批次，server 在入口拒绝叠加发布。离线主机阻止发布。runner 按当前 run 排空，后续验收和返工在原工作区排队；至少保留另一台在线、正常且配置了 slot 的主机。

更新器用 Go，与现有 module 共用构建和检查，独立二进制负责监督和切换进程。首版自动安装支持 Linux；其他平台维持编译检查。更新器自身显式安装，不依赖模型执行更新步骤。

## U1：协议、心跳和维护基础

- 正式 runner 协议从 1 开始，无版本协议登记为 0。每代支持 N 和 N−1；初次安装以空闲 bootstrap 完成，新自动流程要求心跳和更新器能力。
- 握手声明构建、范围、能力和进程实例，run 固定创建时的通信协议。旧版本 run 的续租和结果不能因为 server 更新被丢弃。
- 空闲及维护期间也发送心跳，默认 15 秒，必要时按租约取更短间隔；server 接收时间超过 60 秒判离线。实例和序号防止旧进程及乱序消息覆盖状态。
- 心跳报告当前模式、已应用控制 revision、持有 run、发布阶段及未确认操作；server 返回已提交的维护指令。维护/ready/恢复接单转换持久化并去重。
- server 领取事务及 runner 本地都实施维护门禁；未知领取先对账。暂停、人工接管、unknown、未交付结果及资源操作都阻止 ready。
- 兼容代码集中为版本适配器，登记协议及退役版本并在代码中标记。make check 在过期代码未移除、登记和标记不一致时失败。N+1 必须保留 N 并移除 N−1 的通信适配，保留拒绝旧协议测试；数据库迁移及历史读取独立管理。
- AGENTS.md 强制 breaking change 递增协议并同时完成设计、兼容、退役及测试。

## U2：发布产物与 Go 更新器

- release bundle 固定 release ID、server 和 runner 平台产物、大小、SHA-256、协议及存储格式要求。server 通过主机鉴权提供文件；同哈希 runner 跳过替换。
- 更新器以原服务用户运行，使用版本目录、原子状态文件及独占锁，保留配置与数据，监督唯一受管进程，不直接改业务表。
- 本地入口为 tend-updater upgrade --release <bundle>，CLI 提供状态、重试和取消。进程阶段持久化，未知结果先对账。
- 候选 runner 保持维护完成配置、journal、provider 和握手检查；两次连续健康心跳后由 server 授权接单。
- 下载失败保留旧版本；尚未接受新业务的候选失败，可在确认进程退出后恢复匹配备份。接单后不恢复旧 journal；server 接受新写入后不恢复旧数据库。

## U3：编排、会话保护和界面

- server 发布预检查核对所有启用主机，以及未结束 run/未确认操作的协议。固定参与主机，拒绝新发布或参与配置变更。
- 停止启动新主会话轮次，当前轮及工具回调正常完成，新消息持久排队，runner 继续执行。默认等待 30 分钟，超时保持旧服务并恢复处理。
- 临近切换关闭新 claim，准备 D81 交接，并为已有 run 确认一次固定截止的 300 秒维护授权，覆盖 120 秒 server 重启预算。持久化后等 runner 确认且剩余余量足够才停机；回执丢失不视为授权成功，重复心跳不无限顺延。恢复后回到正常续租，已发出的旧授权不得提前回收。到期仍 fencing 和对账。
- 更新器确认旧 server 退出、保存匹配备份后启动候选；runner API 优先恢复续租和对账，主会话完成 resume/D81 交接才恢复投递。普通同版本重启不受发布时的在线主机门禁阻塞。
- runner 顺序为等待维护、排空、ready、安装/重启、健康确认、正常。优先空闲主机，其次按活动 run 数和主机 ID；每次切换复查另一台可用主机。默认排空 30 分钟，超时不强杀。
- 取消停止后续更新，恢复未切换且确认安全的主机，保留已升级版本；保留服务的主机离线时停止后续维护并通知。
- Web 主机组件分别展示在线、维护及 slot 占用，侧栏和大看板复用；手机折叠标题显示维护数量。维护显示文字和琥珀色，不冒充离线。详情可见剩余 run、版本、协议、下载和阻塞。
- Chat/看板共享发布状态入口，重启期间保留最后观察并标记等待恢复，重连读取权威状态。
- 持久 system 通知增加升级类型：批次开始、每台成功恢复、批次完成、失败/需要处理。阶段与下载细节只在详情显示。按批次/主机/阶段去重，同事务写状态和通知，不唤醒模型；后续上下文获得事实。

## 验证与交付

按 U1、U2、U3 分工实施；首版共享协议、journal 迁移和编排入口，合为一个集成 PR 验证完整链路，避免部署只有协议而没有恢复入口的中间版本。PR 必须通过 make check、交叉编译、独立 review 和 CI，通过后 rebase 合入。

必测：两代协议与旧代拒绝、兼容登记到期、空闲心跳及乱序、维护与 claim 竞争、未知领取与交付、维护授权丢回执/超期/恢复、各更新阶段崩溃和取消、原 run/workspace 继续、主会话排队与 D81、仅剩一台主机、通知去重、桌面/窄屏/深浅色及重连。

上线前补齐两台 runner 的基础执行/独立验收 smoke，空闲安装控制协议和更新器；随后用专用工作区做双机滚动演练，验证一台继续执行时另一台更新恢复，再交换。清理本次测试 workspace 和执行资源，保留账本、产物和证据。真实演练通过后启用日常入口。

## 独立评审后的恢复约束

- runner 确认维护授权时，同时报告保守截止时间的 server 时钟下界：从原截止扣除本地保守折扣与整个请求往返耗时；不要求时钟同步。server 的固定停止授权截止还要再扣除完整重启预算，不能沿用整个维护授权期限。
- updater 明确证明候选没有启动、已恢复匹配旧版本后，发送固定绑定的终态回退回执。server 核对当前进程、哈希和原候选，恢复旧服务并标记需要处理；取消该批次后用新批次重新安装。晚到回执在暂停状态也会对账。
- 下载失败重试按新的控制 revision 清理旧错误；明确拒绝与不确定授权分别处理，后者保留原 request ID。
- 配置同步允许同配置重启，未结束批次禁止修改参与主机；实际候选协议及存储版本必须与发布清单一致。

- 停止旧服务后、候选启动前若授权过期，以持久阶段证明未启动，恢复旧进程；不因过期留下一项无法结束的停机操作，也不重做不确定的候选启动。
- 批次取消同步至本机尚未获准切换的 updater，使用 staged 阶段比较交换避免竞态。runner 通过持久控制标记与心跳回执确认本地取消；所有参与主机确认后才允许下一批，防止连续取消覆盖旧意图。已经完成主机的过期授权仅作历史，不阻止后续主机重试。

- updater 为已结束操作保存最小身份收据，为尚未到达的取消操作保存 tombstone；取消确认不能仅依据一次 status 中未出现该操作。后续批次结束后，迟到旧 POST 仍不得重新安装；相同 ID 不同发布内容继续冲突。
