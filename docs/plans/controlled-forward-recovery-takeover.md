# 前向恢复交付接管计划

## 目标与边界

继承已有前向恢复实现及其独立评审结果，修完阻止交付的明确缺陷，通过既有工程门禁后交付可审阅的 PR。不另建恢复状态机，不编辑原任务工作区，不修改生产状态或制造旧升级成功记录。原实现交接时的未完成与失败历史保留。

## 实施步骤

1. 验证原任务冻结的完整文件清单、摘要、基线和 index stage；将候选重放到当前主线。若只取得旧候选，明确记录其版本及未采纳的新现场。
2. 解决追加迁移编号和设计决策冲突，保持已有迁移不可变。
3. 修复归档预备状态下主 Agent 的恢复 readiness 与 admission fence 循环等待，并增加覆盖真实状态组合的回归。
4. 固定更新器交接取得原 flock 后重新读取并核验完整持久状态；过时快照不得继续安装。
5. 复制更新器产物时校验实际临时文件字节的固定摘要后再发布，首次安装与续跑使用相同约束。
6. 运行有针对性的回归；在唯一重型检查窗口运行官方完整检查。按当前候选执行独立评审，逐项处理意见，之后提交、PR、CI 与线性合入。

## 生产前置

生产执行由单一操作者负责。必须重新核验旧进程、运行实例、固定产物与状态代次，取得真实 writer fencing 及唯一部署窗口证据。仅使用审查通过的专用恢复入口，保留旧操作未确认历史，并验证新实例的真实健康、持久回执、账本关联与窗口释放。隔离开发不依赖生产 fencing 已完成。

## 独立评审补充

最终候选合入前，还需修复已复现的三个恢复边界：已提交请求先去重并重新授权，再对新请求执行 admission fence；仅允许原生历史适配器为既有 thread/turn 补记终态事实；format 2 重启缺少固定 handoff journal 时必须在轮询前拒绝。新业务、无身份的补记与普通流式输出继续受 fence 限制。为这三个边界保留真实回归，完成新候选的独立评审后再启动完整检查。

## 最终评审与真实跨主机证据

将本机 kernel writer 列表与远端操作者见证分开。远端见证固定 host、来源与私有证据文件摘要，仅表示操作者审阅过远端关闭绑定和退出事实，不使用本机 PID 查询冒充远端证明。保持本机 writer、活动服务、更新器和候选的身份约束。修复 HTTP admission 在去重前拒绝已提交恢复期重试，以及 CLI 校验和执行安装器使用不同字节的问题；增加针对实际复现的回归。

恢复期 HTTP operation 只跳过新增的 recovery body admission 检查，让事务去重后决定新动作是否拒绝。保留既有 archive-prepared 的 body 前拒绝及私有主机维护语义；不扩展归档协议。既有 slow-body 零读取与归档维护回归必须继续通过。
