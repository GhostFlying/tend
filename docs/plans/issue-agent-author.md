# Issue 对话作者具名显示

## 问题与边界

Issue 消息头从负责人执行快照读取显示名称，但 runner 负责人快照由执行 pin
重建时没有填入显示名，因而退回内部技术引用。进度事件已使用执行时冻结的
Agent 目录版本解析名称。修复只统一读取投影，不改变执行身份、配置或权限。

## 实施步骤

1. 核对原始截图、消息头与进度事件的作者来源，并保留复现证据。
2. 消息头根据该消息绑定的原始执行解析作者：保留已有冻结显示名；runner
   执行从对应 Run 的冻结目录读取具名定义；缺少目录时保留诚实技术回退。
   不以当前负责人或最新目录改写旧消息。
3. 增加回归覆盖 runner 快照缺名、历史名称、交接、缺失定义、已有 hosted
   显示名与没有执行记录的消息，并验证真实 Issue 活动读取入口。
4. 在隔离沙盒中通过实际浏览器验证桌面及手机视口的消息头、进度与输入框；
   记录其与原始生产截图及真实手机验证的区别。
5. 完整本地检查、独立整 PR 审阅与 CI 通过后，按既定授权合入并受控部署，
   发布可追溯的中文报告。后续候选增量继续同一审阅责任。

## 验证

- 针对作者冻结来源的 Go 回归测试及 Issue 活动 API 测试。
- Chromium 桌面及手机视口截图、DOM 名称、交互及控制台记录。
- 自动 CPU 预算的完整 `make check` 与最终候选 CI。

不增加数据库迁移或新协议字段，不把目录可读性当作执行可用性证明。
