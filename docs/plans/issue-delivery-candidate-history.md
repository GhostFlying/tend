# Issue 时间线中的 PR 候选历史

PR 的初次观察、候选切换和后续检查均来自 Issue 活动接口。观察快照会保留
previous_head_sha，逐条比较会把同一次推送显示多次。

- 在 Web 时间线按 Issue 与 PR 标识追踪连续 head。每次切换创建一张卡片，
  后续同 head 观察更新它。不同 PR、无法识别 head 的观察和审阅事件保留各自位置。
- 卡片沿用首次观察的位置，展示最新快照和检查明细。冲突和失败检查无需展开即可发现。
  可展开每条原始观察及其通知诊断。投影适用于分页历史，不修改接口、账本或发布流程。
- 通过 Issue 页面验证 21 条同 head 快照、检查数 6→8 且总状态等待中、目标分支
  移动、冲突与失败检查、跨 PR 隔离，以及 head 切换和历史分页。

## 补读更早观察时保留阅读位置

给候选摘要和每条原观察使用不同的滚动锚点。浏览器回归先将首条已加载观察展开，
滚至其中的检查项，再放行返回 12 条更早同候选观察的分页请求。核对桌面和窄屏
上同一检查项相对滚动窗的位置、原观察的展开状态，以及后续实时更新。
