# 连续责任的停止交接、事实恢复与限制收敛

## 原因与目标

真实外部等待允许执行物理停止、结束 Run 并归还资源，Task 与原请求继续存在。
目前未结原生回执的发现依赖内存 attachment 的清理，结束的事件载体又可无限等待，
阻住后继读取；升级只检查当前 Run，却同时禁止为历史责任分配 reader。阶段成果
和原件还被当前执行状态、未来部署证据或上传 Run 相等条件限制。

本次以“真实停止 → 未结事实可发现并接手 → 原身份对账 → 正常继续或维护”作为
同一个修复单位。复用现有 Task、Run、原请求、native receipt、outbox、原件和
对象授权，不新增通用恢复工作流、read-grant、人工审批、业务 Task 或停止证书。
设计写入 D227，并修订相关 D219/D221/D222/D226 表述，说明各自事实与资源边界。

## 不同事实的含义

- Issue/Task 表达持续目标与授权；Run/lease 表达一次实际执行和资源持有。
- 原 request/thread/turn 与原件出处不随 session、transport 或后继 Run 改写。
- 物理停止可释放已停止的执行资源，同时保留尚未结清的业务事实。
- 读取/引用原事实、产生新业务效果、停止/替换物理资源分别校验实际所需条件。
- 事件 EOF、原生终态、来源消费、消息/附件投影及最终用户交付分别保存真实结果。

## A. 正常停止与恢复的统一交接

1. 外部等待、暂停、普通关闭和原生停止的现有事务，统一保留原执行尚未结清的
   回执责任；不依赖原 server 连接恰好走完 defer 才能发现 started 请求。
   先检查现有关系能否可靠派生；仅确有必要时追加持久字段，不建立平行真源。
2. 事件消费者排完已持久尾部、确认载体已结束后退出，释放旧连接及会话占位。
   处理空读与最后事件提交的竞争，错误保留原事件和 ACK 身份；退出不代表业务
   完成，也不隐式重新 close/start 或执行旧工具。实际活跃 Run 不提前结束。
3. 普通续行、暂停/等待恢复、升级 park 复用同一历史事实选择与承接顺序。
   暂停新业务不阻止原已准入请求的有限只读恢复。优先使用可用载体，无载体时
   允许既有真实 reader 准入；不复活旧租约、不重放输入，不强制新业务 Task。
4. 只读历史使用真正的 thread/read 适配器；缺 AppliedModel 不阻止它读取已知
   原 thread，未知模型事实保持未知。真正 resume/start 仍使用正确执行配置。
5. park 检查当前责任内的历史未结事实，而非仅当前 Run；复用已有纯观测操作
   分类，不要求 models/find/usage 的未知结果先成功才可停止物理载体。业务效果
   未知仍按原请求对账并隔离依赖它的动作，不泛化冻结无关操作。
6. drain 根据真实工作、启动/清理、writer/原生资源判断；不要求一个没有在途
   动作的旧 Main 先恢复模型或初始化 session 才允许替换。新候选健康就绪另行核验。
7. 可信适配器保存已观察的原生终态，所需来源消费和用户消息投影分别推进。
   输出投影失败须可从原件恢复，不伪造已发布，不使已观察事实因展示错误消失。
   优先沿已有原始回执与 pending 投影表达，不为了命名新增一套状态系统。

## B. 同 Task 的原件沿真实出处复用

1. 当前合法负责人可发现、读取并引用同 Task/Issue 内已确认上传的原件，包括
   旧 Run 已停止、先前 result 登记失败而未 finalized 的文件。
2. 原上传 Run/request 与真实检查出处不改；当前调用者只是本次结果/引用的
   登记者。对象归属、真实 file ID、name/size/hash 和分享范围继续核验。
3. 不要求重新上传或重跑检查来满足当前 Run 相等。阶段成果和原件引用不要求
   未来 upgrade；实际声称升级和最终验收时才核验真实批次与安装事实。
4. 沿已有结果/原件、owner API、Agent 工具及 CLI 扩展，生成类型按需生成。
   外部新业务执行权限和无关对象访问不因历史事实引用而扩大。

## 验证与交付

关键回归从真实外部等待工具与停止 yield 开始，贯穿 runner transport、mainthread
pool、原回执与升级准入；测试不先替系统调用 SettleOpenTurns 补上要验证的交接。
覆盖旧事件尾部/ACK 丢失、真实活跃与已停止、历史终态/缺失/非终态、后继存在与
不存在、同责任和其他 epoch、维护取消/重启。证明原 slot 真实释放、旧连接退出、
纯读不发模型或修改 thread policy、原结果和输入不重复、后继可以实际继续。

另覆盖原上传成功但结果失败后跨 Run 读取/引用且原 producer 不改，错误对象与
漂移字节拒绝，以及未初始化但无外部工作可 drain、纯观测未知不挡物理退出。
对未改变的既有边界复用原回归，只针对真实新影响补查。

在同一修复分支收敛原子提交后，独立整 PR 审阅、最终完整本地检查及所需 CI。
保留所有失败与未知，不以红回归或旧源码 green 代替最终验收。实现后评估协议
变化，按现有 N/N-1 规则交付；迁移只追加。

发布使用同源码完整 format 2 集，先读取实际混合版本、原业务升级和配置基线。
已取消的旧批次不重启、不复用原 ID/截止；若旧服务因同一缺陷无法排空，沿现有
正式受控恢复接点处理真实停止/备份/安装，不能用强制更新代替正常模型验收。
实际全节点进程/配置/正常 ACK 核验后，通过 Tend chat 让原负责人继续。

本批不启动已记录的 Agent 分配/类别设计或维护交接 backlog；不代做原业务合入、
部署和最终报告，不直接改业务状态。Refs: D219、D221、D222、D226；拟 D227。
