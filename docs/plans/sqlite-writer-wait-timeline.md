# SQLite 写连接等待窗口诊断

## 目标与调用路径

`manager.event.ack` 等待入口是 `App.AcknowledgeManagerEvent` → `Store.Write`
→ 单连接写池。一次失败样本只有失败时刻的活跃写者，无法解释此前一串已归还
连接的写入。沿用现有慢写和取消告警，在同一条日志中给出等待窗口、实际观测到的
持有区间和覆盖边界。对照原操作、写入编号、Run、事件序号及已知的 close 请求。
观察结果不参与排队、事务、会话关闭或重试决策。

## 实现

- 在 `Store.Write` 的现有 `sql.DB.Conn` 与 `sql.Conn.Close` 边界记录。保留
  活跃写者和最近 256 次归还记录。持有起点是取到连接后的采样。每个归还记录先
  标记调用 Close 前的时刻，再记录其返回或下一次取得连接给出的最早已知上界。
  该区间内的准确交接时刻不可见。用已确认的持有下界计算与等待窗口的交集，
  避免把交接的不确定部分或后继写入计给前一个写者。
- 获取失败时在诊断锁内同时取原活跃快照和窗口摘要。获取成功的慢写在结束时
  使用冻结的等待终点。最多显示 8 个持有者，按占用交集选择并按取得连接时间
  展示。全部仍保留的匹配记录都参与计数和占用下界。窗口早于保留区间时标记
  历史截断，输出条数截断单独计数。等待中没有已确认持有者的时间显示为未归因。
  独立备份的直接 VACUUM 路径、池内分派和返回时差都可能出现在未归因时间。
- 沿用请求、trace、事件及 attachment identity。在 native close 排队和确认回执
  已有边界携带可核对的 close ID。关闭原因仍取现有 close_trigger 日志。
  持有记录只保存元数据与阶段，不保存原始错误、SQL、参数、消息或调用栈。
- 常规快写不扫描、分配或编码摘要。环形缓冲每次归还最多写一个定长记录，
  归还确认更新原槽位。锁内不执行数据库、业务回调或日志。

## 验证

- 真实 SQLite 单连接路径，用 callback 门闩冻结长持有，用逐段门闩控制多次短
  持有，再以同一等待者的失败摘要和生产文本日志核对时间、写入、原 Run、事件
  和脱敏字段。覆盖成功慢写窗口、归还交接与并发的记录、环形覆盖与输出截断。
- 测量当前热路径在不输出日志情况下的基线与改动后成本，列明采集容量和时间
  覆盖条件。执行仓库的受影响检查与独立候选审阅，交付可审阅 PR。
