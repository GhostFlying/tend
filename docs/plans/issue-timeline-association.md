# 简化 Issue 时间线的准入记录和消息关联操作

- 活动读取用账本事件的主 Agent 身份与前后两条控制版本识别「待安排 → 待推进」。在原位置用「接收与投递记录」收起准入项，展开显示原操作者、状态变化和时间。保留原事件顺序与负责人领取、暂停、失败和其他状态变更。缺少版本证据时继续显示原活动。
- Issue 详情的 Agent 回复仅显示跨 Issue 的关联链接，从消息菜单打开原有关联编辑器。复用保存、并发版本检查和消息关联记录。其他会话保留原入口与标签。
- 在真实 Issue 页面入口用桌面键盘和手机触控检查准入记录、两条回复、当前 Issue 自关联、跨 Issue 导航和关联保存。用服务端活动读取回归验证实际状态转换、操作者和旧记录语义。
- 与讨论首屏性能工作共用活动读取和时间线。将改动限于状态事件的投影、活动行的折叠渲染与回复操作，分页、预取和过程读取留给首屏性能工作。合入前对照对方候选的共享文件。
