# 统一附件与独立文件存储

状态：代码已实现；本地验证完成，独立 review 修正、CI 和发布验收随本次交付完成。Refs: D86、D87。

## 约定

- 聊天附件与任务交付文件原样保存在服务数据目录的独立文件存储；SQLite 只保存元数据、身份、关联与处理状态。
- 上传原文件不设应用层大小、累计大小或图片分辨率门槛。流式写入、计算摘要与下载，不将整个文件编码进新消息或一次性读入内存。实际 IO/磁盘/网络失败可见且允许用原请求身份重试。
- Web 统一附件入口，选择/粘贴/拖入、文件卡片、可用图片预览、原文件下载；IndexedDB 保存 Blob 与稳定上传/消息请求身份，上传完成后发送引用。未知回执先对账，刷新重试保持身份。
- 预览和自动模型输入与保存原文件分离。原图过大、不支持或 GIF 不影响上传；原生静态图片输入可作为便利，agent 始终能按附件引用获得原始文件，并自行决定读取、抽帧、解析等操作。
- 既有图片、交付文件的 ID、字节与关联保留。追加迁移，旧 BLOB 逐个文件导出，确认落盘与摘要后才清空对应数据库原文；崩溃可重入。旧客户端的内联图片消息仍可接收，旧请求可按原身份对账。
- 文件写入为可重试的不可变内容暂存，不是业务提交；原子完成暂存后由 app 的单事务完成元数据、事件、去重和消息关联。业务失败不产生有效引用；临时写入失败清除本次临时文件。不在本轮引入自动删除已保存原文件的策略。
- 原生 session/rollout 仍归 harness 管理；Tend 的网页聊天记录、任务账本与恢复状态继续存库。备份须覆盖数据库、独立文件目录及原生历史。

## 实施分工

1. A1：文件存储与追加迁移、流式读写、旧 BLOB 逐个文件导出及恢复测试。
2. A2：聊天附件上传/下载、消息附件引用、agent 原文件获取与静态图片便利输入、历史与交接信息。
3. A3：任务交付上传/下载、worker/CLI 链路统一流式文件能力，移除文件尺寸门槛，保留旧协议请求兼容。
4. A4：Web 通用附件输入与预览、Blob 发送队列、重试/刷新/离线与下载。
5. A5：迁移字节核验、超旧限制及高分辨率/动画/普通文件验证、浏览器与真实 agent 验证，make check、独立 review、CI、PR、受控部署和数据回查。

## 验收边界

使用非图片文件、超过旧 5 MiB/20 MiB 的文件、超过旧像素门槛的图片与多帧 GIF；确认原字节、hash 和引用一致，上传不完整不发布有效引用；丢回执/离线刷新不重复创建消息。二进制不进入新数据库行/消息 payload，新传输内存开销与文件体积解耦；旧 BLOB 一次性迁移逐文件读取，峰值受单个历史文件大小影响，部署前核对历史文件大小。文件预览失败不阻止发送与下载。runner 旧上传格式继续有效，通信语义新增/放宽不递增协议版本；若实现发现破坏兼容的变更则按 N/N−1 流程处理。

## A4 Web 实施细化

- 队列为每个 Blob 持久化独立上传请求 ID 和回执；未知上传先查询原请求，查无记录才重投同一 Blob/身份。回执全部落盘后冻结消息引用，再沿原消息 ID 投递，兼容旧内联图片 outbox。
- 统一文件卡使用 Blob/object URL 作本地可用预览，不读取 Base64、不按类型、尺寸或数量拒绝。原文件发送与图片预览成功与否独立。
- 下载通过 Bearer 交换短期、单文件签名 URL，再由浏览器原生下载；历史图片优先通用附件元数据，缺省时保留图片历史入口。上传使用可取消传输，不套普通 JSON 请求总超时。
- 定向回归覆盖上传丢回执、离线刷新、多个附件引用冻结、旧队列兼容及真实 IndexedDB Blob；生产构建浏览器 fixture 检查任意文件、预览失败、原生下载、窄屏和明暗主题。

## 验证记录

- Go 覆盖流式上传下载、取消与中断、重复请求、附件关联、旧 BLOB 重入迁移及原字节校验；验证超过旧大小门槛的文件、50 MP 图片、空文件和多帧 GIF。
- Web 覆盖 Blob 离线队列、未知回执对账、刷新后续传、取消发送和原生下载；生产构建浏览器 fixture 验证桌面与窄屏、明暗主题和预览失败后的原文件发送。
- 真实原生 agent 通过原路径读取随机文本和双帧 GIF，自行解析完整动画并核验摘要；测试会话与临时资源已清理。
- 独立 review 的两项有效意见均纳入修正：外挂 agent 返回 CLI 下载命令；展开历史图片前重新获取短期预览链接。
- 发布按不可变产物和受控升级流程执行；部署前保存账本与原生历史基线，部署后核验历史文件摘要、元数据、消息与会话历史，并确认两台 runner 恢复接单。
