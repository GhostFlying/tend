# 续行启动的前驱一致性与未启动证明

Refs: D233。

## 原业务目标与故障链

原目标是在同一 Task 中完成独立审阅，等待 CI 后继续报告和交付。实际故障起点是
续行 assignment 同时保留历史 session 与较新的 ExternalWait 来源：runner 选择
后者的状态目录，harness 却优先选择前者的身份。环境继承在启动进程前拒绝，随后
继承的 thread 又使 runner 放弃明确的未启动证明；关闭对账读取尚未生成的本轮
进程归属文件，后一个错误覆盖启动错误，执行被保留为待对账。

## A. 同一前驱决定身份、会话与目录

runner 与 harness 复用同一个前驱选择函数，保留 runner 已有的 pause、question、
ExternalWait、历史 session 的优先顺序。Run、thread 和状态目录必须来自同一个
选定来源。保留严格恢复和可选历史回退的既有边界，不改变 wire、schema 或权限。

## B. 区分继承会话和本轮启动

第一次尝试在本次调用中继承前驱 thread 后，harness 返回明确的
ErrWorkerNotStarted，仍可记录本轮未启动的事实。仅有旧 thread、缺文件、普通
启动错误或前一次未结尝试不能提供该证明。关闭对账失败时同时保留原始启动错误，
不丢失任何 unknown。

## C. 验证真实调用路径

通过 runner.work/execute、真实 app-server harness 与环境继承路径构造混合来源；
用不存在的测试执行文件在模型启动前明确拒绝，验证正确来源被读取、本轮停止事实
持久化、原 Run 正常释放且没有重放。另验证明确的未启动证明可跨关闭/重开 journal
读取；普通未知启动与旧尝试继续保留未知，启动和关闭错误都可观察。测试不调用模型。

已有卡住的执行先评估正式恢复入口和一次针对原负责人的指令，不为单个历史 Run
新增迁移、重写 journal 或构造进程归属文件。若现有入口缺少必要的停止事实，则
保留原 Run、租约和具体缺口；本 PR 不把本地复现当成生产关闭证明。

最终候选经过独立完整 PR 审阅、本地 make check、自然触发的精确候选 CI 与保护
检查后合入。源码修复、部署、原审阅最终报告及整个业务完成分别记录。
