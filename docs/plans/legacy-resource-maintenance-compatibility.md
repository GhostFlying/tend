# 历史资源与维护就绪的兼容

## 范围

将旧资源的隔离状态与 runner 升级就绪分开。server、runner、updater 互信，
故障模型为崩溃、回执丢失/重复和并发接单。后来迁移新增字段的缺失，不能直接
证明历史 worker 仍在运行；资源不可复用也不意味着空闲 runner 不可替换。

## 实施

- 对账失败的资源仍进入资源 blocked map，不补停止证明、不创建释放请求，
  不自动授权复用或清理。
- 仅当 server 明确确认任务终态、所有关联 journal run 均 done、无 held/fenced
  或活动 executor，并且 worker/thread/物理资源字段符合旧版空值格式时，
  将资源状态降为维护告警。
- 该兼容路径还要求 journal 无待确认请求或释放意图。当前 worker、缺失 journal、
  活动执行和不确定副作用继续硬阻塞维护。
- 保留资源告警日志，只让真正影响 runner 排空的资源状态阻止全局就绪。
- 增加兼容与负例回归，执行 runner race/vet。不得按日期或真实主机识别旧数据。

现有对账响应还包含活任务已解绑的资源，因此增加可选的任务终态正向事实。
旧 server 未提供该字段时保持原有保守行为，不将非终态解绑误判为历史终态。
