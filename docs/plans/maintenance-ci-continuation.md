# 自维护审计与 CI 结果接续

目标是同一 Issue owner 实际处理原 CI 等待的结果。已有工作、有效提醒和正常等待保持安静；原生或外部不确定结果按原身份核对。实施采用 D201 维护库、单会话、正式 owner 接口和现有 Task/Run，不额外启动生产观察器。

1. 审计记录上次真正处理的变更边界。冻结本次有界输入，按对象合并，标出待复核介入；提交审计、原生失败、中断和重启都不应提前消费它。
2. 在现有 case 命令支持登记已核实的同链问题、读取原对象证据和记录介入；稳定身份处理重入。介入回执与原工作恢复分开保存。
3. 沿正式 CI 结果和原 owner 等待调查接续来源，把明确缺失的交接单次交给维护 Agent。检查活动 owner、现有提醒、暂停/延后和未知外部效果，沿原入口恢复，复查原 owner 已处理同一 CI 事实；证据不足保持待核。
4. 通过故障与健康对照、原回执丢失/重启、有界分页覆盖 CLI 和原业务动作。独立 review、最终本地与 PR CI 覆盖同一候选并完成受保护线性合入。交付范围止于源码合入。

回归用例控制外部 provider 快照与维护模型，用真实领域命令建立等待、完成物理停止并接续，注入原提醒来源缺失。调用现有恢复入口、领取 owner Task、分页面读取原来源并正式处置，全程保留同一等待。覆盖单来源批次回复、直接回复、显式引源通知及无关通知。历史纯报告、人工暂停、明确延后、基线变化、未知回执和恢复后再次丢失分别核验。程序测试另查超过单页容量的 Issue 持续变化时保持首次待处理顺序、冻结期间发生的新变化、失败/重启后的冻结页、相同 UTC 小时重复调用和人工登记后核销。
