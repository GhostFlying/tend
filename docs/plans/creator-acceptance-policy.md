# 创建者决定独立验收（D167）

## 目标与边界

由创建 Issue 的真实 Agent 决定是否要求独立业务验收，顶层创建入口代表主 Agent 或用户的显式决定。调查类工作不因框架而必须再派一个独立验收执行；创建者仍可明确要求。仓库 PR 的独立代码审查、CI 和交付验收不受此政策影响。

## 计划

1. 服务端在 Issue 创建事务中冻结创建者身份和来源，不接受输入声明创建者。可选政策包含是否要求独立验收和理由；缺省、历史缺字段沿用现有强制规则。
2. 提供具有 request_id 和 Issue revision CAS 的具名政策操作。原创建者的真实 Agent 身份可改变后续工作政策，顶层由主 Agent 决定；用户也可通过 owner CLI/Web 显式选择，并记录实际决定者而不替换原创建者。当前执行 Agent、重分配后的 Issue owner 和 worker 不因持有执行权获得免验权。历史来源不明不能补造。
3. 新 Task 创建时冻结当时政策、来源和 revision。免验合同可以省略不使用的验收 Agent 筛选；仅服务端快照控制创建/刷新校验和首次执行分配是否需要 reviewer，旧校验默认严格，既有容量/工作区/身份门仍有效。修改政策不批量取消已有验收、人工决策或责任，也不修改旧 Task。执行者没有写入 Task 免验政策的输入面。
4. 不要求独立验收时，仍必须保存合法且属于当前代次的交付 artifact，并通过既有 context、输入、结果及完成条件检查。领域层直接形成真实完成事实而不制造 passed acceptance。完成通知和责任核对区分真实验收通过与创建者策略，继续保留 merge/deploy 等交付责任。
5. 同步 owner API、生成 schema、具名 CLI（创建、修改、读取与请求恢复）、能力目录、主 Agent 工具和 Web 创建/详情策略。所有端共享来源和权限规则。
6. 回归覆盖真实创建者与伪造/当前执行者拒绝、CAS/同请求重放、legacy、显式 required、调查 optional 的完整合法提交、迟到旧结果、冻结后政策变化不改在途验收、完成通知不假称独立通过及交付证据不降级。

## 存储与兼容

追加迁移 0087：记录创建者来源、Issue 当前政策和 Task 的不可变政策快照。旧独立验收 contract 保留，新的免验 contract 通过统一只读投影参与同样的 owner/pin/代次检查；不创建空 review 子 Issue。完成核对使用独立真实 artifact 记录。交付责任表和它的唯一执行子表在同一迁移内保留原值、状态和外键后重建，新增互斥的真实 artifact 完成依据，旧 acceptance 外键不造假。已有数据不回填免验，不改已提交迁移。runner 原提交与验收协议不增加必填字段，不改变旧请求默认语义。

## 验证与交付

先进行有意义的 domain/app/API/CLI/主工具/Web 定向回归和实际渲染，再独立审查与 CI；完整检查使用统一预算。所有修复通过独立原子 PR 合入，旧生产保持停止，最终集中重建部署。

## 独立审查补全

1. Artifact 与 Issue 结果读面带上原 Task 冻结政策及实际完成状态；结果卡仅在当前合法完成且冻结策略免验时显示免验完成，不能读取 Issue 的后来策略或把历史旧产物冒充当前完成。覆盖原 Task 已免验后 Issue 改回强制、旧产物及正常待验/真实验收结果。
2. 策略编辑器在核对恢复请求前保留原选择与理由；stale、确定失败和网络未知均不能清除用户原输入。使用真实持久 journal 的恢复流程验证 false 值与理由保留，并使定义旁注符合冻结策略。
3. 不存在的政策目标按既有边界映射为 not_found，保存并重放同一 request_id 的确定失败；不将数据库或未知错误一概转成未找到。覆盖 owner API 及原请求回放。

4. CI 补充回归：历史完成 Task 可有产物而未设置 current_artifact_id。SQL 三值逻辑中的 NULL 表示缺少当前完成依据，读面必须保守返回非当前完成且保留原产物读取权限；不把 NULL 扫描成 bool 错误，也不伪造完成。以原 canonical 无 stage 证据用例覆盖。

## 主会话指令一致性

具名 Main 创建顶层 Issue、Issue 创建者创建子 Issue 时，工具说明和持久角色指令必须一致：由真实创建者明确选择独立验收政策与理由，调查和只读报告可选择免验；未声明与历史政策仍强制。当前执行者不能替创建者免验，已有 Task 遵循冻结快照。协调者仍不执行原生工作，合法报告与结果事实、仓库 PR 审查、CI 及交付验收不因此省略。完成指令区分真实 acceptance 依据与已明确免验的 artifact 完成依据，不制造验收通过。部署与受控升级的专门指令不在本次调整范围。

以实际角色指令和具名会话配置回归验证这些边界，避免工具支持免验而 standing instructions 又机械要求创建 review 子 Issue。
