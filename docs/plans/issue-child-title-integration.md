# 长标题候选与已合入子 Issue 进度的最终整合

本次仅刷新同一长标题候选与实际 main 的组合，不改变产品设计或历史验收。

1. 从 provider 和 Git 同时核实 main、原 PR head、已合入的子 Issue 进度提交、
   CI 实际父对象和严格保护规则；原图按冻结摘要下载并查看。
2. 在原分支 rebase 到 fresh main，仅解决真实测试入口冲突。保留
   childTitleOnly、childProgressOnly，以及包含、重叠、滚动和末行点击断言。
3. 对最终候选运行两套定向浏览器回归及必要 Web 检查；复用既有无差异 Go
   完整检查，交由 fresh CI 检验最终组合，不盲重复本地完整检查。
4. 更新原 PR 的 head、base 和验证边界。提交实际 diff、原图、截图及命令日志，
   停在 merge 前，等待独立增量正式验收，不将旧 passed 转授新 head。
5. 只读核实生产批次与 lineage。生产窗口保留给先行交付责任，本次不启动
   更新、排空或重启，不占排空资源等待；将实际状态交协调方排队。
