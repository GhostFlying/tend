# 用量来源的有限重试与永久退役

状态：R1–R3 已实现；R4 验收与独立 review 记录见关联 PR，合入与部署分别验收。
依据：D195、D207；补充 `idle-cpu-lifecycle.md` 的未决来源处理。

## 1. 问题与目标

`thread/start` 返回的原生 history path 是来源定位信息，不是文件已经落盘的证明。
Tend 接收该路径并规范化进程 home 别名，不自行预测 rollout 文件名。
原生 recorder 可以先确定路径、延后创建文件；创建线程不等于发起模型执行。

当前主会话在 `startNativeUsage` 登记来源，中央采集器接管停止后的收尾。
`Discover` 无法找到归属匹配的历史时返回错误；重试间隔达到三十秒后仍无限重试。
server 普通候选仅排除 `writer_stopped=1 AND coverage='caught_up'`；runner journal
也将读取候选和上传请求共同视为工作。因此已停止但从未生成文件的来源不能退出调度。

现场只读检查发现一个已停止、游标为空、无对应 Tend turn 的来源；原登记文件、
对应日期与归档目录及原生线程索引均未找到它，登记后即开始报不可用。
这些证据支持未执行空线程的解释，但不能将缺少执行记录直接作为未发送请求的证明。
本设计不将其自动记为零用量，也不因线上不存在旧部署而删除当前部署中的历史事实。

目标：来源的自动读取可以永久结束，用量完整性独立保留；无可执行读取或待确认上传时
采集器阻塞，不因未知历史存在而周期扫描。已有计账事实、原请求和未知结果保持可恢复。
不增加常驻文件监听、全历史巡检或用量结果缓存。

## 2. 状态与证据

### 2.1 调度和计账分别记录

来源保留原 source ID、归属、path、thread/session、游标及 `coverage`。
增加持久化的采集状态，不把新的调度状态塞进旧 `coverage` 字符串。

| `collection_state` | 含义 | 自动读取 |
| --- | --- | --- |
| `dormant` | 只登记来源，尚无执行；或当前执行已完成、writer 仍可复用且读取已追平 | 无，等待实际执行或停止事实 |
| `active` | 已持久化执行发送意图，或已观测到原生执行/用量事实 | 执行期间保持现有增量读取 |
| `settling` | turn 延后补读，或真实 writer 停止后的最终发现与分页排空 | 按具体收尾截止或读取退避 |
| `needs_reconcile` | 读取失败预算耗尽，但 writer 停止尚未证明 | 无；保留执行与停止未知 |
| `retired` | 当前采集代次的自动读取永久结束 | 无；只有新执行或显式恢复可建立下一代 |

`retired` 记录下列互斥原因，不能仅凭状态计算计账成功：

| `retirement_reason` | 条件 | 用量结论 |
| --- | --- | --- |
| `complete` | writer 已停止，最终发现完成，所有归属文件与分页已读完，无半行或未提交游标 | 原 `coverage='caught_up'` |
| `empty` | writer 已停止，有可信的从未发送执行证明，且无已读记录、用量事实或未决执行/上传 | 无需采集；显示“未执行”，不制造零值用量事实 |
| `unavailable` | writer 已停止，读取失败预算耗尽，尚有缺文件、不可读、损坏或不完整记录 | 保留原 pending/syncing，显示“采集已结束，用量不完整” |

上传是否确认是第三个独立维度：本地 `retired` 不代表服务器已接收。
有原注册或上传 Envelope 时，原请求继续对账；不能因来源退役删除请求或推进上传确认。

### 2.2 必须持久化的证据

在 server 本地来源和 runner journal 中存储等价字段：

- `collection_epoch`、`revision`：当前采集代次及其 CAS 版本。
- `collection_state`、`retirement_reason`、`retired_at`、停止证明、执行请求引用与原代次构成的退役证据。
- `execution_evidence`：`no_dispatch_proven`、`possible`、`observed` 或 `unknown`；
  关联原执行请求，记录是否曾尝试发送，不能由查询不到 turn 推导。
- writer 身份及已有停止证明引用；原 `writer_stopped` 仍只由真实停止事实更新。
- `first_failure_at`、`last_progress_at`、`next_retry_at`、`retry_deadline_at`、错误分类。
  退役、恢复和策略版本写入可审计记录；无变化不反复写这些字段。

`no_dispatch_proven` 只可用于新机制完整覆盖的来源：先持久化执行发送意图并使来源
进入 `possible/active`，事务成功后才向原生端发送。进程在发送前后崩溃均按原请求
对账；发送失败或回执丢失不能回滚成“未执行”。既有来源默认 `unknown`。
恢复/接管原生历史的来源即使本进程未发送，也不能标为 `no_dispatch_proven`。
内部摘要、fork、子 session、continuation 也必须覆盖实际执行入口和归属证据。

`empty` 要求整个来源此前都没有执行可能性，不是“本代没有新增 turn”；已经执行过的
线程即使新代没发请求，也只能按已有历史完整性收尾。

## 3. 生命周期与失败预算

### 3.1 登记、执行和停止

1. 取得原生路径仅登记 metadata，默认 `dormant`，不创建计时器、不做周期发现。
   已有原生历史或恢复线程带未知执行证据，按一次受限恢复任务处理，不能当成空来源。
2. 发起执行前原子持久化发送意图、执行请求引用、来源激活和新代次，再调用原生端。
   执行期间最多两秒读取；新的原生用量事实可唤醒读取。
3. turn 完成保留现有延后补读；追平且无失败时回到 `dormant`，不将 turn 完成当作
   writer 停止。半行、缺文件或未知操作继续按具体未决项处理。
4. 真实停止唤醒 `settling`。有完整空来源证明时直接以 `empty` 退役；其他来源执行
   最终身份验证、关联文件发现和分页排空，完成后以 `complete` 退役。
5. 同一线程后来再次执行或显式恢复时开启新 `collection_epoch`，从原游标接续，
   保留上一代退役原因与证据。新执行不会自动修正以前缺失的计账结论。

已有停止证明只约束原 writer 身份；来源由新 writer 接管执行时登记新身份，不沿用
旧停止证明。开始新的 turn 本身既不是旧 writer 停止证明，也不能抹除旧 writer 的未知。

永久退役约束当前采集代次，不禁止复用原生线程；来源路径变化也不能改变原归属、
丢弃游标或将其他线程的历史并入。未知业务执行的对账不由采集退役终止。

### 3.2 有限自动重试

默认使用现有 2、4、8、16、30 秒按来源退避；本设计提出读取失败的无进展预算为
**五分钟**。该值是调度策略默认值，不是“超过五分钟就证明没有用量”的判断。
策略与时钟可注入；首版不增加用户配置入口。

- 第一次可恢复读取失败时持久化截止；重启、进程收养和重复唤醒不能刷新预算。
- 只有成功提交新的完整记录、有效游标前进或已完成最终验证才算进展；成功扫描目录、
  文件 mtime 变化、相同报错和收到重复事件均不续期。已有半行没有形成完整记录也不续期。
- 有分页数据时按每批 256 条继续排空，不因耗时超过五分钟就丢弃成功读取的积压。
- 正常活跃执行没有新增用量不是失败，不启动预算；只有实际读取失败或无法收尾才启动。
- 截止到达后，writer 已停止则提交 `retired/unavailable`；停止未知则提交
  `needs_reconcile`。两者都退出自动读取候选，不能伪造 writer 停止或上传成功。
- `needs_reconcile` 后收到真实停止证明，可进行一次新的最终收尾窗口；这由新的停止
  事实触发且只适用一次，不由重复通知刷新。反复的通用 wake 不恢复已退役来源。
- 原生路径/归属冲突等不可自动修复错误直接进入 `needs_reconcile`；有停止证明时
  可记为 `retired/unavailable`，仍保留错误。文件截断/替换先走现有校验与读取规则。
- 状态提交失败不能视为已退役。先按来源退避重试原状态提交，不重新扫描历史；
  数据库恢复后原子落盘，再退出调度。网络上传失败使用其独立请求退避，不消耗本地读取预算。

退役或需对账状态只在转换时发一次结构化通知。停止重复 WARN 依靠状态退出调度，
不以限流日志掩盖仍在进行的文件扫描。

## 4. 存储、并发、恢复与通信

### 4.1 唯一所有者与原子提交

主会话继续拥有未停止来源；中央采集器只接管已有真实停止事实的本地来源，runner
独立拥有其本机来源。共享 `nativeusage` 的纯状态派生与错误分类，不共享可变身份。

每次激活、writer 交接及恢复增加代次或 revision。读取任务携带 source ID、epoch、
revision、writer 身份；提交样本、游标和状态前在同一事务校验。旧收尾或旧停止证明
不能覆盖新执行；校验失败不写任何样本或游标，按新代状态继续，不提交半个结果。
退役状态、审计事件及有效的 `token_usage.changed` 在同一事务提交，回滚不通知。

server 新增迁移，为调度状态和 `next_retry_at` 建候选索引；普通候选在 SQL 层排除
`dormant`、`needs_reconcile`、`retired`，不先读完所有历史 JSON 再过滤。
runner journal 对状态建立等价可索引列，`HasUsageWork` 分别判断到期读取和待确认
请求。来源退役不截断注册/上传回执通道；已有 Envelope、request ID、payload、游标
原样重试。退役状态变化本身需要上报时也先持久化请求，不冒充旧用量上传回执。

### 4.2 既有数据恢复

迁移保留 source ID、事实、游标、请求和归属。一次性 SQL 迁移将已停止且 caught_up
映射为 `retired/complete`，不访问文件或重放样本。其余已有来源的执行证据为
`unknown`；只加载已有未决项和实际活跃绑定，不能重新遍历已结清历史。
缺少持久失败截止的旧 pending 在首次受限恢复时固定五分钟预算，后续重启不刷新。
既有布尔停止记录作为既有事实保留，不凭“无活跃任务”新造停止证明。

现场的游标为空、无 turn 的单条来源不能仅凭数据库缺行自动变成 `empty`。
能补足原始无发送证据则按 `empty` 结清；否则在停止已确认且受限恢复仍不可读后
以 `unavailable` 退出，保留未知用量。这不依赖或新增旧部署兼容入口。

### 4.3 runner 状态上报与协议边界

本地读取退役状态与用量样本上传分开。新增能力 `native-usage-collection-v1` 和
host 限定操作 `runner.usage_collection`，携带 run/thread/session、epoch、revision、
采集状态、退役原因与证明摘要；不上传本地路径，不授予业务执行权限。
server 按既有 host 归属验证，仅存该 host 来源的单调状态，拒绝旧代覆盖和身份变更。
server 确认回执与 source 状态、审计通知在同一事务，runner 沿原 Envelope 对账。
用量数据的已收齐证明仍走原 `runner.usage_upload`，不得用退役状态替代。
过时状态的原操作仍取得可恢复的明确过时/已被替代结果，不覆盖当前代次；runner
保存该终态回执并结束该状态请求的重试。只有传输或提交结果仍未知时继续对账，
不能让已确定过时的状态请求成为新的永久重试源。样本上传沿原事实去重规则处理，
不能因状态上报过时而丢弃尚未确认的样本。

新 runner 在 runtime 声明能力，server 只对声明该能力的 hello 返回可选协商确认；
runner 收到确认后才能发送新操作。缺少确认时不发送新字段或操作，不改变现有
upload/registration payload 与覆盖值；本机诊断仍显示真实状态，服务端显示未取得
采集观测而非猜测成功。此为新增可协商能力，不收紧旧有效请求、改变旧默认语义或
递增通信代际；覆盖规定的 N/N−1 严格解码与双方缺少能力测试。
协议实现若需要改变旧字段语义，必须拆出并按仓库规则升级通信版本，不能以本设计
为授权顺便变更。同步生成协议类型与能力目录。

## 5. 查询、CLI 与显式恢复

用量金额、样本和原覆盖结论不因调度退役重算。查询分别显示“自动采集中／休眠／
待对账／已退役”和“已收齐／未执行／不完整”。保留原 coverage 与 pending 字段语义，
增加可选的采集状态汇总及未知观测计数；Web 不把 retired/unavailable 显示为已收齐。
新增字段同步 schema 和生成类型，不新增轮询，仍使用原 owner 事件流。

pending 继续表达尚未证实收齐的用量来源，包含 unavailable 和停止未知；不能因退出
自动调度就减少这个计数。系统验证 empty 后，该来源无预期用量，从 pending 中排除，
单独计入 empty，不用虚构的 caught_up 上传或零值样本消除告警。聚合按原归属的逻辑
来源去重，不能将同 session 下仍未结清的其他来源一并排除。

新增有类型的管理入口，经原 app 请求去重、owner 权限与来源 revision 校验：

```sh
tend usage collection list --state retired --reason unavailable --limit 50 --after "$CURSOR" --json
tend usage collection show "$SOURCE_ID" --json
tend usage collection retire "$SOURCE_ID" --revision "$REVISION" --reason unavailable --request-id "$REQUEST_ID" --json
tend usage collection resume "$SOURCE_ID" --revision "$REVISION" --request-id "$REQUEST_ID" --json
```

这些命令随本次实现提供；部署新版本后可用。list 支持 host、run、conversation、
thread、state、reason 过滤及稳定游标分页。show 返回原身份、采集代次、停止/执行
证据、游标摘要、预算、退役原因和待上传请求，路径只在相应本机诊断中显示。
CLI 的 `--revision` 对应该来源控制记录的 `expected_control_revision`；普通后台
读取另以 epoch/revision 做内部 CAS，不借用 host 或业务任务的控制版本。
retire 仅停止采集；`empty` 原因只由系统验证完整证明后产生，不能由调用者声明。
writer 停止未知时 retire 请求只能转入 `needs_reconcile`，不能写假停止或完整覆盖。
resume 创建新的受限采集代次，不重新派发模型或业务请求，也不改变原样本去重键。
runner 来源由服务端经既有经认证的 runner 控制通道下发带固定请求身份的采集指令，
本机原子应用并回执；离线显示待应用，不能仅改中央投影就宣称本地已经停止/恢复。
指令及回执只对已确认新增能力的节点编码，保持 N/N−1 对旧控制 payload 的严格解码。
管理命令的同 ID 重试恢复原结果，不另开代次；未确认的原上传不阻止处理其回执。

现有 `usage reconcile`、`reconcile-run`、host preview/upload 继续用于受归属约束的
显式补采，不借此自动重新调度所有退役来源。恢复后复用游标与事实去重；损坏或替换
文件走原身份验证，不能靠修改来源路径接入无关 session。

## 6. 实施顺序与验收

1. **R1 共用状态与证据**：追加迁移及 runner journal 索引，纯状态机、epoch/CAS、
   结构化读取错误和持久预算；补齐所有原生执行入口的先记意图后发送。
2. **R2 三类采集器**：metadata 登记休眠、有限补读、空来源/完整/不可用退役与
   停止未知暂停；保留上传队列和旧原请求恢复。
3. **R3 观测与处置**：协商的 runner 状态/指令、有类型 owner 操作和完整 CLI、
   coverage 分开展示、生成类型与事件更新；不引入新轮询。
4. **R4 独立验收与交付**：聚焦回归后，最终候选完整 `make check`、规定的独立
   review、required CI，最新 main rebase 后通过 PR 合入。部署另行明确授权。

回归矩阵：

- thread/start 返回 path 但无文件，始终未发送执行；真实关闭后 empty，虚拟时间
  推进一小时无目录发现、文件读取、游标写入或退役来源周期查询。
- 执行发送意图落盘前失败、落盘后发送前崩溃、已发送回执丢失；均不误判为空，
  原请求不重复执行。接管线程、摘要、子 session 与 continuation 同样覆盖。
- 文件晚于 turn 完成落盘、超过 256 条积压、半行、文件缺失/恢复、权限错误、
  截断/替换/改写与来源不匹配；能读取的分页持续排空，错误到期有限结束。
- 停止失败和未知保持 needs_reconcile；收到真实停止事实只打开一次最终窗口。
  正常活跃但无新用量不触发失败预算。
- 五分钟截止跨重启不刷新；事务失败不提前退役、不反复读文件；有效进展可以继续，
  空扫描、重复 wake、mtime 变化与相同错误不能无限续期。
- 本地退役后已有注册/上传/状态请求仍取得回执；网络故障、乱序状态、回执丢失、
  退役与恢复交错均保留原 Envelope，样本不漏不重。
- 旧收尾与新执行竞争、同 ID 管理命令重试、退役后再次执行、新代读取旧文件；
  旧结果不覆盖新代，空闲对象存在不激活采集。
- 不少于现场规模的已完成、空来源和不可用来源；恢复只读活跃/未决索引，无事实
  变化和到期读取时没有周期历史访问。需要重试的上传单独计数。
- CLI 分页/筛选/完整 JSON、权限、CAS、离线指令及原请求恢复；N/N−1 严格解码、
